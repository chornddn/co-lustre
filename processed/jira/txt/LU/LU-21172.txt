--- Description ---
Problem
On a kernel with CONFIG_DEBUG_OBJECTS_TIMERS, recovery-small test_152 prints this warning on the MDS (3 times, in thread mdt00_001):

ODEBUG: object ... is on stack ..., but NOT annotated.

Cause
lod_ost_alloc_qos() puts "struct semaphore_timer timer" on the stack when down_write_trylock(lq_rw_sem) fails, then sets it up with timer_setup(). Debug objects expects a timer on the stack to be set up with timer_setup_on_stack() and released with destroy_timer_on_stack(). This code came with LU-15393 (f46782b4c7).

There is no harm on a normal kernel; the test still passes. It is only noise on a debug kernel.

Possible fix

timer_setup_on_stack(&timer.timer, process_semaphore_timer, 0);
...
timer_delete_sync(&timer.timer);
destroy_timer_on_stack(&timer.timer);

Environment
Found on a 2.17.57-based build, single node, Rocky 9.8 debug kernel (5.14.0-687 with KASAN, lockdep and debug objects). The code is the same in master (2.17.61).
