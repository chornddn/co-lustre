--- Environment ---
Two-MDT Lustre test filesystem with ldiskfs targets. MDT0 held the parent directory. MDT1 held the child directory.

--- Description ---
Observed behavior

An empty directory, dirx, was placed on MDT1 under a parent on MDT0. With MDT0 read-only and MDT1 writable, rmdir returned EROFS. Immediately afterward, ls -l still listed dirx as d?????????, and direct lookup of the child's FID returned ENOENT.

Backend evidence

	MDT0 retained the dirx directory entry and its allocated local agent inode 912. Both recorded FID [0x24000040a:0x3:0x0].

	MDT1 still had allocated directory inode 29266, generation 994172360, with the matching LMA, two links, and the linkEA backlink to the MDT0 parent. The local REMOTE_PARENT_DIR entry still resolved to that inode.

	The decoded MDT1 Object Index shard contained two other FIDs from the same sequence, but the mapping for the dirx FID was absent. The expected mapping was 29266/994172360.

Expected behavior

If the read-only parent prevents rmdir from completing, the existing directory should remain reachable. In this test the name survived, but the child became inaccessible and its Object Index mapping was absent. The exact failure point and the outcome after recovery of MDT1 remain unverified.

Related issue

LU-20421 documents partial completion in the distributed rename path. This case was observed with rmdir.
