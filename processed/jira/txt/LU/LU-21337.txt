--- Description ---
When a user who is not root runs "lctl get_param .*.stats", lctl

reads the stats over netlink.  In the plain output, the last character

of each counter line is lost, so the last field (sum of squares) is

wrong.  If that value has one digit, the field is empty.  Root (debugfs)

and "lctl get_param -y" print the correct value.

Same counter, read at the same moment:

non-root plain   statfs                              309 samples [usecs] 0 26 534 267
non-root -y      statfs: {samples: 309, units: usecs, min: 0, max: 26, sum: 534, sumsquare: 2670}
root             statfs                              309 samples [usecs] 0 26 534 2670

Cause

print_out_stats() in lustre/utils/liblustreapi_param.c puts a space

before each field (" %s").  At YAML_MAPPING_END_EVENT it then does

buf[len - 1] = '\0' to "eat last white space".  There is no

trailing space, so this removes the last digit of the line.

Fix

Remove the cut and print the line as it is built.

Reproducer

$ lctl get_param -n llite.*.stats > /tmp/root.out        # as root
$ su  -c 'lctl get_param -n llite.*.stats'         # as non-root

Compare the last field of each "samples" line between the two outputs.

Use a counter whose sample count does not change between the two reads.

Note: non-root netlink stats reads can also hit LU-20903 (key table

overflow in lustre_stats_dump()).  The fix for this ticket is only in

userspace, but its test needs the LU-20903 fix.
