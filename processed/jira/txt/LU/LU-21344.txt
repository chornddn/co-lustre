--- Description ---
For a DNE striped directory, /.Trash is a virtual directory whose stripes are the per-MDT Trash Can stubs of the directory's shards. With trash_can_delete_policy=timestamp, a repeated deletion of the same name is stored as .: mdd_trash_insert_obj() keeps the stub chosen for the original name and inserts the timestamped name into that same stub.

A lookup through the virtual .Trash hashes the full timestamped name in lmv_locate_tgt_by_name(), so it can go to another stripe than the stub that holds the entry. Then:

	readdir of .Trash lists the entry, but stat/lookup of it fails: with ENOENT if the stripe it hashes to has a stub, with ENODEV if that stripe has no stub;

	rm -f /.Trash/. returns 0 but leaves the entry;

	other operations by path through .Trash (e.g. restore) are likely affected the same way (not tested).
