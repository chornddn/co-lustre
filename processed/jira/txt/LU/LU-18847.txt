--- Description ---
There is a way to get name duplicates in a striped dir:

Suppose an app  either have a CWD in some plain dir or have an open file descriptor for that dir.

After that, the dir is being migrated and has converted to a striped form for performing the migration.

The initial plain dir is now a stripe of the striped dir, and the app still has a possibility to create objects in the that stripe 

not caring about uniqueness of the file names across the whole striped dir.

Here is an example:

Session1: creating a test dir:

[root@rocky ~]# mkdir /mnt/lustre/testdir
[root@rocky ~]# 

Session2: in another session changing working directory to /mnt/lustre/testdir:

[root@rocky ~]# cd /mnt/lustre/testdir/
[root@rocky testdir]# 

Session1: starting and interrupting dir migration (using gdb):

touch /mnt/lustre/testdir/foo-{01..20}
LD_LIBRARY_PATH=$PWD/../utils/.libs/:$PWD/../../lnet/utils/.libs/:$PWD/../../lnet/utils/lnetconfig/.libs gdb ../utils/.libs/lfs 

Session1: creating a subdir :

[root@rocky tests]# mkdir /mnt/lustre/testdir/a_duplicated_dir
[root@rocky tests]# 

in another session, doing the same

Session2:

[root@rocky testdir]# mkdir a_duplicated_dir
[root@rocky testdir]# 

in Session1, checking the result:

--- Comment (JIRAUSER24100, Wed, 14 Oct 2026 20:36:54 +0000) ---
Status of the 2.18 blocker here: the duplicate-name fixes (64468, 66833) are merged, but the layout version check they added can LBUG the MDS, and nothing posted so far fixes that. 69430 (LU-20831) does not touch this path.

The crash: LASSERT(S_ISREG(...)) in lod_layout_check(), reached via mdt_layout_version_check() from mdt_reint_open(). Six hits with that stack between 2026-06-05 and 2026-07-10, all in racer. None since, but racer has not run file or directory migration by default since 2026-08-02 (LU-17620), so that proves nothing.

Cause: mdt_reint_open() never checks that the parent exists (mdt_reint_create() does, with mdt_object_exists()). A normal open-create is stopped by its lookup, but a volatile open (lfs migrate, lfs mirror extend) takes LCK_NL and skips both lookups, so a parent that was removed or migrated away reaches lod_layout_check() with no type bits and hits the assertion.

Fix: in mdt_reint_open(), after mdt_object_find() for the parent, return -ENOENT (or -ESTALE, which the client retries) when the parent does not exist, as mdt_reint_create() does; and have lod_layout_check() return an error rather than assert on an object that is neither a directory nor a regular file. A test: a volatile open (lfs migrate of a file) racing rmdir or migration of its directory.
