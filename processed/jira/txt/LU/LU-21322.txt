--- Description ---
After a namespace LFSCK finishes with LF_INCOMPLETE (some MDT failed or did not join), lfsck_namespace_double_scan_result() stores status LS_PARTIAL. On the next mount lfsck_namespace_setup() does not handle LS_PARTIAL, so it prints

LustreError: lfsck_namespace_setup()) testfs-MDT0001-osd: unknown lfsck_namespace status 8

and falls through to LS_CRASHED, putting the namespace component on li_list_scan. mdt_postrecov() then auto-triggers it after recovery, so a finished namespace LFSCK runs again at every mount. As other MDTs may not be up yet at that time, the restarted run can again end partial, and the message and restart repeat on each mount.

Seen on 2.17.62: status partial, flags incomplete, the last run started and finished within a second about the time of the mount, failed_phase2: 1.

Layout LFSCK already treats LS_PARTIAL as idle in lfsck_layout_setup(). The namespace setup has missed it since LS_PARTIAL was added.
