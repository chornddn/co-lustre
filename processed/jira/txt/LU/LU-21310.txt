--- Description ---
For a buffered sync write (O_SYNC/O_DSYNC, or a direct write that falls back to buffered IO), the BRW is built and sent from generic_write_sync() inside vvp_io_write_start(), before the OSC cio_start runs. osc_io_write_start() then sets the OSC m/ctime to the current time again, after the BRW was sent. The client shows a newer mtime than the OST has, and after the lock is cancelled stat returns the OST value, so the mtime goes back.

Since commit 4fcbd1af9ec3 ("LU-3321 clio: add pages into writeback cache in batch"), osc_page_touch_at() already sets the OSC m/ctime as each page is committed, before any BRW is built, so the update in osc_io_write_start() is redundant.

Reproducer (new sanity test_39v):

set fail_loc=0x80000412 (OBD_FAIL_OSC_DELAY_SETTIME), do a 4KiB O_SYNC write, stat, then cancel_lru_locks osc and stat again. The second mtime is 1s older.
