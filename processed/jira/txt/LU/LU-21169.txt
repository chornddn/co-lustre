--- Description ---
A client whose nodemap lacks hsm_ops cannot read released files, even when file permissions allow access. Clients should be able to recall and read released files without permission to perform HSM management operations.

Allow explicit restore and automatic recall regardless of whether the client’s nodemap includes hsm_ops. This allows administrators to restrict HSM management to designated nodemaps while preserving users’ access to archived data. Retain role checks for HSM management and copytool operations, coordinator restrictions, and normal file access permissions.

Reproduction steps:

	Configure HSM with a working copytool whose nodemap includes hsm_ops.

	Configure a separate requesting client whose nodemap lacks hsm_ops, with nodemap enforcement active.

	From an authorized client, archive and release two files that the requesting user has permission to read.

	From the requesting client, read the first file to trigger automatic recall.

	From the same client, run lfs hsm_restore on the second file.

Actual behavior: Automatic recall and explicit restore are blocked because the requesting client’s nodemap lacks hsm_ops. The recorded read fails with “No data available.”

Expected behavior: Both restore paths succeed, subject to coordinator restrictions and file-state checks. Normal file permissions govern subsequent reads, while HSM management and copytool operations still require hsm_ops.

Related ticket: LU-18581 — Add an HSM rbac role.
