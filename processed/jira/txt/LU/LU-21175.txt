Looking at the spec file to see what happens when we specify `--with=mofed` we can see that it creates the o2ib_path in the following way:

```

WITH_O2IB=""

%if %{with mofed}

o2ib_path=$(find -H %{mofed_default_path} -type d -name ofed_scripts | xargs dirname)

if [ -z "$o2ib_path" ]; then

echo "ERROR: could not find OFED devel headers"

exit 1

fi

```

The man pages for "find" show: 

```

 -H     Do not follow symbolic links, except while processing the command line arguments. 

```

But as you stated, DOCA 3.2 builds the ofa_kernel through DKMS, which creates symlinks pointing to the build directories:

 

```

/usr/src/ofa_kernel/default        -> /etc/alternatives/ofa_kernel_headers

/usr/src/ofa_kernel/x86_64/  -> /usr/src/ofa_kernel-dkms/x86_64/

```

 

Ultimately, find never reaches its destination and returns nothing. Switching find -H to find -L would follow the links but on a classic MOFED install, we might run into a different type of issue, which is probably why we were using -H. Today, we have the following in our lustre.spec.in file:

```

WITH_O2IB=""

%if %{with mofed}

o2ib_path=$(find -H %{mofed_default_path} -type d -name ofed_scripts | xargs dirname)

if [ -z "$o2ib_path" ]; then

echo "ERROR: could not find OFED devel headers"

exit 1

fi

if [ $(echo $o2ib_path | wc -w) -ge 2 ]; then

echo "ERROR: multiple OFED versions installed"

exit 1

fi

WITH_O2IB="--with-o2ib=${o2ib_path}"

%else

...

```

In the above, %{mofed_default_path} is `/usr/src/ofa_kernel/` (unless --with-o2ib is specified). I think we can fix this by making a small tweak:

```

%if %{with mofed}

o2ib_path=""

for d in %{mofed_default_path}/%{_arch}/%{_kver} %{mofed_default_path}; do

[ -d "$d" ] || continue

o2ib_path=$(find -H "$d" -type d -name ofed_scripts | xargs -r dirname)

[ -n "$o2ib_path" ] && break

done

if [ -z "$o2ib_path" ]; then

... 

```

Since -H follows symlinks that are passed to the command line, this should get us to the desired DKMS tree. 

%{mofed_default_path}/%{_arch}/%{_kver} matches:

   1. classic MLNX_OFED where x86_64/ is a real directory

   2. DOCA with DKMS where x86_64/ is a symlink

 

"%{mofed_default_path}" is the fallback case, which runs the same search that we have today.
