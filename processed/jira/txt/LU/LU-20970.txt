Hi colmstea, I can't put this into the ATM project, so here it is. A nice-to-have, but I'm not sure how much work it would be and I'd rather you spent time on e.g. reducing test clusters to 3/4 VMs than working on this.

With the long test queues recently (over 3600 sessions ATM), it is useful to know the relative position of a build's test sessions within the queue, to make decisions like "should I refresh this patch now to address nits (and move to the end of the queue) or leave it alone since testing will start in an hour". Selecting the Maloo Test Queue URL shows the list of sessions, but that just shows "in the queue" and gives no information about position.

It would be useful if queued sessions could list their relative position from the head of the queue (especially when in the filtered view), since showing the full queue and counting/scrolling to find them is cumbersome, and searching for the build number just shows an identical screenful of queued sessions with no indication of the position.

While horizontal screen real estate is at a premium, the Review, Suite/Test, Started Time, Remaining, Instance columns are all unused for queued sessions, so repurposing some of them would be OK. Maybe Suite/Test or Instance could be the position, Started could indicate when the session was first submitted, and Time Remaining is the rough ETA (either wallclock or wait time) for when the session will start.

Having the Session URL for queued sessions would also avoid a trip through the build link to find which patch this is, if that is easily achieved since we already have the estimated test time for each session index and the query would need to count all the sessions ahead of it anyway to get the number.
