--- Description ---
sanity-quota test_91 ("new quota index files in quota_master") fails with "mkdir failed": after the test stops mds1, removes the quota_master index files with debugfs and restarts mds1, the first mkdir on the client returns EIO. The client log shows seq_client_alloc_seq(): cli-cli-lustre-MDT0000-mdc: Cannot allocate new meta-sequence: rc = -5, then seq_client_alloc_fid(): Can't allocate new sequence: rc = -5. Because test_91 exits before its closing stopall/formatall/setupall, the later subtests of the set (test_92, 94, 95a, 95b, 96, 97b, 97c, 97d, 97g, 98, 300) fail in the leftover state (pool_new failed, setup quota failed, trusted_nodemap mismatch, import is not in FULL state), so this ticket covers the whole test set.

Seen on the branch with the same error and the same seq_client_alloc_seq -5 in the client log:

	lustre-master-next full-part-2, 2026-11-07, test set a8b4b8b4-558d-4ac6-9a43-ae9416147b8d (onyx-156vm220)

	Janitor sanity-quota ldiskfs+DNE rocky8.10, 2026-11-07 and 2026-11-08 (j:71392, j:71395, j:71397)

	review-dne-part-4 for LU-19895 clio change 65094 PS61 (build 135702), session ee04a5ef-8373-463f-b841-a060f5a0dd48, test set 13e24eb2-7483-4054-b7cd-92836c525098. That series only touches the client data path and did not fail this test in its 31 earlier review-dne-part-4 runs.

No existing ticket covers it (LU-19256 and LU-17214 are "quota don't update on QSD", a different error). It looks like a recent regression in MDT0000 sequence allocation after an MDT restart on a DNE ldiskfs configuration; with this error, 5 failures in the last 30 days, 4 of them on 2026-11-07 and 2026-11-08.
