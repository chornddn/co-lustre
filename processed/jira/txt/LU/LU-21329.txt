--- Description ---
LU-18842 added llapi_file_open_volatile_param() and llapi_layout_file_open_volatile(), which first ship in 2.17.59. rustreapi's OpenOptions::volatile() calls them under the LUSTRE_2_18 feature.  lu-version sets that feature for any installed 2.17.50 or later, so a build against 2.17.50-2.17.58 headers fails:

error[E0425]: cannot find function `llapi_file_open_volatile_param` in this scope
error[E0425]: cannot find function `llapi_layout_file_open_volatile` in this scope

Reproduced with master's rustreapi and the 2.17.53 headers.

The fix does what LU-20663 does for the stripe pattern union: probe the generated bindings rather than the version.  lustreapi-sys/build.rs looks for llapi_file_open_volatile_param and passes the result to rustreapi as links metadata (DEP_LUSTREAPI_HAS_FILE_OPEN_VOLATILE). rustreapi/build.rs turns it into the has_file_open_volatile cfg.  A layout test checks that a stripe pattern given to OpenOptions reaches the file through both open() and volatile().

Depends on LU-20663.  In Gerrit it is stacked on LU-6142, which is on LU-20210, LU-20664 and LU-20663.  LU-20208 (docs.rs) skips bindgen, so whichever of the two lands second must set this cfg from the docs snapshot too.
