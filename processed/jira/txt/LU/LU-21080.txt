--- Description ---
sanity-sec test_27c: the server node crashed with a NULL pointer dereference in ping_evictor_main (ll_evictor thread), CR2 = 0000000000000030.

Config: review-dne-zfs-part-2, el10.1 ZFS servers (6.12.0-124.56.1.el10_1_lustre), master 43a09f028a (2.17.60_73), session 0572e44c-4787-43a2-ade7-95c8622c84a9, node onyx-141vm40.

Console log:

BUG: kernel NULL pointer dereference, address: 0000000000000030

RIP: 0010:ping_evictor_main+0x1a6/0x8c0 [ptlrpc]

Comm: ll_evictor

Call Trace: ping_evictor_main The faulting load is obd->obd_type->typ_name (the LUSTRE_OSP_NAME strcmp) right after list_first_entry(&pet_list, ...). R13 holds the address of pet_list itself, so the pet_list was empty when the thread took its first entry: obd was derived from the list head and obd_type read as NULL. The loop only waits for a non-empty list or PET_TERMINATE, and ping_evictor_main() is the only place that removes entries, so the list was emptied (or the state flipped) between the wait and the first-entry read, for example two evictor threads alive across a ptlrpc ping_evictor_stop()/start() cycle (the node had reloaded ptlrpc several times earlier in the session). The code is not touched by the tested patch (LU-12669, change 69392); the crash happened in sanity-sec while the earlier sanity-lfsck test_2e had also logged an unrelated osd_index_it_key memcpy field-spanning WARN.

Frequency: test_27c failed 2 of 2369 review-dne-zfs-part-2 runs since 2026-10-01 (one CRASH, one TIMEOUT); no existing LU ticket mentions ping_evictor_main with a NULL dereference (LU-18669 and LU-18569 are Autotest timeouts of this test).

Suggested fix: in ping_evictor_main() recheck list_empty(&pet_list) under pet_lock before list_first_entry() and continue the loop when empty.
