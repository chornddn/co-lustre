--- Description ---
A site that used `lctl set_param -P` with a parameter name from 2.16

loses the setting after an upgrade, with no message. LU-8066

(commit 43e1ae99ff) moved the mdc parameters `mdc_lsom` and

`mdc_dom_min_repsize` to sysfs as `lsom` and `dom_min_repsize`.

Steps to reproduce:

1. On a master (2.17.55 or newer) client, run

   `lctl set_param -P mdc.*.mdc_lsom=Off` and

   `lctl set_param -P mdc.*.mdc_dom_min_repsize=4096`. These two names are the

   2.16 names.

2. Remount the client.

3. Read the parameters under their new names.

Result: `set_param -P` returns 0. After the remount, the settings do

not apply, and the console shows no message. The control parameter

`max_rpcs_in_flight=16` keeps its name, and it applies.

Expected result: the old name applies under the new name, and lctl

prints one warning for each renamed parameter.

Both `set_param -P` paths end in the userspace command `lctl

set_param`. The udev rule runs it, and the upcall runs it. lctl already has a

table of deprecated parameters in `setparam_check_deprecated()`. A

rename map there covers both paths with no kernel change. The kernel

rename table `cfg_interop_param` covers only `conf_param` records.

Tested on 1 VM node: the loss occurs without a fix. With a 56-line

prototype rename map, both 2.16 names apply after the remount.
