--- Description ---
sanityn test_80a fails with "migrate open files should failed with open files" when the sanityn script comes from a b2_15 (2.15) client against master servers (clientversion=2.15 interop).

The b2_15 test_80a has no version gate: it expects "lfs migrate -m" of a directory containing an open file to fail. Since LU-18806 (servers >= 2.16.50) migrating open files succeeds, so the old script's expectation is wrong and the test fails every time it runs in that configuration. The master script already gates on MDS1_VERSION >= 2.16.50.

Seen on change 70562 patchsets 1 and 2 (session 8a02541d-225b-454b-a8ed-d5dc1c150dbf, subtest d45b03e1-e7a6-4b1a-bc5c-bb5576748f91), change 67227 patchsets 7 to 9 (Sept 2026), and change 62059 (2025). Servers were 2.17.61 builds. The failing path is not touched by 70562: the test opens the file once with multiop O_c and has no exec open.

Possible fix: a lustre/tests/except/sanityn.ex on master so that 2.15 client scripts skip 80a against servers >= 2.16.50. An existing hidden EX ticket (EX-12526) may cover the same error but could not be read.
