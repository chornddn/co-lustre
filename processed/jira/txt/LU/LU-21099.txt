--- Description ---
Linux 7.2 includes commit 21c05ca88a54 ("workqueue: Add warnings and ensure one among WQ_PERCPU or WQ_UNBOUND is present"). alloc_workqueue() now WARNs, with a full stack trace, when it is given neither flag, and then sets WQ_PERCPU itself. WQ_PERCPU was added in 930c2ea566af (v6.17).

Seen on every module load on Amazon Linux 2027, kernel 7.2.8 (x86_64 and aarch64), with the 2.15 client:

workqueue: cfs_rh is using neither WQ_PERCPU or WQ_UNBOUND. Setting WQ_PERCPU.
WARNING: kernel/workqueue.c:5851 at __alloc_workqueue+0x468/0x4d0
 ... libcfs_init+0xab/0x2b0 [libcfs]

Behaviour is unchanged, since per-CPU was already the default, but the WARN panics hosts running with panic_on_warn.

On master these alloc_workqueue() callers pass neither flag:

	lustre/obdclass/hash.c: cfs_rh

	lnet/klnds/kfilnd/kfilnd.c: kfilnd_wq

	lustre/ptlrpc/gss/gss_svc_upcall.c: gss_cleanup_wq

	lustre/osd-ldiskfs/osd_handler.c: %s-integrityd

Fix: pass WQ_PERCPU explicitly, with a configure check that defines WQ_PERCPU as 0 on kernels that lack it.
