--- Description ---
In DNE, update llog appends to a remote plain llog can overwrite the previous record. The llog header then has a bit set for a record whose bytes were overwritten, and the next recovery fails for that target:

  Sequence:

  1. llog_cat_new_log() creates a plain llog on the peer. osp_md_create() caches attrs {size 0}; osp_trans_stop() does not wait for the reply.

  2. Append A: llog_osd_write_rec() uses the cached size: header (bit 1) at 0, record #1 at 32768. Queued. osp_md_write() advances the cached size.

  3. The create reply arrives: osp_create_interpreter() -> osp_obj_invalidate_cache() clears la_valid but does NOT set opo_stale, so the dt_object_stale() check in llog_osd_write_rec() does not fire.

  4. Append B: dt_attr_get() -> osp_attr_get() -> osp_remote_sync(), a synchronous RPC not ordered with the update queue. The peer has not run A yet and returns size 0. B takes the empty-file path: record #2 at 32768.

  5. The peer runs A, then B. #2 overwrites #1; bit 1 stays set.
