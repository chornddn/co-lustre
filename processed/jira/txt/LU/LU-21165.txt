--- Description ---
jt_del_ost() stores the getopt_long() return value in a "char c". On architectures where plain char is unsigned (aarch64, ppc64le) c never equals -1, so the option loop runs past the last option into "default: return CMD_HELP", and "lctl del_ost -n -t FSNAME-OST0000" always prints the usage message.

conf-sanity test_123ah fails on aarch64 servers with:

  del_ost --dryrun failed with 4

x86_64 is not affected because char is signed there. The variable should be an int.

Introduced by commit 1121816c4a4e ("LU-7668 utils: add lctl del_ost").
