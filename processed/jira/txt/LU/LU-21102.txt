--- Description ---
sanity-hsm test_12h ("Restore a released file implicitly from a second node") can fail with "request on  is not SUCCEED on mds1" without any restore being attempted.

The test copies /etc/hosts of the first client into the file, archives and releases it, then runs `do_node $CLIENT2 diff -q /etc/hosts $f`. That compares the second client's own /etc/hosts with the file. When the two nodes' /etc/hosts differ in size (here the file is 758 bytes), GNU diff -q reports "differ" from the sizes alone and never reads the file, so no layout intent or RESTORE request is generated. The following wait_request_state $fid RESTORE SUCCEED then times out after 200s.

Evidence, session d8974ad4-4913-482b-b2ad-b1164dc5fccb (review-dne-part-4, el9.7 ldiskfs, tcp), subtest 1d3d0a9d-d73f-4059-8747-c2554cf3f420:

	test log: "diff -q /etc/hosts .../f12h.sanity-hsm" exits 1 at once, "Files /etc/hosts and .../f12h.sanity-hsm differ", and the RESTORE action never appears in mdt.*.hsm.actions;

	CLIENT2 debug log: the diff process (pid 91677) only does getattr on the released file (i_size 758); no read, no OST RPC, no layout restore;

	MDS: the release completed (mdt_hsm_release, old objects destroyed).

Other earlier "is not SUCCEED" failures of test_12h (e.g. change 55618 ps8) wait on the ARCHIVE request instead and are a separate cause. Fix: have CLIENT2 compare against the same data the file was created from (e.g. copy_file from a file both nodes share, or compare with cat | cmp against a saved copy), not its own /etc/hosts.
