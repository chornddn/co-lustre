paf0186, I believe 9fc5497ecb ("LU-19536 obdclass: use wait queue for DIO copy sync", https://review.whamcloud.com/62095) lets an unaligned DIO write send bounce pages that were never filled from userspace or zeroed. I found it while reviewing a backport of that patch. Current master (54dc726b562) still has it, and I found no follow-up fix in master or in the open changes on Gerrit. A reproducer with a fail_loc and a sanity test is below.

What happens

When the copy loop of __ll_dio_user_copy() stops part way for a write, with -EINTR on a fatal signal or with -EFAULT after more than two short copies, the end of the function still marks the copy done and stores and returns the number of bytes copied so far (lustre/obdclass/cl_io.c in master):

	/* For write operations, update state and wake any waiting threads */
	if (rw == WRITE) {
		unsigned long flags;
		ssize_t result = original_count - count ?
			original_count - count : status;

		spin_lock_irqsave(&sdio->csd_write_lock, flags);
		/* Store result (bytes copied or error) for waiting threads */
		sdio->csd_write_status = result;
		/* Mark copy as complete (successfully or not) */
		sdio->csd_write_copied = true;
		...
	}

	/* the total bytes copied, or status */
	RETURN(original_count - count ? original_count - count : status);

osc_build_rpc() only checks for a negative return (lustre/osc/osc_request.c):

		if (sdio && sdio->csd_unaligned && sdio->csd_write) {
			rc = ll_dio_user_copy(sdio);
			if (rc csd_write_copied);
		}

So the BRW for the whole sdio is sent with the rest of the bounce pages never copied from userspace, and the DIO reports success. The bounce pages come from the obd page pool (ll_allocate_dio_buffer() calls obd_pool_get_folios_array()), which does not zero them. Before 9fc5497ecb this case left csd_write_copied clear and hit the LASSERT(), so it was at least loud.

How it can be reached

	-EFAULT: part of the user buffer becomes unreadable after the up-front fault_in_iov_iter_readable(), e.g. another thread of the application unmaps or mprotects it (also hwpoison or userfaultfd). For parallel DIO the copy runs later in ptlrpcd with the user's mm.

	-EINTR: only when the submitting thread does the copy itself (non-parallel DIO) and gets a fatal signal. In ptlrpcd and in the ll_ucp kthread fatal_signal_pending(current) is false, so a signal to the process does not interrupt the copy there.

Possible fix

	For a write the copy is all or nothing, as the BRW covers the whole sdio: if count is not 0 after the loop, store a negative status in csd_write_status (-EFAULT if status is 0) and return it instead of the partial count. Reads can keep the partial count.

	Keep "copy finished" apart from "copy succeeded" (a failed flag, or set csd_write_copied only for a full copy), so that waiters return the stored error instead of sending BRWs or redoing the copy from the already advanced csd_iter.

	In osc_build_rpc(), fail the extent if the return is negative or differs from csd_bytes, and keep the LASSERT() for the success path only.
