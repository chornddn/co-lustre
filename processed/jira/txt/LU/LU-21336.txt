--- Description ---
h2name_or_ip() in test-framework.sh builds a NID for each address from

"hostname -I" on the node.  The link-type filter added in LU-20173 only

removes addresses of the wrong link type.  On a node with more than one

ethernet interface it still returns several NIDs, but LNet listens on

only one of them.  A client given an extra NID as a failover peer of a

target retries it forever.

The workaround is to put the data IP in ${facet}_HOST instead of the

hostname, because h2name_or_ip() maps a literal IP to exactly one NID.

This makes the node lists harder to read and breaks name-based lookups

in test-framework.  For example, node_fstypes() compares its argument

with facet_host(), so yaml.sh reports file_system: "NA" for every

server.

LNet already knows the right NIDs: host_nids_address() asks

"lctl list_nids".  h2name_or_ip() should use it and fall back to

"hostname -I" only when LNet is not loaded.
