--- Description ---

Hypothesis

The ldiskfs inodes still in kernel cache reference block preallocations using different ext4 groups distributed on all the volume surface. The group bitmaps does not seems to be in cache, so a read is needed (due to cache eviction?). This is causing random 4K IO to read all the bitmaps.

Here some preallocation information:

The s_stripe = 1024 value appears to be a FS formatting error: the admin intended to define a stripe width of 1 MB, but the unit used is ext4 blocks, which results in 4 MB.

This means that the minimum allocation size is 4MB which not helping our issue.

# cat /proc/fs/ldiskfs/sdb/prealloc_table
1024 2048 4096

I have checked some inode preallocation, most of time, there is 1 preallocation per inode. These preallocation are usually at an offset of 1024-8192 blocks (non aligned write on small files).

Reproducer

I have been able to reproduce this type of behaviour on the OSTs after the maintenance window (~100000 prealloc entries in slab):

echo 2 > /proc/sys/vm/drop_caches

This took ~6s

On another OST:

echo 1 > /proc/sys/vm/drop_caches
echo 2 > /proc/sys/vm/drop_caches

 This took ~15min.
