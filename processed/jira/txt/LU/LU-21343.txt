--- Description ---
Problem

For fid2path, mdt_trash_path_check() refuses a trash path under another nodemap's directory, but it only runs when the walk in mdt_path_current() reaches LU_TRASH_FID. The walk stops earlier at the root FID that the client sends (gf_root_fid).

On MDT0001 and above, that root FID is not checked: exp_root_fid is only set by mdt_get_root(), which lmv_get_root() sends to MDT0000 only, so the -EXDEV check in mdt_fid2path() is skipped there. __ll_fid2path() sends the FID of the inode the ioctl is issued on as the root. So a client of a confined nodemap that issues OBD_IOC_FID2PATH on an fd of .ltrash/MDT0001 gets the path below that directory, including another nodemap's directory name, the parent FID and the file name. fid2path is not gated by the byfid_ops role. File contents are not exposed: opening by FID still needs byfid_ops.

Possible fix

For a client of a confined nodemap, when the walk stops at the client's root FID instead of LU_TRASH_FID, walk up from that root by linkEA; if it reaches LU_TRASH_FID, refuse with -ENOENT. A prototype (mdt_trash_root_check() in mdt_path_current(), a multiop "h" command for llapi_fid2path_at() on an fd, and a check in sanityn/test_117zh) was tested on 4 MDTs: the fd of .ltrash/MDT0001 then gets ENOENT, the owner nodemap still resolves its own entries with lfs fid2path, and sanityn 117zh/120i pass. It also refuses the owner nodemap a path relative to a directory inside the trash, which lfs never asks for.

Alternatives: set exp_root_fid on every MDT so the existing -EXDEV check applies everywhere, or check the root against the nodemap's fileset roots.
