--- Description ---
recovery-small test_130a and test_130b fail with EIO on 'lfs mkdir -i2 -c1 -H crush2/all_char' in review-dne-zfs-part-5 (zfs, 4 MDTs, 2 MDS), right after test 113.

Test 113 sets fail_loc=0x80000157 (OBD_FAIL_MDS_LDLM_REPLY_NET) on the MDS nodes for about 60s. MDS-MDS and LWP connections lose their replies in that window. On the MDS (onyx-158vm132), as 130a starts, the log shows:

  lustre-MDT0000: Received MDS connection from 10.240.24.85@tcp, removing former export from 10.240.24.46@tcp

  lustre-MDT0000-osp-MDT0002: operation out_update to node 0@lo failed: rc = -107

  lustre-MDT0000-osp-MDT0002: This client was evicted by lustre-MDT0000

  osp_attr_get() lustre-MDT0000-osp-MDT0002: osp_attr_get update error [0x200000007:0x1:0x0]: rc = -5

The same eviction of the MDT0002 osp import happens at the start of 130b. A mkdir -i2 needs MDT0002 to talk to MDT0000, so it returns EIO.

Test 113 only checks client connections (lfs df) after clearing the fail_loc, so the MDT-MDT imports can still be recovering when the next test starts. The failure is a test ordering race, not a code bug: tests that stripe a directory onto another MDT should wait for MDT-MDT connections after test 113 (for example wait_osp_active or similar).

Seen once in 4424 recovery-small runs over 30 days (rate 0.0002), on change 64546 patchset 12, whose diff touches only llapi nodemap code. Failing test sets: https://testing.whamcloud.com/test_sets/7e9ef4c7-5cd2-47d8-88df-99a35f75f224
