--- Description ---
After a file is chowned, a fallocate from a client that still has the file open with the old owner cached still charges the quota of the old owner, and the new owner is charged nothing.

	The previous owner is charged for a file they no longer own, and the new owner's usage is not counted against their quota.

	The mismatch stays until the file is chowned again. A chown to the same owner restored the OST object (tested, see below).

	 

	 

	It needs an fd opened before the chown. A fresh open after the chown does not reset the owner (tested, see below).

	A plain write and an ftruncate through the same stale fd do not reset the owner (both tested, see below). Only fallocate does.
