--- Environment ---
Client: lustre-client 2.15.6 on Linux 6.18 (x86_64). Servers: Lustre 2.15, ZFS-backed MDT, HSM with changelog-driven copytool/archiver.

--- Description ---
When a client is evicted by the MDT while it holds an archived file open for write, the final modifications made by that client are never reported to changelog consumers (e.g. a copytool policy engine), so the archive copy stays stale.
  
  Sequence:
  1. Client opens file F for write, writes data. F is archived while open (hsm_state: exists archived).
  2. MDT evicts the client (e.g. lock callback timeout, or lctl set_param mdt.*.evict_client=nid:). mdt_export_cleanup() -> mdt_ctxt_add_dirty_flag() sets HS_DIRTY on F (LU-3677), but the session ucred is zero-initialized, so uc_enable_audit == 0 and mdd_changelog_enabled() suppresses the CL_HSM record. F becomes "exists dirty archived" with no changelog record.
  3. The client reconnects; the application keeps writing (data goes to OSTs) and then closes F.
  4. The close RPC carries MDS_DATA_MODIFIED with the pre-eviction open handle. mdt_close_internal() returns -ESTALE ("no handle for file close"). mdc_close() resets -ESTALE to 0 because the open was committed (bug 3633 logic). ll_prepare_close() already cleared LLIF_DATA_MODIFIED, so the modification is lost. Even if the MDT had processed the close, HS_DIRTY is already set, so no CL_HSM record would be emitted.
     
  Result: no CL_HSM (dirty) record is ever written for the post-archive writes;  a changelog-driven archiver never re-archives F. Archive copy size
