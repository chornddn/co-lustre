LU-20443 llite: use atomic state machine for statahead threads

Replace smp barrier based synchronization on sai_task and unsafe
access to lli_sa_enabled with atomic state machine to fix race
conditions between start_statahead_thread() and
ll_deauthorize_statahead().

This introduces sai_task_st atomic state field and new helper
functions (ll_sa_thread_should_stop, ll_sa_thread_stop,
ll_sa_thread_stopall_locked, ll_sa_thread_wait_event,
ll_sa_thread_wait_stop) to centralize thread state management,
improving code maintainability.

This cleanups the way to handle lli_sax references.
ll_sai_put() now automatically puts a sax reference: a sax reference
is taken for each sai allocated, so it makes sense to put a reference
when a sai is freed. It avoids to handle sax references independently
in ll_deauthorize_statahead() or ll_statahead_thread().

Fixes a possible use-after-free in revalidate_statahead_dentry() on
@info when sa_get returns -EINVAL.

lli_sai field is removed to use lli_sax->sax_sai_list for all the
cases. A sai reference can be obtained via ll_sai_get(dir).

lli_sa_pattern is now reset on context release to avoid races in
stataheads threads.

Fix race conditions in start_statahead_thread()/ll_ioctl_ahead() on
lli->lli_sa_pattern.

Fixes: b977caa2dc7d ("LU-15660 statahead: statahead thread doesn't stop")
