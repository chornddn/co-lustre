--- Commit Message ---
LU-20534 mdd: add single-stripe layout swap

Allow swap_layouts to exchange a single OST object between two
files, selected by OST object FID. Negotiate support with
OBD_CONNECT2_ONE_OBJ_SWAP and add llapi_fswap_layout_fids() for
tools such as lfs migrate.

Skip mdd_dom_fixup() and HSM xattr rewrite for SINGLE_STRIPE, and
reject CLOSE|SINGLE_STRIPE. Find objects in both COMP_V1 and SEL
layouts.

Add a new LL_IOC_LOV_SWAP_LAYOUTS_FID ioctl backed by a 64-byte
struct lustre_swap_layouts_fid (adds sl_fid1/sl_fid2) instead of
growing the existing 32-byte struct lustre_swap_layouts, so
LL_IOC_LOV_SWAP_LAYOUTS and old userspace keep working unchanged.
ll_file_ioctl() accepts both ioctls; the plain one is rejected for
SINGLE_STRIPE. wiretest/wirecheck cover both struct layouts.

Mask SWAP_LAYOUTS_MDS_RELEASE in ll_swap_layouts() and
mdt_swap_layouts() so clients cannot invoke the server-only
HSM-release path and skip uid/gid checks.

mdt_swap_layouts() now calls mdt_init_ucred()/mdt_exit_ucred() so
permission checks use real client credentials instead of an
uninitialized ucred. mdd_layout_swap_allowed() allows a uid/gid
mismatch under CAP_FOWNER, so root can migrate/replace stripes on
files it does not own.

mdd_swap_single_stripe() rejects mismatched lmm_stripe_size between
the two LOV components (-EINVAL) to avoid corrupting the RAID0
mapping. Object size lives on the OSTs and is not validated here;
llapi_fswap_layout_fids() documents that the caller must supply a
stripe of matching size so file size does not change.

AI code review results below, please doublecheck

Some serious concerns, see inline comments. The main ones: the new stripe index is bounded only by lmm_stripe_count, which is not the size of the on-disk objects array for an uninstantiated component, so a client-supplied index can read and write past the end of the layout buffer on the MDS; the client now forwards the raw userspace flag word to the server, which lets a user set the server-only SWAP_LAYOUTS_MDS_RELEASE and skip the uid/gid check; and growing struct lustre_swap_layouts changes the value of LL_IOC_LOV_SWAP_LAYOUTS itself, since the size is encoded by _IOW(). Test coverage is also thin - sanity-ec test_35a only exercises composite/composite and never checks a bad comp_id, an out-of-range stripe index, a simple v1/v3 layout, or a file with no layout, which is where most of the inline findings live.
