--- Commit Message ---
LU-20534 mdd: add single-stripe layout swap

Allow swap_layouts to exchange one OST object between two files,
selected by OST object FID. Negotiate with OBD_CONNECT2_ONE_OBJ_SWAP
and expose llapi_swap_stripe() for tools such as lfs migrate_stripe.

Skip mdd_dom_fixup() and HSM xattr rewrite for SINGLE_STRIPE so MDT
DoM data and archive state stay with the parent file. Reject
CLOSE|SINGLE_STRIPE; find objects in COMP_V1 and SEL layouts.

Test-Parameters: trivial

(15 comments)

AI code review results below, please doublecheck

Some serious concerns, see inline comments. The main ones: the new stripe index is bounded only by lmm_stripe_count, which is not the size of the on-disk objects array for an uninstantiated component, so a client-supplied index can read and write past the end of the layout buffer on the MDS; the client now forwards the raw userspace flag word to the server, which lets a user set the server-only SWAP_LAYOUTS_MDS_RELEASE and skip the uid/gid check; and growing struct lustre_swap_layouts changes the value of LL_IOC_LOV_SWAP_LAYOUTS itself, since the size is encoded by _IOW(). Test coverage is also thin - sanity-ec test_35a only exercises composite/composite and never checks a bad comp_id, an out-of-range stripe index, a simple v1/v3 layout, or a file with no layout, which is where most of the inline findings live.
