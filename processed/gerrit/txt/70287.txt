LU-14319 flr: handle foreign mirrors in more places

A file attached to PCC-RO has a foreign HSM mirror with no data in
Lustre, and some code would handle it like a data mirror:
- lov_foreign_hsm_to_le() wrote the archive ID and version of the
  buffer to itself, so these fields of an HSM component were left
  with stale buffer contents on disk;
- a client setting a layout taken from such a file, e.g. a copytool
  restoring the striping of an archived file, or "lfs setstripe
  --copy", would get -EINVAL, as lod_qos_parse_config() parsed the
  foreign component as a plain one;
- "lfs mirror extend -N" would use the foreign mirror as template
  for the new mirror and fail with -EINVAL;
- "lfs mirror resync" would try to copy data into a stale foreign
  mirror;
- the MDT would not see a released file with a foreign mirror as
  released, and return neither its size nor its block count.

Fix lov_foreign_hsm_to_le().  Drop foreign mirrors covering [0, EOF)
from the layout of a new file set by a client, in the lov_foreign_md
form or as the plain component with LOV_PATTERN_FOREIGN that
llapi_layout_to_lum() makes of them.  Skip them in
llapi_layout_get_last_init_comp(), which also changes what "lfs find
--printf %L*" prints for such files, and in the stale components that
"lfs mirror resync" copies and reports as resynced, and do not clear
the stale flag of an HSM or PCC mirror at RESYNC_DONE.  Skip foreign
components in
mdt_hsm_is_released(), as mdt_hsm_set_released() does.  Also swab
all the components of a layout after a foreign one in
lustre_swab_lov_comp_md_v1().

So "lfs mirror resync" of a file whose only stale mirror is a
foreign one returns without a change, and leaves the file in the
WRITE_PENDING state until that mirror is updated.  "lfs migrate" of
a file with a foreign mirror drops the mirror instead of failing.

Add sanity-pcc test_53 to check mirror verify, setstripe --copy and
mirror extend of a PCC-RO file.
