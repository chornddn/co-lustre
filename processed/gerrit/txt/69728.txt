LU-20606 lfs: find --device --speed

Add --speed OBJS_PER_SEC to lfs find over a target. It sets
lfsp_max_rate, so the scan reads at most OBJS_PER_SEC objects per
second. 0 is no limit, the default. The name and unit follow
lctl lfsck_start --speed. A sweep with --local or --fsname reads one
target at a time, so the limit holds for each target in turn.

OBJS_PER_SEC is a decimal number up to UINT32_MAX. A sign, a suffix,
or a value that does not fit is refused. strtoull() would take "-1"
and wrap it to a huge value, so the value must start with a digit.

The value is kept in struct find_param's unused fp_unused_u32, renamed
fp_speed, so the size of the struct does not change. Only lfs reads
it.

A walk of a mounted directory does not use the scan code, so it
refuses --speed, as it refuses --internal. It refuses --speed 0 too:
fp_speed_set records that the option was given.

conf-sanity 300a runs lfs find --device --speed over the MDT and
checks that the answer is the same as without it, and that it takes
at least as long as the limit allows. It also checks that bad values,
and --speed without a target, 0 included, are refused.
