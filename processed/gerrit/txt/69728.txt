LU-20606 lfs: find --device --max-rate

Add --max-rate RATE to lfs find over a target. It sets lfsp_max_rate,
so the scan reads at most RATE objects per second. 0 is no limit, the
default. A sweep with --local or --fsname reads one target at a time,
so the limit holds for each target in turn.

RATE is a decimal number up to UINT32_MAX. A sign, a suffix, or a
value that does not fit is refused. strtoull() would take "-1" and
wrap it to a huge rate, so the value must start with a digit.

The value is kept in a new field at the end of struct find_param,
fp_max_rate, next to fp_device. Only lfs reads it.

A walk of a mounted directory does not use the scan code, so it
refuses --max-rate, as it refuses --internal.

"--max" was a unique prefix of --maxdepth. It is now ambiguous and is
refused. "-maxdepth", "--maxd" and "-D" still work.

conf-sanity 300a runs lfs find --device --max-rate over the MDT and
checks that the answer is the same as without it, and that it takes
at least as long as the rate allows. It also checks that bad values,
and --max-rate without a target, are refused.
