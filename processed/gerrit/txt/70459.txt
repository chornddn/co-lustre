LU-21061 lod: give new stripes of a split dir its default LMV

The MDT of a stripe of a striped directory takes the default LMV from
the stripe for the subdirectories and files it makes there, but the
stripes that a split adds get none, while the master and the old
stripes keep it.  A plain directory that is split keeps its default
LMV only on its inode, which becomes stripe 0, since MDD does not move
it to the new master (LU-13560).  New subdirectories and files lose
the default layout, and with it the pool of the tree: their files get
objects outside the OSTs of the pool.  The stripes that a split adds
are also allocated on any MDT, not only on those of the pool.

In lod_dir_declare_create_stripes() and lod_xattr_set_lmv(), set the
default LMV of a directory being split on its new stripes, as
lod_split_dmv() reads it from the master.  For a plain directory, take
it from stripe 0 if it names a pool, for any MDT and with a stripe
count of at least 1, and set it on the master and stripe 0 too.  In
lod_dir_declare_layout_split(), allocate the new stripes from the MDTs
of the pool of the default LMV, or else of the request, as for a new
directory, as many as the pool has left.  An automatic split of a
directory with a stripe on every MDT of its pool gets -EALREADY, as
for a directory split already.  mdt_auto_split() then sets
mot_auto_split_disabled on the directory, so that
mdt_getattr_internal() stops queueing it and its locks are not taken
again at every getattr while it stays cached, until a later split or
merge moves its entries again (mdt_restripe_migrate_add()).

Add ost-pools tests 35i-35l: splits by hand and auto-splits of plain
and striped directories, in one pool and in small pools nested in a
big one.
