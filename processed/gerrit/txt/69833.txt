LU-20903 obdclass: fix stats key table overflow

A Netlink stats request, which non-root lctl get_param uses
for exports stats, builds a key table that is two entries
larger than the buffer allocated for it. The table is
sized for LUSTRE_STATS_ATTR_MAX + ls_num - 1 keys, but
indices up to LUSTRE_STATS_ATTR_MAX + ls_num are written,
so 32 bytes are written past the end of the allocation.
Since lkl_maxattr is also one too large, the reply carried
a key for a dataset attribute that is never sent.

Size the table for all of its slots and set lkl_maxattr to
the last dataset attribute actually used. Also copy the
fixed keys one by one, since a struct assignment does not
copy the flexible array member and compilers differ in
whether they copy the keys anyway.

Add sanity 104e to run exports stats queries as a non-root
user against the MDS and OSS. It names each export, since
the Netlink source filter cannot glob over the dots of an
IPv4 NID.
