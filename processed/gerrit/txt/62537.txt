LU-18756 ofd: repair missing parent FID on OST read

An OST object gets its parent FID (trusted.fid) only when a client
writes to it, truncates it or changes its ownership. Objects that
never received such an RPC, e.g. the unwritten stripes of a sparse
file, have no parent FID, so scanning an OST cannot map them back to
the MDT file that references them, e.g. to migrate them off the OST.

On OST_READ, queue a repair of a missing parent FID to the resource ID
repair thread, which writes it in the same transaction as any missing
UID/GID/PROJID. The parent FID, stripe index and OST layout from the
obdo are stored as a write stores them, so LFSCK finds the component
ID of PFL files. Like the ID repair, it is disabled by
enable_resource_id_repair=0. It is queued whether or not
enable_resource_id_check is set, but not when that check denies
access.

Only a missing parent FID, or one that fails fid_is_sane(), is
repaired. A valid parent FID that differs from the obdo may come from
a second layout referencing the object, which is left to LFSCK. The
parent FID sent by the client is trusted like the UID/GID repaired
from the same RPC, also from clients of read-only exports; a write
stores it unconditionally.

filter_fid::ff_parent::f_ver holds the stripe index, so only f_seq and
f_oid of the parent FID are checked with fid_is_sane().

Stripes that are never read, e.g. beyond EOF, still have no parent
FID.

Add sanity-sec test_75c: unwritten stripes 0 and 1 of PFL files get
their parent FID and layout on read, with the ID check disabled and
enabled; a read with another parent FID keeps a valid one; and an
object missing both IDs and parent FID gets both repaired.
