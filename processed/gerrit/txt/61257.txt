LU-19222 llite: don't force unmount of shared client

"umount -f" of a bind mount, or of the copy of a Lustre mount in
a container mount namespace, would call ll_umount_begin(), which
marks every MDC and OSC import of the client superblock inactive.
The kernel calls ->umount_begin() for every MNT_FORCE unmount,
even when other mounts still use the superblock, so the remaining
mounts would fail with -ESHUTDOWN until the client was remounted.

The superblock reference count cannot tell these mounts apart
from the copies held by systemd services in their own mount
namespaces, which propagation unmounts with the original mount.

Add a umount.lustre script, which umount(8) runs for Lustre.  For
"-f", if another mount in this mount namespace has the same client
instance ("lfs getname -i"), it unmounts without forcing.  Only
mounts with the same device number are checked, and the check has
a time limit, so it does not block if the servers are unreachable.

In ll_umount_begin(), do not force an unmount requested from a
mount namespace other than the one the client was mounted from,
unless it comes from the initial (host) mount namespace.
Such an unmount can still be forced after setting the imports of
that filesystem inactive:

    lctl set_param mdc.FSNAME-*.active=0 osc.FSNAME-*.active=0

Add sanity test_83a for a bind mount and test_83b for a mount
namespace.

umount(8) runs the helper as a child process and waits for it, so
conf-sanity test_5a, which kills a running umount, now calls the
helper directly, and sanity test_160h counts only the umount
processes in D-state.
