LU-10499 pcc: add lctl pcc abort command to abort attaches

This patch adds a new PCC command "lctl pcc abort [--wait|-w]
[--detach|-d] <$LUSTRE_MNTPT> [$PCCROOT]".
--wait|-w: wait all in-flight attaches aborted.
--detach|-d: detach the PCC copies when scan the PCC backend.

It can be used to abort in-progress attaches for a given PCC
backend. It does not remove the PCC backend from a client.

Add PCC_CLEANUP_FL_KEEP_CONF to keep the PCC backend configured,
PCC_CLEANUP_FL_NOT_DETACH and PCC_DETACH_FL_NOT_DETACH so that the
scan of the PCC backend only aborts the attaches.

Fixes from the original patch:
- the PCC copies are kept by not asking for PCC_DETACH_FL_UNCACHE,
  instead of passing a new userspace-only PCC_DETACH_FL_KEEP_DATA
  flag to the kernel.
- name the flag to keep the PCC backend PCC_CLEANUP_FL_KEEP_CONF
  from the start, rather than PCC_CLEANUP_FL_NOT_DEL.
- print the error returned by the scan, not errno.
- document "lctl pcc abort" in lctl-pcc.8, without dropping its
  DESCRIPTION section, and do not renumber existing UAPI values.

Add sanity-pcc/test_109 to verify it.
