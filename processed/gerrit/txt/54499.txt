LU-10499 pcc: add lctl pcc abort command to abort attaches

Add the command "lctl pcc abort [--detach|-d] [--verbose|-v]
[--wait|-w] MNTPATH [PCCPATH]" to abort the attaches in progress to
one or all PCC backends on a client, without removing the backends.
The files already in the cache stay attached, unless --detach is
given, which detaches them but keeps their PCC copies.  With --wait
it waits for the aborted attaches to finish.

Add PCC_CLEANUP_FL_KEEP_CONF to keep the PCC backend configured, and
PCC_CLEANUP_FL_NOT_DETACH and PCC_DETACH_FL_NOT_DETACH so that the
scan of the PCC backend only aborts the attaches.  NOT_DETACH keeps
the PCC copies, as PCC_CLEANUP_FL_KEEP_DATA does.

"lctl pcc del|clear --keep-data --abort" now aborts the attaches in
progress, and like --keep-data alone keeps the cached files attached.

Document the command in the new lctl-pcc-abort.8 man page, and add
sanity-pcc test_109 to verify it.

Some concerns, see inline comments. The main one is that PCC_CLEANUP_FL_NOT_DETACH still removes the PCC copies unless PCC_CLEANUP_FL_KEEP_DATA is also passed. As a design question, `lctl pcc abort` scans every file in the PCC backend and issues one ioctl per file, only to find the few attaches in progress. The kernel already tracks those (PCC_STATE_FL_ATTACHING, pccd_attach_count, pccs_dio_copies). Scanning also misses an attach whose PCC file does not exist yet, so `abort -w` can return while an attach is still running. Was a kernel-side "abort" pccdev command, like "del", considered?
