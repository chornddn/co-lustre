--- Commit Message ---
LU-20438 lnet: Implement distance-based PCIe P2PDMA routing

This patch completes the P2P hardware distance topology abstraction,
vastly optimizing network interface (NI) selection for GPUDirect RDMA.

By introducing the lnd_get_device callback on the LND, LNet dynamically
queries and evaluates the physical PCIe distance between the GPU
(page provider) and all active Host Channel Adapters (HCAs).
This ensures LNet bounds multi-rail transfers to perfectly matched NICs
collocated beneath the identical PCIe switch, sidestepping NUMA traffic.
If no NIC matches the specific PCIe hierarchy or distance mapping is
unsupported natively by the LND, the NIs correctly tie and seamlessly
fall back down to the generalized round-robin distance routing tier.

Introduces `struct lnet_device_id` as the primary cross-layer token for
identifying the backing hardware provider of incoming memory pages, paving
the way for dynamic routing capabilities. Also addresses the
LNET_MD_BULK_HANDLE flags correctly registering when nested internally
through ptlrpc logic. Finally, the Linux kernel does not universally
export an API to retrieve the PCI device provider from a P2PDMA
ZONE_DEVICE page, housing it inside the privately scoped
`struct pci_p2pdma_pagemap`. This explicitly maps mainline structures
across recent unexported kernel shifts, safely extracting the PCI device
natively without resorting to costly iterative PCIe root bus scanning.
