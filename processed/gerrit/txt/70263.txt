LU-20869 tests: test one upgrade image per conf-sanity 32a-d

Each of conf-sanity 32a, 32b, 32c and 32d runs t32_test over every
disk image tarball (five for ldiskfs, three for zfs), so the four
tests together took about 1900 hours of CI time per 30 days, and
that grows as new version images are added.

With SLOW=no, test one image per subtest. 32a to 32d pass $SLOW to
t32_check to opt in, and each such call takes the next image from
the version sorted list, starting at the build version (including
the commit count, e.g. 2.17.60.45), so 32a to 32d test four
consecutive images, and a repeated subtest moves on to the next
image. A retest of the same build tests the same images, so a real
failure is not hidden by a different selection, while successive
builds rotate every image through every subtest. T32INDEX=N sets
the starting index, to test one chosen image even with SLOW=yes.

SLOW=yes and T32IMAGE keep testing every image. 32e to 32j already
test only the one image their upgraded feature needs.

On a rocky9 VM with ldiskfs (5 images), ONLY="32a 32b 32c 32d":
  before (SLOW=yes): 322 + 573 + 621 + 337 = 1853s, and 2699s
  after  (SLOW=no):  about 310 to 460s over four runs

Rainshadow shows the four tests at a mean of 1641s per run over
about 4200 runs per 30 days. Saving about 1200s per run, about
1300 hours per 30 days.

Test-Parameters: trivial testlist=conf-sanity env=ONLY="32a 32b 32c 32d"
