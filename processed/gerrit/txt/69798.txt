--- Commit Message ---
LU-20276 tests: Wait for ZFS frees after sanityn/56a,56b

On ZFS nodes with less RAM, sanityn 56a/56b OOM
during the llverdev write part when run in loop.
Because maloo(CI) and master-next run the same
code on different setup, the result depends on
the installed memory, so (as suggested) these
tests should be skipped on small-RAM nodes. The
existing LU-20276 guard only covered 56b; extend
it to 56a as well. Workaround from JIRA is still
worth keeping for 70/71, but it does not address
OOM issue directly

Test-Parameters: trivial testlist=sanityn fstype=zfs serverdistro=el9.7
Test-Parameters: trivial testlist=sanityn fstype=zfs serverdistro=el9.8
Test-Parameters: trivial testlist=sanityn fstype=zfs serverdistro=el10.1
Test-Parameters: trivial testlist=sanityn fstype=zfs serverdistro=el10.2
