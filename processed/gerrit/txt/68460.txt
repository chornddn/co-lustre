--- Commit Message ---
LU-20438 lnet: Add struct lnet_device_id and PCI pgmap extraction

Introduces `struct lnet_device_id` as the primary cross-layer token for
identifying the backing hardware provider of incoming memory pages, paving
the way for dynamic routing capabilities.

Finally, the Linux kernel does not universally export an API to retrieve
the PCI device provider from a P2PDMA ZONE_DEVICE page, housing it inside
the privately scoped `struct pci_p2pdma_pagemap`. Extracting this
out-of-tree requires assuming the structural layout, which has shifted
heavily upstream:
- v5.4 to v6.6: 'pgmap' is positioned first.
- v6.7 to v6.18: 'pgmap' is pushed to the last element to resolve GCC-14
  -Wflex-array compile warnings (backported widely).
- v6.19+: P2P memory management was modularized; 'provider' is now nested
  inside a local p2pdma_provider 'mem' substructure.

This commit natively maps these three mainline topological shifts, safely
extracting the PCI device natively without resorting to costly iterative
PCIe root bus scanning on the routing fast paths.
