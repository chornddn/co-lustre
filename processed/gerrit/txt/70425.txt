LU-20730 llapi: read a namespace walk as LFU chunks

A client walking a directory with llapi_scan_namespace() also gets one
callback per object, and there is no way to read that walk as an LFU
Object Stream.

Add LFU_SOURCE_NAMESPACE to llapi_lfu_open(), and let LFU_SOURCE_ANY
walk a directory. The walk cannot be paused, so it runs in a thread of
its own: its callback waits for a read and writes each record into
that read's buffer; when the buffer is full it ends the read and holds
the record for the next one. The walk's threads take turns at the
buffer, and closing the stream cancels the walk.

A walk has no position to resume from, so its cursor counts the
objects sent and carries a per-stream token: only the last read's
cursor goes on, anything else is -ESTALE, and a walk has one shard.

Records carry the path below the start point in LfuEa.path, the statx
attributes, and the layout, directory stripe, HSM state and lazy size
rebuilt in the form the MDT stores, so a consumer decodes them as it
does a device stream's. lfsp_filter is given llp_data.

llapi_scan_test test11, run by sanity 56Ee, walks a tree of 306
objects in 2-slot reads of 4 KiB with one and four walk threads, and
checks that the stream sends what the callback delivers, with the same
paths, that a filter drops what it rejects, and that stale cursors, a
second shard and closing mid-walk are handled.
