LU-20730 llapi: read a namespace walk as LFU chunks

llapi_scan_namespace() walks a directory on a client and calls back
once per object. There is no way to read such a walk as an LFU Object
Stream, the way a device scan can be read.

Add LFU_SOURCE_NAMESPACE to llapi_scan_open(), and let LFU_SOURCE_ANY
walk a directory. The walk cannot be paused, so it runs in a thread of
its own: each object it finds is written into the buffer of the
current read, and when that buffer is full the read returns and the
object waits for the next read. Closing the stream stops the walk,
also one whose filter drops every object left.

A walk cannot resume from a position, so its cursor counts the
objects sent and carries a token of its stream. Only the cursor of the
last read continues the walk; any other is refused with -ESTALE, and a
walk has a single shard. A directory the walk cannot read is skipped,
as llapi_scan_namespace() skips it; the read that ends the walk
returns what it has, and the next read returns the error.

A record carries the path below the starting directory, the statx
attributes, and the layout, directory striping, HSM state and lazy
size in the form the MDT stores them, so a reader decodes them the
same way as a device scan's. rdev is in the form a device scan sends.
A big-endian client sends no layout, as it has the layout in host
order. Every record is named by its FID, and an object without one is
counted as an error. Not every attribute is known for every object,
so a walk needs LFU_FEATURE_PARTIAL_RECORDS. lsop_filter runs on the
walk's threads and sees the object's path. What it drops, and the
objects the walk could not read, are counted in the last chunk, as a
device stream counts them. A directory of another filesystem than
lsop_fsname is refused with -EXDEV.

llapi_scan_test test11, run by sanity 56Ee, walks a tree of 307
objects in reads of two 4 KiB slots, with one and with four walk
threads. It checks that the stream sends what the callback gets, with
the same paths, that a filter drops what it rejects and both summaries
count it, and that stale cursors, a second shard, a walk without
partial records and closing the stream during a walk are handled,
also while the filter drops every object.
