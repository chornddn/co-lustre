LU-19804 quota: enforce projquota on PROJINHERIT rename

When renaming a file into a directory with the project inherit flag,
it will inherit the new project ID, then the project quota should be
enforced on this project ID.

This patch reserves the quota space before the rename and releases
it after the rename completes. If the rename overwrites the last
link of a file charged to the same project, the space freed by
unlinking that file in the same transaction is credited to the
reservation.

The size and blocks of the object are not known on the MDT, since
the data lives on the OSTs, so the client sends them in the rename
request, but only for the renames that are charged. The MDT then
charges the largest of the client values, the MDT inode attributes
and the lazy SOM (LSOM) attributes read from trusted.som, which are
only the minimum size that a client could have reported. A strict
SOM is exact and is used instead of all of them. The blocks the MDT
inode holds itself are already reserved by the projid change
declared on the object, so they are not charged twice. An old client
which sends nothing is covered by the same rules, its request then
carries the MDT inode and LSOM values on their own.

A file released by HSM has no data in the filesystem anymore, only
the size and blocks of what was archived are kept in the inode and
in the SOM, so moving it does not consume any project space. The
state is read from trusted.hsm and the space is charged again when
the file is recalled.

The client glimpses the OSTs before the rename if its cached size or
block count is 0, which means either an empty file, a file written
locally that was not looked up since, or a file whose data was
written by another client.

The size and blocks the client sends also raise the lazy SOM of the
source object, in the same transaction as the rename: a rename can
not be replayed if only part of it was committed, so the update can
not run in a transaction of its own. A strict or stale SOM is left
alone, and a file without a SOM gets one from its next close, as
mdt_lsom_update() does. The values are the cached ones of the
client, without a lock, so they can leave the lazy SOM larger than
the real size until the next truncate.

MDS_RENAME_SIZE_VALID reuses the bit of the obsolete MDS_SOM flag
instead of taking a new one, since a rename request never carries
the close-time meaning of that bit, so no additional bit of the
32-bit mds_op_bias is consumed.

The mdd_attr_set() group quota code is refactored onto the new
mdd_quota_reserve()/mdd_quota_commit_or_release() helpers, which are
shared with the rename path, qsd_reserve_or_free_quota() also gets a
bypass so that root renames charged to a project ID are not enforced
against PRJQUOTA when the active nodemap grants ignore_root_prjquota
role and the QSD's root_prj_enable is off.

The test_99 is added in sanity-quota, it also checks that a rename
raises the LSOM of the source object.
