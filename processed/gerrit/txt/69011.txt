LU-19804 quota: enforce projquota on PROJINHERIT rename

When renaming a file into a directory with the project inherit flag,
it will inherit the new project ID, then the project quota should be
enforced on this project ID.

This patch reserves the quota space before the rename and releases it
after the rename completes. If the rename overwrites the last link of
a file charged to the same project, the space freed by unlinking that
file in the same transaction is credited to the reservation.

The size and blocks of the object are not known on the MDT, since the
data lives on the OSTs, so the client sends them in the rename request
and the MDT charges the larger of them and its own values. If neither
the client nor the MDT inode has a usable value, as for an old client
which does not send them, the size-on-MDT attributes are read from
trusted.som and used instead. The lazy SOM (LSOM) values are only the
minimum size that a client could have reported and can lag behind the
real one, while a strict SOM size is exact and is used in preference
to the value reported by the client.

The client glimpses the OSTs before the rename if its cached size or
block count is 0, which means either an empty file, a file written
locally that was not looked up since, or a file whose data was written
by another client. The values it sends are also used to refresh the
LSOM of the source object, unless that object is remote, in which case
its own MDT updates it.

MDS_RENAME_SIZE_VALID reuses the bit of the obsolete MDS_SOM flag
instead of taking a new one, since a rename request never carries the
close-time meaning of that bit, so no additional bit of the 32-bit
mds_op_bias is consumed.

The mdd_attr_set() group quota code is refactored onto the new
mdd_quota_reserve()/mdd_quota_commit_or_release() helpers, which are
shared with the rename path, qsd_reserve_or_free_quota() also gets a
bypass so that root renames charged to a project ID are not enforced
against PRJQUOTA when the active nodemap grants ignore_root_prjquota
role and the QSD's root_prj_enable is off.

The test_99 is added in sanity-quota.
