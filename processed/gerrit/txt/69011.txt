LU-19804 quota: enforce projquota on PROJINHERIT rename

When renaming a file into a directory with the project inherit flag,
it will inherit the new project ID, then the project quota should be
enforced on this project ID.

This patch reserves the quota space before the rename and releases it
after the rename completes. If the rename overwrites the last link of
a file charged to the same project, the space freed by unlinking that
file in the same transaction is credited to the reservation.

The object size is difficult to get on MDT, then the client sends
the size/blocks into the rename request so the MDT has the accurate
value for reserving quota.

When the cached size is 0 at client, it first glimpses the size from
the OSTs, since the file may have been written by another client. The
MDT uses the values when they are provided, otherwise it falls back to
the attributes it has locally.

The mdd_attr_set() group quota code is refactored onto the new
mdd_quota_reserve()/mdd_quota_commit_or_release() helpers, which are
shared with the rename path, qsd_reserve_or_free_quota() also gets a
bypass so that root renames charged to a project ID are not enforced
against PRJQUOTA when the active nodemap grants ignore_root_prjquota
role and the QSD's root_prj_enable is off.

The test_99 is added in sanity-quota.
