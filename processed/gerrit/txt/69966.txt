--- Commit Message ---
LU-21023 tests: test directory migration under load in sanityn

Add sanityn tests that migrate a directory between MDTs, back and
forth with various layouts, while an application uses it through the
other mount, and check that the namespace stays consistent with LFSCK
(-o, any repair fails the test):

- 80d: I/O through file descriptors opened before the migration, and
  the FID of an open file, survive it. Every migration must succeed.
- 80e: path-based namespace operations (create, write, truncate, link,
  symlink, mkfifo, rename, unlink, readdir) never fail.
- 80f: a process whose cwd is in the migrated directory may get
  -ESTALE through it, as the cwd holds the old inode, but can
  re-resolve the path and keep working.
- 80g: likewise for an open directory handle, which reopening by path
  replaces; a running executable from the directory survives.

They need the fixes of this series on the MDS, OSS and client, so
they skip with servers or clients older than 2.17.60.

Let run_lfsck() take extra lfsck_start options and also fail when
LFSCK failed to check or repair any object (failed_phase1/2), and fix
its error message, which used unset variables.

Test-Parameters: mdtcount=2 mdscount=2 testlist=sanityn env=ONLY=80
