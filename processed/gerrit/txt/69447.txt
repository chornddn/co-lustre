LU-20808 mdt: read the xattrs an IT_MDT_TO_MDT_READ names

Have the MDT owning the locked object read the xattrs an
IT_MDT_TO_MDT_READ names, as stored, while it grants the lock, and
return them in the reply: a struct mdt_read_xattr for each name, in
the order of the request, and the values that came back one after the
other, in a single buffer.

An absent xattr is answered too, with -ENODATA: the requester caches
that as readily as a value, which spares it a round trip in the
common case of a directory with no default layout or ACL. The values
share the room the requester asked for. One that does not fit in what
is left is answered with -ERANGE and the length it needs, and the
requester reads it itself. Any other error is passed back as the
status of that xattr.

The values are read raw, because the requester caches each as what its
own OUT_XATTR_GET would have returned: the on-disk form, not LOD's
view of it.

A request with more than MDT_READ_XATTRS_MAX names, or with a name
that is empty, unterminated or longer than XATTR_NAME_MAX, is refused
with -EPROTO.
