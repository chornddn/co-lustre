LU-21189 osd-ldiskfs: don't fail on qid array overflow

A rename() overwriting an existing target while all quota types are
in use declares more quota ids than the arrays tracking them can
hold, and fails with -EOVERFLOW from osd_declare_qid() or -EINVAL
from qsd_op_begin().

Such a rename needs up to 15 quota ids, as destroying the unlinked
target declares quota for both its inode and its blocks. That matched
the 15 slots of ot_id_array exactly, leaving no headroom at all,
while lqt_ids had only 12 slots. Raise OSD_MAX_UGID_CNT from 15 and
QUOTA_MAX_TRANSIDS from 12 to 17, and document how the worst case is
obtained. The arrays are not sized much above it because lqt_ids is
embedded into osd_thread_info, which must stay below PAGE_SIZE. A
build time check keeps QUOTA_MAX_TRANSIDS from falling below
OSD_MAX_UGID_CNT again.

mdd_declare_rename() also wasted a slot: when the rename changes the
project id of the renamed object it sets LA_PROJID in the attributes
it declares, but leaves la_projid at whatever stale value the
mdi_la_for_fix happened to hold. osd_declare_attr_set() then reserves
quota for that bogus project id instead of the one the object
actually gets, pushing the transaction to 16 ids. Declare the target
parent's project id, the same value the execution phase assigns, so
that it deduplicates against the id already declared for the target
parent.

Finally, stop returning -EOVERFLOW from osd_declare_qid() when
ot_id_array is full. Credits for the extra id are reserved either
way, the only thing lost is the ability to deduplicate it against the
following declarations of the same transaction, so over reserving
credits is much better than failing the whole operation. Warn about
it unconditionally, naming the quota id, as it is not expected to
happen.

Add sanity-quota tests for it: rename the existing test_87 to
test_87a and add test_87b, renaming a directory over another one (12
block quota ids plus 3 inode quota ids for the destroyed target), and
test_87c, renaming a regular file into a parent with the project
inherit flag and a different project id. test_87c also checks in the
MDS debug log that the project id declared for the renamed file is
the one it gets. Both call rename(2) directly instead of mv(1), only
use users and groups already present in the test environment, and
skip with an older MDS.
