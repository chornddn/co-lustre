LU-20686 nodemap: save filesets in target nodemap cache

Each MDT and OST keeps a local copy of the nodemap index, written by
nodemap_save_config_cache() when the node gets a new config from the
MGS, and loaded at mount if the MGS is not reachable.  This copy
should be a full replica of the MGS nodemap index, so that it can be
used if the MGS is lost.  But nodemap_save_config_cache() did not
write the fileset records (header and path fragments of primary and
alternate filesets) that the MGS index holds since 2.16.53.  A target
that started without the MGS would have no filesets in its nodemaps.

Write the filesets of each nodemap to the cache with the same records
as the MGS index, using nodemap_idx_fileset_header_add() and
nodemap_idx_fileset_fragments_add().  Remove a fileset that is only
partly written, since it would load as a shorter path.  A primary
fileset set through the params llog is not in the MGS index and is
still not written.  All other record types were already written.
Write offset and capabilities records only while they are set, as
the MGS index does, so the cache holds the same records as the MGS
index.

Also resize the filesets loaded by nodemap_load_entries() to their
real length, as is done for a config received from the MGS, and
print the real error if writing a nodemap cache fails.

Add sanity-sec test_27ae to check that an OST started without the
MGS gets the same nodemap config, filesets included, from its cache.
