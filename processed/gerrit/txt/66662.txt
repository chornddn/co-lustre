--- Message (Gerrit AI review for Lustre, 2026-07-24 08:28:08.000000000) ---
Patch Set 2:

Experimental feature testing in progress, please pay attention to the comments

Some concerns. The i_ino %lu -> %llu/(u64) conversion looks incomplete for the v7.1 client build. i_ino widened from unsigned long (v7.0) to u64 (v7.1-rc1, include/linux/fs.h), so %lu with inode->i_ino is a -Wformat error under the same -Werror that makes the converted hunks here necessary. Sites still using %lu in unconditionally-built client code:

    lustre/llite/llite_lib.c:2915   CDEBUG() in ll_update_inode()
    lustre/mdc/mdc_locks.c:111      LASSERTF() (two i_ino args)
    lustre_compat/fs/crypto/crypto.c:544   CDEBUG() in llcrypt_msg()
    lustre_compat/fs/crypto/keysetup.c:89  WARN_ONCE()

The last two are in the same fscrypt_objs build unit as the hooks.c/policy.c hunks in this patch, and CDEBUG()/LASSERTF()/WARN_ONCE() are all printf-format-checked (libcfs_debug_msg is __printf(2,3)), so these will break the v7.1 build too. A tree-wide sweep of inode->i_ino format specifiers (rather than the handful converted here) would close this. The folio_batch and d_alias handling looks complete.
