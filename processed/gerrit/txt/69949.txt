LU-21020 lov: wait for mirror once all were tried

When fast mirror switching has tried all mirrors of a file,
lov_io_mirror_init() sets ci_tried_all_mirrors but leaves ci_ndelay
set, so the lock enqueue and BRW of the next try still carry
LDLM_FL_NDELAY and OBD_BRW_NDELAY. They fail at once with -EAGAIN,
and cl_io_loop() returns -EIO. A read of a mirrored file fails while
its OSTs are in failover, where a read of a file with one mirror
waits for them.

Clear ci_ndelay once ci_tried_all_mirrors is set, so that every user
of it waits for the OSTs in that round. This includes the glimpse of
stat(), which now waits as well instead of failing.

cl_io_loop() mapped -EAGAIN to -EIO in that round only while
ci_ndelay was set. Check ci_tried_all_mirrors first, so that an
-EAGAIN which does not come from the non-delay flags, e.g. from a
component that is not valid, still ends as -EIO and not -EAGAIN.

Add sanity-flr test_33f.

Thanks, the problem is real: once lov_io_mirror_init() sets ci_tried_all_mirrors, the next try still carries LDLM_FL_NDELAY/OBD_BRW_NDELAY and fails with -EIO instead of waiting.

I think the fix belongs in LOV rather than in each OSC user of ci_ndelay, see inline. That covers every consumer at once (lock enqueue, BRW, DIO, and the setattr RPC flag that https://review.whamcloud.com/69762 adds), and avoids conflicts with https://review.whamcloud.com/69702 (LU-20708, same osc_io_submit() condition) and 69762 (same osc_lock_init() line). https://review.whamcloud.com/64919 already does the same for an EC file with a single data mirror, by clearing ci_ndelay where it sets ci_tried_all_mirrors.

Some concerns, see inline comments. The all-mirrors-down case is fixed, but the round with ci_ndelay cleared is picked by a restart counter, not by checking whether any mirror can serve the read. Waiting in that round can block a read that a healthy mirror could have served. Since ci_tried_all_mirrors now implies !ci_ndelay, the !ci_tried_all_mirrors test in osc_io_iter_init() is dead code and could go on the next refresh.
