LU-16475 lov: remove a deleted OST from mounted nodes

"lctl del_ost" cancelled the records that add an OST to the client
and MDT config logs, but clients and MDTs that were already mounted
only process records added to the end of a log, so they kept the OST
until they were remounted.

Add an optional LCFG_DEL_TGT config record for the MGS to append
to those logs.  A client or MDT that has the OST set up deactivates
it at once, so that it gets no new objects and "lfs df" no longer
lists it, and frees its OSC or OSP once no object uses it any more.
Until then it tries again from delayed work, backing off from 30s to
an hour, and frees it at umount at the latest.  A node that does not
have the OST set up, such as one that mounted after it was removed,
ignores the record.  Older nodes ignore it after a console error.

Clients look up stripe objects on a target only under a new
lov_target_sem, which also guards changes to the target array, and
MDTs only while they hold a reference on the target table, so that
the target is not freed under them.  MDTs do not allocate objects on
a removed OST even if it is activated again.
