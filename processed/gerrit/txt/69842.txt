LU-21001 lmv: move new dirs off a busy parent MDT

When a client picks the MDT for a new directory by QoS, it only
weighs free space and inodes. If space is balanced, or the parent
MDT has enough space, the dir stays on the parent MDT, and so do
all files later created under it, however busy that MDT is.

Every reply already carries the MDT's service time estimate, the
worst queue wait plus handling time over the AT history, and the
MDC import keeps it per portal. Use the MDS_REQUEST_PORTAL estimate
as a load indicator, without any protocol change.

If a new dir would stay on its parent MDT, and that MDT's estimate
exceeds the lowest one by lmv.*.qos_load_threshold seconds (default
3, 0 to disable), place the dir by QoS weight instead, with each
MDT's weight scaled by lowest estimate / its estimate. If space is
balanced, all MDTs get equal weight before scaling.

Round-robin dirs, within max_inherit_rr depth or by 'lfs mkdir -i
-1' with balanced space, and dirs moved off the parent MDT by space
imbalance, ignore load as before. An MDT the client has not heard
from within at_history is never considered busy.

Disable the load check in test_qos_mkdir(), which checks an exact
round-robin distribution, and add sanity test_413m to verify that
new dirs leave a parent MDT slowed by OBD_FAIL_PTLRPC_PAUSE_REQ,
while round-robin dirs stay evenly spread.
