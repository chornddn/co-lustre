LU-20208 rustreapi: support documentation builds on docs.rs

docs.rs builds the documentation without Lustre headers or lfs, so
the -sys build scripts cannot run bindgen and lu-version cannot set
the LUSTRE_2_* features there.

When DOCS_RS is set, the -sys crates copy a committed snapshot,
src/bindings_docs.rs, instead of running bindgen, and lu-version
sets the features from a committed lustre_version.txt.
lustreapi-sys derives has_lsp_union from the snapshot.  The new
"just update-doc-snapshots" recipe regenerates both from the tree's
headers and DEFAULT_VERSION.

Move the header search into lu_version::get_include_paths():
LUSTRE_INCLUDE_DIR (a ':'-separated list), then pkg-config, then the
in-tree include directories.  It does not emit the pkg-config link
flags, so changelog-sys now links liblustreapi itself.
