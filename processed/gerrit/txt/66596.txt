## Summary of Fixes

### 1. **Section Mismatch Error** (in `lustre_compat/misc.c`)

**Problem**: The function `cfs_arch_exit()` was calling `llcrypt_exit()`, which is marked with the `__exit` annotation. However, `cfs_arch_exit()` itself was not marked as `__exit`, causing a section mismatch warning because a normal function cannot reference a function in the `.exit.text` section.

**Fix**: Added the `__exit` annotation to `cfs_arch_exit()`:
```c
void __exit cfs_arch_exit(void)
```

**Rationale**: The `__exit` annotation tells the linker that this function is only used during module unload/exit. Since `cfs_arch_exit()` calls `llcrypt_exit()` (which is marked `__exit`) and is itself only called during module exit (as seen in the `compat_module_exit` macro), it should also be marked `__exit`. This resolves the section mismatch by ensuring both functions are in the same `.exit.text` section.

### 2. **Format Truncation Warning** (in `lustre/utils/mount_utils.c`)

**Problem**: The compiler detected that `snprintf(real_path, sizeof(real_path), "/dev/mapper/%s", dm_name)` could write up to 4108 bytes (13 bytes for "/dev/mapper/" + up to 4095 bytes from `dm_name`) into a 4096-byte buffer, causing potential truncation.

**Fix**: Changed the format string to use a precision specifier:
```c
snprintf(real_path, sizeof(real_path),
         "/dev/mapper/%.*s", 
         (int)(sizeof(real_path) - 13), dm_name);
```

Also removed the redundant check `sz < sizeof(dm_name)` since it's always true.

**Rationale**: Using the `%.*s` format specifier with a maximum width of `sizeof(real_path) - 13` guarantees that the total output (prefix + dm_name) will never exceed the buffer size. The precision specifier limits how many characters from `dm_name` are printed, ensuring the output fits within `real_path`. This eliminates the truncation warning while preserving the intended functionality of constructing the device mapper path.
