--- Commit Message ---
LU-18298 tests: retry the PCC backend umount in sanity-pcc

umount_loopdev() waits for the backend mount to go idle by polling lsof,
then umounts once. That poll cannot see what usually holds the mount:
an attached PCC inode pins it through pcci_path, and an open PCC copy
pins it through the file, and both are kernel references that belong to
no process. lsof reports the mount idle on the first iteration, the
grace loop exits immediately, and the umount fails.

cleanup_pcc_mapping() does not help here either, as lctl pcc clear frees
the dataset but detaches no inode, so any file still attached at cleanup
keeps the mount busy.

Retry the umount itself instead, dropping the client caches between
attempts. That releases the Lustre inodes and with them the PCC copies
they hold, which is what the loop was trying to wait for. Keep the lsof
call, it still reports a process holding the mount, which is the case
the old loop did handle.

This is what test_100 trips over: it attaches with projid={0}, so any
root owned file written under the mount during the run is attached, and
"umount: target is busy" ends the test after everything it checks has
already passed.
