--- Commit Message ---
LU-21104 ptlrpc: make an idle import valid when activated

Deactivating an import marks it invalid.  For a connected import, the
reconnect started when it is activated again makes it valid, but an
import that was IDLE is not reconnected: ptlrpc_recover_import()->
ptlrpc_set_import_discon() only acts on a FULL import, so the idle
import is never recovered and all I/O to the OST fails:

  client# lctl set_param osc.lustre-OST0000-osc-*.active=0
  client# lctl set_param osc.lustre-OST0000-osc-*.active=1
  client# touch /mnt/lustre/f
  touch: setting times of '/mnt/lustre/f': Input/output error

In ptlrpc_set_import_active(), mark an idle import valid without
reconnecting it, so that it connects on its next request like any
other idle import.  Check that it is idle, not deactivated again and
not being invalidated (imp_inval_count, as ptlrpc_recover_import()
does), under the imp_lock that clears IMPF_INVALID, so that a racing
deactivation or reconnect cannot come in between and
ptlrpc_invalidate_import() keeps IMPF_INVALID set.

Add sanity tests 812d and 812e.  812d waits for the import after
activation: with SSK, the ctx fini RPC for the contexts that the
deactivation flushed reconnects the idle import, and active=1 does not
wait for that reconnect (LU-21040).  812e activates the import while
OBD_FAIL_PTLRPC_CONNECT_RACE holds active=0 in its invalidation.

Fixes: 5a6ceb664f07 ("LU-7236 ptlrpc: idle connections can disconnect")
