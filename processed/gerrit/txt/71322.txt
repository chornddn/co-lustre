LU-15444 osp: take destroy RPC version at llog write

A remote MDT applies OUT requests in RPC version order.  A sub
transaction used to get its version at its first update llog write
in llog_osd_write_rec(), under the llog lock, so the version order
matched the llog index order.  Since LU-16159 osp_md_destroy() takes
the version during execution, before llog_add(), so a concurrent
transaction can add a lower llog index with a higher version.  The
remote MDT then applies the header, bitmap and tail writes of the
two appends in reverse order.  After a remote error,
llog_cat_refresh() reads back a tail that is behind a set bitmap
bit, and the next append hits the LBUG in llog_osd_write_rec():
"index N already set in llog bitmap".  The paused destroy also holds
back every later update to that MDT until it reaches trans stop.

Only mark the request in osp_md_destroy().  osp_trans_stop() takes
the version if no write took it, so a destroy without llog write is
still sent after earlier writes.

Add recovery-small/169.  It pauses a striped directory rmdir before
its update llog write (new OBD_FAIL_UPDATE_LOG_DELAY) while a striped
mkdir adds a record, then checks the llog index and RPC version order
in the MDT0000 debug log.
