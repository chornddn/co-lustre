LU-21031 osd-zfs: refuse names longer than NAME_MAX

With ZFS 2.3 and newer, a directory ZAP accepts entry names
up to 1023 bytes, so a ZFS MDT stores a 256 character name
from a client that does not check the length itself, such
as "lfs mkdir" on 2.16. osd-zfs readdir returns EOVERFLOW
for any name over NAME_MAX, so that directory can never be
listed or removed again. In rolling upgrade testing this
leaves d110.sanity behind and every later sanity run fails
in its initial cleanup.

Refuse such names on insert with ENAMETOOLONG, as ldiskfs
does.
