LU-10499 pcc: DIO attach copy for encrypted files

The PCC copy of an encrypted file holds its ciphertext, so the
kernel copy sets S_PCCCOPY to read the Lustre file as if the key
were not loaded.  The DIO copy by ll_fid_path_copy was not used for
encrypted files, since its direct reads would decrypt the data when
the key is loaded.

Now that direct IO of a file opened with O_CIPHERTEXT transfers the
ciphertext whether the key is loaded or not, have ll_fid_path_copy
open the source file with O_CIPHERTEXT for its direct IO, and use
the DIO copy for encrypted files.  O_CIPHERTEXT has no effect on
the direct IO of other files, except that its O_NONBLOCK does not
restore a released file, whose copy then fails and the kernel falls
back to the buffered copy.  A ciphertext read reaches the end of the
last encryption unit, so the copy may be up to one unit larger than
the clear text size, as with the kernel copy, and the helper and the
kernel check of the copied size both accept that.

Add sanity-pcc test_50d to verify the PCC copy of an encrypted file.

Mostly good, minor comments inline; none of them needs a re-spin by itself, though the O_SYNC question is worth an answer.

test_50d only exercises a single thread and a single read: pcc_copy_data_dio() shrinks iosize to the rounded file size, so the helper computes zero threads and uses one.
