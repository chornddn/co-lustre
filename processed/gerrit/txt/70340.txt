AI code review results below, please doublecheck

The code changes are safe: every new error path drops the lock, the buffers and (for writes) the grants correctly. Some concerns, see inline. The only new check that can actually trigger is the zero-buffer case, and the commit message doesn't describe it. A refresh is worth it mainly for the commit message; the inline minors can go along with it.

This is a pre-existing issue, not caused by this patch, and could be a separate change: a niobuf with rnb_len == 0 is never rejected before dt_bufs_get(). On ldiskfs, osd_bufs_get() then reads lnb[npages - 1] with npages == 0. For the first niobuf that is tbc->local[-1], outside the allocation. Rejecting zero-length niobufs in tgt_io_data_unpack(), next to the existing ioo_bufcnt checks, would cover both OSDs and the DoM path in mdt_io.c. It would also give a sanity test (like 819a/819b) a simple way to exercise the new -EPROTO path.
