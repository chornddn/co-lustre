LU-20971 utils: fix pfind work unit path buffer overflow

work_unit_create() allocates PATH_MAX + 1 bytes for the path of a
work unit, but find_worker() gives that buffer to
llapi_semantic_traverse() with a size of 2 * PATH_MAX, and the
traversal appends the name of each entry to the path in place. For
a directory whose path is longer than about PATH_MAX - NAME_MAX,
the worker writes past the end of the buffer, which makes glibc
abort "lfs find" with "double free or corruption". A directory path
longer than PATH_MAX is also silently truncated when the work unit
is created, while the serial traversal handles it.

Store the work unit path with its exact length, and have each worker
thread build the entry paths in a private buffer of FIND_PATH_BUFLEN
(2 * PATH_MAX) bytes, the size of the serial traversal buffer. Use
the same constant in param_callback(), which gave the traversal a
size of 2 * PATH_MAX + 1 for a buffer of 2 * PATH_MAX bytes.

Test sanity test_56Da is extended to exercise this case.
