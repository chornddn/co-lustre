LU-20290 lnet: refactor discovery visibility framework

Separate policy evaluation from full-view permission composition.

Several discovery-visibility policies can now be active at once. At
most one of them enumerates the filtered ping views; the others only
vote on whether the shared full/global view may answer a request. The
core serves the full view only when every active policy permits it,
so a policy that scopes access to the merged view alone plugs in with
no views of its own.

Reject a policy that has no name, or that enumerates views without
the per-view selectors the core calls on them.

The active set replaces a single pointer, so give it a publication
rule: the voters read it from the serve and Push paths without
ln_api_mutex, and the count is raised only after the slot below it is
stored and lowered before any slot is cleared.

Add a D_NET message where the composition refuses the full view for a
Push. The message gives the name of the policy that refuses. It helps
you to find the cause of a Push that the core stops.

No functional changes.
