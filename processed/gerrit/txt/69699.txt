LU-20963 lod: use a reconnecting OST only when needed

OST umount (OSS failover) only raises IMP_EVENT_DISCON: opd_imp_active
stays set, so osp_statfs() kept returning cached statfs and LOD could
not tell that the OST was gone, and used it as before.  osp_statfs()
now returns -EAGAIN while the import is disconnected
(opd_imp_connected), and still returns -ENOTCONN for an inactive or
deactivated OSP.  Do not use opd_pre_status for this: it stays -ENODEV
after reconnect until orphan cleanup is done.

lod_statfs_and_check() keeps a reconnecting OST active and returns
-EAGAIN if its cached statfs data is still usable (not full or
read-only), so the active target count (and the stripe count limit
derived from it), ltd_discon, lod_sync() and lod_obd_set_info_async()
(e.g. evict_client by NID) are not changed by a transient disconnect.
lod_ost_alloc_qos() leaves a reconnecting OST out, and
lod_ost_alloc_rr() and lod_ost_alloc_specific() skip it in their
first passes, but use it in their last, blocking pass, which only runs
if too few stripes were found, and wait in osp_precreate_reserve() as
before.  The specific allocator also waits for a reconnecting OST
requested with "-i", but not again after a reconnecting OST timed
out, and an OST listed with "-o" is waited for.  A
create during OSS failover or right after an OST restart then still
waits for the OST instead of failing with -ENOSPC or getting fewer
stripes than lod_stripe_count_min().

osp_statfs() still fills in the cached data for a reconnecting OST,
and lod_statfs() counts it, so that client df does not lose the space
of an OST during failover.  lod_trans_space_check() checks a
reconnecting target with its cached state, so that a distributed
transaction (e.g. migrate) does not fail with -EAGAIN.  lod target_obd
shows a reconnecting OST as INACTIVE, and a SEL component is not
extended onto it.

Move opd_imp_connected out of the osp_device bitfield, since LOD
allocation now depends on it, and osp_import_event() writes it without
a lock while the precreate thread updates other bits in the same word.

Refresh ltd_discon from every statfs result while the target is
already inactive (e.g. ENOSPC then deactivated), not only on the
active-to-inactive transition.

Add sanity.sh test_27ya to verify that target_obd shows the OST as
INACTIVE after umount and setstripe avoids the disconnected OST when
the other OSTs can provide all stripes.  Create its directory on
MDT0000, whose OSP import the test checks.  Add test_27yb to verify
that a create in a two-OST pool still gets both stripes when one OST
is disconnected.
