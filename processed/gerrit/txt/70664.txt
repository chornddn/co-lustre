--- Commit Message ---
LU-21177 mdc: keep parent UPDATE lock for volatile create

mdc_intent_open_pack() cancels the client's UPDATE lock on the
parent directory by early lock cancel before every create. A
volatile file is not linked into its parent, and since 2.14.52
(LU-14693) the MDT takes no DLM lock on the parent for it, so the
lock stays valid and the cancel only costs: it runs
ll_prune_negative_children(), which walks all cached children of
the parent under its d_lock. Tools working by FID (lfs migrate,
lfs mirror extend or split on .lustre/fid/[FID]) create their
volatile files in .lustre/fid, which caches one dentry per FID
looked up. With 400k of them, one volatile create spends about
5 ms in the walk, and path walks through .lustre/fid on the same
client spin on its d_lock meanwhile.

Do not cancel the parent's UPDATE lock for a volatile create. An
older MDT still locks the parent and revokes the lock by a
blocking callback, as for any create without early lock cancel.

Users of liblustreapi's volatile helpers, such as the HSM copytool
restore, also unlink the volatile name after the open, which
cancels the lock in mdc_unlink(). The change "llapi: don't unlink
volatile file opened on Lustre" removes that unlink.

Fixes: 8c04afb5236f ("LU-14693 mdt: skip DLM when opening volatile files")
