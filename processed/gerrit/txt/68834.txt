LU-20438 clio: eagerly evaluate P2P DMA capability via layout

Evaluating P2P DMA support in osc_io_init()/mdc_io_init() is too late:
lov_io_rw_iter_init() limits each cl_io_loop() pass to one stripe
chunk, and the sub-IO of a stripe is only created in that pass. If the
first stripe an I/O touches supports P2P DMA but a later one does not,
cl_dio_pages_init() pins and submits P2P pages for the first chunks,
then fails to pin the pages of the next chunk, leaving a partial I/O.

Move the check into lov_io_init_composite(), after lov_io_slice_init()
has set the I/O extent and selected the mirror. Check the OSC/MDC
import of every instantiated stripe of the selected mirror that
intersects the I/O extent (the whole file for O_APPEND), so
ci_p2pdma_unsupported is set before the first page is pinned, while an
I/O confined to P2P-capable stripes can still use P2P DMA. DoM and all
RAID0-based patterns (overstriping, parity, compression) are covered,
and stale components are included for designated mirror (resync) I/O.

Remove the now-redundant check in mdc_io_init(). The osc_dio_submit()
fast-fail remains as a last resort, e.g. for an import that reconnects
during the I/O.
