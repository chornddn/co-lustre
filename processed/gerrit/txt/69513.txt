LU-20503 tests: restart grace timer in test_block_soft

The block grace timer starts when the write that crosses the soft
limit is issued, and the writes and the quota queries that follow
can take longer than the grace time on a loaded system, so the timer
is already over when the test issues the writes that are expected
to succeed. The test then measures how fast the filesystem
is instead of the grace time behaviour, and fails with "write
failure, but expect success" (test_3b) or "mmap write failure, but
expect success" (test_3a).

In the debug logs of the failing run (ZFS 4MDTs/8OSTs, 60s grace)
that write is done by dd as ten 1KB writes, and ll_do_tiny_write()
sends each of them synchronously to the OST (osc_queue_sync_pages()
with no DLM lock), which took between 1.4s and 17.9s each, 49s in
total, followed by the mmap write and six lfs quota dumps. The
grace timer of that subtest started at 1788773828 and expired at
1788773888, while the check ran at 1788773897.

Restart the block grace timer of every quota that limits this test
file (the global one and each pool one) right before those writes,
and check that it was running before restarting it, so a master
that fails to start it is still reported.
