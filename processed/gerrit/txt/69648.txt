LU-20890 quota: don't panic on ENOSPC in lquota_disk_write

Replace ASSERTION in lquota_disk_write with CERROR. Even if we are
unable to insert a new or old record, the old one has already been
removed. At this step kernel panic can not restore anything and the
best we can do is to print an error with the ID needs to be repaired.
Below is an example of a panic in case of ENOSPC at the MDT. Note, the
same ASSERTION might be triggered at the OST side as well.

     ASSERTION( rc == 0 ) failed: failed to insert record in quota
     index [0x200000006:0x2020000:0x0]

Also replace LBUG in qmt_dqacq0. It can be hit on the same error
(ENOSPC, ENOMEM, EIO, etc.) when lquota_disk_write returns an error
and the slave index is rolled back.
