LU-20662 statahead: skip repeated stat() of the same entry

ll_statahead_enter() decides whether a directory is a candidate for
the file name indexing statahead pattern by counting how many stat()
calls in a row land on a child whose name ends with a number.  It
only checks that the last character is a digit, it never parses the
number, so it cannot tell one indexed entry from another.  Repeated
stat() calls on a single file therefore look exactly like a walk over
a sequence of indexed files, and the directory is enabled for
statahead after @statahead_fname_predict_hit such calls.

This is easy to hit without any name indexing workload at all.
"lfs mirror extend" fstat()s the source file in migrate_open_files()
and again in mirror_extend_layout(), and fstat()s the volatile
destination file in between, whose name ends with "fd=%.2d".  Three
getattrs, two distinct files, and the parent directory is enabled for
statahead.  In sanity test_270h that leaves d270h.sanity enabled for
statahead long after the test has finished, and the statahead RPCs
issued later are accounted to mdc stats sampled by test_271f, which
fails with a bogus "resend occured on append" error.

sa_pattern_fname_detect() already handles this case: it parses the
trailing number, rejects a repeat of the last seen index, and requires
the indexes to be sequential.  Factor the suffix parsing out into
sa_fname_index_parse() and use it in both places, so that
ll_statahead_enter() records the index it has seen and no longer
counts repeated access to a single entry as a match.

Add sanity test_123m to check that repeated stat() of one indexed file
does not start statahead, while stat()ing distinct sequentially
indexed files still does.
