--- Commit Message ---
LU-20923 llite: handle unexpected MDS reply contents

Several llite paths relied on invariants that an MDS reply or granted
lock is expected to satisfy, and handled only the expected case.  Make
each path handle the unexpected contents gracefully:

 - ll_update_inode() copies the FID from the reply body into the
   inode.  Check the reply FID against the inode FID before applying
   any attribute, and return -EPROTO on a mismatch, so a stale or
   foreign reply is dropped rather than partly applied; the FID is
   still populated the first time, when the inode FID is not yet set.

 - ll_inode_from_resource_lock() returns the inode cached on a lock
   resource, which is keyed by FID.  When the cached inode's FID does
   not match the resource name, log it and return no inode (as for the
   bogus-magic case) so the caller skips it; the grabbed inode is
   released with iput() after the resource lock is dropped, as iput()
   may sleep.

 - ll_lock_cancel_bits() maps an OPEN-bit lock's mode to the open mode
   to close.  For a lock granted in any other mode, log it and skip
   the open-close, leaving the OPEN bit cleared.

 - ll_lease_open() requires the open intent reply to carry the
   DISP_ENQ_OPEN_REF disposition.  Return -EPROTO when it does not; no
   open handle has been filled at that point, so only the intent is
   released.
