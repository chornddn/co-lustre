LU-20924 osd-ldiskfs: allocate internal files as metadata

On hybrid flash/HDD ldiskfs targets, Lustre internal index and log
files are regular files, so ldiskfs allocates their blocks as data in
the HDD groups.  OI lookups are the main small random IO on an OST,
and the other IAM indexes and the last_rcvd, reply_data and LAST_ID
record files are updated in place like other metadata.

Set LDISKFS_STATE_META_ALLOC on these inodes before osd-ldiskfs
allocates blocks for them, so ldiskfs places them in the IOPS groups
like directories.  The state is set before every IAM block append and
every block allocation in osd_write() to a regular file, which is only
used for internal files.  Only the header (first 64KiB) of a plain
unnamed llog (changelog, OSP sync and DNE update llogs) is updated in
place, while the records are appended and written back by journal
checkpoint sequentially, so for these the state is set only while
allocating blocks in the first 64KiB and cleared for later blocks.
This is done under i_append_sem with each allocation, since changelog
and OUT update writes to one llog run in parallel, and the block
preallocation for llog appends stops at 64KiB.  They are identified by
their unnamed-llog or update-log FID sequence, and DNE update llogs by
their normal FID, which no other regular file written by osd_write()
has.  Named llogs (CONFIGS, changelog_users...) and catalogs are
long-lived, so they are fully metadata, catalogs recognized by
LLOG_F_IS_CAT in the llog header that llog_osd_write_rec() writes
before each record, or read from the first block once after the inode
is loaded.  OST object and DoM file data are written through the bulk
IO path and stay data.  The state is kept in memory only, so it also
applies to existing filesystems.

Add conf-sanity test_172 to check that directories, internal files,
named llogs, catalogs and llog headers of a hybrid MDT and OST are in
the IOPS groups and plain llog records and file data are not.

Patch Set 1: Code-Review+1

Tested PS1 with ltvm on rocky9 (5.14.0-611.55.1.el9_7), 2 MDTs and
2 OSTs so the DNE update llogs are written too: conf-sanity test_172
passes (56-66s, x3).

The same test_172 on the parent 75721f5625 (69716 only) fails with
"mds1 blocks allocated in the wrong groups" (reply_data and plain
llog headers O/1/d*/* misplaced), so the test catches a missing
osd-ldiskfs change.

I also checked the allocations directly with eBPF. bpftrace with a
kprobe/kretprobe on ldiskfs_mb_new_blocks() records, for every
allocation on the Lustre targets, the inode, logical block, result
block and whether the request has HINT_DATA (0x20).  Inodes were
mapped to paths while test_172 mounts each target as ldiskfs for its
own check.  IOPS groups end at block 32768 (MDT) and 24576 (OST).

Allocations on the hybrid targets during test_172:

                                       requests       blocks
   file class                          without        IOPS/HDD
                                       HINT_DATA
   MDT internal files (oi.16.*,        272/272        272/0
     last_rcvd, reply_data, LAST_ID,
     lov_objid, fld, seq_*, quota,
     LFSCK, nodemap...)
   MDT named llogs and catalogs        21/21          75/0
     (CONFIGS/*, CATALOGS, changelog_*)
   MDT plain llog headers, < 64KiB     3644/3644      3706/0
     (changelog, unlink, update_log_dir)
   MDT plain llog records, >= 64KiB    2/62           8/240
   MDT DoM file data                   0/1            0/128
   OST internal files (O/*/LAST_ID)    156/156        156/0
   OST named llogs (CONFIGS/*)         3/3            12/0
   OST object data                     0/102          0/2148

The 64KiB split for plain llogs is exact, including the DNE update
llogs. The two record allocations without HINT_DATA are both in
O/1/d2/2 ([0x1:0x2]), which looks like the OSP sync catalog and so
is expected to be fully metadata. Regular files allocated without
HINT_DATA appear only on the two hybrid targets during test_172,
not on MDT0001, the second OST, or the non-hybrid mounts before and
after it.
