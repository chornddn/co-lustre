LU-20790 efalnd: Repost an Rx when it is freed

Each QP counts its free receive slots in rq_space. kefalnd_free_rx()
increases it when a receive buffer is released, and
kefalnd_refill_rx() posts at most rq_space buffers.

When a message arrives, kefalnd_handle_rx() handles it and then
refills one buffer, so the buffer is meant to be released first and
refilled second. That holds for a regular receive: LNet consumes the
message while it is being handled, the buffer is released, rq_space
goes up by one, and the refill reposts that slot. A delayed receive,
e.g. a message waiting for an MD to be posted or for router buffers,
breaks that order. LNet keeps the buffer past the handler, so the
refill runs first, finds rq_space at zero and posts nothing. The
buffer is released later from another thread, which raises rq_space
but posts nothing. From then on each message releases and reposts
exactly one buffer, so the extra free slot is never filled. Every
delayed receive leaves one more slot empty, until the QP has no
receive buffers posted and peers stall retrying.

Refill in kefalnd_free_rx() right after the release, so the order
holds wherever the buffer is released, and drop the refill calls this
makes redundant.
