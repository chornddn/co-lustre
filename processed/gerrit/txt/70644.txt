LU-21164 libcfs: open dump files with init's fs in kthreads

Linux 7.3 starts all kthreads in an empty nullfs root, so path
lookups from kthread context fail with -ENOENT unless they switch to
init's filesystem state with scoped_with_init_fs(). Lustre opens
files by absolute path from kthreads to dump the debug log
(debug_path, the debug daemon) and pages with checksum errors, so on
7.3 these all fail and nothing is written, e.g.:

  can't open /tmp/f60f.sanity.1793998958.261983 for dump: rc = -2

This breaks sanity test_60f, test_77c, test_170 and test_410.

Wrap these lookups in scoped_with_init_fs(): the debug log dump in
libcfs_debug_dumplog_internal(), the debug daemon file in
tracefiled(), the checksum dumps on the client and the server, and
the kinode test thread. Dumps requested by "lctl dk" still resolve
the path in the caller's context. Add a configure check for
scoped_with_init_fs(), and make it a no-op on older kernels, where
kthreads use init's root.
