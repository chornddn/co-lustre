--- Commit Message ---
LU-21249 scripts: harden ZFS OST degradation updates

Fix several areas where the zedlet might fail due to bugs or might not
log enough information when failing to identify the problem.

* Set degraded only when the target has OST in the name since we
are using obdfilter.*.degraded in the set_param.
* check failures from ZFS, ZPOOL, and LCTL queries so they do not hide
configuration problems that prevent correctly setting and unsetting
the property.
* map command failures to exit status 5, and log the dataset and
parameter.
* Query pool health before discovering datasets to avoid blocking on
unavailable pools.
* Read the local lustre:autodegrade property for each discovered
dataset and query the obdfilter parameter only for matching OST
service names with autodegrade enabled.
* Continue processing after a dataset fails and return status 5 after
all datasets have been considered.
