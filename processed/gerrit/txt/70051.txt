LU-21040 ptlrpc: do not wait for reconnect on active=1

Setting "active=1" on an MDC, OSC or OSP import through sysfs waits
up to obd_timeout in ptlrpc_recover_import() for the target to
reconnect.  The same store method applies "conf_param *.osc.active"
records from the config logs.  On a server all config logs are
reprocessed one after another by mgc_requeue_thread(), so with the
OST down every local MDT log stalls for obd_timeout.  With 6 MDTs on
one MDS the last MDT got the update after 6 * obd_timeout, and
conf-sanity test_66 timed out waiting for MDT0000.  The wait also
returns -ETIMEDOUT after the import was already activated, which
osp_process_config() reported as "unknown param osc.active=1".

Only start the reconnect from the sysfs "active" store and do not
wait for it to finish.  "lctl --device N activate" still waits.
"lctl set_param {mdc,osc,osp}.*.active=1" now returns before the
import is FULL, so scripts should wait for the import state instead.
