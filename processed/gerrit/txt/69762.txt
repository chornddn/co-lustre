LU-20287 lov: don't block setattr on unavailable OST

chown/chgrp/chmod/touch wait in cl_setattr_ost() when a stripe OST
is down: VFS sets ATTR_CTIME and the client sends OST_SETATTR to
every stripe. That RPC only carries times/flags; UID/GID/PROJID are
authoritative on the MDT and are pushed by MDS osp_sync (persistent
llog, retried until the OST returns). Skipping the client RPC
therefore does not leave stale ownership on OST objects.

For non-truncate/non-fallocate setattr on any layout, mark LOV
sub-IOs ci_ndelay so OSC sends OST_SETATTR with rq_no_delay and
rq_no_resend (plus a 5s delay limit for idle import reconnect),
and ignore -EAGAIN/-ENOTCONN/-ESHUTDOWN/-ETIMEDOUT for such sub-IOs
in osc_io_setattr_end(). Ndelay applies only when the new mtime/atime
are >= max(ctime, sa_cur_time), where sa_cur_time is the known prior
inode/cached OST times: ll_merge_attr() takes max(MDT, OST), so
skipping an OST that already holds a newer time would leave that
value visible. Missed updates are not repaired later, and on a slow
but connected OST the client update may also be dropped.

The CLM_WRITE [0, EOF] lock in vvp_io_setattr_lock() uses that same
baseline, not ctime alone. Plain touch/utime(NULL) therefore takes
the lock when sa_cur_time is ahead of the client clock (writer clock
skew, or a future timestamp) and revokes other clients' cached
extent locks; that path does not set ndelay. That is intentional:
without it ndelay would skip the newer OST and max() would keep the
wrong time.

Still block when:
- mtime/atime moves earlier than that baseline;
- OP_XVALID_FLAGS is set (chattr, encryption flag): MDS never
  pushes flags to OSTs.

This only unblocks the setattr RPC itself (including chmod(2)).
stat/glimpse can still hang when no usable stripe/mirror is
reachable: e.g. coreutils chmod stats via FTS before chmod(2),
so the command may block on plain files even though the syscall
would not. That is unchanged here (see LU-11962 for MDT SOM).

Also re-push UID/GID/PROJID from the MDT inode on FLR RESYNC_DONE
in lod_layout_change() with the layout version update. osp_sync
normally retries ownership pushes; this is belt-and-suspenders if
an MDS->OST ownership setattr was skipped (e.g. exercised with
OBD_FAIL_LFSCK_BAD_OWNER; layout LFSCK can also repair that).

Add sanity 39v (plain file) and sanity-flr 100a/100b.
