LU-19921 ptlrpc: add GSSIAM upcall operations and helper

This patch adds the upcall operations and tunable attributes
for the GSSIAM security flavor, along with the userspace helper
program (l_gssiam_upcall) and its manual page (l_gssiam_upcall.8).
The helper serves as a reference implementation that returns a
mock IAM token and passes it back to the kernel via a sysfs
downcall for testing and verification.

Specifically, this patch implements:

- UAPI Downcall Interface: Adds GSSIAM_DOWNCALL_MAGIC and
  struct gssiam_downcall_data to lustre_user.h, along with
  idd_token() and idd_principal() inline accessor helpers for
  kernel-to-userspace downcall communication.

- Kernel Upcall & Cache Operations: Implements the upcall and
  downcall parsing handlers (gssiam_do_upcall, gssiam_parse_downcall,
  gssiam_upcall_compare) in lustre/ptlrpc/gss/gssiam_upcall.c.
  The upcall mechanism protects uc_upcall path lookups and
  call_usermodehelper() invocations under uc_upcall_rwsem,
  validates downcall payload string lengths against overflow,
  applies configured cache expiration times, and supports
  sysfs cache flushing by key for principal-based mounts.

- Userspace Helper Program: Adds lustre/utils/gss/l_gssiam_upcall.c
  to handle kernel sysfs upcalls, format GSSIAM downcall
  payloads, and return appropriate error codes on missing
  parameters or downcall open failures. Uses logmsg() and
  initerr() for standardized logging across GSS tools.

- GSS Logging Refactoring: Moves __logmsg(), g_log_level,
  log_prefix, and log_hex() from lgss_utils.c into err_util.c
  and err_util.h. This allows standalone GSS helper programs
  (such as l_gssiam_upcall and l_gssiam_auth) to call logmsg()
  and initerr() without depending on liblustreapi.la or
  Kerberos/OpenSSL libraries, ensuring they build as native,
  installable ELF binaries without Libtool shell script wrappers.
