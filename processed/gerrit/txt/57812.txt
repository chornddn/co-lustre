Rechecked the delta since PS1, which I had +1'ed. PS5 is the master commit 392f558f40 (change 57117) plus three additions: the masked hash type check in mdt_dir_layout_update(), taken verbatim from master 81ac7c0c98 (LU-12273, not in b2_15); the --clear-fixed line in the lfs migrate help from master aebc28eea7 (LU-18653); and LMV_HASH_FIXED_FLAG corrected to LMV_HASH_FLAG_FIXED in the man page and the commit message.

The mdt_xattr.c hunk is needed: with lfs setting the fixed flag, the unmasked b2_15 check failed sanity 230k/230w/230z in PS1 and PS4. Everything else matches master, all helpers exist in b2_15, and the change still cherry-picks cleanly onto the current b2_15 tip (v2_15_8-21).

Main concern: master follow-up 870525f417 (LU-20685, a 2.18 blocker, Fixes: 392f558f40) is not included. With this patch a b2_15 client also sends the fixed flag in the setxattr that completes a directory migration, and every 2.15 MDS without this patch (2.15.8 and older, already deployed) rejects it with EINVAL. Details in the [major] comment in lfs.c; -1 until that client-side mask is part of the port.

[minor] The commit message does not mention the hunks taken from other master commits, see the comment in mdt_xattr.c. Your open thread on PS3 lfs.c (I will push this minor change on master) is done: it landed as aebc28eea7, so it can be resolved.

A question about code this patch does not touch: master also has 103c1f560c (LU-18639 dne: a correct check for dir split, Fixes: 392f558f40). lod_dir_declare_layout_split() and lod_object_lock() are the same in b2_15 (pre-existing, not touched by this patch). Is a port of it planned, with f26654ef23 for the sanity 230p version check?

Tests and CI: jenkins build 110446 is fine; Maloo +1 on PS5 after the review-zfs retest (sanity-flr, LU-15300). PS1 and PS4 failed review-dne-part-1 sanity 230k (migrate -m 0 -c 2 failed), 230w (stripe count mismatch) and 230z (migration is not finished, resume migration failed), which is the failure an unpatched 2.15 MDS gives a PS5 client. The results are from January 2025 on the 2.15.6 base; with the client mask added, an interop session like the one in 870525f417 (testlist=sanity serverversion=2.15 mdscount=2 mdtcount=4 env=ONLY=230w) would prove it.
