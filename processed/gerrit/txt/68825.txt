LU-20107 nrs: one ceiling per CPT for both scheduler heads

A global rule divides its rate over the scheduler heads that the
start command reaches. A command for both queues reaches two heads
for each CPU partition. The node tier change therefore divides the
rate over 2 * ncpts. The ceiling holds, but the high priority head
takes
an I/O RPC only under a blocking lock callback. Half of the node
rate idles in the common case.

A divisor of the partition count alone gives the other defect. The
two heads keep two clocks, so the pair can pass twice the partition
share. A limit rule must never pass its rate.

Give the node class one limit clock for each CPU partition. Both
heads of a partition read and advance that clock, and the divisor
goes back to the partition count. The high priority head still wins
a tie, because ptlrpc_server_allow_high() polls it first.

Add sanityn/test_77xj, which measures one job under real high
priority traffic and bounds its RPC rate by the node rate.

This change replaces the 2 * ncpts divisor of the node tier change.
It stands on its own so that it can be reviewed apart, and can be
squashed into that change.
