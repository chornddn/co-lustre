LU-20514 llite: find NFS name of a file from its linkEA

ll_get_name() read the whole parent directory to find the name of a
regular file when exportfs reconnected its file handle, e.g. on an
NFS export with subtree_check, which is slow for a large directory.
Unlike a directory, the name of a file cannot be taken from its
linkEA as it is: the client may cache a linkEA of the file that still
lists a name another client unlinked, since the MDT does not revoke
the XATTR lock of a file when it unlinks a name of the file.

Take the name of a file from its linkEA as well, and check with a
getattr by name in the parent that the name still has the FID of the
file.  Try the next linkEA name in the parent if it does not, and read
the directory only if no name is found.  The getattr asks only for the
FID, which the MDT looks up without taking any locks, except for a
long no-key name.

Add sanityn test_102d to check that knfsd reconnects a file with hard
links in a subtree_check export without reading its parent, in a
plain and a striped directory, when the first linkEA name is rejected
as stale (OBD_FAIL_LLITE_NFS_STALE).
