LU-10499 pcc: asynchronous PCCRO attach command support

Currently PCCRO attach via the command "lfs pcc attach" will block
during the data copying.
There is a requirement that this command can also do data copy
asynchronously. Thus we add an option "--async|-A" to the command
which will not block while the file data is being fetched.
The attach is done synchronously if llite.*.pcc_attach_thread_max
attach threads are already running, or a thread cannot be started.
Configuration errors, such as an unknown PCC backend id, are still
returned before the thread is started, while a failed background
copy leaves the file unattached.  Encrypted files can be attached
asynchronously as well, and sanity-pcc test_21j now does that.

Add sanity-pcc test_103 and test_104 to verify that it works
correctly, using a new OBD_FAIL_LLITE_PCC_COPYDATA_PAUSE fail_loc
to see the attach in progress.

LU-10499 doc: man pages for asynchronous PCCRO attachment

This patch updates the man pages for asynchronous PCCRO attachment
for "lfs pcc attach -A" command.

LU-10499 tests: use smaller files in sanity-pcc/103+104

Running fallocate is fast, but the actual PCC data copy may be slow.
Use smaller test files for sanity-pcc test_103 and test_104 to speed
up testing, and also wait longer in case the copy is slow.

Add some extra debugging on failure so we can see the file attach
state on failure, in case there is something wrong with the parsing.

Create the PCC backend loop device as a sparse file and format it
with lazy journal and inode table init.  The tests now compare files
with plain cmp, so the CMP_LINES limit on "cmp -bl" output is not
needed, and LU-19575 already changed the umount_loopdev() retry.
