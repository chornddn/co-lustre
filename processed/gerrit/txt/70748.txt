LU-21132 build: take const mnt_idmap in VFS callbacks

Linux commit v7.3-rc1-23-gc3150ded7bc0 ("fs: port ->getattr() to pass
const mnt_idmap") and the rest of the vfs-7.4-rc1.idmap series made
the idmap argument of the inode_operations and xattr_handler callbacks
const, so Lustre's callbacks no longer match the slot types.

Declare the callbacks with const struct mnt_idmap *idmap, as that
kernel does.  For older kernels add a configure check and, next to the
macros that drop the argument for kernels without one, macros that
strip the const through ll_idmap_arg().  It works by token pasting, so
the argument must be named idmap in every callback.

Also define ll_get_acl() once per kernel variant, and rename the memfs
do_mkdir() to memfs_do_mkdir() so its macro does not clash with
llite's do_mkdir().
