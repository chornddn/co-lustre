LU-17240 tests: start targets through shared start_facets()

mountmds() and mountoss() each have their own loop to start targets
in parallel, and conf-sanity needs a third copy for its MDTs.

Add start_facets(), the counterpart of unmount_facets(), to start a
list of targets through start() with their usual devices and mount
options, plus any options given.  The MGS and MDT0000 start first,
and the other targets after them, in parallel if enabled for their
type.  With --skip-mounted, a target that is already mounted only
has its variables set, as mountmds() and mountoss() did.
mountmgs(), mountmds() and mountoss() now use it.  This changes no
timings by itself; it lets conf-sanity use the same parallel start
instead of a copy of it (next patch).  It is not
mount_facets(), which remounts targets after a failover with the
device and options of their last start().

If MDT0000 fails to start, mountmds() now returns without starting
the other MDTs, instead of trying them anyway.  Every caller fails
the test on that error.

unmount_facets() now also takes a comma-separated list, as
get_facets() prints it, and removes $TMP/mgsactive along with
$TMP/mds1active when the MGS is combined with MDT0000, which
stopall() did itself before.
