LU-15864 ofd: recreate lost objects for all requests

An OST restart loses the objects it had precreated but not
committed. Write replay recreates them during OST recovery,
and the MDT's orphan cleanup does so once the MDT is out of
its own recovery. When the MDT restarts too, as when MDTs and
OSTs share a server, that can be well after the OST has
finished recovery. A request reaching the OST in between finds
its object missing and fails with -ENOENT. A write with a
cached lock fails this way and the application gets -EIO; a
setattr from the MDT is dropped as if the object were gone.
Only lock enqueue handled the window, by returning -EINPROGRESS
since LU-15195.

Recreate a missing object, and those below it in its sequence,
if its ID is above the OST's LAST_ID and either the OST is in
recovery or the MDT has yet to run orphan cleanup for the
sequence, within the hard recovery timeout. Do this for read,
write, getattr, setattr, punch, fallocate, sync, seek, fiemap
and ladvise, using a local transaction so that a request is not
given a transno for it. Do not recreate while LFSCK rebuilds
LAST_ID, nor more than OST_MAX_PRECREATE objects, the most that
orphan cleanup destroys if the MDT never used them: write replay
used to recreate any gap. Outside recovery, stop after
DISK_TIMEOUT and return -EINPROGRESS so that the client resends.

Lock enqueue cannot create the object, as orphan cleanup inits
LVBs while holding the sequence's create lock. Its -EINPROGRESS
kept stat and chown of a lost object waiting for orphan cleanup,
however long the MDT took to recover. Give a lost object the
empty LVB of the object it will be recreated as instead. A
missing object at or below LAST_ID was destroyed, and still
gets -ENOENT.

Add replay-ost-single tests 12c to 12l, which fail over the
MDT and the OST together with orphan cleanup delayed and check
that each kind of request succeeds. Pin their directory to MDT0000
and require OST0000 so that allocation cannot use other targets.
Keep statfs behind the replay barrier from reporting read-only
space, which otherwise redirects ZFS allocations to another OST.

Patch Set 3:

Patch set 3 extends this to every OST request that looks up an object (read, write, getattr, setattr, punch, fallocate, sync, seek, fiemap and ladvise), and gives a lost object an empty LVB on lock enqueue instead of -EINPROGRESS, so stat and chown no longer wait for orphan cleanup. It also fixes what the AI review found in patch set 2: the gap is no longer truncated to int, a large gap no longer returns -EOVERFLOW (which replay takes as a VBR failure), and recreation holds ofd_lastid_rwsem so it cannot race an LFSCK LAST_ID rebuild. The replay-single test is replaced by replay-ost-single 12c to 12l, which fail over the MDT and the OST together; all ten fail on master and pass with this patch.

Related: the compressed write path in https://review.whamcloud.com/68347 (ofd_compress.c) has its own 'BRW to missing obj' check, which would need the same ofd_object_recreate() call if it lands after this.
