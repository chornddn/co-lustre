LU-20205 ldlm: fix hpreq_check when first cancel lock is gone

With HPREQ_CHECK1, ldlm_cancel_hpreq_check() only checks the first
lock handle. But this lock can already be gone on the server, while
BL_AST locks packed behind it still need the HP queue:
- the lock was taken for LRU cancel, which clears CANCEL_ON_BLOCK,
  and then got a BL_AST, so the server already cancelled it;
- the lock was force-packed by ldlm_cancel_pack() in ldlm_cli_cancel()
  after another cancel RPC also packed it, and that RPC was handled
  first.
In both cases the check stops at i > 0 and returns 0, so the cancel
RPC is not HP and the client may be evicted on lock callback timeout.

Stop after the first lock only if it still exists. Otherwise scan the
other locks for AST_SENT as before.
