LU-21023 mdt: return -ESTALE for a migrated file or directory

A request that waited for the lock of a file behind its migration then
found it destroyed, and returned -ENOENT for a name that still
existed: stat, getfattr, setfattr, chmod, truncate or link of the file
failed. A plain directory isn't destroyed by migration but stays as a
stripe of the new directory until the migration completes; a client
that revalidated or opened it by its old FID got the stripe LMV, which
lmv_stripe_object_create() rejects with -EPERM, so "ls -l" failed and
"rm -rf" skipped the directory and failed with -ENOTEMPTY.

- mdt: add mdt_object_is_stale() for a non-directory that was
  destroyed while the request waited for its lock, e.g. unlinked or
  migrated (mdt_object_destroyed(), not just dying: layout LFSCK can
  drop a live object with dt_object_put_nocache()). Return -ESTALE
  for it in mdt_getattr_name_lock(), both when it is revalidated by
  FID and when it is looked up for another MDT (mti_cross_ref), and in
  mdt_getxattr(), mdt_reint_setxattr() and mdt_attr_set(), so the VFS
  looks a path-based call's name up again and finds the new FID.
- mdt: add mdt_dir_is_stripe_now() and return -ESTALE when a directory
  revalidated by FID in mdt_getattr_name_lock(), opened by FID in
  mdt_open_by_fid_lock(), or changed by mdt_attr_set() or
  mdt_reint_setxattr() has become a stripe; a change to the stripe
  would be lost with it. Revalidate uses the LMV that
  mdt_getattr_internal() read, the others read only the LMV header.
- mdt: in mdt_reint_link(), return -ESTALE when mdo_link() fails with
  -ENOENT because the source no longer exists. A remote source is only
  invalidated by its migration, not dying, so mdt_object_is_stale()
  doesn't catch it.
- llite: in ll_inode_revalidate_fini(), log -ESTALE at D_INFO, not
  D_ERROR. Don't clear nlink for it as for -ENOENT: a resent getattr
  that lost its lock also gets -ESTALE for a live file.
