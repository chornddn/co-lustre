LU-18838 statahead: fix ll_sa_running double-decrement on error paths

start_statahead_thread() and ll_ioctl_ahead() both increment
sbi->ll_sa_running once, and both release @sai on error with ll_sai_put().
ll_sai_put() itself decrements ll_sa_running when it drops the last
reference to @sai.  The error paths then also called an explicit
atomic_dec(&sbi->ll_sa_running), decrementing a second time for the same
increment.  Under racer load kthread_create() fails repeatedly with
-EINTR, so this fires often and drives ll_sa_running negative (observed
-14/-1 in a timeout vmcore).  A negative counter is also unsafe: it can
mask genuinely running statahead threads from the ll_kill_super() drain
loop.

Decrement explicitly only when @sai was released with ll_sai_free()
(the fail_free path), or when the failure happened before @sai was
allocated; otherwise let ll_sai_put() account for it.
