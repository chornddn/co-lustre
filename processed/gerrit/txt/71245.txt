LU-20455 tests: per-subtest .ltsh headers, linux_version

Allow each subtest in a .ltsh file to have its own YAML header in the
comment block just before its test_NNN() function, after the file
header that holds the keys shared by all of its subtests, so that the
metadata of a subtest can be read next to its code.  The fields of
such a header are the same as for a subtest under "subtests:".  A
header not followed by a test_NNN() function, a subtest with a header
in both places, or a missing file header before the subtest headers
is an error of the file.  Convert sanity.d/test_230i.ltsh to this
form, and add the "migrate_dir" keyword for 230i and 230j.

Add a "linux_version:" requirement to check the client kernel
version, like "linux" lines in lustre/tests/except/*.ex files.  Have
build_test_filter() compare those lines with LINUX_VERSION_CODE.
LINUX_VERSION is a dotted string, so the arithmetic failed and these
lines always skipped their subtests.  Have version_code() limit each
field to 255, as the kernel does, so that e.g. a 5.10.300 kernel does
not compare newer than 5.11.0.

Move sanity-lnet test_290 to sanity-lnet.d/test_290.ltsh, with its
kernel version check as "linux_version:".  Set the LTSH_* hooks in
sanity-lnet.sh to do nothing, since its subtests set up LNet
themselves and need no filesystem.

Give a "client_version:" requirement for the moved subtests, the
version of the last commit in their "commit:" list.  The test scripts
are installed with the client, so it changes nothing yet, but it will
let subtests run with a separately installed client later.  Have
README-ltsh.md and the lustre-test-scripts agent skill ask for it in
every subtest header.

Move the conf-sanity-framework.sh settings for .ltsh subtests to the
top of the file.

Have checkpatch.pl not ask whether MAINTAINERS needs updating for new
.ltsh files, since most patches adding a subtest will add one.

Add sanity-ltsh test_1j for "linux_version:", and test_8a and test_8b
for headers before each subtest.
