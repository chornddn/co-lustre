LU-19276 llapi: add llapi_changelog_(de)register

Add llapi_changelog_register() and llapi_changelog_deregister()
to allow them to be used by external applications.

Man pages llapi_changelog_register/deregister.3 are added and
lctl-changelog_register/deregister.8 are updated to reflect the
new changes. sanity.sh/test_160q is modified to verify this patch.

Move llapi_obdname2devno() and llapi_ioctl_dev() into internal
library functions so that they are more easily usable, but not
yet fully public API functions.

Rename yaml_get_device_index() to llapi_yaml_get_device_index()
to avoid namespace clash with yaml library, and fix resource
leaks on error cleanup paths.

Remove long unused jt_lcfg_device() wrapper function.

**The Error:**
```c
fprintf(stderr,
    "%s: filesystem name '%s' must be 1-%d chars: %s\n",
    progname, LUSTRE_MAXFSNAME, optarg, strerror(-rc));
```

The format string expected:
- `%s` → progname ✓
- `%s` → filesystem name (should be `optarg`)
- `%d` → maximum length (should be `LUSTRE_MAXFSNAME`)
- `%s` → error message ✓

But the arguments were:
- progname ✓
- **LUSTRE_MAXFSNAME** (int) - passed to 2nd `%s` (expects char*)
- **optarg** (char*) - passed to `%d` (expects int)
- strerror(-rc) ✓

**The Fix:**
I swapped the order of `LUSTRE_MAXFSNAME` and `optarg` to match the format string:

```c
fprintf(stderr,
    "%s: filesystem name '%s' must be 1-%d chars: %s\n",
    progname, optarg, LUSTRE_MAXFSNAME, strerror(-rc));
```

**Rationale:**
This matches the format specifiers with their corresponding arguments, ensuring type safety and correct output. The error message will now properly display the filesystem name followed by the maximum allowed length.
