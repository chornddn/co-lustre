LU-20994 osd-ldiskfs: end bios on RAID row boundaries

osd_do_bio() fills each bio until the disk blocks stop being
contiguous or bio_add_folio() fails. How far a full bio reaches
depends on how many of the buffer pages merge into multi-page
bvecs, so it usually ends in the middle of a RAID row (full
stripe). The RAID device then gets that row in two bios and must
take its partial-stripe path for it: a read-modify-write, or a
slower stripe-cache path instead of a full-row write.

On md RAID6 8+2 OSTs with 1 MiB rows and 4 MiB O_DIRECT writes,
about half of the requests reached md in 2-4 bios cut mid-row, and
23% of the rows were written as partial stripes; md wrote 17.2
GiB/s against 21.4 GiB/s in a run where 90% of the requests
happened to be a single bio.

Use the ldiskfs stripe as the row size: mount -o stripe=, else the
superblock's stripe width, else its stride. With only a stride set
this is the RAID chunk rather than the row, so bios end at chunk
boundaries instead, which is harmless. For writes, at each row
boundary end the bio if the next row, or what is left of the I/O
if less, does not fit in the bvecs left in it. The bvecs a row
needs are counted from its pages, one per physically contiguous
run, so bios still grow past one row when the pages merge (for
example with higher-order I/O buffers). A row that needs more
bvecs than any bio can hold is split anyway, so no cut is made for
it. A fragment within a page also stops at a row boundary. Reads
and OSTs without a stripe are unchanged.

Test: md raid6 8+2, 128 KiB chunk as an extra OST, 300 x 4 MiB
O_DIRECT writes, bios traced at md0 (block_bio_queue), 3 runs each:
  stripe off: 600 bios, 300 ending mid-row
  stripe on:  650 bios, 0 ending mid-row (150 x 4 MiB,
              50 x 3 MiB, 450 x 1 MiB); data verified
md raid6 6+2, 256 KiB chunk (1.5 MiB row, more than 256 pages):
  stripe off: 975-999 bios; stripe on: 753-754 bios, no extra cuts

On a site with 8+2 RAID6 OSTs (1 MiB rows), 3 clients writing
4 MiB O_DIRECT, the share of rows written as full stripes went
from 77-94% to 100%, and client writes went from 16.4 to 20.8
GiB/s with 2 OSTs on one server (+26%) and from 33.1 to 35.4 GiB/s
with 4 OSTs on two servers (+7%).
