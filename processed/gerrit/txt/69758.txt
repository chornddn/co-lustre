LU-20982 utils: mkfs.lustre refuses foreign signatures

`mkfs.lustre` on ldiskfs overwrites a device holding an xfs or ext4
filesystem, an LVM, RAID or LUKS member, or a partition table, without
`--reformat`. The only refusal is `osd_is_lustre()`;
`ldiskfs_make_lustre()` always passes `-F` to mke2fs, and mke2fs checks
for an existing filesystem only when stdin and stdout are ttys. Under
automation there is no tty, so a wrong device path destroys data
silently. `mkfs.xfs`, `mdadm --create` and `pvcreate` all refuse in this
case.

- `mkfs_lustre.c`: `check_foreign_signature()` probes the device with
  `blkid -p -D -o export` before an ldiskfs format when `--reformat` is
  not given, after the `osd_is_lustre()` check. Exit 0 (signature) or 8
  (colliding signatures) refuse with a message naming the signature and
  `--reformat`. Exit 2 proceeds. blkid missing or failing warns and
  proceeds, so systems without util-linux blkid keep working. `-D` is
  required: without it `blkid -p` exits 0 on a blank partition with only
  `PART_ENTRY_*` keys.
- `mkfs.lustre.8`: `--reformat` also covers a foreign signature.
- conf-sanity test 168: ext4 on an image file; `mkfs.lustre` fails
  without `--reformat`, passes with it.

ZFS is not probed: `mo_device` is a pool/dataset name there. mke2fs `-F`
is unchanged.

Every `add` / `$MKFS` call in conf-sanity and test-framework already
passes `--reformat` (test 116 formats a blank file, exit 2), so no
existing test changes behaviour.
