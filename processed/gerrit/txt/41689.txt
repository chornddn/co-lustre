LU-14407 osd-zfs: add direct and uncached IO support

OpenZFS 2.4 adds two DMU IO modes:
  - Direct IO (DMU_DIRECTIO) bypasses the ARC entirely.
  - Uncached IO (DMU_UNCACHEDIO) goes through the ARC but evicts
    the buffers once the IO completes.

This patch lets osd-zfs use both modes for bulk data IO. Caching
bulk data in the ARC often adds overhead with little benefit, so
these modes can improve performance on fast flash pools and on
large disk pools.

Direct IO is disabled by default. Enable it with the new tunable:

    lctl set_param osd-zfs.*.direct_enabled=1

Once enabled, the OSD honors the ZFS "direct" dataset property. The
OSD tracks changes to this property through a dsl_prop callback, so
updates take effect without remounting:

  - disabled: direct IO is never used.
  - always:   direct IO is used if IO meets alignment checks.
  - standard: the default. The OSD decides for each IO:
      * On a non-rotational pool, it behaves like "always".
      * Otherwise, a write uses direct IO if its length is at least
        writethrough_max_io_mb. A read uses direct IO if its length
        is at least readcache_max_io_mb, or if the file size is at
        least readcache_max_filesize. These thresholds apply to
        each niobuf, not to the whole RPC.

Direct IO follows the same alignment rules as O_DIRECT in the ZFS
POSIX layer. If the policy selects direct IO but the IO is misaligned,
the OSD falls back to uncached IO.
  - Reads must be page aligned.
  - Writes must be both page and recordsize aligned.

Direct and uncached IO support is compiled in only when configure
detects the OpenZFS 2.4 interfaces (HAVE_DMU_DIRECT):
  - dmu_read_abd()
  - dmu_write_abd()
  - abd_alloc_from_pages()
  - DMU_DIRECTIO / DMU_UNCACHEDIO

Lustre still builds against older OpenZFS releases. In that case
the data path is unchanged and direct_enabled has no effect. With
direct_enabled=0 (the default), the data path is also unchanged on
OpenZFS 2.4. Only non-rotational auto-detection takes effect.
