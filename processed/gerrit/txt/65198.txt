LU-20104 lnet: fix selftest session teardown and BRW bugs

Fix lnet-selftest crashes and stale sessions, on top of the
LU-20342 module-unload deadlock fixes.

Split the server srpc_ev into srpc_bulkev and srpc_replyev.
The shared event was reused for the bulk MD and then the reply
MD, so a late bulk UNLINK landed on the rewritten reply event
and double-completed a recycled RPC, causing the list_add
corruption in srpc_lnet_ev_handler reported by James Simmons.
Also gate the bulk/reply events on ev->unlinked, and require
both events fired before completing an RPC re-entering
srpc_handle_rpc in SWI_STATE_DONE.

Order session teardown so client-side batches drain before the
session is deactivated and server-side RPCs are drained.  On the
console, set ses_shutdown before the batch-stop loop, since that
loop contains the first point where lstcon_rpc_trans_postwait()
drops ses_mutex; without it a concurrent end_session can run
nested and free the batches the loop is still walking.  The stop
transactions are created with a NULL translist so they stay off
bat_trans_list, both so lstcon_rpc_trans_check() does not abandon
them once ses_shutdown is set and so lstcon_batch_destroy()'s
assertions still hold.

Bound the console teardown drain in lstcon_rpc_cleanup_wait(),
which previously waited forever under ses_mutex in an
uninterruptible sleep - an unkillable hang that also blocked
module unload.  The bound is derived from rpc_timeout, since an
outstanding console RPC cannot be recycled before its own timer
fires, and the sleeps are now killable.  On expiry the session
objects are left allocated and ses_shutdown stays set: the
transactions and RPCs that failed to drain still point at the
batches, groups and nodes the destroy phase would free, so the
session is left inert rather than half-destroyed.

Bound the node-side drain loops with a fixed timeout instead of
2 * rpc_timeout.  rpc_timeout is a module parameter documented as
"0 == never", which would collapse the deadline to "now", and
these loops run from sfw_remove_session() on the ordered
lst_serial_wq where they block every other framework RPC on the
node, so they have to stay well inside the console's SESEND
transaction timeout.

Fix BRW offset handling: mask offset with ~PAGE_MASK, allocate
bulk with off+len, and reject off+len > LNET_MTU.  The unmasked
offset in brw_client_prep_rpc() dates back to the original offset
support; the missing off+len bound came in when the server-side
preallocated bulk replaced srpc_alloc_bulk(cpt, off, npg, len,
sink) with srpc_alloc_bulk(cpt, len) plus srpc_init_bulk(), and
swapped the npg > LNET_MAX_IOV check for len > LNET_MTU.  NB the
len > LNET_MTU check is retained ahead of the off+len check: len
is a __u32 from the wire, so it also guards the addition against
wrapping.

Add lnet-selftest.sh tests for teardown stress, BRW offset
edge cases, and the workqueue list-corruption race.

test_teardown_race checks every setup step.  lst add_group exits 0
even when some nodes fail to answer, so without an explicit node
count check the batch runs empty and the test reports success
having exercised nothing.

test_teardown_deadpeer covers teardown against a peer that stops
answering, with rpc_timeout=0 so the client-side RPC timers are
disabled and end_session has only its own abort path to rely on.

Test-Parameters: trivial testlist=lnet-selftest,sanity-lnet
