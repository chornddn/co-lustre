--- Commit Message ---
LU-20589 llite: fail IO when the restart budget runs out

ll_file_io_generic() restarts an IO when a lower layer sets
ci_need_restart, at most RETRY_ATTEMPTS times.  One producer of
that request is can_populate_pages(), which compares the cached
layout generation of the inode with the generation the IO took a
copy of.  On a mismatch vvp_io_write_start() returns 0, a success
which moves no bytes.

If the generation keeps changing, for example because the client
cancels its own layout locks from LRU reclaim, every attempt is
used.  Control then reaches RETURN(result > 0 ? result : rc) with
result and rc both 0.  The io->ci_result fallback does not help,
because cl_io_start() sets ci_result to 0 when the start method
returns 0.  write(2) then returns 0 for a non-zero request and the
data is dropped without a message, and read(2) reports a false end
of file.

Report -EIO when the budget is used up and nothing was moved, and
log the fsname, FID and IO range at a rate limit.  A transfer which
moved some bytes is still returned as a short IO.

Make the layout mismatch fault injection repeatable so that a test
can use up the budget.  Add sanity test_251b, which checks that
both a write and a read fail instead of returning 0.
