--- Commit Message ---
LU-20568 lfs: allow --ec 1+2 for a single data stripe

--ec currently requires k >= 2 and p <= k, so a 1-stripe file (or
the first PFL component) cannot get 2-OST redundancy with --ec 1+2.

When k == 1 each parity is a memcpy of that data stripe, not Cauchy
encoding, so p may exceed 1. Allow k == 1 in lfs and llapi, copy the
data onto every parity object, and treat suggested == 1 in
ec_split_stripes() as total raidsets of k0 == 1. For k >= 2, p <= k
is unchanged.
