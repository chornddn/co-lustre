LU-20690 lod: write 1+N EC data around a lost OST

A write to an EC file would fail while the OST of a data stripe in a
component of 1-data raid sets (--ec 1+N, or one data stripe) was
unavailable: the data mirror is the only mirror that can be the write
primary, and its object could not be written.  Yet each of the N
parity objects of such a raid set holds a copy of the data object at
the same object offsets.

When a write era starts (RDONLY -> WRITE_PENDING) the parity is still
in sync, so lod_ec_swap_unavail() swaps each unavailable data object
of such a component in the write extent with a parity object of the
same raid set on an available OST.  The data mirror stays a complete
write primary, and the parity component, which the write stales as
before, holds the unavailable object until the next resync rewrites
it.  The filter_fid of a swapped object is updated from the layout
that the next write to it carries; until then LFSCK reports an
unmatched pair and repairs the filter_fid.  The swapped-in object may
be outside the pool or OST list of the data component.

The swap needs each parity copy to be as large as the data object.
A copy written by resync with O_DIRECT ended on a page boundary, past
a file size that is not page aligned, and ended at the last data when
the file had a trailing hole, so a swapped-in copy would change the
file size.  The EC resync now truncates the parity mirror to the file
size when EOF is inside a component of 1-data raid sets, as FLR
resync does for a mirror.  Parity resynced by an older lfs is not
trimmed.

Swapping only happens at the start of a write era, while the parity
component is in sync.  An OST lost during a write era, and a 1-data
raid set in a component with larger raid sets, whose parity is not
at the data offsets, still need the OST to return.

Add sanity-ec test_313 to write 1+2 files with a data OST unavailable,
for an unaligned size, a sparse tail, a second PFL component and the
second stripe of a 2-stripe component, and check the swap, the file
size and the data before and after resync.
