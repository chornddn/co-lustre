LU-20690 lod: write 1+N EC data around lost OST mirror

A write to an EC file would fail while the OST of a data stripe in a
component of 1-data raid sets (--ec 1+N, or one data stripe) was
unavailable: the data mirror is the only mirror that can be the write
primary, and its object could not be written.  Yet each of the N
parity objects of such a raid set holds a copy of the data object at
the same object offsets.

When a write era starts (RDONLY -> WRITE_PENDING) the parity is still
in sync, so lod_ec_swap_unavail_data() swaps each data object of such
a component in the write extent that is on a disconnected or
deactivated OST with a parity object of the same raid set on an
available OST.  An OST that is only full or takes no new objects is
still written.  The data mirror stays a complete write primary, and
the parity component, which the write stales as before, holds the
unavailable object until the next resync rewrites it.  The swapped-in
object may be outside the pool or OST list of the data component.

The swapped-in object counts for the file size, so it is only used if
its size is that of the data object for the file size that the last
resync stored as strict SOM.  A copy written by resync with O_DIRECT
ended on a page boundary past a file size that is not page aligned,
and at the last data when the file had a trailing hole, so the EC
resync now truncates the parity mirror to the file size when EOF is
inside a component of 1-data raid sets, as FLR resync does for a
mirror, and only warns if that fails.  Parity resynced by an older
lfs, left past EOF when EOF is in a component with larger raid sets,
or of an EC layout version that the MDS does not know, is not swapped
in.

After the layout change, the MDD rewrites the filter_fid of the
swapped-in object with its new stripe index and component in a
transaction of its own, as after a layout swap, so that it names the
stripe it now is for LFSCK and lfsck_verify_pfid.  The object swapped
out to the parity component is on the unavailable OST and keeps its
old filter_fid.  OSP OST objects can now be invalidated, so that the
MDS fetches the size of a parity copy from the OST.

Swapping only happens at the start of a write era, while the parity
component is in sync, for the components of the extent that the
first write of the era touches.  An OST lost during a write era, and
a 1-data raid set in a component with larger raid sets, whose parity
is not at the data offsets, still need the OST to return.

Add sanity-ec test_313 to write 1+2 files with a data OST unavailable,
for an unaligned size, a sparse tail, a second PFL component and the
second stripe of a 2-stripe component, and check the swap, the file
size and the data before and after resync.  Add test_314 to check that
stale parity past EOF is not swapped in, and test_315 to swap the
second stripe of a 2-stripe 1+2 file twice.

Test-Parameters: trivial testlist=sanity-ec,sanity-flr ostcount=8
