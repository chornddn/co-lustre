LU-21298 tests: skip sanity-pcc/204a-c for old servers

sanity-pcc test_204a, test_204b and test_204c would fail with a
master client and 2.16 servers, because "lfs pcc pin" sets the
virtual lustre.pin xattr, which only MDTs with the enable_pin_gid
patch map to trusted.pin.  Older MDTs return -EOPNOTSUPP.

Raise the MDS version check in these subtests from 2.15.61 to the
commit that added lustre.pin handling to the MDT.

Test-Parameters: testlist=sanity-pcc serverversion=2.16 env=ONLY=204,HONOR_EXCEPT=y

Looks good; the new gate matches the commit that added the MDT-side lustre.pin mapping, and no re-spin is needed.

(suggestion) The test skip is correct, but it also hides a real interop gap. llapi_pcc_pin_file() and llapi_pcc_unpin_file() now always use XATTR_LUSTRE_PIN, with no fallback. As a result, `lfs pcc pin` and `lfs pcc unpin` from a master client always fail with EOPNOTSUPP against a 2.16 MDT, even for root. Before 84100d7f7d this worked through trusted.pin. Should liblustreapi retry with XATTR_NAME_PIN on -EOPNOTSUPP, which keeps the old root-only behaviour on older MDTs? That could go in a separate patch under this ticket.
