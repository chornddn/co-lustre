LU-20350 o2iblnd: stand down auto bounce when RO is enabled

The auto predicate is blind to PCIe relaxed ordering. It stages an
inbound bulk whenever the sink is a NUMA hop from the HCA, but a HCA
allowed to relax the ordering of its writes is not penalised for that
hop. Staging one then replaces a DMA the CPU never touches with a copy
the CPU has to make, and costs throughput rather than recovering it.
An operator has to pick the bounce setting per node to avoid it.

Read the relaxed-ordering enable bit of the HCA's PCIe Device Control
register at device bringup and leave a transfer direct when the HCA
may write with relaxed ordering. Auto is then correct on a node either
way and needs no per-node setting. Force is unchanged and remains the
override.

The bit is the master gate above the per-mkey request, so it only
predicts the ordering a bulk write really gets if the region asks for
relaxed ordering in the first place: a device in per-mkey mode applies
it to a region registered with IB_ACCESS_RELAXED_ORDERING and to no
other, while one in force-relax mode applies it regardless. So
register the FastReg bulk region with the flag where the verbs layer
knows it. That only opts in. The Device Control bit still gates every
write above it, and the kernel clears that bit on a root complex whose
reordering is known to be unsafe, so a platform that must not reorder
still does not.
