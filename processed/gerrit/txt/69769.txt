LU-11962 flr: fix FLR and SOM state after a layout swap

The SOM xattr stays with the inode when its layout is swapped, e.g. by
"lfs migrate" of a mirrored file after "lfs mirror resync".  The new
layout is usually not FLR, so writes do not go through a layout write
intent that makes SOM stale, and mdt_lsom_update() does not change
strict SOM at close.  The MDT then keeps returning the old size and
blocks as strict, and clients do not glimpse the OSTs.  Also,
lod_parse_striping() does not reset the FLR state for a plain layout,
so after such a swap LOD keeps the state of the layout it replaced.

Make strict SOM stale on both files in mdd_swap_layouts(), in the
transaction of the swap, so that a replay never finds the swap
committed without it.  HSM release keeps the strict SOM it sets.
Revoke the UPDATE locks too, so that clients drop strict attributes
they cached, and reset the FLR state of a plain layout in
lod_parse_striping().  As rename takes an UPDATE lock on its target,
mdt_swap_layouts() now locks the two files in ascending FID order,
as rename does, so that the two cannot deadlock.

Add sanity-flr test_60c to check that strict SOM is not kept across a
layout swap, and test_60d for a layout swap racing with a rename.
