LU-11962 flr: fix FLR and SOM state after a layout swap

The SOM xattr stays with the inode when its layout is swapped, e.g. by
"lfs migrate" of a mirrored file after "lfs mirror resync".  The new
layout is usually not FLR, so writes do not go through a layout write
intent that makes SOM stale, and mdt_lsom_update() does not change
strict SOM at close.  The MDT then keeps returning the old size and
blocks as strict, and clients do not glimpse the OSTs.  Also,
lod_parse_striping() does not reset the FLR state for a plain layout,
so after such a swap LOD keeps the state of the layout it replaced.

Make strict SOM stale on both files after mdt_swap_layouts() and
MDS_CLOSE_LAYOUT_SWAP, as HSM restore already does, and revoke the
UPDATE locks too, so that clients drop strict attributes they cached.
Reset the FLR state of a plain layout in lod_parse_striping().
