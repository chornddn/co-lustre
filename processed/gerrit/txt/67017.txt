LU-20403 ptlrpc: refresh import conn on primary migration

ptlrpc caches a connection keyed on the peer's primary NID and then
freezes it: ptlrpc_connection_get() resolves the primary once,
reconnect reuses the connection, and it is never re-resolved. The
client import reply ME (ptl_send_rpc) is keyed on that frozen NID.
When LNet's primary for the peer later migrates, which can happen for
any unlocked peer, the reply is stamped with the new primary and no
longer matches. It then takes the costly lnet_try_match_md() same-peer
fallback or is dropped, which leaves the import stuck in CONNECTING.

Add LNetPeerPrimaryNID(), a non-blocking primary lookup that neither
discovers nor allocates, and detect a migration on every send.

ptl_send_rpc() calls ptlrpc_refresh_import_primary() before posting
the reply ME. On a change it installs a connection keyed on the
current primary through import_switch_connection(), the single place
that swaps imp_connection so a forward import's DLM export connection
always moves with it, and re-keys the current imp_conn_list entry so a
later reconnect cannot restore the stale connection. The replacement
is resolved with ptlrpc_connection_get_primary(), a variant that skips
the internal blocking primary lookup, so the send never blocks on
discovery.

The lookup takes a per-CPT lnet_net_lock and does one peer-table
lookup, the same work lnet_select_pathway() already performs for the
send that immediately follows. ptlrpc_connection_put() does not free a
connection at runtime (connections are cached in the hash until module
unload), so the connection swaps are safe.

Add conf-sanity test_73g. It migrates the servers' primary NIDs under
a live client and checks the client imports recover, exercising the
client-side refresh.
