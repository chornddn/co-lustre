LU-12669 ec: wait for stripes that parity cannot rebuild

A read of an EC file whose raid set has more data stripes on stopped
OSTs than parity can rebuild fails with -EAGAIN or -EIO, while the
same read of a file without parity waits for the OSTs to return,
e.g. after an OSS failover.  Adding parity to a file should not make
it less available than a plain striped file.

When CIT_EC_RD finds too many unavailable stripes or too little
parity, set the new cl_io::ci_ec_wait, which cl_io_loop() turns into
a restart, and restart the read up to the end of that raid set as a
plain read without the no-delay flag, which waits for the stripes'
OSTs.  The rest of the read goes back to the no-delay read, so later
raid sets are still rebuilt from parity.  A synchronous direct read
whose aio was freed for the CIT_EC_RD restart gets a new one.  A read
of a deactivated OST still fails at once.

Change sanity-ec test_29a to check that such a buffered or direct
read waits for its OSTs and then returns the right data, and add
test_29b for a read whose second raid set is rebuilt from parity.
