LU-20923 mdc: keep existing inode on a lock FID collision

An MDC lock resource is keyed by the object FID, and
mdc_set_lock_data() attaches the inode being set to that resource.
When the resource already references a different inode that is still
live, keep the existing inode attached and do not attach the new one;
a later access re-enqueues the lock.  This replaces the previous
requirement that a resource could only ever reference an inode on its
way out (I_FREEING).
