LU-21054 build: link the program in the mpitests check

LB_CONFIG_MPITESTS checks whether the MPI tests can be built with
AC_COMPILE_IFELSE, so the test program is only compiled and never
linked. A broken MPI library passes the check, mpitests are enabled,
and the build then fails when linking the programs in
lustre/tests/mpi. Since mpitests are enabled by default with the
mpicc found in PATH, this hits builds that did not ask for them.

This was seen on ARM64 clients with an OpenMPI whose libmpi.so has
a NEEDED entry for liblustreapi.so.1, which does not exist on the
build node before Lustre is installed.

Link the program in the check, so a broken MPI library disables
mpitests at configure time instead of failing the build. Also stop
dropping the MPI tests silently when the check fails: warn when
mpitests were enabled by default, and fail configure when they were
explicitly requested with --enable-mpitests.
