--- Commit Message ---
LU-17961 sec: fix access mode from intent open flags

accmode_from_openflags() tests kernel FMODE_* bits against
it_open_flags, which ll_file_open() fills in the enum
mds_open_flags encoding. Only the read and write bits line up
between the two encodings.

For an execve of a file whose dentry is already cached,
ll_file_open() maps __FMODE_EXEC to MDS_FMODE_EXECUTE, which is
the same bit as FMODE_PWRITE. So the access mode comes out as
MAY_READ|MAY_WRITE, and the MAY_EXEC arm never fires because
FMODE_EXEC is not used in enum mds_open_flags. A binary carrying
a supplementary group entry with r-x permissions is then rejected
when looking for a group to retry with, even though sending that
group would have granted access. ll_atomic_open() stores the raw
kernel open flags instead, so the same execve does get MAY_EXEC
on that path: the two open paths disagree.

Test the bits of both encodings, as neither gives a meaning to
the other's execve bit. FMODE_PREAD and FMODE_PWRITE are dropped,
as they are never set in an intent and only alias mds open flags.
