LU-20840 mdt: don't drop stalled dir migration

mdt_restripe_migrate() migrates one sub-file at a time, and if
mdt_reint_migrate() returns -EBUSY for the entry at
mot_restripe_offset, the error path removes the stripe from the
mdr_migrating list and drops it, abandoning migration of the
remaining entries in that stripe.  -EBUSY is returned when the entry
is a sub-directory that is itself being restriped, when
mdt_migrate_links_lock() or the lookup of the entry runs out of
retries, or when an HSM restore is running on it.

Treat -EBUSY as transient: keep the stripe queued, move it to the tail
of the list so that other stripes on this MDT, including the ones this
entry waits for, can make progress, and retry it after a delay.  The
delay is recorded per stripe in mot_restripe_next, so a stripe that is
backing off doesn't hold back the other stripes, and the restriper
main loop sleeps only for the remaining delay of the stripe at the
head of the list instead of busy-spinning; it never sleeps without a
timeout while a migration or a layout update is pending.  A stripe
that is ready is moved to the head of the list, so it isn't held back
by one that is backing off.

Move mdr_update_time from wall-clock ktime_get_real_seconds() to a
boot-relative timeout_t, so the layout update delay no longer follows
wall-clock steps.

Take mdr_lock instead of mdt_lock where a stripe is removed from
mdr_migrating, as mdt_restripe_migrate_add() appends to it under
mdr_lock.

Add sanity test 230D and a fault injection point
(OBD_FAIL_MDS_RESTRIPE_MIGRATE_BUSY) that makes the restripe migration
return -EBUSY once, then verifies that the migration still completes.
