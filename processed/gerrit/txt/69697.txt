LU-20967 osd-ldiskfs: name the failure_domain local file

The failure_domain file added in LU-19066 has no entry in the
osd_lf_maps[] table in osd_scrub.c, so osd_lf_fid2name() returns no
name for its FID and osd_obj_spec_insert() creates no directory entry
for it in the OST device root.  e2fsck then treats the inode as
disconnected and wants to reconnect it into lost+found:

  Pass 4: Checking reference counts
  Unattached inode 88
  Connect to /lost+found? no
  myfs-OST0003: ***** WARNING: Filesystem still has errors *****

Add a FAILURE_DOMAIN entry to osd_lf_maps[] with OLF_SHOW_NAME, like
health_check, so the file is linked into the device root under its own
name and e2fsck no longer reports an error.

Existing targets already have the unnamed inode, and the same can
happen to any named local file whose name is lost to directory
corruption that e2fsck repaired.  The initial OI scrub already walks
osd_lf_maps[] to drop stale OI mappings for files that no longer
exist; make it instead relink a file that still has a valid OI mapping
and inode but no name in the root, so such files are recovered on
mount rather than left unattached.
