LU-20542 sec: install reverse ctx when export reconnects

A client whose idle DISCONNECT fails (for instance because
the new context it needs is refused, as in sanity-sec
test_27d right after the client switches to a nodemap shared
key) goes IDLE but leaves its export on the server. When it
reconnects, it negotiates the new context before it has the
export handle, so the server never installs the matching
reverse context, and the reconnect keeps the reverse import
as it is when the flavor is unchanged. Lock callbacks keep
using the reverse context of the client's previous context.
Once the client has dropped that, the callback fails with
-ECONNREFUSED and the client is evicted.

On reconnect of an existing export, install the reverse
context of the connect request's root context, and switch
the export to the nodemap it authenticated with, as is done
for a context init that carries the export handle. Do not
install a reverse context twice from the same context: the
copy would restart its sequence numbers and its callbacks
would look like replays.
