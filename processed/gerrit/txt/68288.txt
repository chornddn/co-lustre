LU-20637 llapi: name a device scan's objects

A target scan has names and parent FIDs but no paths, so lfs find
printed FIDs, and a user had to turn them into pathnames manually.

Name each match during the scan, as a walk prints it. Every directory
the scan meets is kept, FID to parent and name, and a match is printed
once its parent chain reaches the root. A match met before one of its
directories waits for it, in memory up to 256 MiB and then in a
temporary file. Paths start with "./", or with the --fid2path mount.
With the mount, a directory the scan never met (under DNE, one on
another MDT) is looked up once after the scan, an OST object is named
by its owner's link, and a fileset mount limits the output to its
subtree. An encrypted name prints as a client without the key shows
it.

--print-fid prints FIDs instead, on a walk too, and costs no naming.
-printf %LF on an OST object prints its owner's FID. --all-links
prints a hardlinked file under each of its names. A device scan fills
lfsr_name and lfsr_parent_fid only when asked, with the new
LLAPI_SCAN_NAME. llapi_scan_rec_path() names one record through a
mount. Also new: lfsp_fsname (a target of another filesystem is
refused with -EXDEV), LLAPI_SCAN_OWNER and lfsr_owner_fid, and
LLAPI_SCAN_NAMES_ENC. An OST printed by name needs --fid2path, or
fails with -ENOTDIR.
