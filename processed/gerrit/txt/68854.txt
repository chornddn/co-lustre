--- Commit Message ---
LU-17296 nrs: order BRW RPCs by offset inside an mClock class

Inside one mClock class bucket the queue is FIFO. A fair shared HDD
OST loses the seek order that the ORR policy gives.

Add a locality= key to the mClock start command. The key puts the
read RPCs and the write RPCs of one bucket in a red-black tree. The
logical offset of the first fragment orders the tree. Requests with
an equal offset keep the arrival order. The FIFO list still holds
every request, so the emptiness of the list keeps its meaning for
the class bucket. The selection between the buckets does not change.

The TBF policy does not hold the key, and a TBF start with the key
returns -EINVAL.

The mClock request grows to 64 bytes, and the request union of the
NRS layer grows with it. A build assertion records the new bound.
