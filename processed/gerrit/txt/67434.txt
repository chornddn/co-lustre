LU-18838 statahead: fix ll_sa_refcnt leak from ctx re-read at teardown

ll_statahead_thread() dropped its statahead-context reference by
re-reading the global lli->lli_sax at teardown:

	ctx = lli->lli_sax;
	ll_sai_put(sai);
	if (ctx)
		ll_sax_put(ctx);

but lli->lli_sax is not stable for the lifetime of the thread.
A concurrent pattern transition (the 'LIST => FNAME' path) or a
deauthorize+reauthorize of the directory can replace lli->lli_sax
with a different context between the time the thread started and
the time it tears down.  The thread then puts the current
lli->lli_sax while the context it actually holds a reference on
is never released.  Its sax_refcount never reaches 0, so
ll_sax_free() is never called, ll_sa_refcnt stays > 0, and
ll_kill_super() spins forever in its
'while (ll_sa_running > 0 || ll_sa_refcnt > 0)' drain loop -- umount
hangs (D-state, needs reboot).  Reproduced under racer/DNE; a timeout
vmcore showed one directory with lli_sax set, sax_refcount == 1, an
empty sax_sai_list and lli_sa_pattern == LSA_PATTERN_NONE.

Record the context each sai is attached to in sai->sai_sax at thread
creation, and have the thread drop that exact reference at teardown
instead of re-reading lli->lli_sax.  The reference charged to the sai
keeps the context alive until the thread puts it, and the sai still
pins it on sax_sai_list until ll_sai_put(), so reading sai->sai_sax
before ll_sai_put() frees the sai is safe.
