LU-20690 tests: read one parity stripe in sanity-ec 312

sanity-ec test_312 read the parity mirror of a 4+2 file through the
MIRROR scope, expecting a buffered read to be refused with -EINVAL
and a direct read to succeed.  Once "ec: store EC parity like
RAID10" stores every parity slot as p stripes,
lov_io_designated_stripe_valid() refuses any read of such a slot that
does not name one of its stripes, so the direct read would fail with
-EINVAL as well, and the buffered read would be refused for that
reason rather than for being buffered.

Read stripe 0 of the parity slot through the STRIPE scope in both
cases, which does not depend on how the parity is stored.
