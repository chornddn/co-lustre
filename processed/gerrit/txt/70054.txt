LU-16932 tests: fix sanity-hsm test_251 timeout race

sanity-hsm test_251 set active_request_timeout=1 before archiving, so
the coordinator could cancel the request 1-2s after it was STARTED.
wait_request_state polls about every 1.3s, so it would sometimes see
the request go from WAITING straight to CANCELED and fail with
"request on FID is not STARTED on mds1".

Shorten active_request_timeout only after the request is STARTED, as
test_252 does.  Restore active_request_timeout and loop_period with
stack_trap, so a failure no longer leaks them into later subtests,
where e.g. test_254b failed because its requests timed out too soon.
