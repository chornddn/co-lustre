--- Commit Message ---
LU-21023 mdt: take the UPDATE lock of a migrated file

An unlink or link of another name of a file being migrated takes the
LOOKUP lock from the MDT of that name's parent, and only the UPDATE
lock on the MDT of the file. The migration's source lock had no
UPDATE bit, so the two never conflicted: an unlink could drop a link
while the migration moved the file, and left the new object with no
name, which LFSCK then put in lost+found.

Take MDS_INODELOCK_UPDATE with the source lock of a non-directory.
