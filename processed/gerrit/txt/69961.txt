LU-21023 mdt: take the UPDATE lock of a migrated file

An unlink of another name of a file being migrated takes the LOOKUP
lock from the MDT of that name's parent, and when that is another
MDT, only the UPDATE lock on the MDT of the file. A name under other
link parents is covered by mdt_migrate_links_lock(), and one in the
source parent stripe by the LOOKUP lock of the source lock, taken on
that stripe's MDT. A name in the target parent stripe, when that is
on another MDT (a migrating or restriping parent), is only PDO-locked,
and the source lock had no UPDATE bit, so the two didn't conflict:
the unlink could drop the name while the migration moved the file,
and left the new object with no name, which LFSCK then put in
lost+found.

Take MDS_INODELOCK_UPDATE with the source lock of a non-directory in
mdt_reint_migrate().
