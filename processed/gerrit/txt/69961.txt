--- Commit Message ---
LU-21023 mdt: take the UPDATE lock of a migrated file

An unlink of another name of a file being migrated takes the LOOKUP
lock from the MDT of that name's parent, and when that is another
MDT, only the UPDATE lock on the MDT of the file. The migration's
source lock had no UPDATE bit, so when the other name was in the
source or target parent stripe under a different name hash (those
are only PDO-locked, and mdt_migrate_links_lock() skips them), the
two didn't conflict: the unlink could drop the name while the
migration moved the file, and left the new object with no name,
which LFSCK then put in lost+found.

Take MDS_INODELOCK_UPDATE with the source lock of a non-directory in
mdt_reint_migrate().
