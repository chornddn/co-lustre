LU-18857 mgs: refuse all registration when closed

With allow_register=0 the MGS only refused an unknown target index.
A known index could still re-register from any node, and rewrite the
MGS config: a tunefs --writeconf of an OST regenerated its log, a
--failnode or --param change added NIDs to the client log, a new
device formatted with an existing index took it over, and a writeconf
of MDT0000 erased all logs of the filesystem, then failed to rebuild
them with -EACCES.  A filesystem named like an MGS internal log
("nodemap") registered while closed, and "_mgs" made the MGS use an
index map that does not exist.

Refuse every registration (writeconf, update, new device, or a restart
that finds the client log empty) while closed, before anything is
erased.  A plain restart of a registered target is still allowed, but
a wbcfs target, which registers at every mount, needs a window.
A writeconf of a target on the MGS node, or 'lctl lcfg_erase' on the
MGS, opens a one hour window itself with class_allow_register_open(),
so the admin's writeconf still works.

mount.lustre cleared LDD_F_UPDATE on disk before the mount, so a
parameter change refused by the MGS was lost.  Set it again if the
mount fails.

Also:
- refuse reserved or unterminated fsnames in mgs_target_reg()
- count only target logs as an existing filesystem, so a client
  mount of an unknown fsname does not make it registrable
- allow an IR update only for a registered index, and return errors
  instead of the LASSERTs on that path
- skip the CONFIGS scan when the default window can no longer arm
- use IS_ENABLED(CONFIG_LUSTRE_FS_SERVER) for the allow_register timer
- suggest 'options mgs allow_register=0' to lock down, since a
  dedicated MGS never applies 'set_param -P'
- retry a test target mount once with a window open after -EACCES
- add conf-sanity 157h-157k, update allow_register.4, tunefs.lustre.8
