LU-20908 llite: swap one object at lease close

A single-object layout swap (SWAP_LAYOUTS_SINGLE_STRIPE) can only go
through MDS_SWAP_LAYOUTS, which does not look at a lease.  A writer
that opens the file after the caller last checked its lease and data
version can still write to the old object before the swap, and that
data is lost when the old object is destroyed.  A group lock would
close the gap but, on a composite file, takes a write intent over the
whole file, which instantiates every component and makes the other
mirrors stale.

Carry the two OST object FIDs in close_data, as struct close_data_swap
in the union that already holds cd_data_version2, so that the swap is
done in mdt_close_handle_layouts().  There the MDT holds mot_open_sem
and checks that the lease is not broken before it swaps, as for the
full layout swap of lfs migrate --non-block.

OBD_CONNECT2_ONE_OBJ_SWAP, added in 2.18 for the single-object
MDS_SWAP_LAYOUTS, now also means the MDT swaps one object at close, so
no release has one without the other.  It keeps a client from sending
this to an older MDT, which would swap the whole layouts, and the MDT
from reading the new fields from a client that never set them.  The
DNE close goes to the MDT of the file, not the MDT0000 llite checks,
so mdc_close() checks that MDT too, and without the flag releases the
lease without the swap and returns -EOPNOTSUPP.

Also check the two files before the lease is taken from the file
descriptor, not after: a failed check there freed the open handle
without a close, and the lease and the MDT open stayed until umount.
llapi_fswap_layout_fids() now accepts SWAP_LAYOUTS_CLOSE, and returns
-EBUSY for a broken lease, which close reports as -EBUSY or -ESTALE
depending on whether the lease open has committed.

Add a lease option to swap_single_stripe and sanity-pfl test_29d,
which swaps one object at lease close and checks that a broken
lease leaves both layouts unchanged.
