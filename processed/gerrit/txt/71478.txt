LU-21334 utils: leave md stripe_cache_size alone by default

mount.lustre defaulted md_stripe_cache_size to 16384, so every md
device under an OST was raised to 16384 stripe heads at each mount.
Each head holds one page per member device, so this cost about
285 MiB for a 4-member array and 670 MiB for a 10-member array, and
the md driver could not shrink below it.  A 2 GiB server with four
arrays lost 1.14 GiB to stripe caches, then mount.lustre failed with
"page allocation failure: order:4" and netlink returned ENOBUFS.

Change the default to 0, so the device keeps its own value unless
-o md_stripe_cache_size=<num> sets one.  Document the sizing rule in
mount.lustre(8) for sites with md RAID5/6 over HDDs that need a larger
cache: a 10-member RAID6 with 8 writers of 4 MiB lost 52% of its write
throughput at 256 compared with 16384.  Also fix the man page: the
value is a count of stripe heads, not KiB, and only OST devices are
tuned.
