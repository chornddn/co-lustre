LU-20090 nrs: add rule sequence number to represent the rule order

This patch adds the rule sequence number to represent the rule
order in the rule list. The sequence number is increased
monotonically when adding a new rule.
The rule with the larger sequence number has the higher priority.

In the dynamic classification strategy, once found a matched class
bucket by hash lookup according to the allowed class types, it
still needs to check the rules in the rule list with the sequence
larger than the one for the rule of the found class bucket.

To reduce the complexity of the rule matching, next step each
allowed calssification type manages its own rule list. And each
allowed classification type has its own priority.
If the allowed type A has the higher priority than the allowed
type B, then all rules belonged to the allowed type A will have
the larger sequence number than the rules belonged to the allowed
type B and also have higher priority.

Add a test case sanityn/test_77te to verify it works as expected.
