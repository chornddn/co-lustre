LU-20896 osc: encrypt direct IO pages at their own file index

A direct write larger than about 1MiB to an encrypted file with the
key loaded stores data that does not decrypt back to what was
written. OSC encrypts a direct IO page by pointing its folio at the
file mapping and setting the folio index to the page's file index,
then computing the block number as the folio index plus the page's
offset within the folio. When the user buffer is backed by a
transparent huge page, that offset is not zero, so the page is
encrypted as another page of the file, while a direct read decrypts
it at its own index. The pages of one large folio can also be in
different RPCs that are prepared concurrently, which all change the
same folio index.

So the page's offset within the folio should not be taken into account
when computing the encryption IV.

8MiB direct write with the key loaded, 4MiB buffer, 15 runs:

  transparent huge pages   always   never
  without the fix          15/15    0/15 corrupt
  with the fix              0/15    0/15 corrupt

Add sanity-sec test_66a to write and read an encrypted file with
direct IO from a huge page buffer.
