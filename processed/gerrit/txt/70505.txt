LU-20211 osc: discard a truncate size range from cache

When the MDS replaces the objects of an unavailable OST on truncate,
the client drops its dirty pages past the new size before the layout
change.  That is the data the truncate removes, so no data is lost,
but it must not be written back to the replaced objects, or the
write would wait for the unavailable OST.  Each object is discarded
from the object offset of the truncate size: for truncate(0) that is
the start of the component or stripe within the object, and it can
be inside a chunk-wide extent, e.g. with 1MiB ZFS chunks.
osc_cache_writeback_range() asserted that a discarded extent lies in
the chunk-aligned range, which is only true for a lock cancel, and
would lose dirty pages before the range.  Write back an extent only
when it holds a page before the range, since only a kept object maps
data there, and discard the others whole.

An active extent of an mmap write racing the discard hit an
assertion.  Wait for the writer to release it, as the layout change
does in lov_layout_wait(), then discard it.  Only a fatal signal
stops the wait.  mdc_io_fsync_start() discarded the whole DoM object
for any range: discard only the requested range.

Add a PFL file to sanity/test_27xt with dirty pages only in the
component on the stopped OST, which starts inside the first chunk.
Add sanity/test_27xs, where OBD_FAIL_LLITE_MKWRITE_PAUSE holds an
mmap write's active extent while truncate(0) replaces the layout.
