LU-20959 llite: skip OST sync in fsync of unmodified file

fsync() always sends OST_SYNC to every stripe of the file, even when
this client did not change the file, so fsync() of a file that was
only read waits for an unavailable OST.  An EC file can otherwise be
read while one of its OSTs is down.

Skip the OST sync in ll_fsync() unless lli_need_sync_to_oss is set,
as sync_on_close already does.  fsync() no longer commits data that
another client wrote, or that this client wrote before its inode was
evicted from cache, which POSIX does not require.  Set the flag for
fallocate(), set it again when a write completes in case an fsync()
cleared it meanwhile, and when an OST sync fails.

Also only clear it in cl_sync_file_range() for CL_FSYNC_ALL: a local
flush (CL_FSYNC_LOCAL) from writeback or lseek(SEEK_DATA) does not
commit the data on the OST, but cleared the flag, so a following
fsync() or sync_on_close did not sync either.

Add sanity test_63g to check the OST_SYNC count for each case.
