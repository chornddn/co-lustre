--- Commit Message ---
LU-21109 ptlrpc: refuse ctx init RPC on a closing import

A client mount with GSS can fail with EEXIST when it starts soon
after a umount. The new OSC cannot register its ldlm namespace,
because the old OSC with the same name still exists.

lgss_keyring checks the import before it sends SEC_CTX_INIT. The
umount can invalidate the import between the check and the send.
The send path always passes ctx init requests. Thus the request
goes out after the invalidate wait is over. The request holds the
import, and thus the old OSC, until the reply arrives.

Fail a ctx init request with -ESHUTDOWN when the import is CLOSED
or the device is stopping. Add sanity-sec test_67.
