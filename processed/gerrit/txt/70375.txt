LU-21109 ptlrpc: refuse ctx init RPC on a closing import

A client mount with GSS can fail with EEXIST soon after a umount.
The new OSC cannot register its ldlm namespace, because the old OSC
with the same name still exists.

gss_do_ctx_init_rpc() checks the import, then sends SEC_CTX_INIT.
A umount can invalidate the import between these steps.
ptlrpc_import_delay_req() passes all ctx init requests. The request
then holds the import, and thus the old OSC, until the reply arrives.

Fail a ctx init request with -ESHUTDOWN when the import is CLOSED
or the device is stopping. Return that error to lgss_keyring, not
-ETIMEDOUT, because a retry cannot succeed. Add sanity-sec test_67.

The fix narrows the race. The upcall holds the import until the send
fails. A mount in that window can still fail with EEXIST.
