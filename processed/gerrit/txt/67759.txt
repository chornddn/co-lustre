LU-20107 nrs: add node tier hierarchical scheduling

Add a node tier to the classful schedulers. Each flow
classification of a service (ptlrpc_service) on one node gets a
parent class bucket. A CPT tier TBF or mClock scheduler still
manages the leaf buckets. The node tier coordinates the bandwidth
between the CPT tier schedulers.

The policy must start with the "global=1" key. Only a global head
takes the "root" and "node" rule keys:
  lctl set_param ost.OSS.ost_io.nrs_policies="mclock projid global=1"

A new "nrs_hsch" debugfs entry of each service starts or stops a
node tier rule:
  lctl set_param ost.OSS.ost_io.nrs_hsch=
  "<mclock|tbf> [reg|hp] start rulename projid={100} rate=100 \
   root=0 node=0"
  lctl set_param ost.OSS.ost_io.nrs_hsch=
  "<mclock|tbf> [reg|hp] stop rulename"

A NULL or empty argument returns -EINVAL.

The node tier first divides the global rate equally between the CPT
tier rules. A command with no queue token builds a rule for the
regular head. It builds a second rule for the high priority head.
The divisor is then the CPT count of the service multiplied by 2.
The two heads therefore share one node ceiling. A global rate below
the divisor returns -EINVAL. The service also logs one error line.
Without that test an IOPS rule divides by zero.

Each CPT tier rule owns a shared class bucket that the LRU mechanism
does not manage. A policy callback initialises it. Without that
callback the first request of a global rule meets an assertion under
mClock.

Add sanityn/test_77w{a,b,c,d}.
