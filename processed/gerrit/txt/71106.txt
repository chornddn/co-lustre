LU-21047 llite: drop active extent before waiting for a page

A writer keeps its OSC extent active between commits of its page
queue. When it has to sleep on a page lock in ll_write_begin(), the
owner of that page can be waiting in osc_extent_find() for the same
extent, which writeback has marked for fsync. Neither can proceed and
the writes hang. group_lock_test test40 in sanity test_243 hits this
on ZFS, where the 1MB chunk puts all of its writers in one extent.

Release the IO's active extents before sleeping on a page lock in
ll_write_begin(), and before reading a partial page, whose
cl_page_own() can wait for a page owner the same way. Add a
cio_extent_release method to LOV so the release reaches the OSC
sub-IOs.

A dirty page must be the first one in the commit queue, or the
pages before it can wait for grant while it stays locked, and
writeback blocks on it. Reading a partial page unlocks it, and
another writer of the same group lock can cache it meanwhile.
Commit the queue before that read.

Add sanity test_42f, which uses a new fail_loc to hold one writer's
commit while a second writer and fsync race it on the same extent.
It needs an OST chunk larger than a page (ZFS) and skips otherwise.
Add sanity test_42g, in which a second writer caches a page while
the first has it unlocked to read it, with the dirty cache full.
