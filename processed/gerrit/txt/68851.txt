LU-17296 tests: prove the mClock jobid+nid class buckets

The mClock policy accepts a jobid+nid key. That key needs no
configuration on the client. A client that sets no job ID gets one
class bucket for its node. A client that sets a job ID gets one
bucket for each job and node pair.

Add sanityn test 77xh. The test starts the policy with
"mclock jobid+nid weight=1". It then reads the class bucket keys
from the D_RPCTRACE log of the OSS. With jobid_var=procname_uid,
the test checks for two job IDs and one NID. With jobid_var=disable,
the test checks for one bucket with the NULL job ID sentinel.

The probe that makes the buckets reads only 8 MiB. The debug log
of the OSS holds some seconds of an I/O flow. A longer flow
removes the class insert lines from the log.

The test then runs an fio pair of two job IDs through the two class
buckets. It holds the two IOPS values inside a band of 1.4.

Document the jobid+nid key and the zero-config start string in
Documentation/man4/nrs_policies.4. The same section states that the
share is per OST and per CPT.
