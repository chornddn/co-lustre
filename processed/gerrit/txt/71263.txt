LU-20911 lov: rebuild EC stripes with no object from parity

A read of an EC file failed with -EIO if a data stripe had no
object, as for the dummy slot that LFSCK leaves in a layout for a
lost OST object, although the parity of its raid set could rebuild
the stripe as it does for an unavailable OST.

Switch such a read to CIT_EC_RD in lov_io_iter_init(), except for AIO,
whose earlier chunks may still be in flight, and count the stripe as
lost in lov_ecio_add_data_sub(), with a debug message rather than a
console warning, so that parity rebuilds it into pages with no
sub-object (lov_page_init_composite()).  No lock covers these pages,
so they are kept only until the layout lock is cancelled, which any
change of the data does first.  A stripe with no object in a component
without parity, a write and a fault still fail.

Use OBD_FAIL_MAKE_LOVEA_HOLE, which was never used so far, to clear
the objects on the OSTs that fail_val selects (cfs_fail_index()) when
the client unpacks a layout, and add sanity-ec test_45a to read an EC
file with no object for its first data stripe.
