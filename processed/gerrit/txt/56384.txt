LU-14058 tests: clean up sanity.sh MDT name generation

Use the pre-generated ${MDT[$mdt_idx]} array variable instead of
$FSNAME-MDT000x from an MDT index, rather than open-coding this
throughout the test scripts.  The ${MDT[$idx]} array is populated
at startup time, which can be used for the MDT name in most cases.

Fix mdtname_from_index() to generate the MDT name from FSNAME when
given a filesystem name, so it works before the filesystem is mounted.

Otherwise, several tests and functions do not properly handle
MDSCOUNT > 10 (over MDT0009) configured in the filesystem.

Fix test-framework.sh::create_pool(), pool_add_targets(), and
destroy_pool() to process all MDTs.  The mds facet iteration changed
from "$(seq $MDSCOUNT)" over to "for ((...; mds_id < $MDSCOUNT; ...))"
but for facet names it needs to use "<=" to handle all of them.
Change it to use MDT index numbers, so "<" is OK in this case.

The pool helpers must derive the MDT name from the pool's filesystem
name rather than the ${MDT[]} array, since conf-sanity/32h drives them
with FSNAME set to the upgrade filesystem.  That filesystem is served
entirely by the mds1 facet, so it passes an MDT count of 1.

Other behaviour changes in test-framework.sh: ostname_from_index()
and ostuuid_from_index() are rewritten like the MDT helpers,
lss_gen_conf_one() takes the target label instead of a role and
index, changelog_register() saves and restores the changelog mask
once for all MDTs rather than once per MDT, and get_lustre_env()
calls get_mdt_devices() so that ${MDT[]} is populated for every
suite.

Except test_51d for many MDTs until OST allocator fixed.
Except test_160h and test_300ug for MDSCOUNT > 8 until fixed.
Except test_181 for MDSCOUNT > 4 until crash fixed.

Fix test_33h/33hh to create more files with many MDTs.
Fix test_160i to check changelog on all mds facets instead of mds1,
    fix subdirectory creation to be spread across all MDTs evenly.
Fix test_230o/p/q to handle more MDTs.
Fix test_413a/b/c to handle odd numbers of MDTs.
Fix test_51f to stripe its test directory across all MDTs, so its
    up to 100000 open files are not all created on a single MDT
    with high MDSCOUNT.

Limit MDT count for some tests that take too long otherwise.

Test script style cleanups in affected subtests.
