LU-20603 llapi: namespace scanner API

Add llapi_scan_namespace(). It walks a mounted filesystem and gives
the caller one record per object, instead of a formatted line.

The parameter block and the record can grow later:
- lfsp_size says how much of the parameter block the caller knows.
  Bytes past this library's definition must be zero, up to
  LLAPI_SCAN_PARAM_MAX_SIZE (4096 bytes). Only whole fields are
  copied, so a size that ends inside a field drops that field.
- lfsp_want says which fields the caller needs, so it pays only for
  those. A bit this library does not know is dropped, not refused,
  and lfsp_got reports what the scan can answer.
- lfsr_valid says which fields were filled. A field the scanner could
  not get has its bit clear, so it is not mistaken for zero.
- An unknown lfsp_flags bit, or reserved bytes that are not zero, are
  refused. Otherwise a newer caller's flag would be ignored silently.

The record starts with a struct statx, so a consumer can cast it to
one and read the Lustre fields after it. Static asserts check the
offset and the size. lfsr_padding names a hole the compiler left.
The prefixes are lfsr_ and lfsp_, because sp_ is already used in the
tree.

Fixes in the shared helpers, so that they can be shared safely:
- For an object that is not on Lustre, lmd_fid kept an old value, so
  the record got a FID made from the file name. The two callers that
  have no FID now clear it. convert_lmd_statx() no longer clears it,
  because cb_find_init() has a real FID there.
- llapi_scan_get_lmv() also clears lum_pool_name, which kept the
  previous directory's value.
- A foreign directory's LMV is not changed. Writing the MDT index at
  offset 8 overwrote the foreign type.
- STATX_INO is added to LLAPI_SCAN_MDT_MASK. Asked for alone, it came
  back as zero with its bit clear.
- LLAPI_SCAN_LMV_FOREIGN asked for alone now also fetches the LMV.

get_projid() is no longer static, so the gather can use it. Its
per-object messages are now LLAPI_MSG_DEBUG, so a caller can silence
them with llapi_msg_set_level().

llapi_scan_namespace.3 says how long each part of a record stays
valid. Some parts end when the callback returns, and the layout and
LMV buffers stay until the next object is gathered.

test10 scans a tree that is not Lustre: the stat fields are set, and
FID, layout, LMV, MDT index and HSM are clear. It skips itself when
the tree is on Lustre.
