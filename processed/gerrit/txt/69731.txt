--- Commit Message ---
LU-19895 osc: account cached folios in base pages

With large folios one osc_page covers a whole folio, up to
256 base pages, but the OSC LRU still took one slot for each
osc_page. The IO reservation is made in base pages and the
unused part is returned at the end of the IO, so a 1 MiB
folio kept a 4 KiB charge. max_cached_mb was then not
enforced: with max_cached_mb=64, a 256 MiB buffered write
stayed fully cached while used_mb reported 1.

Charge each osc_page with the base pages of its folio, and
count the LRU, busy and unevictable totals, the shrink scan,
shrink targets and cross OSC reclaim in base pages too, so
they agree with max_cached_mb, osc_cached_mb and readahead.
An IO longer than one page now reserves slots for whole
folios of the largest order its file can cache, rounded in
file offsets, so a folio it finds in its range, including
one already in the page cache, never waits for slots while
the IO holds other queued folios. A folio that still does
not fit what is left of the reservation takes the rest from
the shared cache, and gives the reservation back before it
waits. A file limited to order 0 pages behaves as before.

Add sanity/858 to check that max_cached_mb bounds the page
cache and used_mb matches it after a large folio write.

--- Message (Patrick Farrell, 2026-10-16 01:15:49.000000000) ---
Patch Set 1:

This depends on 65094 (patch set 39) and fixes its cache accounting: with large folios one osc_page covers up to 256 base pages, but the OSC LRU charged one slot per osc_page, so max_cached_mb was not enforced and used_mb undercounted. Here the LRU, busy, unevictable, shrink and reclaim counts are all in base pages, and an IO longer than one page reserves whole folios so it never waits for slots while holding queued folios.

Tested on el10.0 (6.12) ldiskfs, 1 MDT and 2 OSTs. With max_cached_mb=64, a 256 MiB buffered write left 256 MiB cached with used_mb=1 on 65094 alone; with this change 41 MiB cached and used_mb=41. The new sanity/858 fails on 65094 alone (128 MiB cached over a 64 MiB limit) and passes with this change. sanity 42 63 64 101 118 124c 124d 150 277 428 600 853 854 857 858 pass, except 600c, which hits ENOSPC on the small test OSTs after 428; it also fails that way on 65094 alone and passes when run by itself. A 90 second mixed buffered, mmap and truncate load under max_cached_mb=64 ran without hangs and the cache counters returned to zero afterwards.
