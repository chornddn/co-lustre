LU-20690 ec: copy parity in 1+N recovery reads

A raidset with one data stripe stores a copy of that stripe in each of
its p parity objects: llapi_ec_compute_parities() memcpy()s the data
instead of calling ec_encode_data() when k == 1, so --ec 1+N writes p
identical copies.  The client recovery path did not know this and
always ran the Cauchy decode, where the coefficient of parity stripe i
is gf_inv(i + 1).  Only parity stripe 0 has coefficient 1, matching
what is on disk.  A read that lost the data stripe and parity stripe
0, and fell back to any other parity, thus returned data * 2, * 3,
... rather than the data.

Copy the first parity page that could be read over the error page
when the raidset has one data stripe, in lov_ec_recover_page().  The
RS setup is of no use in that case either, so skip the encode matrix
in lov_ec_bufs_alloc() and the scratch matrices, GF tables, matrix
inversion and ec_init_tables() in lov_ec_recover_init() when dcount
is 1.

Add sanity-ec test 40e, which fails the data OST and the OST of
parity stripe 0 in a 1+2 layout, so the read has to be rebuilt from
parity stripe 1.
