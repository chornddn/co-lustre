LU-21141 nodemap: do not walk nm_list without the lock

nodemap_clear_dynamic_nodemaps() links the nodemaps through nm_list
under active_config_lock.  It then drops the lock and walks the
list.  Other code relinks nm_list under that lock.  A concurrent
call of this function does the same.  Thus two nodemap commands on
an MGS with a local target are enough.  The walk then follows a list
that it does not own, and the node can crash or hang.

Copy the names of the dynamic nodemaps under active_config_lock.
Delete them by name after the unlock.  Before each delete, check
that the name still belongs to a dynamic nodemap.  Let only one call
of the function delete at a time, because nodemap_del() walks
nm_subnodemaps without the lock.  Move the nm_parent_entry unlink in
nodemap_destroy() under active_config_lock, because nodemap_create()
links that entry under the lock.

An explicit nodemap_del that runs with a clear still walks
nm_subnodemaps without the lock.  This patch does not change that.

Add sanity-sec test 72g.  It holds one nodemap change between the
copy and the deletes.  It then runs nodemap_activate, which relinks
nm_list, and a second change.
