LU-10868 build: strip debug info from deb kernel modules

The Debian packages that ship kernel modules, the
lustre-{client,server}-modules packages and lustre-tests, carry every
.ko with its full DWARF and have no -dbgsym package for them.  The
modules are built with -g and dh_strip never touches them: it only
handles ET_EXEC, ET_DYN and static libraries, while a kernel module
is ET_REL.  binary-modules, which module-assistant runs, has no other
strip step.  The RPM build makes modules visible to find-debuginfo.sh
explicitly, so it does not have this problem.

Add strip_ko, which binary-modules runs and which lustre-tests runs
after dh_strip.  It moves the debug info of each module into a
build-id keyed -dbgsym package, laid out as dh_strip does so that
dh_gencontrol and dh_builddeb build it, then strips the module with
--strip-debug.  dh_strip has already started the -dbgsym package of
lustre-tests for its binaries, so the build-ids of its modules are
appended to the same one-line list.  Keep .symtab, which module
loading needs, and the .BTF and .BTF.base sections that pahole adds.
Honor nostrip, noautodbgsym and noddebs in DEB_BUILD_OPTIONS as
dh_strip does, and let STRIP, OBJCOPY and READELF be overridden.
Fail the build if a module has no build-id.
