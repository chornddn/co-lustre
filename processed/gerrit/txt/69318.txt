LU-14773 tests: reuse ssh connections for remote commands

Every do_node()/do_nodes() call opens a new ssh connection, paying
TCP setup, key exchange and login, twice with VERBOSE set ("lctl mark"
and then the command). This dominates the runtime of short subtests.

When PDSH uses ssh, share one connection per node (ControlMaster,
ControlPersist=$SSH_MUX_PERSIST, 120s default), with keepalives so a
dead node fails instead of hanging; close it before a node is powered
down or up. The master keeps the cwd it was started from, so ssh runs
via a "cd /" wrapper in $PATH so as not to pin $MOUNT. Run "lctl mark"
in the same call as the command. SSH_MUX=false disables sharing.

conf-sanity test_162 relied on the old ssh delay to let the client
notice the MDT0000 restart before its check; ping MDT0000 first so
the import wait sees the reconnect.

sanity-sec do_fops_quota_test() sampled quota usage while earlier
deletions were still being reclaimed, so usage fell between the
samples. Wait for deletions and a stable reading first.

sanity subset, 2 servers + 2 clients:  before  after
  VERBOSE=false                          389s   289s
  VERBOSE=true                           473s   269s

CI timings for PS2 (build 134798), 127 test sets: total suite time is 11.4% lower. Across all of Maloo that is about 10% of CI time, about 29,000 hours saved per 30 days out of about 278,000.

Compared against 250 other patchsets whose base has the same landed test fixes, leaving out other test speedup changes. This matters: PS2's base has the first LU-20869 batch and much of the fleet does not, so a plain comparison overstates the gain (about 15%).

Total suite time is 0.886 of control. Across 126 controls with comparable coverage, p5 is 0.987, p95 is 1.038 and the lowest is 0.958, so this is outside the normal spread.

Ratio to control by suite:
  conf-sanity 0.79, sanity-sec 0.78, sanity-hsm, sanity-lfsck, sanity-scrub and sanity-pcc 0.77 to 0.80, sanity-lnet 0.85, sanity-quota 0.90, replay-single 0.92, sanity 0.95

Oleg is right that Autotest already shares ssh connections: one MGS logged 11 logins in a session of hundreds of remote commands. That points to folding each mark into its command as the source of the gain here, not ssh reuse, and it would explain why the Janitor sees 20 to 30% and Maloo 11%.

The sanity run on PS1 that took longer is within noise: sanity gains only 5%, and a single run varies by about 13% either way.

This is one build, so the per suite ratios are rougher than the total.
