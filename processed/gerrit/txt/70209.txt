LU-20869 tests: import zpool for writeconf_facet on ZFS

writeconf_facet stops the facet with -f, which exports the ZFS
pool, then runs tunefs.lustre --writeconf on a pool that is not
imported. tunefs.lustre exits 19, and writeconf_or_reformat falls
back to "tunefs.lustre failed, reformatting instead" on every
call, which costs a reformat and gen_config each time.

Import the pool before tunefs.lustre and export it afterwards, as
the start path expects.

conf-sanity on ZFS in a test VM, 257 tests, before and after:
13 tests (21c 29 35a 46a 50c 50d 50f 50g 51 57a 57b 59 64) logged
the reformat fallback before and none do after. Their total run
time went from 900s to 607s (about 22s per fallback avoided). All
257 tests have the same result before and after (tests 36, 117
and 158 fail both ways).

At about 13 fallbacks per run and 2400 ZFS conf-sanity runs per
30 days, the VM figure is about 195 hours saved per 30 days; CI
reformats are slower than the VM's, so the CI saving is larger.
