LU-20290 lnet: add nodemap NID range discovery visibility

Add a discovery visibility policy based on Lustre nodemap NID
ranges. This allows a server to advertise only the NIDs that are
reachable by clients belonging to a visibility-enabled nodemap.

Persistent non-default nodemaps may enable discovery visibility with
the new discovery_visibility property. Lustre publishes the configured
NID ranges to LNet as client visibility classes. For each class, LNet
builds a discovery view containing server NIDs that can reach the
LNets represented by the configured client ranges, either directly or
through a live LNet route. CIDR nodemap ranges are compiled with the
kernel nidlist parser and participate in the same matching logic.

Clients that do not belong to a visibility-enabled nodemap continue
to use the unrestricted discovery view. Dynamic nodemaps do not create
separate discovery visibility classes and inherit the visibility
implied by their persistent parent.

Add the external_disc_visibility LNet parameter to declare discovery
visibility policies whose authoritative state is supplied by an upper
layer. The supported external policy is nodemap_nidrange. The
servicenode policy remains configured independently with
ptlrpc.target_nid_policy=servicenode and composes with nodemap_nidrange
when both are active.

When nodemap_nidrange is required, unrestricted discovery remains
available until Lustre begins publishing authoritative nodemap state.
Invalidation then activates the policy and clears readiness, so initial
and subsequent publication failures fail closed.

Failure to publish the derived LNet visibility state does not make a
valid persisted nodemap configuration unloadable; the MGS remains
mountable while discovery stays fail closed until publication succeeds.

Recompose nodemap visibility when local NIs or routing reachability
changes. Route add/delete, router discovery state, cached route
aliveness, and gateway NI status transitions dirty the views and defer
rebuilding to the discovery thread. Avoid rebuilding after LNet has
entered STOPPING.

Raise the filtered-view safety limit from 128 to 1024 so multi-tenant
nodemap configurations have practical headroom while retaining atomic
whole-generation failure rather than silently dropping a visibility
class. Expose discovery_visibility through the nodemap lproc interface
and document both the property and external_disc_visibility.

Extend conf-sanity coverage for nodemap synchronization, routed view
refresh, CIDR ranges, MGS restart with persisted nodemap state, and a
slow test with more than 128 visibility classes.

Example configuration:

    options lnet external_disc_visibility=nodemap_nidrange

    lctl nodemap_add tenant1
    lctl nodemap_add_range --name tenant1 \
        --range 10.10.0.0/16@tcp
    lctl nodemap_modify --name tenant1 \
        --property discovery_visibility --value 1

To compose this with servicenode visibility, configure the policies
independently:

    options lnet external_disc_visibility=nodemap_nidrange
    options ptlrpc target_nid_policy=servicenode
