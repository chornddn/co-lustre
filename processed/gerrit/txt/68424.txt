LU-20290 lnet: add nodemap NID range discovery visibility

Add a discovery visibility policy based on Lustre nodemap NID ranges.
Visibility-enabled nodemaps define client classes that advertise only
server NIDs that are up and can reach the class networks directly or
through a live route.

Only persistent, non-default nodemaps with ranges form explicit
classes; dynamic nodemaps inherit their parent's class. Clients outside
these classes, or all clients when nodemaps are inactive or the policy
is cleared, get unrestricted nodemap visibility. Other configured
visibility policies still apply.

Extend external_disc_visibility with nodemap_nidrange. Bootstrap
discovery remains available until Lustre publishes authoritative
nodemap state. Once activated, publication failures fail closed and
are retried from delayed work. Gate peer Push updates until required
external visibility is ready.

Classify GETs by the requester source NID. For Push, select a peer NID
belonging to the class and send the view to that same NID. When
combined with servicenode visibility, require the registered service
connection NID to belong to the nodemap class.

Re-evaluate visibility on NI status and route changes, coalescing
flaps with independent 500 ms hold-downs. Skip rebuilds and global
Push updates when policy partitions are unchanged, including when
another target registers the same servicenode NIDs. NI add/remove
and failed-rebuild retries retain the full rebuild path.

Keep persisted nodemap configuration valid when LNet publication
fails, while discovery remains fail closed. Publish locally cached
nodemap state when targets restart without the MGS. If a failed policy
clear restores a ready generation, force peers through Push again.

Persist discovery_visibility in the nodemap record's flags2 word as
NM_FL2_DISC_VISIBILITY (0x10), and add the configuration command
LCFG_NODEMAP_DISC_VISIBILITY (0xce06a).

Add LNetDiscNidrangePolicy{Required,Invalidate,Set,Clear} and export
lnet_disc_nidrange_status_changed() for NI status notifications,
including o2iblnd. Make cfs_match_nid() accept a const NID list in
both kernel and libcfs implementations.

Raise LNET_DISC_MAX_VIEWS from 128 to 1024, growing the per-peer ACK
bitmap from 16 to 128 bytes. Include partially unrestricted composite
views in batch numbering. Add disc_view_rebuilds and
disc_view_unchanged read-only module parameters and the
OBD_FAIL_MDS_NODEMAP_DISC_VIS_DELAY failpoint.

Document discovery_visibility and extend conf-sanity coverage for
publication, routing, CIDR ranges, restart, large class sets, and
unchanged composite views.

Without a configured visibility policy, legacy discovery behavior
is unchanged apart from the new read-only module parameters. The
discovery_visibility nodemap property can still be configured and
persisted, but has no effect unless nodemap_nidrange is enabled.

Example configuration:

    options lnet external_disc_visibility=nodemap_nidrange

    lctl nodemap_add tenant1
    lctl nodemap_add_range --name tenant1 \
        --range 10.10.0.0/16@tcp
    lctl nodemap_modify --name tenant1 \
        --property discovery_visibility --value 1
    lctl nodemap_activate 1

To combine with servicenode visibility, configure both policies
independently:

    options lnet external_disc_visibility=nodemap_nidrange
    options ptlrpc target_nid_policy=servicenode

Test-Parameters: trivial testlist=conf-sanity
