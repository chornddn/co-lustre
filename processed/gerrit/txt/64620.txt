LU-19548 lfs: updated mirror split for EC support

An EC data mirror and its parity mirror form a pair joined by a
bidirectional link (lcme_mirror_link_id). Splitting one mirror
without the other strands a parity mirror that protects no data,
or leaves a data mirror with no EC protection.

When splitting a data mirror, the MDS now splits (or destroys)
its paired parity mirror in the same atomic operation. The pair
is found via the mirror link id rather than by assuming the data
and parity components are adjacent in the layout, and the link on
any mirror left behind is cleared so no dangling reference
remains. A split that would remove every mirror, such as a lone
data+parity pair, is refused.

Add the --force-no-ec option to split a data mirror on its own,
leaving its parity mirror in place. When splitting a parity
mirror directly, --force-no-ec also suppresses the warning that
removing the parity eliminates EC protection of the data mirror.

One documented path looks untested: splitting an EC data mirror to a NEW_FILE with -f but WITHOUT --force-no-ec. The man page states both the data and parity mirror are moved to NEW_FILE, and this is the only path that stamps the two-mirror victim buffer (mdd_split_ea() parity_id branch: lcm_mirror_count=1 + LCM_FL_RDONLY) onto a real file via LU_XATTR_CREATE, producing a standalone 2-mirror EC file. test_7e exercises the same buffer only for object purge (-d), so the "victim becomes a valid EC file" behavior is not verified. Consider adding a 7e-style 3-mirror case that co-splits the data mirror to -f victim and checks the victim ends up with the data+parity pair.
