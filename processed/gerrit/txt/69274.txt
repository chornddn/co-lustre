LU-20107 nrs: add the GDNRS coordinator and node agent

All the targets of one server node share the PtlRPC services and the
per-CPT NRS schedulers of the node, so a QoS setting is a setting of
the node, not of a target. Today an administrator writes the same
command to the nrs_policies file of every OSS and MDS by hand, and
the nodes drift apart when one write is missed.

Add the Global Distributed NRS (GDNRS). A coordinator runs on MDT0
and one agent runs on every server node. The coordinator takes a
command through the debugfs file gdnrs.cdtor.$FSNAME.conf in the
form of the nrs_policies file:

  lctl set_param gdnrs.cdtor.$FSNAME.conf=
    "<tbf|mclock> [reg|hp] [<class type>] [key=value ...] [service=]"
    "<fifo|crrn|orr|trr|delay> [reg|hp] [service=]"

A classful policy name is a scheduler start command; any other policy
name is a scheduler stop command that names the policy to start in
place of the classful scheduler, and a policy the service of an agent
does not know fails there. The service= key names the PtlRPC service
of the command, ost_io when absent; [reg|hp] and queue= select one
NRS head instead of both. gdnrs_parse_cmd() reuses nrs_parse_cmd()
with NRS_TYPE_FLAG_DYNAMIC, so the coordinator needs no knowledge of
the class type of the schedulers on the agents, and converts the
parsed nrs_cmd to the wire struct gdnrs_cmd. The scheduler type bits
and the NRS head bits ride in gc_confl.

The command goes down MDT0 -> MDD -> LOD -> OSP as a new GDNRS_CONF
RPC (RQF_GDNRS_CONF, RMF_GDNRS_CONF, swabbed in pack_server.c) to one
target of every node. Targets of one node share a struct lu_svr_qos,
so LOD sends one RPC per lsq_id of the OST descs and of the MDT
descs. LOD holds no OSP for the local MDT, so the node of MDT0 only
gets a metadata command through another MDT it hosts; LOD checks the
peer NIDs against the local NIDs with LNetGetId() and applies the
command through the local agent when no target of the descs is here,
so the node is neither skipped nor configured twice. Every node gets
the command even if an earlier one failed and the first error goes
back to lctl set_param. OSP sends the command to an OST on
OST_CREATE_PORTAL, as osp_statfs_update() does, so the command does
not queue in the ost service whose scheduler it may be replacing,
and to an MDT on OUT_PORTAL.

The agent handler tgt_gdnrs_handlers is in the slice tables of OFD
and MDT, so any service of the node takes the RPC. It finds the
ptlrpc_service of the portal of the command and runs
ptlrpc_nrs_policy_control() on the heads the command names, like the
nrs_policies write path. The start parameters of a policy become
struct nrs_params: np_arg is the argument string of the lprocfs path
and np_data the parsed command of the agent, so op_policy_start()
takes struct nrs_params instead of a char *, and a parsed command
always restarts the policy. The head bits of the command only pick
the NRS heads; gdnrs_cmd_to_nrs_cmd() strips them with the type bits
before the scheduler checks nc_confl against its supported flags,
otherwise "tbf hp nid" fails with -EINVAL on every agent.

Add sanityn 77wm, which switches ost_io between tbf, mclock and fifo
from the coordinator and checks the primary policy on every OSS,
77wn, which switches ost_io to crrn, orr and trr, 77wo, which
selects the reg or hp head of the default service, 77wp, which
configures the mdt and mdt_io services, and 77wq, which writes
malformed and unknown commands and checks that the coordinator
rejects them and the schedulers stay.
