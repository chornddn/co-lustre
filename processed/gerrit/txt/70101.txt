LU-20963 lod: use ready OSTs after create timeout

lod_ost_alloc_specific() sets an allocation-wide timedout after one
reconnecting OST returns -ETIMEDOUT from declare.  Later passes then
skip every reconnecting OST, including ones whose precreate pool still
has objects.  osp_precreate_reserve() would hand those out immediately
while disconnected, because opd_pre_recovering is only set after
reconnect.  A create such as "lfs setstripe -i 0 -c 3" can then fail
with "have 2 want 3" / -EFBIG during OSS failover when a sibling OST
still has precreated objects.

After a timeout, still clear -EAGAIN for a reconnecting OST with
os_fprecreated > 0.
