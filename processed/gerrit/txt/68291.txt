--- Commit Message ---
LU-18298 utils: do not write open a file to detach it from PCC

lfs pcc detach opened the file O_RDWR only to issue the detach ioctl.
The open lock that comes with it takes CW on LOOKUP|OPEN, conflicting
with the client's cached lock over LAYOUT; cancelling that runs
vvp_conf_set() and detaches the PCC inode, so the ioctl finds nothing
and returns success with the HSM archive still there - sanity-pcc
test_1c, 1d and 13a fail their wait_request_state.

Detach by FID with an ioctl on the parent directory instead, holding
the file with an O_PATH descriptor until the ioctl returns, as it only
finds a cached inode.  O_PATH takes no open lock and does not need the
encryption key.  The open mode gate goes away too: a mode 0400 file
its owner could not detach now detaches.  lfs pcc detach now reports
the error returned by llapi_pcc_detach_file() rather than errno.
