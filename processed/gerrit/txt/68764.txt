LU-20724 tests: add fsx option to drop client caches

-f only calls msync(MS_INVALIDATE), which leaves the DLM
locks in place, so the client still serves reads from
cache.

Add -Q P: a 1 in P chance per operation of syncfs() plus
writing "clear" to ldlm.namespaces.*{osc,mdc}*.lru_size,
cancelling the unused locks and discarding the pages they
covered.  Only client namespaces have an LRU to clear.
The sync is required: clearing the lru does not reliably
drop the cache with dirty pages still around.

The namespaces are matched by the fsname of the file under
test, so a drop covers every file on that filesystem, and
on a combined MDS and client node the MDT's own OSP
namespaces for it as well.  They are resolved once and
kept, since globbing them costs more than the drop.  A
namespace that cannot be cleared fails the drop, since it
may be the one holding the data cache.

Clearing the lru needs root, so prove it works before
running any operations, and fail the run if it stops
working later, rather than finishing a run that never
dropped a cache.  The draw in test() only runs when -Q is
given, so a seed replays the same without it.  Drops are
skipped while a -b replay is still simulating.

Drops are logged to the oplog so logdump() shows them.
Take the operation number in that dump from the log entry
rather than counting entries.  That was already wrong
before this: OP_CLOSEOPEN without -c and OP_MIRROR_OPS
without -M return from test() without logging anything, so
the count had drifted from testcalls, which is what -b
replays and what gendata() stamps into the data.

Add -Q to sanityn test_16l.  Hoist the getopt option
string into a variable to keep it under 80 columns.
