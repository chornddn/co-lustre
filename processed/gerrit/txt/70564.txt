LU-10948 ldlm: age out idle cached write open handles

A cached write open handle stays open on the MDT until its CW OPEN
lock is cancelled, which for an idle file is the LRU age of 600s.
Until then the MDT would not see the close, so the file size update,
the changelog CLOSE record and actions taken at last close were
delayed by up to 10 minutes after the application closed the file.

Add a short-lived LRU list to the namespace, for unused locks that
should be cancelled sooner than the LRU age, in the order they were
last used.  ldlm_namespace_set_short_lru() sets a callback that picks
these locks and their maximum age.  The LRU scan moves the locks not
used for that long to the head of the normal LRU list to be
cancelled, marked LRU_SHORT_EXPIRED, so that they do not make the
scan cancel a batch of other locks.  The oldest of these locks are
also used when the normal list is too short for an LRU cancel.

MDC puts unused CW OPEN locks on that list, with the age set by
`llite.*.opencache_max_ms` (60s by default), which is also how soon a
file must be opened again to count as hot.  The cached write handle
is closed once the file is no longer hot.  llite passes the age to
each MDC through LMV with KEY_OPENCACHE_MAX_MS, including MDTs added
later.  With opencache_max_ms=0, no file is hot, and these locks are
cancelled at the next LRU scan.

Add sanity test_441b to check that a reused write handle stays
cached and an idle one is closed.
