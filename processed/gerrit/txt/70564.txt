LU-10948 ldlm: age out idle cached write open handles

A cached write open handle stays open on the MDT until its CW OPEN
lock is cancelled, which for an idle file is the LRU age of 600s.
Until then the MDT would not see the close, so the file size update,
the changelog CLOSE record and actions taken at last close were
delayed by up to 10 minutes after the application closed the file.

Keep unused CW OPEN locks on their own LRU list, in the order
the cached handles were last used.  The periodic LRU scan moves the
locks not used for `llite.*.opencache_max_ms` (60s by default) to the
head of the normal LRU list to be cancelled, so the handle is closed
once the file is no longer hot.  Expired locks do not make the scan
cancel a batch of other locks, and the oldest of these locks are also
used when the normal list is too short for an LRU cancel.  llite
passes opencache_max_ms to each MDC namespace through LMV with
KEY_OPEN_DENY_MAX_AGE, including MDTs added later, and
ldlm_namespace_set_open_deny_max_age() sets it.  Setting it to zero
moves these locks to the normal LRU list, to be left to the LRU age.

Add sanity test_441b to check that a reused write handle stays
cached and an idle one is closed.
