LU-21140 lmv: snapshot a changing directory for readdir

While a striped directory is being split or migrated, readdir can
list a name twice or not at all. LMV reads each stripe in its own
RPCs, at different times, and merges the pages by hash, so a name
that moves from an old stripe to a new one between two reads is
seen in both or in neither.

While a directory auto-splits, "ls -U dir | sort | uniq -d" prints
duplicated names, and "ls -U dir | sort -u | wc -l" returns fewer
files than were created.

Read every stripe of a directory whose layout is changing into pages
kept on the open file, when the first entries are requested, and
serve the listing from them. Each stripe is read under a PR UPDATE
lock that is kept until the last stripe has been read, so no name
can move between the stripes in the meantime. A move takes a
conflicting lock on both stripes, in stripe index order, so the
locks are taken in that order too. Only the first page of a stripe
enqueues the lock; reading the other pages under the lock already
held avoids a new request queuing behind a conflicting lock that is
waiting for ours to be cancelled.

Add the lock hand-over to md_readdir_info and mdc_read_page(). The
snapshot is dropped at EOF, on seek and on close. If it cannot be
taken, readdir reads the stripes directly as before.

Add sanity test_230D, which lists a directory while it auto-splits.

Test-Parameters: mdtcount=2 mdscount=2 testlist=sanity env=ONLY=230D,ONLY_REPEAT=10
