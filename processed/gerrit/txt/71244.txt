LU-20276 osd-zfs: limit memory of large object frees

Freeing a large object in osd_unlinked_object_free() dirties all of
its L1 indirect blocks.  ZFS limits the frees and dirty data of each
pool separately (zfs_per_txg_dirty_frees_percent, zfs_dirty_data_max),
so destroying large objects on many OSTs of one OSS at the same time
can pin more dirty memory than the node has.  sanityn test_56a/56b
create sparse objects with one L1 block per GiB, ~16K per OST, and
their destroys in the following tests drove a 4GiB OSS with 8 ZFS
OSTs out of memory in dbuf_dirty(), with ~30K dirty indirect blocks.

Estimate the indirect blocks each free dirties from the object size,
counting at most zfs_dirty_data_max for each OSD, and start a free
only while the total for all OSDs stays within a quarter of RAM.
Frees start in arrival order, and an OSD whose pool is suspended
does not hold up the others.  Use zfs_dirty_data_max if ZFS exports
it, otherwise its default of min(RAM/10, 4GiB).

Remove the sanityn test_56b exception for ZFS servers.
