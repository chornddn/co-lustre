LU-20964 llite: keep zero page owned if read ahead

When truncating an encrypted file to a size that is not a multiple
of PAGE_SIZE, ll_io_zero_page() assumes the page at the new EOF,
reads it if it is not uptodate, zeroes the end of it and writes it.
It sets PagePrivate2 so that ll_io_read_page() keeps the page owned
and locked.

But if the page was read ahead and not yet used, it has
cp_defer_uptodate set and is not uptodate. ll_io_read_page() then
marked it uptodate and called cl_page_disown(), whatever PagePrivate2
says. This cleared the owner and unlocked the vmpage, so
ll_io_zero_page() queued for write a page it did not own anymore:
  (cl_io.c:944:cl_page_list_add()) ASSERTION( page->cp_owner != NULL )
  ll_io_zero_page+0x46c/0x850 [lustre]
  ll_setattr_raw+0x95c/0x1130 [lustre]
  do_truncate+0x94/0x100

Do not disown the page in that case either, as is already done after
an actual read.

Add sanity-sec test_48d to exercise this. The client must hold a PW
lock covering the page before the truncate, otherwise the lock
request in ll_io_zero_page() cancels the read lock and drops the
read-ahead pages, so the test writes the file before reading it.

Fixes: edcd05e5ac03 ("LU-15803 sec: correctly handle page lock in ll_io_zero_page")
