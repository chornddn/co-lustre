LU-5964 tests: allow createmany to replace unlinkmany

The functionality of unlinkmany is really just a subset of createmany.
Allow createmany to replace unlinkmany by checking argv[0] and setting
the "do_unlink" flag in this case and disallowing the create options,
-i and -u/-r with a name format.

That allows removal of the code duplication that is unlinkmany.c.

unlinkmany takes on the createmany behaviour where they differ: the
count is optional, so it removes names until the first one missing
or until -t expires, a count of zero or less does nothing, a name
that is a directory is removed with rmdir, and the summary reports
"ops/second". In-tree callers rely on none of the old behaviour.
unlinkmany options must come before the name format, and it does not
take createmany's deprecated trailing "-seconds", so a negative count
stays a count.

The rmdir fallback now applies only to the name that is a directory,
so the regular files after it are still unlinked.

Fix replay-vbr.sh test_11b to not pass "-o" as an argument.  This
was a copy-paste error from the "createmany -o" line above, but fails:

    CMD: unlinkmany -o /mnt/lustre2/f11b.replay-vbr-2- 100
    CMD: createmany -o /mnt/lustre/f11b.replay-vbr-1- 100
    unlink(-o0) error: No such file or directory
    total: 0 unlinks in 0 seconds: -nan unlinks/second
