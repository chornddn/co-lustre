LU-17740 mds: remove user_xattr,acl MDT options

Remove the "user_xattr" and "acl" options from the MDT.  Both
are on by default in ldiskfs, and osd_mount() now strips them
and their "no" forms out of the backing mount options, so they
cannot be turned off for an OSD.  Only "noacl" was stripped
before, so an MDT that was mounted with "nouser_xattr" will
start serving user.* xattrs again.

The ZFS OSD already reported MNTOPT_USERXATTR unconditionally,
and only the server-side "noacl" option could clear MNTOPT_ACL,
so osd-zfs now behaves the same way as osd-ldiskfs.  A ZFS MDT
that was being mounted with "noacl" will start enforcing the
ACLs already on disk and turn the identity upcall on, both of
which that option suppressed.

It is still possible to mount the client with "(no)user_xattr"
to enable/disable this option for specific clients.  The MDT
no longer backs that up: it always grants OBD_CONNECT_XATTR,
so "nouser_xattr" is now enforced only on the client that
asked for it.

With "user_xattr" gone, no backing filesystem asks for a
mandatory mount option any longer, so check_mountfsoptions()
and the wanted_mountopts argument it was fed by are dropped
from mkfs.lustre and the osd prepare_lustre() interface.
