--- Commit Message ---
LU-19916 mgs: allow reading config logs on a follower

An MGS follower refused every ioctl with -ENODEV, so an admin could
not check that a follower was running, compare its copies of MGS0's
config logs with the originals, or dump the configuration from any
server: "lctl --device MGS llog_print <log>" failed there.

Let mgs_iocontrol() of a follower handle the ioctls that only read its
logs: llog_print, llog_info, llog_check and llog_catlist.  They read
the copies of MGS0's logs in the CONFIGS of the target the follower
runs on.  mgs_follower_ioctl_check() allows a log by name only, since
a log ID can name any llog of that target, and llog_check of one of
its catalogs would destroy the catalog's empty plain logs.  Any other
ioctl is refused with -EROFS, which says why better than -ENODEV.

conf-sanity test_145h checks that a follower prints, lists and
describes the same <fsname>-client log as MGS0, and refuses to print
it by log ID or to cancel a record in it.
