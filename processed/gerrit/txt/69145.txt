LU-20770 lnet: bulk conns use accept_port by default

LU-19139 added accept_port_bulk with a fixed default of 988,
even if accept_port is changed.  A client with
accept_port=7988 then connects its bulk sockets to port 988,
which older (2.15, 2.16) servers do not listen on, so it
runs with only a control conn.  Since LU-19763 enabled
zero-copy on VMs, a ZC request on the control conn cannot be
ACKed by the server (-113), all conns are closed, and the
client is evicted (e.g. sanity test_27cg).

Default accept_port_bulk to accept_port, so a separate bulk
port is only used if explicitly configured.  If a bulk
connect to a separate port is refused, retry on accept_port
for older peers.  Print the port that was actually refused
in the console error.

2.17 peers always send bulk conns to port 988, so keep
listening on 988 if accept_port is changed and
accept_port_bulk is not set, as was done before, until
2.19.53.  Only warn if that listener cannot be started,
since 988 may be in use by something else.  Setting
accept_port_bulk explicitly (e.g. equal to accept_port)
disables the port 988 listener.

Also fix a leak of lsock if lnet_sock_listen() fails.

Add sanity-lnet test_292 to verify bulk conns use
accept_port.
