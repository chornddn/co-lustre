LU-20590 ldlm: never file an LRU-excluded lock on the LRU

ldlm_cli_inodebits_convert() returns a lock to the client LRU with no
examination of LDLM_FL_NO_LRU, and thus a lock which its owner holds
out of the LRU can become a reclaim candidate again.

No lock reaches this today, but not because the flag is rare on a
client: mdt_remote_object_lock_try() enqueues LDLM_IBITS and
osp_md_object_lock() passes LDLM_FL_NO_LRU, so an MDT acting as a
client does hold ibits locks with the flag. The reason is the caller
set. ldlm_cli_convert() has exactly one caller, ll_md_blocking_ast(),
so only the regular ibits locks of a client file system reach the
convert path, and those never carry the flag. The one llite lock
which does, the lease, uses ll_md_blocking_lease_ast instead.

Refuse to file such a lock in ldlm_lock_add_to_lru_nolock(). Callers
decide list membership without an examination of the flag, so the
refusal belongs at the point a lock is added and not at each caller.
