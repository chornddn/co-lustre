LU-15437 fld: extend procfs to allow fldb changes

Allow the server "fldb" and "space" files to be updated via
set_param so that the FLDB on MDT0000 can be restored from a dump
saved earlier with:

    lctl get_param -n seq.ctl-testfs-MDT0000.fldb > fldb.save

A single line adds one range and a whole saved list is applied in
one write, so the FLDB can be reconstructed from an earlier dump or
from another MDT.  A range that exactly matches an existing one is
skipped, so replaying a dump is idempotent; a range that conflicts
with an existing one returns an error.  The historical closing ')'
and decimal index are still accepted on input.

Writing the "space" file now stores the new value to disk and drops
the server's pre-allocated sequence sets, so that the next sequence
handed to a client is taken from the updated space rather than from
a set that was reserved out of the old space.

Convert the LASSERT() in seq_server_init() for a bad on-disk
sequence range into a graceful error, since the range can now be
set from userspace.

Fix conf-sanity test_68, which used "[[ ]]" for numeric comparison
of sequence values (a string comparison that never detected reuse),
and extend it to check that a whole FLDB can be restored in a
single write.
