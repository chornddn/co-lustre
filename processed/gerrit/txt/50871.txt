Those sites are on the open/create fast path for every file on both client and MDT, so this floods the console and the debug log for workloads that never touch O_TMPFILE, not just for tmpfile users. Please strip all of it before the next refresh.

The new test coverage is thin: tmpfile_test.c only checks that open(O_TMPFILE) returns a descriptor. Since the point of the feature is a nameless, open-unlinked file, consider also verifying st_nlink == 0, that data can be written and read back, and that linkat(fd, "", dirfd, path, AT_EMPTY_PATH) materialises the file.
