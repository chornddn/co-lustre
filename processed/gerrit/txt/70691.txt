LU-16504 llog: recreate a lost remote update catalog

If the update catalog of an MDT on another MDT is lost there while the
MDT keeps it open, e.g. because its create did not commit before the
other MDT failed, every new plain llog the MDT adds to it fails.  The
other MDT used to LBUG in out_tx_write_exec() on the catalog write:

  (dt_object.c:533:dt_record_write())
  ASSERTION( dt->do_body_ops->dbo_write ) failed: [0x1180000441:0x1]

and as the MDT resends the update after each restart of the other MDT,
it kept crashing.  With the write failing with -ENOENT instead, every
cross-MDT update to that MDT fails, until this MDT restarts.

When preparing a log of a remote update catalog fails with -ENOENT in
llog_cat_declare_add_rec(), ask the other MDT whether the catalog is
gone, and if so recreate it in llog_cat_renew() with the same FID, so
the catalog list there stays valid, and an empty header.  Retire the
plain llogs of the lost catalog and clear their catalog index, which
llog_cat_cleanup() now skips, so that cancelling their last records
frees no slot of the new catalog.

Add recovery-small test_154c and, for old-format catalogs, test_154d,
which remove the update catalog of MDT0000 from MDT0001 while MDT0000
is up.
