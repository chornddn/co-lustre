LU-20211 lod: count offline OSTs to skip per-stripe checks

Checking a file for stripes on unavailable OSTs looks up the OST of
every stripe and its state, on every truncate (layout replace probe),
FLR primary mirror pick and migration parent FID update, even though
an OST is rarely unavailable.  A read-only OST was also treated as
usable for truncate, so a truncate of a file with an object there
would fail with -EROFS instead of replacing that object.

Add lod_ost_offline_count, the number of OSTs that cannot modify
their objects: the OSP import is not connected or is deactivated, or
the OST reported OS_STATFS_READONLY in its last statfs.  LOD gives
each OST's OSP a pointer to the count with KEY_OFFLINE_COUNT when the
OST is added, and clears it under ltd_mutex before the OST is
removed.  The OSP raises the count by one while it is unusable,
checked under a lock at each import event, read-only state change in
osp_pre_update_msfs() and pointer change, so an OST that is offline
when it is added is counted at once and a late IMP_EVENT_ACTIVE
cannot undo a newer disconnect.  A connected OST that is full or not
precreating is not counted, since it can still be truncated and have
its parent FID changed.

Skip the per-stripe checks while the count is zero in
lod_layout_check(MD_LAYOUT_UNAVAILABLE) and
lod_obj_stripe_replace_parent_fid_offline_cb().  lod_ost_offline()
treats a read-only OST and an invalid (deactivated) import as
offline, as the count does, reading the import and the OSP's cached
statfs rather than waiting for LOD's next statfs refresh.

lod_primary_pick() must still avoid a mirror on any inactive OST, so
it skips its check only while every OST is active, and takes each
stripe's OST index from llc_ost_indices[] instead of an FLD lookup.

While the checks are skipped, a stripe on an OST index that was
removed from the configuration is no longer reported unavailable.

Show the count in lod.*.ost_offline_count, and add sanity/test_27xw
to check that it rises when an OST is deactivated, stopped or made
read-only and returns to zero afterward, that truncate(0) moves a
file off a read-only OST, and that a no-create OST is not counted.
