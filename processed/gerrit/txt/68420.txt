LU-20650 doc: man page and tests for the new flags

lfs-find.1 gains --since, --since-cookie, --changelog and --resolve:
what each answers, that --since is a strict subset of the same search
without it, that a bare index belongs to one MDT and is refused where
that is ambiguous, that a number which could be an index or an epoch
second is never guessed at, and that reading a changelog neither
consumes it nor needs a registered user while records exist only while
some user is registered.

Three sanity cases.  160aa asserts the promise --since is worth having
-- that its answer is a subset of the same find without it, and a
smaller one -- rather than asserting a particular file, so it does not
depend on what else the filesystem is doing.  160ab walks the
refusals: -size, an object time, --maxdepth, a path below the mount
and an unknown MDT are each refused, and --resolve lets the first of
them through.  160ac runs the cookie three times: the first writes it,
the second returns the new object and not the old one, the third
returns nothing, and then a stale anchor and both anchors together are
refused.

160ac asks for creations only.  A wide mask records the test's own
reads, and then "nothing changed since" is never true -- which is what
hid an off-by-one in the cookie until a narrow mask made every run
repeat the last object of the one before it.

Test-Parameters: testlist=sanity env=ONLY=160aa,160ab,160ac

The bigger question is whether this should be a patch at all.
