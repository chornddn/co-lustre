LU-20840 mdt: don't retry terminal auto-split failures

When a directory auto-split fails with -E2BIG, the target stripe count
is larger than the MDT count that LOD knows about, i.e. the MDT's
mdt_mds_mds_conns and LOD's ld_tgt_count disagree.  This can happen
for a while when an MDT is added: the new MDT's OSP connects before
this MDT's LOD has processed the config record that increases its MDT
count.  mdt_getattr_internal() re-queues the directory for auto-split
on every getattr while its dirent count exceeds the split threshold,
so a failing split repeatedly takes the parent PW lock and the stripe
EX locks, blocking clients and wasting CPU.

Use the existing (previously unused) mot_auto_split_disabled flag on
struct mdt_object as a negative cache: set it, under mdr_lock, when a
split fails with -E2BIG, on the object that getattr re-queues (the
stripe for a striped directory, otherwise the plain directory
itself), and skip mdt_auto_split_add() for objects that have it set.
mdr_lock is needed because the flag shares a bitfield word with
mot_restriping, which mdt_auto_split_add() sets under that lock.

Record the MDT count at the time of the failure in the restriper, and
retry once the count changes, so a directory is not excluded from
auto-split forever when the disagreement was temporary.  The flag is
per in-core object, so it is also cleared when the object is evicted
and re-instantiated.
