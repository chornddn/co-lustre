LU-20477 lfsck: stop OSTs whose start was interrupted

When "lfsck stop -A" interrupts an MDT's layout LFSCK while its
start notification to an OST is still in flight, the MDT drops
that OST and never sends it the stop, though the OST may have
started. The OST is then left scanning. This is seen on ZFS,
where the OST start waits for a txg sync, as sanity-lfsck
test_12a failing with an OST in 'init' or 'scanning-phase1'.

Keep an OST whose start notification was interrupted on the
list of targets told about the exit, so that it is stopped too.

The MDTs do not wait for the OSTs to handle the stop, so make
test_12a wait for each OST to report 'stopped'.
