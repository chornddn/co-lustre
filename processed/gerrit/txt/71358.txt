LU-20911 lfsck: check EC raid set uniqueness at runtime

LFSCK's layout scan did not check EC raid set OST or failure-domain
uniqueness at all; the only enforcement was in LOD at allocation time
(lod_fdom_check_ec_allowed(), lod_ec_check_data_usable()), so LFSCK
missed violations introduced after a file was striped: an OST or
object swap could put two raid set members on the same OST, and an
OST's failure domain could be changed to collide with another member
of the same raid set, in each case defeating the fault tolerance the
EC layout was meant to provide.

Add lfsck_layout_check_raidset_uniqueness(), called from
lfsck_layout_master_exec_oit() for each EC raid set found while
scanning a striped layout.  It flags any OST index repeated among a
raid set's live stripes, and separately flags any two live stripes
whose OSTs currently report the same failure domain, fetched via
dt_statfs() the same way LOD's QoS allocator does, so the check
reflects live configuration rather than what existed at allocation
time.  A pair of stripes already reported as a duplicate OST is not
also reported again for sharing a failure domain, since that follows
trivially from being on the same OST.

Both cases are reported with CWARN.  The intent is to draw attention
to the fact that mismatches exist, e.g. right after failure domains
are configured on a large, pre-existing filesystem, not to enumerate
every occurrence across what can be billions of files: a complete
per-file audit belongs in a separate tool.  CWARN's existing
per-callsite console rate limiting bounds how often each of the two
warnings can print and reports how many were skipped in between, so
this scales to a full-filesystem scan without flooding the console.

Add sanity-lfsck tests 60-62 covering a duplicate OST within an EC
data component, a duplicate OST shared between data and parity
components (created with swap_single_stripe, since LOD's allocator
itself prevents this at setstripe time), and two raid set members
whose OSTs are given a matching failure domain after the file was
striped.  Add test 63, which checks that a valid EC layout with more
than one raid set does not trigger a false uniqueness warning just
because its raid sets share OSTs or failure domains with each other.
