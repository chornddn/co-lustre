LU-20611 utils: lfind, find over a target

Add lfind(8), a server-side command -- and only that.  It runs lfs
find's predicates against a Lustre target's own objects, read straight
off the device, on the MDS or OSS whose disks hold that target.  It is
built under SERVER, so a client package does not carry a command with
nothing to read, and the man page and its usage both say where it
belongs.  No mount, no MDS process and no client: an unmounted target,
a snapshot or a failover partner's LUN is as scannable as a serving
one.

Not a mode on lfs find, which is a client command by construction --
llapi_is_lustre_mnt() requires ":/" in the mount's device name, so a
server target mount is deliberately not recognised and lfs find
answers -ENODEV on a server with no client mount.  A device scan is
disk-reading, root-only, path-less and one target at a time; that is
a different command, not a flag.  And lfs ships in lustre-client
while the scan backend does not, so the flag would have answered
-ENOTSUP on every client install there is.  lfind installs under
SERVER, where it can run.

The predicates are the same ones, not a second copy: lfs_find_parse()
is compiled into both programs.  What differs is documented in
lfind(8) -- it prints FIDs because a target has no paths, --name
matches against every name in the link xattr, one invocation covers
one target and under DNE that is part of a namespace rather than all
of it, and a predicate the target cannot answer is refused rather
than quietly matching nothing.

The target is named three ways.  --device always works.  --target
resolves a name through osd-ldiskfs.<name>.mntdev, which exists only
while that target is mounted here.  --local takes every target this
node serves, skipping the MGS, whose llogs are not objects with FIDs,
and scanning a combined MGS/MDT once; a target that fails is reported
and the sweep goes on, with a non-zero exit if any failed, so a
partial sweep cannot be taken for a whole one.  On a client there are
no targets and it says so rather than reporting an empty scan.

conf-sanity test_165 diffs lfind --type f against what the client
saw, on a stopped filesystem: every regular file has to come back,
and the directory must not.

A usage error the parser reports through its return value rather than
its stopped flag now ends the run before the scan, instead of after
every match had been printed; and a second device named without an
option following it is caught rather than dropped in silence, which
is what pathend being unset meant.  A target whose device cannot be
read is reported and fails the sweep, since --local promising every
target and delivering some of them is the same trap.

lfind.8 moves to SERVER_MANFILES.  It was in MANFILES, installed under
UTILS, while the binary is built under SERVER, so a client build
shipped the man page for a command it does not install.

lfs_find_parse.c no longer drags zlib and lnetconfig in, so lfind
links neither.
