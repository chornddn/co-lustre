LU-20682 llite: validate xattr value in ll_xattr_set()

ll_xattr_set() reads the LOV and LMV EA handed in by setxattr(2)
before passing it to the MDT, with no check that the value exists
or that it is long enough.  removexattr(2) and a zero-length
setxattr(2) both arrive with value == NULL, so the lmm_magic and
lum_magic loads oops the client.  A short value carrying a
big-endian LOV magic is byte-swapped in place by
lustre_swab_lov_user_md() past the end of the kernel buffer, and a
short value under the "lmv" name has its lum_hash_type rewritten
past the end of the buffer.

Skip both branches when value is NULL.  Swab the LOV EA only when
the value holds a whole struct lov_user_md and at least the
ll_lov_user_md_size() bytes its header describes, the same check
ll_setstripe_ea() makes on the "lov" path.  That header is
big-endian here, so read its magic and length fields with
be32_to_cpu() before sizing it.  Apply the LMV fixups only to a
value that holds a whole struct lmv_user_md.  Anything shorter
goes to the MDT unchanged, which validates the layout as before.
