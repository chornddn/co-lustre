--- Commit Message ---
LU-20682 llite: validate xattr value in ll_xattr_set()

ll_xattr_set() swabs the LOV and LMV EA from setxattr(2) without
checking the value.  removexattr(2) hands it value == NULL, and a
value carrying a byte-swapped LOV magic is swabbed by the stripe
and component counts it holds, past the end of the kernel buffer.

Touch the value only when it exists and holds the LOV or LMV
header.  On little-endian clients a byte-swapped LOV magic comes
only from a malformed value, so return -EINVAL for it and keep
the swab for big-endian clients.

Fixes: 9d17996766e0 ("LU-10100 llite: swab LOV EA user data")

Patch Set 8: Code-Review+1

This fixes an important and easily reproducible problem. On the parent commit, an unprivileged user can crash the client from userspace.

How I reproduced it (Rocky 9.7 client, 5.14.0-611 kernel, slub_debug=FZPU):
- The new sanity test_102u panics the base client.
- By hand, as a normal user on a file I own: setfattr -n lustre.lov.<name> -v 0x0bd60bd0 <file> (a 4-byte value carrying a byte-swapped composite magic) takes the node down in ll_xattr_set(). A zero-length/removexattr value reaches the same path with value == NULL.

With this patch applied I could not reproduce any of it: test_102u passes with slub_debug on and no kernel warnings, and normal and composite layouts still work (sanity 27*/102*/56xd: 84 pass 0 fail; sanity-pfl: 60 pass 0 fail). I checked both the crash and the fix on real VMs.

On Timothy's point: even if the swab paths are rarely useful on modern little-endian Lustre, the crashing path is reachable today on x86, so bounding it is correct. Removing swab entirely would be a larger, separate change.

A few possible improvements, none blocking:
1. lustre_swab_lov_comp_md_v1(): a bad entry is continued but the function still returns 0 after partially swabbing that entry's header; returning -EINVAL (as it does for a bad header) would be more consistent, since purge/qos already act on the error.
2. The new return value is checked in lod_declare_layout_purge() and lod_qos_parse_config(), but ignored in lod_declare_layout_add/set/del(), lod_get_default_lov_striping() and lov_getstripe().
3. test_102u ignores every setfattr exit code and only checks that stat works afterward; checking the expected EINVAL per call (or scanning the console) would catch an overwrite that doesn't crash immediately.

+1 -- a useful patch that fixes a serious, user-triggerable crash.
