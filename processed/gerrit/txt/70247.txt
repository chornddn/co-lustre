LU-21078 build: make deb packages reproducible

Starting with Debian 14 ("forky"), Debian requires packages to be
reproducible, so that anyone can rebuild a package and verify that
it matches the published binary
(https://lists.debian.org/debian-devel-announce/2026/05/msg00001.html).
Lustre debs built from the same tree on the same machine did not
match: each build produced files with different checksums.

There were three causes:

- The changelog entry written by "make debs" and "make dkms-debs"
  used the current time, and dpkg-buildpackage derives
  SOURCE_DATE_EPOCH from it, so file mtimes in the packages
  changed on every build. The module-assistant step runs outside
  dpkg-buildpackage and never saw that value.
- configure saves each kernel feature check in
  kconftest.results/$RANDOM, and the dkms and lustre-source
  packages copied these directories.
- The lustre-source tarball recorded file mtimes, owners and
  ordering.

Set SOURCE_DATE_EPOCH to the HEAD commit time, export it so that
every packaging step uses it, and use it for the changelog date.
Sort the entries in the lustre-source tarball and normalize their
owner and mtime. Exclude kconftest.dir and kconftest.results from
the rsync copies.

See https://wiki.debian.org/ReproducibleBuilds for background.
