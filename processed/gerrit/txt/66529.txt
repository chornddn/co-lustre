LU-19917 mgc: dynamic MGS NIDs discovery

Enable fault tolerant MGS on the client: the client MGC can connect to
any server running an MGS follower, and it learns about those servers
on its own.

. an MGS NID list can be given to the client mount command, and the
  NIDs are shuffled so that clients spread the MGS load and a large
  cluster starts faster.  A server MGC still tries the primary MGS
  first, in the order given
. the imperative recovery log adds every server NID to the client MGC
  import, at the tail, so that fault tolerant MGS works with no
  configuration while the MGS NIDs from the mount line stay preferred
. the server MGC device is renamed to "mgc<NID>", because it only ever
  connects to the primary MGS, while the client MGC is "MGC<NID>".
  sk_utils.c, lustre_param.c, conf-sanity and recovery-small match the
  MGC name case-insensitively for this
. a client MGC pings at max(PING_INTERVAL_SHORT, obd_timeout / 20),
  capped at PING_INTERVAL, so that it notices a dead MGS and switches
  in time to not miss an IR update
. a follower builds the fsdb on the first MGS_CONFIG_READ when the
  filesystem is present in its CONFIGS directory, and serves the
  nidtbl it has, rather than making the client retry
. the IR log parser reports why it stops, instead of breaking silently
. "lfs check mgts" skips the server MGC, which now has its own device,
  and the tests that assumed a single MGC device match "MGC*"
. add conf-sanity test_163, and rework test_160 to check the client
  MGC, since a server MGC no longer shares the client MGC device
. conf-sanity test_5b starts its OST with "nomgs", so that no MGS
  follower serves the config the test expects to be unreachable
. conf-sanity test_161 stops everything itself: it used to inherit an
  unmounted filesystem from test_160, which is excepted for an older
  client now that test_160 only checks the client MGC
. conf-sanity test_73e waits for the OSTs to re-register with the
  restarted MGS before mounting the client, instead of racing them
. recovery-small set_ir_status() sets the IR state on every server
  node, since a follower keeps its own copy of it
