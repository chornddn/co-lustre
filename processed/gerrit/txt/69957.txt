LU-21022 fld: index the FLD cache with an interval tree

fld_cache_lookup() finds the cached sequence range that contains a
given sequence by scanning the sorted fci_entries_head list under
fci_lock.  This is a linear scan, and it runs on hot paths such as
cross-MDT lock and getattr that resolve a FID's location on every
request, so its cost grows linearly with the number of targets.

Sequence ranges are assigned when targets are formatted and change
only if a target gets a new one, after creating billions of objects.
There are typically only hundreds of them and they never overlap, so
the cache holds a small, stable set of non-overlapping ranges that
never needs eviction and is never merged or split.

Index the entries with an interval tree so lookup, insert and delete
are O(log n), at most one entry can contain a sequence.  Drop the
sorted list, the LRU list and the shrinker the original CMD design
used when there were millions of tiny ranges, and the range merge and
overlap-split handling that cannot occur.  An insert of a range that
is already cached is silently dropped as a duplicate.

An empty or inverted range cannot be represented in the tree, reject
such a range with an error in fld_cache_entry_create() rather than
LASSERT, since they come from an on-disk FLDB or an FLD_QUERY reply.
