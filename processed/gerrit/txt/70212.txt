LU-20565 tests: remove duplicate sanity-ec subtests

Many sanity-ec degraded-read subtests repeated the same layout,
write, resync and fault as another subtest.  They would add run time
and setup cost without testing anything the other subtest did not.

Remove each subtest whose checks another subtest already makes:

- 11 (create 2+2): 12a creates the same layout and checks parity
- 30a (write stales parity, resync): 23a and 28a check the same
  ro/wp/stale transitions, 6b checks the data across the resync
- 41f (DIO read after buffered write): 41i does that after a
  buffered degraded read of the same file
- 43c, 44c (EIO when all reads fail): 44a, which also reads the
  file again after the fault is cleared
- 43d (fail 1, then 2 stripes): 63c fails 1, then 2, then 1 again
- 44b (repeat a 1-OST fault): 63a and 63c fail and clear faults
  repeatedly on the same file
- 45a (fail stripes 0 and 1): 43b is the same test
- 45c (fail only parity OSTs): 75a, which now fails every parity
  OST that holds no data rather than one, and also checks stat and
  getstripe
- 47a (2+1 then 4+2 PFL): 68d, which fails each safe OST in turn
- 47c (1M then 4M stripe PFL): 46d
- 47d (read across a PFL boundary): 42d
- 63b (every pair of safe OSTs): 58a is the same test
- 64b (stale parity read, then resync): 48c
- 64c (3 rewrite/resync rounds from mount2): 64a does 2 rounds
- 65a (3-component PFL): 65b uses 4 components of mixed geometry
  and stripe size
- 67b (rewrite and resync 3 times): 75b repeats overwrite, resync
  and degraded read 50 times, and 64a covers truncating rewrites
