LU-20290 lnet: add servicenode discovery visibility policy

Add a discovery visibility policy that groups local server NIDs by
servicenode.

Servicenode membership is explicitly provided through a new internal
LNet API rather than inferred from interface topology. The policy
contributes visibility groups through the generic discovery visibility
framework and participates in normal visibility composition.

The module parameter alone puts the policy in force. A count of the
registered servicenodes must not control it. Discovery operates as
soon as LNet starts, but a servicenode registers only when a target
mounts. If the count controlled the policy, the node would send all
of its NIDs between these two times, and a peer would merge them into
one multi-rail peer. No later group corrects this.

A servicenode group contains only the NIDs of a target that is
already mounted, and the policy refuses the full view to all of the
local NIDs. A NID that no group contains would thus match no view and
would also get no full view. The node would drop all discovery GETs
to that NID, and no peer could find it. A target that registers on
that NID could not mount. The enumerate pass therefore makes a group
of one NID for each live NI that no other group contains. Each NI
stays discoverable, and the node keeps the groups separate.

This patch introduces only the LNet policy implementation and its
internal interfaces. Subsequent patches will populate servicenode
membership from Lustre.
