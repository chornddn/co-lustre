LU-12669 ptlrpc: fetch target statfs with the first ping

A client only fetches the statfs data of an OST, or of an MDT other
than MDT0000, when something asks for it, such as "lfs df", so until
then the client does not know that the target is on flash
(OS_STATFS_NONROT), e.g. to prefer a flash mirror of an FLR file for
reads (lov_init_composite()).

Any request from the client serves as a ping, so if the OSC or MDC
import of a client has no statfs data yet, send OST_STATFS or
MDS_STATFS instead of OBD_PING and cache the reply in the OSC or MDC
as obd_statfs() does.  Do this even if the import is idle by then,
since an unused import goes idle before its first ping.  Like a ping
it is neither resent nor delayed, and it is tried once per connection,
so a target that refuses it, e.g. to a client banned by nodemap, does
not keep the import from going idle.

Also cache the reply to the asynchronous statfs that LMV sends when an
MDC connects (mdc_statfs_interpret()), so that every MDC has the
statfs data of its MDT from the start.

Add sanity test_812e to check that each OSC and MDC fetches the
statfs data of its target after a remount.
