LU-20551 tests: delete persistent send_sepol in 21c

test_21c cleans up by setting sptlrpc.send_sepol=0 via
"lctl set_param -P". That does not undo the test -- it leaves a
persistent entry in the MGS config log whose value happens to
be 0. Before the test there is no such entry at all.

Clients replay the config log on every mount, so a later test
that sets sptlrpc.send_sepol locally loses that value on its
next mount, and sptlrpc_sepol_get() returns NULL without ever
invoking l_getsepol. Such a test then exercises nothing while
still appearing to pass.

Deleting the entry alone is not enough: "set_param -P -d" stops
later mounts from replaying it, but does not revert the value
on nodes that already applied it. Keep the restore and delete
the entry afterwards.
