--- Commit Message ---
LU-20886 o2iblnd: use the FastReg key for immediate payload

FastReg can combine noncontiguous payload pages into one RDMA
fragment. The immediate-send path used the local DMA key for that
fragment, bypassing its registered mapping and reading physically
adjacent memory after the first page.

Any PUT or REPLY of up to 3976 bytes whose pages are not physically
contiguous is affected. Buffered writes reach it on 64K-page clients,
where short I/O is unavailable, when a small write that crosses a
page boundary is flushed synchronously, for example under -EDQUOT.
The OST then reports BAD WRITE CHECKSUM for that extent.

Use the fragment registration key for payload SGEs and retain the
local DMA key for the message header. Detect FastReg gaps from DMA
addresses, allowing adjacent fragments that meet inside a page as
ib_sg_to_pages() does: splitting a contiguous payload in the middle
of a page must not require optional FastReg GAPS support. FMR maps
whole pages per fragment, so it keeps treating such a split as a gap.

Add short write selftests that cross a page boundary on the
sending node in each direction.
