--- Commit Message ---
LU-21148 socklnd: Validate HELLO NID against TCP addresses

SockLND identifies remote peers using the NID advertised in the
HELLO message without verifying that it matches the underlying
TCP connection. Outgoing connections may also select a source
IP address different from the configured NI address.

Introduce a module-wide strict_mode parameter with three settings:

- off: preserve existing connection behavior (default).
- warn: log and count address mismatches without changing
  connection behavior.
- enforce: bind outgoing connections to the NI address and
  reject connections with inconsistent HELLO NIDs or local
  TCP addresses.

Validate the advertised NID's network and address before peer
lookup or modification, preventing inconsistent HELLO messages
from affecting established peer connections.

Handle explicit source-address binding failures without
unnecessary reserved-port retries.

Add sanity-lnet tests 631-636 covering policy configuration,
address binding, HELLO validation, and peer incarnation handling.

Test-Parameters: trivial testlist=sanity-lnet
