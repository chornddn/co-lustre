--- Commit Message ---
LU-20606 llapi: limit a scan's rate

Add lsop_max_rate to struct llapi_scan_open_param: the most objects a
stream examines per second.  0 is no limit.  It takes the place of
lsop_padding, so the struct does not grow, and a library older than
this refuses a non-zero value as it refused a set padding.

Objects are paced one interval apart under a lock shared by a walk's
threads.  A stream that falls behind does not catch up in a burst; a
lag of up to 1 ms is kept, since a sleeper wakes a little late.  A
device stream counts an object when it reads its inode or dnode,
before lsop_filter, and one it skips as unreadable too, but not the
objects an earlier read already sent.  A walk counts directory
entries.  The limit is per stream: shards each have their own.

llapi_scan_device_test test6 and llapi_scan_test test6 check that a
paced stream takes at least the paced time and still sends every
object.
