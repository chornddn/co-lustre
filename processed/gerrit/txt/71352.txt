LU-21306 lmv: keep encrypted op_name for the caller to free

In an encrypted directory, ll_prep_md_op_data() puts the kmalloc'd
encoded name from ll_setup_filename() into op_name and sets
MF_OPNAME_KMALLOCED, so ll_finish_md_op_data() can free it.
lmv_intent_lookup() for MF_GETATTR_BY_FID, and lmv_getattr_name()
when it retries by FID after an OBD_MD_MDS reply, set op_name to
NULL and never put it back, so the name leaked.  The first path is
taken by ll_inode_revalidate(), so each stat() RPC of a file in an
encrypted directory leaked the encoded name.  The second is taken by
IOC_MDC_GETFILESTRIPE and IOC_MDC_LOOKUP on a remote entry.

Save op_name and op_namelen at the start of both functions and
restore them on every return.  Also restore the name when
lmv_intent_lookup() retries a getattr by FID, which would otherwise
assert that op_name is set.

The name is allocated with kmalloc(), so only kmemleak shows the
leak and the Lustre memory leak check does not; there is no test.
