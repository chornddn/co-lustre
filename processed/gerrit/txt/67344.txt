LU-20066 osc: fix NULL deref in osc_cache_shrink_scan on import teardown

Two bugs allow the OSC slab shrinker to crash when lctl cleanup/detach
tears down client OBDs concurrently:

1. cli_name() dereferences cli->cl_import->imp_obd->obd_name, but
   cl_import is set to NULL by obd_cleanup_client_import() during
   osc_precleanup_common().  Since cli_name() is only used for logging
   and imp_obd is always the same obd_device that owns the client_obd,
   reach obd_name directly via container_of() instead.

2. The shrink-list removal (list_del) happened in osc_cleanup_common(),
   after osc_precleanup_common() had already nulled cl_import.  During
   that window the shrinker could grab a cli from osc_shrink_list whose
   cl_import was already NULL.  Move list_del_init() to
   osc_precleanup_common(), before obd_cleanup_client_import(), so the
   OSC is off the shrink list before cl_import is torn down.

Crash reproduced by running sanity test_172 (lctl cleanup/detach of all
client OBDs) concurrently with tests that trigger drop_caches=2:

  pc : osc_cache_shrink_scan+0x178/0x3f0 [osc]
  drop_caches_sysctl_handler -> shrink_slab -> osc_cache_shrink_scan
    -> osc_lru_shrink -> cli_name -> cli->cl_import->imp_obd  (NULL)

AArch64 crash at virtual address 0xb8 (imp_obd offset in obd_import).
