LU-21177 llapi: don't unlink volatile file opened on Lustre

create_volatile(), behind llapi_create_volatile_idx() and the other
volatile helpers, unlinks the volatile name after the open, in case
the file system is not Lustre and created a regular file by that
name. create_restore_volatile() does the same for the HSM copytool
restore. On Lustre the name does not exist, so the unlink is an
RPC that fails with -ENOENT. Before sending it, mdc_unlink()
cancels the client's UPDATE lock on the directory by early lock
cancel, and the cancel walks all cached children of the directory
in ll_prune_negative_children(). For volatile files in
.lustre/fid, as movers and policy engines working by FID create
them, that is one dentry per FID looked up, on every create.

Skip the unlink when the open succeeded on Lustre, which
LL_IOC_GET_MDTIDX on the new file tells.

Add sanity test_185b to check that the directory's pages stay
cached across a volatile create in it through liblustreapi.
