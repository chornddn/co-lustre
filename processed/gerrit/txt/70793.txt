LU-20076 tests: wait for imports without rpc.sh

After a target starts, conf-sanity and fail() wait for the clients'
imports to reconnect through rpc.sh, as do the OSC, MGC and OSP
import waits on the servers. Each rpc.sh call sources the test
framework and its config on the remote node, only to run a loop of
"lctl get_param" checks. CI's conf-sanity logs show about 1,455
rpc.sh calls per run at about 2.4 s each, most of them these waits
and set_hostid.

Send each wait as one remote script instead. It checks the same
imports for the same states with the same timeout, skips a node
with no client mounted as before, and prints the same messages and
debug log marks. With VERBOSE, the debug log mark for the command
is made by the same remote command, not a second one. set_hostid
is a plain remote command too.

Measured on a 2-node cluster (one server with 4 MDTs and 4 OSTs,
one client, about 0.19 s per ssh), VERBOSE, mean of 10 calls:

                            cmds      master   patched
  client wait, 2 nodes     2 -> 1     0.53 s    0.21 s
  MDT OSC wait, 4 MDTs    16 -> 12    3.67 s    2.28 s
  MGC wait                 4 -> 3     0.90 s    0.56 s
  set_hostid               2 -> 1     0.51 s    0.20 s

The remaining commands of the OSC and MGC waits read at_min. rpc.sh
costs only 0.13 s to start there, since that cluster's config names
the MGS NID. conf-sanity 0 1 2 3 5a 17 41a 50a 140 162 pass as on
master, with rpc.sh calls down from 99 to 18, which load and unload
modules.

In CI, where an rpc.sh call costs about 2.3 s against 0.35 s for a
plain remote command, each wait saves about 2 s. Counting the 2,000
client import waits CI logs per conf-sanity run as about 1,000
calls on 2 clients each, plus 260 server import waits and 115
set_hostid calls, that is about 45 minutes of a 9.4 hour run.
