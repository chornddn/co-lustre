LU-16692 osp: roll over FID seq when too few objects left

When a layout needs more objects from one OST than are left at the
end of the OSP's current FID sequence, e.g. "lfs setstripe -o"
listing an OST many times, or a wide overstriped or EC layout from
a given starting OST, the reservation in osp_precreate_reserve()
fails with -ENOSPC and LOD releases all of the objects it reserved.
The precreate thread only switches to a new sequence once all
precreated objects are used, so if nothing else uses that OST every
such create fails with -ENOSPC forever.

Mark the OSP when a reservation fails at the end of the sequence,
and once the last reservation is released abandon the remaining
objects so the precreate thread rolls over to a new sequence.  The
thread asks the OST to destroy the abandoned objects first, and the
OST commits this before replying, since orphan cleanup at connect
time only handles the current sequence.  Have LOD retry the
allocation once after -ENOSPC or -EFBIG, so the create normally
succeeds in the new sequence instead of failing, but not if an OST
already timed out, so a create does not wait twice for that OST.
Retry at most once, together with the existing retry without the
SEL @reserve space, and restore the component's pattern, stripe
count and EC split first, since the allocators change them even
when they fail.

If the OSP is still switching to a new sequence when its wait for
precreated objects times out, e.g. because the OST is slow to store
the new sequence after an MDT failover, return -EINPROGRESS instead
of -ETIMEDOUT while the OST is connected, for up to 4 * obd_timeout
after the switch started.  LOD returns it for a layout that needs
that OST, so the client resends the create instead of failing it.

The OST does not report destroying objects at the end of a full
sequence as a new connection on the console.

Also clear the stripe pointers after putting them in the LOD retry
path, so a failed retry does not put them a second time.

Make force_new_seq_all() in a subtest widen the OST sequences
instead of using up the precreated objects of every OSP, and only
force a new sequence on an OSP that still uses IDIF or already
precreated up to the old width, since it does not learn the new
width until it precreates again.

This makes sanity/27Cd and sanity-pfl/0b,0c,1c,16b about 640s
faster in total over one patchset's review sessions, saving about
340 hours of test time per month.

Add sanity/27Cl to verify that files are created across a sequence
rollover that leaves too few objects for the next file, and
recovery-small/159a,b to do so with an OSP reconnect or an MDT
failover while the end of the sequence is being destroyed, and
recovery-small/159c with a rollover that takes longer than
obd_timeout.
