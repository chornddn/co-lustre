LU-21043 tests: wait for precreated objects in sanity/51d

sanity test_51d raised osp.*.create_count on all MDTs, then slept a
fixed 8 seconds before each pass of test_51d_sub.  With many MDTs
(12 MDTs, 8 OSTs) every OST had to precreate create_count objects for
each MDT, and after 8 seconds many OSPs still had only the initial
objects.  LOD round-robin would skip the OSTs whose pool was empty,
and the test would fail with too few objects on some OSTs and too
many first stripes on the next OST.

Set create_count only on the MDTs that hold the stripes of $tdir,
since all of the files are created there, and restore it with
stack_trap.  Add sub_51d_wait_precreate() to replace the sleep.  It
waits until each OSP of those MDTs, highest index first, has enough
objects precreated for one pass (prealloc_last_id - prealloc_next_id
+ 1), and fails the test if precreation does not catch up.  It waits
in 10s slices and sets create_count again between them if the OSP
lowered it for a slow OST.

Test-Parameters: trivial testlist=sanity env=ONLY=51d,ONLY_REPEAT=20 mdscount=2 mdtcount=12 ostcount=8
