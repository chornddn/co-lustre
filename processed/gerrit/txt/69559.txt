LU-20923 mdt: check remote object is on an MDT before locking

A client supplies the FID of the object an operation acts on, and
the MDT instantiates an object for it.  A FID that passes
fid_is_sane() but maps through the FLD to an OST, or to an unknown
sequence, produces an OSP object with no metadata operations.  The
OSP marks it LOHA_REMOTE, so mdt_object_remote() is true and the MDT
locks it as a remote MDT object: mdt_remote_object_lock_try() calls
dt_object_lock() on the OSP child, which has a NULL do_object_lock
and crashes, or mdd_object_lock() casts it with lu2md() and trips
the device-type assertion.  The request is resent after recovery, so
the MDS crashes again on each mount.

  ASSERTION( o->do_ops->do_object_lock ) failed:
  Call trace:
   lod_object_lock [lod]
   mdd_object_lock [mdd]
   mdt_remote_object_lock_try [mdt]
   mdt_object_lock_internal [mdt]
   mdt_parent_lock [mdt]
   mdt_reint_open [mdt]
   mdt_reint_rec [mdt]
   mdt_reint_internal [mdt]
   mdt_intent_open [mdt]
   mdt_intent_policy [mdt]
   tgt_request_handle [ptlrpc]
   ptlrpc_main [ptlrpc]

Check in mdt_remote_object_lock_try() that the object's FID maps to
an MDT, and return -EINVAL with the MDT name and FID otherwise,
rather than locking an object that is not a remote MDT object.
