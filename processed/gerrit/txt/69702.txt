LU-20708 llite: rebuild faulting EC pages from parity

A page fault on an EC file with a data stripe on an unavailable OST,
e.g. during an OSS failover, would wait for the OST in the fault's
lock enqueue, while read() of the same page is rebuilt from parity at
once.  So mmap readers of the file, such as git or executables, would
hang.  A read fault on an FLR file whose OST is deactivated would get
-EIO from osc_io_iter_init(), so SIGBUS, though read() of the file
moves to another mirror.

Do the lock enqueues of read faults without delay, and return -EAGAIN
for a CIT_FAULT on an unhealthy OSC as for CIT_READ, so that faults
fail over to another mirror, and for EC switch to CIT_EC_RD after the
mirror rounds, as reads do.  The fault then drops the mmap lock, as
filemap_fault() does for IO, and rebuilds the page into the page
cache with a CIT_EC_RD read into a discard iterator, never switched
to hybrid DIO, where the EC placeholder lock keeps the page Uptodate.
Unless the mapping is read randomly, the rest of the aligned 1MiB
around the page is read after it, and a failure there leaves those
pages to their own faults.  The retried fault takes the page from the
page cache, also with fast_read off.

The fault may be in the user copy of a read() or write() of another
file, which holds lli_trunc_sem of that file and may be recovering EC
pages.  So the rebuild takes lli_trunc_sem without waiting behind a
queued truncate, as a fault does, and does not wait for an Uptodate
page that another EC read is copying out.  A fault that cannot be
retried, one under a read() or write() of the same file, one through
a file descriptor with a mirror or stripe I/O scope, and one whose
page cannot be rebuilt wait for the OST as before.  A fault
from user mode interrupted by a signal in the mirror rounds faults
again once the signal is handled.  The read RPC of a fault is not
sent without delay, since a fault cannot be restarted once its read
fails, so a fault on a page whose extent lock is still cached, on an
OST whose import still looks healthy, also waits for the OST.

Also return VM_FAULT_OOM from __ll_fault() when cl_env_get() fails,
not the errno, and stop reading the VMA in the debug message after a
fault, as it may be gone once the mmap lock was dropped.

Add sanity-ec test_41o and test_49g, which stop or deactivate the OST
of a data stripe, and sanity-flr test_33d, which deactivates each
mirror's OST in turn, each reading the file through mmap.
