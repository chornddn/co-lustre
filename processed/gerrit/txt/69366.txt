LU-20076 tests: keep Lustre version cache on test startup

lustre_build_version() saves each facet's version in a global
<facet>_VERSION variable for later calls, but get_lustre_env() and
other callers only call it as $(lustre_version_code <facet>), so the
variable is set in a subshell and lost.  Every version check goes to
the node again, and lustre_build_version_node() may make three
separate remote calls if the modules are not loaded.
lustre_os_release() also checks /etc/os-release and then reads it in
a second remote command.

Fill the version cache in get_lustre_env() in the calling shell, try
the lctl version fallbacks in one remote command, and read
/etc/os-release with one remote command.

Average of 3 runs on 3 nodes (MDS, OSS, client) over ssh:

                                  before  after
  init_test_env()                 1.79s   1.19s   (-33%)
  lustre_version_code() per call  0.19s   0.001s
