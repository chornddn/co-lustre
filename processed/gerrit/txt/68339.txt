--- Commit Message ---
LU-12669 ec: fix reader deadlock, stale cache, EAGAIN leak

Add a CP_EC_RECOVERY flag to cl_page::cp_flags to serialize concurrent
CIT_EC_RD readers on the same page.  A second reader finding the flag
set drops the vmpage lock, sleeps via schedule_timeout_interruptible()
up to EC_RECOVERY_RETRY_MAX times, then bails with -EAGAIN/-EINTR,
which triggers vvp_io_ec_rd_end() to release all held locks and clear
the flag, with -EAGAIN ll_file_io_generic() restarts the IO, and in
the -EINTR case the reader returns the error to userspace as the IO
has been interrupted.  This avoids both the cp_owner assert crash and
the AB-BA deadlock (a reader holding locked vmpages cannot block on a
flag the recovery owner clears only after its generic_file_read_iter
faults in a page the spinner holds).

cp_flags is an unsigned long with set_bit()/clear_bit()/test_bit() so
the clear after cl_page_disown() does not race with readahead
modifying the cp_defer_uptodate bitfield word.

Clear PageUptodate on reconstructed pages, forcing the next read
through ll_readpage() for a fresh DLM lock.

Convert -EAGAIN from generic_file_read_iter() in vvp_io_ec_rd_end()
into an IO restart, gated by !ci_iocb_nowait so RWF_NOWAIT reads still
receive -EAGAIN instead of looping up to RETRY_ATTEMPTS times.

Improve concurrent-reader test diagnostics in sanity-ec.sh.
