--- Commit Message ---
LU-21002 ldiskfs: unlock group before trim flag error path

In the rhel10.0 version of ext4-introduce-EXT4_BG_TRIMMED-to-
optimize-fstrim.patch, ext4_try_to_trim_range() re-takes the group
lock after starting the journal handle. If blocks were freed in the
group meanwhile, it jumps to out_journal still holding the lock,
then takes it again at out_return. The fstrim thread deadlocks on
itself, and any thread freeing blocks in that group soft-locks
behind it.

Drop the group lock before jumping to out_journal, as the other
kernel variants of this patch already do.
