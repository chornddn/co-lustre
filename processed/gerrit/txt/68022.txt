LU-20587 lnet: fix NULL pointer deref in lnet_peer_ni_show_dump

Check nla_nest_start()/genlmsg_put() for NULL and nla_put_*() return
codes in lnet_peer_ni_show_dump(); on skb-full, roll back the current
peer, rewind idx, and retry on a fresh skb instead of crashing or
aborting/corrupting the dump. Apply the same rollback to the nested
lnet_udsp_info_send()/lnet_nl_put_latency() calls, which had the same
unchecked-pointer/unchecked-put bug. Track whether the peer key table
was already sent via lgpl_key_sent so a skb-full retry on the first
peer can't re-emit it or loop forever, and sample skb_len_before
before the key table is sent so a key-table-only skb still counts as
progress when the very first peer doesn't fit.

Hoist lp/hdr to function scope and do the decref/genlmsg_cancel/idx--
rollback once at msg_full instead of duplicating it in every check
and at the UDSP call site. Each nla_nest_start()/nla_put_*() call is
checked inline with plain kernel-style "if (nla_put_x() || ...) goto
msg_full;" groupings rather than through helper macros, since those
macros implicitly relied on msg_full being in scope at every call
site, which coding-style.rst flags for control-flow macros.

lnet_udsp_info_send() is also called from lnet_net_show_dump(); pass
its rc through instead of forcing -ENOMEM there, and cancel the open
genlmsg on its other error paths too so a failure never leaves a
half-built object in the skb, including the cpts-overflow -E2BIG
returns and the lnet_nl_put_latency() failure path.

Since the peer dump can now span multiple ->dumpit() calls with
ln_api_mutex dropped and retaken in between, a peer present when the
key list was built can be deleted before we get back to it (e.g. by
discovery or a concurrent "lnetctl peer del"). Skip such a peer
instead of failing the whole listing with -ENOENT after part of it
has already been sent - but only when the list was built by walking
the whole peer table (tracked via lgpl_all_peers); an explicit
"lnetctl peer show --nid X" for a peer that never existed must still
report -ENOENT. Track whether LNET_PEER_NI_ATTR_HDR was sent via a new
lgpl_hdr_sent flag instead of comparing idx == 1, since the first list
entry can now be skipped by the race above.
