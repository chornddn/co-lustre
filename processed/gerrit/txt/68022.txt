LU-20587 lnet: fix NULL deref in lnet_peer_ni_show_dump

"lnetctl peer show" of many peers, or of peers with many NIs, at a
higher verbosity crashes the node:

  BUG: kernel NULL pointer dereference, address: 0000000000000000
  RIP: lnet_peer_ni_show_dump+0xbb2/0x1010 [lnet]

lnet_peer_ni_show_dump() has to fit the whole dump into one skb and
ignores the results of nla_nest_start() and nla_put_*().  Once the
skb is full, nla_nest_start() returns NULL and nla_nest_end()
dereferences it.

Check every attribute of a peer entry.  When the skb is full, cancel
the partial entry and return the skb length, so that the dump goes
on with that peer in a new skb.  Fail with -EMSGSIZE only if a peer
does not fit into an empty skb.  Keep in the dump state whether the
key table and the "peer" header were sent instead of deriving it from
the peer index.  Skip a peer deleted since lnet_peer_ni_show_start()
built the list, unless the caller asked for that peer.  Set
cb->min_dump_alloc in lnet_peer_ni_show_start() so that an skb holds
the key table and the peer with the most NIs.

lnet_udsp_info_send() and lnet_nl_put_latency() now report a full
skb with -EMSGSIZE.  lnet_net_show_dump() cannot resume a partial
dump: check its nla_nest_start() calls as well, cancel the open
message and return -ENOBUFS, because newer kernels take -EMSGSIZE as
"call the dump again", which would repeat the same nets forever.

Add sanity-lnet test_630.  It dumps 300 peers with 4 NIDs each (1500
with SLOW=yes) with "lnetctl peer show -v 4" and checks that every
peer is listed once, under a single "peer" key.
