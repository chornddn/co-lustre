LU-20664 rustreapi: NUL-terminate the pool name

OpenOptions::get_stripe_param() pointed lsp_pool at the bytes of a
Rust String, which carries no trailing NUL.  liblustreapi reads that
field as a C string -- lov_pool_is_ignored(), the strlen() in
llapi_stripe_param_verify(), and the "%s" into lum_pool_name -- so
each read runs past the end of the String's allocation until it finds
a zero byte.  A valid pool then fails with EINVAL or ENOENT, trips
the LOV_MAXPOOLNAME check, or faults.

The memory itself is fine: self.pool outlives the call.  Only the
terminator is missing, so copy into a CString.  Return it rather than
dropping it at the end of get_stripe_param(), since the caller uses
param after the call returns; both callers hold it in a named binding
for the duration.

An interior NUL cannot be a pool name, so report it instead of
silently truncating.

Tested with cargo test -p rustreapi --lib stripe_param_pool.
