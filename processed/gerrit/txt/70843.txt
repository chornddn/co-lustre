--- Commit Message ---
DRAFT LU-21180 lod: add kunit test for remote MDT allocation

lod_mdt_alloc_rr() and lod_mdt_alloc_qos() pick remote MDTs for a
striped directory by calling dt_fid_alloc()/dt_locate_at() directly,
with no stubbable wrapper, so they had no kunit coverage: every other
LOD allocator mock stubs that lookup instead of resolving it.

Add lod_mdt_alloc_test, covering round-robin and QoS-weighted
selection, exhausted/degraded/too-few-MDTs paths, and OSS/MDS-spread
avoidance, by giving mock_tgt real object location/allocation
support: mock_tgt_site_init() builds a tiny but real lu_site/
lu_device/lu_object stack so dt_fid_alloc()+dt_locate_at() on a
mock_tgt resolve to a real (if featureless) dt_object, instead of
needing a real OSD/OSP underneath.

Fix two mock_tgt bugs this test exposed, both pre-existing in the
object location/allocation support added for lod_tgt_test and
lod_init_obj_test: every mock_tgt's dt_device needs a non-NULL
ld_type, because lu_object_put() dereferences it unconditionally;
and mock_tgt_top_object_free() must call lu_object_fini() to drop
the top object's reference on the shared fake top device, or that
device's ld_ref never returns to zero. Add mock_tgt_site_drain(),
also called from mock_tgt_site_fini(), to flush the site's delayed-
free list: dt_locate_at() hands out FID_SEQ_NORMAL-range objects,
whose last put lands them there rather than on the LRU that
lu_site_purge() reclaims, so a test case must drain it before
reusing or re-initializing the mock_tgt structs those objects are
layered on.

Export lod_mdt_alloc_rr() and lod_mdt_alloc_qos() for the test
module to call directly.
