LU-11962 flr: handle FLR files with a single mirror

lov_init_composite() refuses an FLR layout (RDONLY, WRITE_PENDING or
SYNC_PENDING) with a single mirror, so I/O to such a file fails with
-EINVAL.  LOD also forces the FLR state of a single-mirror file to
NONE when it parses or writes the layout.  Also, a WRITE_PENDING file
with nothing stale cannot be made RDONLY again: "lfs mirror resync"
does nothing, and lod_declare_update_write_pending() returns -EALREADY
for the resync.

This is for forward compatibility: accept a single mirror in an FLR
layout on the client and in LOD, and let the resync of a WRITE_PENDING
file with nothing stale make it RDONLY with strict SOM.  Nothing
creates such a layout yet, since older clients cannot use it: a new
file with one mirror and a mirror split down to one mirror still get
state NONE.  A later change can make a non-mirrored file RDONLY for
strict SOM once all clients accept it.

Add OBD_FAIL_FLR_SPLIT_KEEP_STATE so that "lfs mirror split" can leave
an FLR file with a single mirror, and sanity-flr test_49b to read,
write, resync and extend such a file.
