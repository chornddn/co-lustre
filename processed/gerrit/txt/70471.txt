LU-20908 lfs: add lfs drain to empty OSTs

Emptying an OST with lfs migrate rewrites every object of each file
that has one there, one file at a time, and leaves finding the files,
closing the OST and taking it out of service to the administrator.

Add "lfs drain --ost OST_LIST MOUNT".  It checks that the other OSTs
have room for what is on the OSTs, closes them to new objects with
no_create, finds the files that have objects there, and moves only
those objects with llapi_ost_object_migrate(), from a pool of worker
threads, to OSTs the MDS chooses.  The OSTs, which must be on this
OSS, are read with llapi_scan_device(), by as many threads as move
files, up to 32, which names the file owning
each object from its parent FID; the MDT sends that for every new
object, so the namespace is not walked.  Objects that name no file
and were never handed out by the MDT are precreated, and left.  Used
objects that name no file, of files created before the MDT sent the
parent FID and never written, make the drain fail with a hint to run
layout LFSCK, which names them.  --files-from or -0 takes the files
from a list instead, which is how a client drains an OST of another
OSS.

A file that is open for writing or changes during the copy is set
aside and tried again once the other files have been, and not sooner
than --retry-delay seconds.  One still open for writing after
--max-retries is moved under a group lock, unless --no-block.
--bandwidth limits the copy over all threads, --io-size and
--io-threads set how each object is copied, --json writes one result
per file, and --stats and --stats-interval print the progress in
YAML, with the keys of lfs migrate --stats, how much space the OSTs
have freed and how fast, and the drain's counts.

With --deactivate or --remove, once a second read of the OSTs finds
no object left in a file and no used object that names none, they
are deactivated on the MDSs, and removed from the configuration with
lctl del_ost, on the MGS.  When the MGS is elsewhere they are run over
ssh on --mgs-node or on the MGS NIDs of the mount, and printed for the
MGS if none of those works.  --remove asks first.
--status shows the state of the OSTs, --reactivate returns them to
service, and --dry-run shows only the space check.

--to-ost N puts the objects of the one OST being drained on OST N,
for a 1:1 replacement; several pairs are replaced by running one
drain for each.  An object whose file already has data over the same
extent on N goes where the MDS chooses, and is counted.

Add sanity-pfl tests 30a-30l: plain, PFL, overstriped, sparse,
hard-linked and never-written files found by the drain itself, FLR
files, --dry-run, --files-from and -0, --deactivate, --reactivate and
--remove, files held open for writing, deleted files, --bandwidth and
the YAML stats, --to-ost, objects that name no file, the MGS
commands over ssh or printed, and a sparse object copied in pieces by
several threads.
