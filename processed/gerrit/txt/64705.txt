LU-19412 libcfs: DNS multi-address name resolution

Expand hostnames into all supported addresses when converting NIDs
for mount.lustre and mkfs.lustre, instead of using only the first
resolved address. Group addresses from each hostname with commas
while preserving separators between explicitly specified NIDs.

Add libcfs_strnids() and resolver callbacks with stored and total
address counts so callers can resize their buffers. Support mixed
IPv4 and IPv6 results for tcp and efa, retaining each address size.
Reject failed lookups, loopback addresses and IPv6 link-local
addresses.

Grow conversion buffers to preserve expanded NID lists and filesystem
suffixes.

## Summary

**Fix Applied:**

Changed the format specifier in `lustre/utils/mount_utils.c` at line 1014 from `%u` to `%zu`.

**Rationale:**

The compile error occurred because:

1. **Type mismatch**: The variable `converted_size` is declared as `size_t` (line 1007), but the `fprintf` statement was using `%u` format specifier which expects an `unsigned int`.

2. **Platform-dependent issue**: On 64-bit systems, `size_t` is typically `unsigned long` (8 bytes), while `unsigned int` is 4 bytes. This mismatch causes the compiler to emit a format warning, which becomes an error when `-Werror` (treat warnings as errors) is enabled.

3. **Correct format specifier**: The C standard defines `%zu` as the proper format specifier for `size_t` types, ensuring portability across different architectures.

The fix changes `%u` to `%zu` to match the `size_t` type of the `converted_size` variable, resolving the format mismatch error.
