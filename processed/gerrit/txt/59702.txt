LU-16960 build: add kernel version to RHEL kmod Release

On RHEL, kmod-lustre* packages built from one Lustre version for
different kernels had the same version-release, e.g.
kmod-lustre-2.17.62-1.el8, so the build for a newly installed
kernel could not be installed before rebooting into it: "rpm -U"
replaced the build for the running kernel, and "rpm -i" reported
it as already installed.

Add the kernel version to the RHEL kmod Release, as the SUSE KMP
Version already has it, e.g.
kmod-lustre-2.17.62-1_k4.18.0_553.187.1.el8_10.x86_64.rpm, without
repeating the arch or dist.  A newer kernel sorts as newer, and
the userspace package names and versions are unchanged.  Pin
kmod-lustre-osd-* and kmod-lustre-tests to the kmod-lustre built
for the same kernel.

Don't mark the packages installonlypkg(kernel-module): dnf never
removes an older install-only package, so installing a newer
Lustre for the same kernel would fail with file conflicts.  Builds
for two kernels are installed together with "rpm -i".

Will including the kernel version into the package name mean that "x86_64" and "el9_6" is included into the package filename twice?  Currently, "rpm -qi" shows:

 Name        : kmod-lustre-client
 Version     : 2.16.1
 Release     : 1.el9
 Architecture: x86_64

and the "rpm -q kmod-lustre-client" output is:

 kmod-lustre-client-2.16.1-1.el9.x86_64

so if we now have "Release: 5.5.14.0_570.19.1.el9_6.x86_64" instead of "Release: 1.el9" then the full package version would be:

 kmod-lustre-client-2.16.1-5.5.14.0_570.19.1.el9_6.x86_64.x86_64

which is going to be ugly...  I think we had this style of versioning in the past, and it was removed because of this.

http://review.whamcloud.com/19954 ("LU-7643 build: Remove Linux version string from RPM release field")

So I think that the removal of the duplicate "x86_64" from the version would be a minimum.
