LU-20238 ec: branch-free byte-indexed scalar base path

Replace the log+antilog gf_mul() form in the scalar *_base hot
paths with the canonical isa-l alloc-free, branch-free base
path: a byte-indexed per-coefficient region-multiply table.

  tbl[b] = c * b in GF(2^8), built once per coefficient
  gf_region_mul(tbl, x) = tbl[x]   (single load, inner loop)

Two motivations:

 1. Performance in the region hot loop. A precomputed 256-byte
    per-coefficient table replaces the per-byte multiply, so the
    cost is one load per byte once the table is amortised.

    Measured with ec_encode_data_base() at k=6/p=2, gcc -O2,
    single core pinned, min of 6, against this tree as it is
    actually built today (see below):

      region  | before    | after     | ratio
      --------+-----------+-----------+-------
      256 B   |  887 MB/s |  652 MB/s | 0.74x
      1 KiB   | 1001 MB/s | 1150 MB/s | 1.15x
      16 KiB  | 1002 MB/s | 1483 MB/s | 1.48x
      64 KiB  |  998 MB/s | 1503 MB/s | 1.51x

    gf_mul() itself is roughly level (1.83 -> 1.61 ns/mul) and
    matrix build (gf_gen_cauchy1_matrix + gf_invert_matrix) is
    unchanged at ~0.33 us, since those paths call gf_mul()
    scalar-wise and never amortise a region table.

    Note the 256-byte row: below GF_REGION_TBL_MIN_LEN the table
    is not paid off, which is why that threshold is 1 KiB and the
    affected routines keep a scalar fallback under it.

 2. Patent-clean. Byte-indexed table lookup (gf-nishida-16 /
    "FullByte"-style scalar GF multiply), structurally
    distinct from the PSHUFB + 4-bit nibble-table pattern in
    ISA-L's SIMD kernels that maps onto US 8,683,296 claim
    21. No PSHUFB, no nibble split, no 16-byte gftbl.

The tree previously carried an unconditional file-scope
"#define GF_LARGE_TABLES" in ec_base.c, so both ec.ko and
libec.a compiled the 64 KiB gf_mul_table_base direct-lookup
table and the small-table branch was dead code. Removing that
define moves both builds onto the 1.5 KiB log/antilog form:
ec_base.o .rodata drops 65792 -> 1536 bytes, while .text grows
2217 -> 3591 for the short-region fallbacks.

Changes:
  - ec_base.c: canonical alloc-free stack byte-table region
    multiply + branch-free gf_mul() in gf_vect_dot_prod_base,
    gf_vect_mad_base, ec_encode_data_base,
    ec_encode_data_update_base, gf_vect_mul_base; rename
    gf_vect_mul_init -> gf_vect_mul_init_base.
  - ec_base.c: GF_REGION_TBL_MIN_LEN (1 KiB) short-region
    fallback to the scalar gf_mul() path in each of the five
    routines above, for regions too short to amortise the table.
  - ec_base.c: drop the unconditional "#define GF_LARGE_TABLES"
    and "#define __WORDSIZE 64"; select the 64-bit little-endian
    gf_vect_mul_init_base() path with BITS_PER_LONG for kernel
    builds and __WORDSIZE for userspace, since __WORDSIZE comes
    from glibc and is undefined under __KERNEL__. Drop the now
    unused <linux/limits.h> include.
  - ec_base.c: gf_region_mul() static inline, taking unsigned
    char so a signed index cannot subscript backwards.
  - ec_base.h: replace the small-table block with canonical
    uint16_t gflog_base (511 sentinel) + doubled gff_base.
  - ec_base_aliases.c: add the gf_vect_mul_init() wrapper.
  - gf_vect_mul.h: declare gf_vect_mul_init_base().
  - ec_base.h, ec_base.c: delete the GF_LARGE_TABLES branch
    outright. With the file-scope define and the inert Makefile
    flag both gone nothing could set it, leaving 4394 lines and
    the 66 KB gf_mul_table_base/gf_inv_table_base pair, plus the
    matching arms of gf_mul() and gf_inv(), unreachable in both
    ec.ko and libec.a.
  - erasure_code.h: drop the stale note that defining
    GF_LARGE_TABLES speeds up the base multiply.
  - ec/Makefile: drop ec_base_o_CPPFLAGS. That is automake
    spelling in a kbuild Makefile and was never read, so neither
    the -DGF_LARGE_TABLES nor the -I . in it ever reached the
    compiler.

ec_base.c uses tab indentation; the vendored GF hex data
tables in ec_base.h stay space-indented as before, which is
where checkpatch's remaining indent errors come from.
Deleting the GF_LARGE_TABLES block drops them from 76 to 59.

Shared by userspace libec.a and kernel ec.ko via the
utils/erasurecode/ec_base.c -> lustre/ec/ec_base.c symlink.
gf_vect_mul_init_base() is a new declaration in the installed
gf_vect_mul.h and a new libec.a symbol; no existing entry
point changes behaviour. ec.ko exports via ec_kmod.c, so the
canonical EXPORT_SYMBOL_GPL(*_base) block is omitted.

Validated on RHEL 10.1 (AVX2+GFNI): exhaustive gf_mul
(65536 pairs) + gf_inv + k=6/p=2 erasure round-trip KAT,
clean -Werror, and gfni_ec_test byte-identical parity on
both columns (the base path is the reference for the GFNI
intrinsic path).
