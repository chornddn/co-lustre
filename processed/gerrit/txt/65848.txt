LU-20238 ec: branch-free byte-indexed scalar base path

Replace the log+antilog gf_mul() form in the scalar *_base hot
paths with the canonical isa-l alloc-free, branch-free base
path: a byte-indexed per-coefficient region-multiply table.

  tbl[b] = c * b in GF(2^8), built once per coefficient
  GF_REGION_MUL(tbl, x) = tbl[x]   (single load, inner loop)

Three motivations:

 1. Performance. The old gf_mul() does 3 table lookups + 2
    conditional branches per byte. This change wins twice: the
    branch-free single-table gf_mul() (gff[log[a]+log[b]], 511
    sentinel + zeroed antilog tail, ~1.5 KB L1-resident) is ~2x
    stock and also speeds matrix build (gf_gen_rs / gf_invert);
    and in the region hot loop a precomputed 256-byte
    per-coefficient table (GF_REGION_MUL, one load per byte)
    replaces the per-byte multiply, ~5x faster than the gf_mul()
    path on rd07 across k=4..16 / m=2..4 and 4 KiB .. 1 MiB
    stripes.

    gf_mul() microbench (ns/mul, min of 6, -O2 -march=native):

      CPU                    | stock     | branch-free
      -----------------------+-----------+-------------
      Ryzen 7 5800X (Zen 3)  | 0.72      | 0.36  (~2.0x)
      i5-1340P (Raptor Lake) | 1.04-1.30 | 0.54  (~2.4x)

 2. Patent-clean. Byte-indexed table lookup (gf-nishida-16 /
    "FullByte"-style scalar GF multiply), structurally
    distinct from the PSHUFB + 4-bit nibble-table pattern in
    ISA-L's SIMD kernels that maps onto US 8,683,296 claim
    21. No PSHUFB, no nibble split, no 16-byte gftbl.

 3. Correctness. The shared uapi ec_base.h carried the old
    single-period gflog_base/gff_base tables, so the
    userspace build (already alloc-free, built without
    GF_LARGE_TABLES) evaluated gf_mul() against tables
    lacking the 511 sentinel and the doubled antilog period
    -- mathematically wrong, masked only by the kernel
    forcing GF_LARGE_TABLES.

Changes:
  - ec_base.c: canonical alloc-free stack byte-table region
    multiply + branch-free gf_mul() in gf_vect_dot_prod_base,
    gf_vect_mad_base, ec_encode_data_base,
    ec_encode_data_update_base, gf_vect_mul_base; rename
    gf_vect_mul_init -> gf_vect_mul_init_base.
  - ec_base.h: replace the small-table block with canonical
    uint16_t gflog_base (511 sentinel) + doubled gff_base;
    add the GF_REGION_MUL macro.
  - ec_base_aliases.c: add the gf_vect_mul_init() wrapper.
  - gf_vect_mul.h: declare gf_vect_mul_init_base().
  - ec/Makefile: drop -DGF_LARGE_TABLES (branch-free path).

Shared by userspace libec.a and kernel ec.ko via the
utils/erasurecode/ec_base.c -> lustre/ec/ec_base.c symlink.
No public-API change; ec.ko exports via ec_kmod.c, so the
canonical EXPORT_SYMBOL_GPL(*_base) block is omitted.
ec_base.c uses tab indentation (checkpatch-clean); the
vendored GF hex data tables in ec_base.h stay space-
indented as before.

Validated on rd07 (RHEL 10.1, AVX2+GFNI): exhaustive gf_mul
(65536 pairs) + gf_inv + k=6/p=2 erasure round-trip KAT,
clean -Werror, and gfni_ec_test byte-identical parity on
both columns (the base path is the reference for the GFNI
intrinsic path).
