LU-18502 ptlrpc: print enable_cap_mask as a YAML flow mapping

When the cap type is not "off", nodemap.*.enable_cap_mask prints
"type: ..." and "caps: ..." on two lines. With --yaml, "lctl
get_param" prints the first line on the line of the parameter name.
A YAML parser rejects this output. A block mapping cannot start on
the line of its key.

In nodemap_capabilities_seq_show(), print the type and the caps as
one YAML flow mapping on one line. The other multi-line nodemap
parameters also use the flow style. Put the caps in quotes. The caps
list uses commas, and a comma ends a plain value in a flow mapping.
Remove the newline that cfs_mask2str() adds at the end of the caps.

In sanity-sec test_25c, set a cap mask on the nodemap before the
YAML check, and check the exact value. A YAML parser accepts a
newline in a quoted value. The test checked only "off" before.

One gap in coverage: sanity-sec test_25c never makes a block-mapping value, so it passes with or without this fix.
