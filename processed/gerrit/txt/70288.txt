LU-10606 lod: store HSM attributes in a layout mirror

The HSM attributes of a file are kept in the "trusted.hsm" xattr,
apart from its layout, so FLR and PCC cannot see that a file has an
archive copy, nor that the copy is out of date.

Store them in a data-less foreign mirror of the layout instead, as
PCC-RO does, with type "posix", the HSM state flags and the archive ID
and version.  lod.*.hsm_layout selects where they are stored when they
change: 0 for "trusted.hsm" (the default until 2.19.53), 1 for the
layout, -1 for both.  A file without a layout keeps them in the xattr.
LOD reads the mirror first, then the xattr, returns both as
"trusted.hsm", also for a remote object, and lists them for a local
one, so the MDD, MDT, coordinator, changelogs, HSM release, restore
and migration, and tools that read the xattr are unchanged.  The
attributes move to the selected place the next time they change, and
are removed from the other one.

Only adding or removing the mirror changes the layout generation, as a
client takes a new generation after a failed restore for a restored
file.  Keep the HSM mirror of a file when its layout is replaced by a
swap, as the attributes do not move with the layout, also with
hsm_layout=0, and refuse to split it from the file.  It is not
resynced by "lfs mirror resync", and a write marks it stale but leaves
HS_DIRTY to be set at close with its changelog record.  PCC-RO adds a
mirror of its own and does not use the HSM one.

Describe the tunable in lod.hsm_layout(4).  Add sanity-hsm test_1g,
test_1h and test_1i for HSM in the layout, and sanity-pcc test_54 for
PCC-RO on an archived file.
