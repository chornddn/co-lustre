--- Commit Message ---
LU-17768 build: embed BTF in Lustre kernel modules

Out-of-tree modules lack .BTF sections because kbuild's
Makefile.modfinal skips BTF generation without
$(objtree)/vmlinux, which kernel-devel does not ship.

Add config/embed-btf.sh and run it from the modules make
target after kbuild.  pahole encodes a distilled base
(.BTF.base) so the module BTF relocates against the running
kernel at load time.

The base BTF must come from the kernel the modules are built
against, not the running kernel: take $(LINUX_OBJ)/vmlinux
when the build tree has one (custom-built kernels; the same
source kbuild itself uses), else /sys/kernel/btf/vmlinux only
when building against the running kernel.  Otherwise skip
embedding, since BTF encoded against a foreign base fails
btf_relocate() at load time, and with
CONFIG_MODULE_ALLOW_BTF_MISMATCH=n that makes the module
unloadable.  The earlier commit b5c451820443 ("LU-17768 build:
embed BTF in Lustre kernel modules") always used
/sys/kernel/btf/vmlinux, so modules built against a kernel
other than the running one would not load, and it was reverted.

Encoding is best effort: a module pahole cannot encode keeps
no BTF rather than failing the build.

Gated at configure time on CONFIG_DEBUG_INFO_BTF_MODULES
(kernel 5.9+).

Keep both .BTF and .BTF.base through find-debuginfo so
they reach the shipped RPMs.
