LU-17916 sec: fix in-kernel fscrypt macros and blocksize

When Lustre is built with in-kernel fscrypt, LL_CRYPTO_BLOCK_SIZE
is defined as FS_CRYPTO_BLOCK_SIZE, which kernel 5.19 split into
FSCRYPT_CONTENTS_ALIGNMENT and an internal definition. It is the
AES block size, so define it as 16, as embedded llcrypt does.

Since the switch to struct folio, llcrypt_decrypt_pagecache_blocks()
takes a folio and a page offset in it, but the in-kernel fscrypt
mapping was still passing 3 arguments to
fscrypt_decrypt_pagecache_blocks(). That function took a page
before kernel 6.3, and was removed in kernel 7.3. Implement
llcrypt_decrypt_pagecache_blocks() with
fscrypt_decrypt_block_inplace(), available in all these kernels,
block by block, as fscrypt_decrypt_pagecache_blocks() does.

Also, llcrypt_encrypt_pagecache_blocks() takes and returns a folio,
and llcrypt_finalize_bounce_page() takes a folio pointer and a page
offset in it. With in-kernel fscrypt, implement both as wrappers
converting between folio and page.

The in-kernel fscrypt build still fails with kernels from 5.9, which
removed fscrypt_inherit_context().

Built with --enable-crypto=in-kernel against 6.12.0-124.56.1.el10 (RHEL10.1, a primary supported kernel) and compared errors with and without this patch.

Fixed by this patch:
- FS_CRYPTO_BLOCK_SIZE undeclared (28 errors) - gone, 16 matches FSCRYPT_CONTENTS_ALIGNMENT.
- llcrypt_decrypt_pagecache_blocks() arg count in osc_request.c and llite/file.c - gone. The new helper is equivalent to the embedded llcrypt version (same lblk_num, folio_page(folio, pgno) + offs == PAGE_SIZE*pgno + offs in llcrypt_crypt_block()).

Still broken, same root cause (51de594ed75a), so I think it belongs in this patch:
- llcrypt_encrypt_pagecache_blocks(): now fails with incompatible pointer types, see inline.
- llcrypt_finalize_bounce_page(): not updated to the (folio **, s32 *) signature, see inline.

Remaining errors not related to the folio switch, as the commit message says: fscrypt_inherit_context, fscrypt_set_test_dummy_encryption, fscrypt_operations key_prefix/max_namelen in llite/crypto.c.
