LU-17973 lov: spread FLR reads across equal mirrors

A client currently reads all of a mirrored file from one mirror,
picked once per file from those with the best preference by a hash
of the lov_object address.  Clients reading the same small file
pick different mirrors and cache it on every OSS, while all reads
of a large file by one client go to a single OSS.

Instead, select the read mirror for each IO, among the mirrors whose
component at the IO offset has the best preference (PREF_RD, then
the number of non-rotational OSTs).  The file is split into chunks
of lov.*.mirror_read_chunk_mb (default 1024), and each chunk is read
from a mirror picked by the FID and the chunk offset, so all clients
cache a small file on one OSS, and the OSS caches of a large file
add up instead of each holding a copy of it.  With more than three
such mirrors, which are there for bandwidth, the chunks after the
first are also offset by a hash of the client NID, to spread readers
of the same chunk over all OSSes.  A read crossing chunks is split
there.  Setting lov.*.mirror_read_chunk_mb=0 keeps the old behaviour.

A read crossing into or out of an EC component keeps its mirror, so
that EC recovery covers the whole read from one mirror.

Also make the PREF_RD weight larger than any non-rotational OST
count of a mirror, which could exceed 1000 for a wide mirror.  Also
reset ci_ndelay_tried after each complete piece of a large buffered
read.  Keeping it made every restart switch to the next mirror as if
the previous one had failed, and sleep after each lo_mirror_count
pieces.

Add sanity-flr test_208c.
