--- Commit Message ---
LU-20808 target: keep OUT from setting up remote objects

out_handle() looks each object up through the MDT stack. When LOD
maps the FID to another MDT, it sets up an OSP object, and
osp_object_init() fetches the attributes from that MDT. The lookup
then fails anyway: dt_locate_at() finds no OSD slice in the object
and returns -ENOENT.

So an OUT thread can wait on another MDT. When that MDT restarts, it
reads its update logs from this one through OUT_PORTAL, which mdt_out
and ost_out share, and finds its request queued behind threads that
wait for it to come back.

Have out_handle() fail such an update with -ENOENT, as before, without
asking the other MDT first. It asks FLD whether the FID is on another
MDT before the lookup, so that such an object is never put in the
site: an object whose setup fails is visible there until it is torn
down, and another thread looking the FID up meanwhile would take it
for gone. Add LOC_F_LOCAL, with which lod_object_init() fails with
-EREMOTE instead of setting up a remote object, for what that check
cannot tell.

This only avoids the OSP attribute read. The FLD lookup itself can
still go to MDT0 for an entry this MDT does not have, as for any FID.
