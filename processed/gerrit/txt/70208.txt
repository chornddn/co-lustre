--- Commit Message ---
LU-20889 tests: check status of each background job

Several tests started commands in the background and then ran
"wait || error ..." or "wait; rc=$?" to check them.  "wait" without
arguments always returns 0, so a failed job would never be detected.
conf-sanity test_110 and test_111 ran "wait $pids" on several PIDs,
which returns only the status of the last one, so a failure of any
other job would be missed.

Add wait_pids() to test-framework.sh to wait for each PID it is given
and return the status of the first one that failed.  Save the PIDs of
the background jobs in sanity test_51b and test_51c, sanityn
cleanup_81d(), sanity-sec test_48b, performance-sanity test_5a-5d,
lfsck-performance namespace_gen_one() and conf-sanity test_110 and
test_111, and check them with wait_pids() or "wait $pid".  Wait for
the ofd_access_log_reader PID in sanity test_165a-165g so that its
exit status is checked.
