LU-20718 lov: ignore stale EC fields from old servers

Before EC was introduced, servers wrote lcme_timestamp only for
NOSYNC components, memset only the layout header and reused the EA
buffer, so other components can hold stale bytes in what EC reads as
the mirror link id and the EC stripe counts.  A 2.17 MDS hands such a
layout to a newer client: with a stale lcme_dstripe_count a plain
mirror looks like EC data, lov_io_mirror_init() sets ci_cross_ec, and
when reading the mirror fails the client switches to a CIT_EC_RD read
that fails with "no updated parity component to restore data: rc = -5"
(sanity-flr test_34b against 2.17 and 2.16 servers).

Apply the same rule as llapi_layout_get_by_xattr() when unpacking a
composite layout: keep a data component's link id and stripe counts
only while a parity component links to it, and the timestamp only for
a NOSYNC component or an EC layout.
