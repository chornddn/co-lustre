LU-21122 lod: allow PFID updates when an OST is full

After a successful layout merge, split or swap,
lod_trans_space_check() can reject PFID updates on a full OST,
leaving the parent FID or component ID inconsistent with the
MDT layout.

Allow only the separate PFID replacement transactions to bypass
the LOD space check on OSTs.  Keep the checks for MDT migration
and remote MDTs, and retain backend allocation errors.

With the space check bypassed, the OST itself can reject the PFID
set.  osp_xattr_set() caches the new value before the OUT RPC is
sent and nothing drops it if the set fails, and OST updates are not
recorded in the update llog, so the rejected set is never redone.
The next mdd_object_pfid_replace() would then read the cached
filter_fid, see it already matching, and skip the stripe, leaving
the stale on-disk PFID unrepaired.  Do not cache xattrs set on OST
objects, so the next layout change reads the real value from the
OST and retries the update.

Expose `mdd.*.pfid_update_attempts`, `mdd.*.pfid_update_failures`
and `mdd.*.pfid_update_enospc` for updates after layout changes.
Account and log failures, including errors from mdd_trans_stop(),
without failing the completed layout operation.

Add sanity-flr/71b and 71c for full OSTs and failed PFID updates,
including ENOSPC returned at transaction stop and a retry of the
PFID update after a rejected set.  Also fix hexadecimal FID
parsing in ost_fid2_objpath().
