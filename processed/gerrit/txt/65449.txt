LU-20176 osd-ldiskfs: refactor OI scrub

Remove the priority OI scrub path and simplify the scrub bookkeeping:

1. Do not scrub inconsistent mappings in priority.  A FID queued for
   priority scrub often could not be repaired, because there was no
   clue in the OI mapping to what it should point at, so the mapping
   stayed inconsistent and triggered repeated partial OI scrubs.  The
   full_scrub_ratio and full_scrub_threshold_rate tunables which
   controlled that partial scan are removed as well, and
   Documentation/lfsck.txt is updated to match, documenting both
   auto-start triggers: an incomplete previous scrub found in the OI
   file at mount, and an RPC hitting a FID whose OI mapping is
   missing, stale, or inconsistent.

2. Drop osd_ldiskfs_consistency_check() from osd_ea_rec_lookup() and
   the OI check in do_osd_stripe_dir_filldir().  They duplicate the
   check in osd_fid_lookup() with subtly different semantics, which
   is racy and confusing; doing the check in osd_fid_lookup() alone
   is enough.  That check now queues any FID whose OI mapping cannot
   be used for OI scrub, starts the scrub with SS_RESET, and only
   looks up the remote parent for MD operative FIDs.

3. Do not remove the OI mapping in osd_object_init() in osd-zfs after
   an LMA check failure: it can race with the OI scrub thread.  The
   ldiskfs osd_fid_lookup() keeps its stale mapping as well, so that
   the FID queued by osd_scrub_oi_insert() carries a mapping the
   scrub can verify and repair, and the object stays reachable until
   then.

4. Move a FID that could not be fixed into the stale list in
   osd_scrub_check_update(), which is also where the
   OBD_FAIL_OSD_SCRUB_STALE fault injection point is checked now,
   in addition to the iget-failure check in osd_fid_lookup().

5. Queue the FID and hold the scrub write lock across the OI mapping
   re-check in osd_scrub_oi_insert(), so the running scrub cannot
   drain it in between; skip the re-check for an object found via
   REMOTE_PARENT_DIR, whose inode never matches the OI mapping; and
   restore a stale-listed FID whose OI lookup still succeeds, so it
   is not reported -ESTALE until unmount.

6. Small fixes found while running the tests: reset the
   prior_updated counter unconditionally and move leftover
   inconsistent items to the stale list when the scrub completes.

7. Update sanity-scrub.sh for the one-pass OI scrub: create a 10 level
   deep directory, so that the bottom directories are scrubbed after
   the upper ones, which makes the tests more reliable; add a
   scrub_start_running() helper that starts the OI scrub on the MDTs
   where the RPC-triggered scrub has already finished, and call it
   wherever a test needs the scrub to be running -- to inject a fault
   that only a running scrub can hit, or to stop the MDT in the middle
   of the scrub; and let scrub_check_status() take a comparison
   operator, so that test_10a can wait for the resumed scrub to leave
   the 'paused' state left behind by the MDT stop instead of requiring
   the 'scanning' state, which it can leave before the status is
   polled because it resumes from its last checkpoint.

   In test_6, handle a zero OI scrub checkpoint, which ZFS reports as
   N/A: the scrub writes no checkpoint until it has checked at least
   one object, and when there is none it restarts from the beginning
   of the device, so that position is 0 and the position the scrub
   resumes from is start.  Also check that the scrub resumed from its
   last checkpoint only while there still is one: the OI scrub file is
   reset when the OI files are recreated at mount, and then the scrub
   legitimately restarts from the beginning.

   In test_10a, where the scrub has to be one that is resumed rather
   than stopped when the MDT goes down, restart the MDTs with the OI
   files recreated (mount -o resetoi) when no scrub is running any
   more, so that the mount-time OI scrub starts.  That one does not
   belong to the LFSCK iteration, which would stop the scrub together
   with itself and leave the status 'stopped' rather than the 'paused'
   this test checks -- which is what scrub_start_running() would have
   started.

## Fix Summary

The compile errors were caused by the patch removing the `os_in_prior` field from `struct lustre_scrub` in the ldiskfs OSD implementation, but the ZFS OSD implementation (`lustre/osd-zfs/osd_scrub.c`) still contained references to this removed field.

### What was fixed:

1. **Line 151-153** - Removed the check for `scrub->os_in_prior` and the code that retrieved the `oii` (inconsistent item) from the list based on this condition. The partial scrub functionality that this supported has been removed.

2. **Line 216-218** - Removed the conditional logic that incremented different counters (`sf->sf_items_updated_prior` vs `sf->sf_items_updated`) based on `os_in_prior`. Now always increments `sf->sf_items_updated`.

3. **Line 352-359** - Removed the assignment `scrub->os_in_prior = 1` when processing items from the inconsistent items list.

4. **Line 414-429** - Simplified the `osd_scrub_exec()` function by removing the conditional block that checked `os_in_prior`. The code now always runs the prefetch logic when not in full speed mode, eliminating the else-branch that was resetting `os_in_prior`.

### Rationale:

The patch (LU-20176) removes partial OI scrub functionality triggered by RPC because it was problematic and complicated the scrub state machine. The partial scrub would only scan inconsistent mappings rather than all inodes, which could fail to fix actual inconsistencies. The `os_in_prior` field was used to track whether the scrub was processing items from the priority list (inconsistent items found by RPC), but with partial scrub removed, this tracking is no longer needed. The ZFS OSD code needed the same changes that were applied to the ldiskfs OSD to remove references to this deleted field.
