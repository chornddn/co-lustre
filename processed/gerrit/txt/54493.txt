LU-10499 pcc: abort in-progress attach by PCC detach command

A user may want to abort in-progress attach for some purposes such
as freeing space for PCC backend.
To support this operation, we add an "abort" option for PCC detach
command to abort the in-progress attach.

"lfs pcc detach --abort" sets PCC_STATE_FL_ATTACH_ABORTING on a file
that is being attached.  The kernel copy checks it for each buffer,
and the DIO copy helper is killed, so the attach fails with
-ECANCELED and removes its partial PCC copy.  The kernel records the
pid of each running ll_fid_path_copy for this, from the usermode
helper init callback.  "lctl pcc del|clear --abort" aborts the
attaches of all files on the PCC backend.  With --wait, both wait for
the aborted attaches to finish.

Changes from the original patches:
- ll_fid_path_copy no longer polls the PCC state of the file with the
  per-file LL_IOC_PCC_STATE ioctl, which is deprecated.  Killing the
  helper aborts the copy at once.
- "lctl pcc del|clear -a" did not work, since "a" was missing from
  the getopt string.
- "lctl pcc del|clear --abort" without --wait skipped the removal of
  every PCC copy, since it checked the input abort flag instead of
  the returned PCC_DETACH_FL_ATTACHING.
- The detach no longer polls with msleep(), see the --wait option.

Add sanity-pcc test_108a for "lfs pcc detach --abort" of the kernel
and DIO copies, and test_108b for "lctl pcc clear --abort --wait".

LU-10499 pcc: abort data copy via ll_fid_path_copy

For data copying via ll_fid_path_copy in direct I/O mode in user
space, the client calls llapi_pcc_state_fd() to obtain the file
PCC state. If it is marked with PCC_STATE_FL_ATTACH_ABORTING, the
data copy process ll_fid_path_copy exits immediately.
To reduce the overhead of these check, we do not check for each
data copy iter, instead, we do a check for certain times of I/Os
(32 times by default). For I/O size of 32MiB, it will be checking
1 times per second at 1GiB/s. There should be some time-lag
before the copy tool quits finally.

Was-Change-Id: I20631e5481a7e97d7a1ed0729bcd269ef6248a2c

LU-10499 pcc: abort data copy when clear PCC backend

This patch adds an option "--abort" for "lctl pcc del|clear"
command tools.
With this option, the user will first set ATTACH_ABORTING flag on
all in-progress attaching files, and then wait for them to abort
the attache when remove a PCC backend from a client.
