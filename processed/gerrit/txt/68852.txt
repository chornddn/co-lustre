LU-17296 tests: one-tenant mClock baseline against FIFO

Tests 77xa to 77xh measure the mClock share between two tenants.
No test measures one tenant at full load. That case must not lose
to FIFO, because the zero-config string is a candidate default.

Add sanityn 77xi. The test makes one fio flow of 16 jobs on one
OST. It measures FIFO and "mclock jobid+nid weight=1" four times
each. The samples alternate: FIFO, mClock, FIFO, mClock, and so on.
Alternation reduces the drift of a virtual machine to one sample.
Pass A sets jobid_var=disable. The policy then makes one class
bucket. Pass B sets jobid_var=nodelocal and jobid_name=%e.%p. The
16 fio threads then make 16 buckets. Each pass takes the median of
the four samples of each policy. The test skips when the spread of
either policy is above NRS_BASELINE_SPREAD, 0.25 by default. The
test fails when the mClock median is below 0.90 of the FIFO median.
NRS_BASELINE_MARGIN sets the margin.

The test prints the eight measurements of each pass. A value in
NRS_BASELINE_POLICY replaces the policy string. A run on hardware
thus needs no edit.

Make the fio profile of nrs_fio_flow_one() adjustable, because the
test makes eight flows. The caller can set NRS_FIO_JOBS,
NRS_FIO_IODEPTH and NRS_FIO_RUNTIME. The job count of 8 and the
queue depth of 16 do not change. The client memory footprint is
therefore the same. Only the default runtime changes, from 120
seconds to 40 seconds.

Bind the backlog monitor loop to the flow time. The flows run in the
background, so the 90 seconds of sleep fit inside the old 120 second
flow. The loop becomes additive at the shorter runtime, and the bound
keeps the loop inside the flow.

Some concerns, see inline comments.
