LU-17296 tests: one-tenant mClock baseline against FIFO

Tests 77xa to 77xh measure the mClock share between two tenants.
No test measures one tenant at full load. That case must not lose
to FIFO, because the zero-config string is a candidate default.

Add sanityn 77xi. The test makes one fio flow of 16 jobs on one
OST. It measures FIFO and "mclock jobid+nid weight=1" two times
each, in the order FIFO, mClock, FIFO, mClock. Alternation cancels
the drift of a virtual machine. Pass A sets jobid_var=disable.
The policy then makes one class bucket. Pass B sets
jobid_var=nodelocal and jobid_name=%e.%p. The 16 fio threads then
make 16 buckets. The test fails if the mean mClock IOPS is below
0.90 of the mean FIFO IOPS.

The test prints the eight measurements of each pass. A value in
NRS_BASELINE_POLICY replaces the policy string. A run on hardware
thus needs no edit.

Make the fio profile of nrs_fio_flow_one() adjustable, because the
test makes eight flows. The default profile is now 8 jobs at a
queue depth of 16 for 40 seconds. Two flows then need 256 MiB of
client memory, and a client with a small memory does not kill fio.
The caller can set NRS_FIO_JOBS, NRS_FIO_IODEPTH and
NRS_FIO_RUNTIME. Bind the backlog monitor loop to the flow time,
because the loop added 90 seconds to each scenario.
