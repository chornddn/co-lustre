--- Commit Message ---
LU-18302 tests: commit client records in recovery-small 134

test_134 remounts the clients and then fails mds1 a few seconds
later. The new clients' last_rcvd records are written in a
transaction that is not synced, so when a HARD failover powers the
MDS off before the next journal commit, the MDTs restart with the
records of the old mounts. Every client is then refused as a new
client during recovery and evicted when it ends, and the rm and mv
fail with EIO or ESHUTDOWN. SOFT failover unmounts the targets,
which commits the records, so only the failover sessions fail.

Sync the MDTs after the remount so the records are on disk before
the race starts. Create the test directories on MDT0000, so that
the race always runs on the MDT that "fail mds1" takes down.
