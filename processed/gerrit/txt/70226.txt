LU-21073 llite: report the size and times the objects report

stat(), lseek(SEEK_END/SEEK_DATA/SEEK_HOLE), O_APPEND writes and
fallocate glimpse the file, then read i_size and the timestamps back
out of the inode.  Between the merge and that read i_size can be
rewritten by writers that do not take ll_inode_size_lock(): a read in
vvp_prep_size() case (A) sets i_size to the KMS, which on a PFL or
mirrored file is the end of the locked component, and so do
ll_update_inode() for an MDS reply and truncate.  ll_merge_attr()
also writes the timestamps in two steps, so a racing reader can see
the intermediate values.  LU-17753 closed that for stat() alone by
holding the size lock across the copy.

Take one snapshot and report from it.  ll_merge_attr() fills a caller
cl_attr under the size lock with the merged size, blocks and times,
and cl_glimpse_lock()/ll_glimpse_attr() return 1 when they filled it.
Paths that do not glimpse (AT_STATX_DONT_SYNC, restore, directories)
fill it from the inode under the same lock; PCC fills it from the PCC
copy.  ll_getattr_dentry(), ll_file_seek(), the lseek, append and
fallocate IO paths and vvp_prep_size() use the snapshot, not i_size.

The strict-SOM shortcut of ll_getattr_dentry() reported i_size, which
the read could have lowered.  ll_update_inode() now saves the strict
MDS size and blocks in lli_som_size/lli_som_blocks, ordered against
lli_attr_valid by a barrier, and the shortcut reports them.

The LU-417 fix-up (blocks 0 while the data is only in dirty pages)
moves to cl_glimpse_lock() and checks the snapshot, so it no longer
runs on every merge.  Remove the unused cl_glimpse_size().

cl_attr carries seconds only, so stat() now reports tv_nsec 0 on every
path, as the glimpse path already did.

Add sanityn test_16n: a read on the second mount must not shrink the
size stat reports for a PFL and a mirrored file.
