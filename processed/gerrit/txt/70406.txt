LU-20076 tests: fewer remote commands in setupall checks

sanity_mount_check() ran one remote command per server
target and one per client mount point, 15 for a DNE
configuration of 4 MDTs and 8 OSTs. Check all server mount
points on all server nodes in one command, and both client
mount points in another.

load_modules() ran load_modules_local() through rpc.sh on
every remote node even when the modules were loaded, and
rpc.sh costs about a second to start. On nodes where
lustre.ko is loaded and the udev rule load_modules_local()
writes is in place, only reset the debug masks as it would,
in the same remote command. A node with an older test
framework that does not write the rule is loaded as before.

Measured on a cluster of one MDS with 4 MDTs, one OSS with 6
OSTs and 2 clients, median of 3 to 6 runs, as is and with
0.25 s added to each remote command:

                      cmds      as is           +0.25 s
  sanity_mount_check 13 -> 2  1.01 -> 0.23 s  4.10 -> 0.71 s
  load_modules        1 -> 1  1.22 -> 0.34 s  1.41 -> 0.56 s

With the two changes before this one, setupall went from 164
to 37 remote commands, 23.3 to 17.7 s as is and 41.6 to
22.8 s with 0.25 s added.

CI runs about 220,000 setupalls and 750,000 load_modules()
calls with the modules loaded in 30 days. At the savings
measured above (0.78 to 3.39 s per sanity_mount_check and
0.85 to 0.88 s per load_modules), that is 48 to 207 hours and
177 to 183 hours, so about 230 to 380 hours of test time.
