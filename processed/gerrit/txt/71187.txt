LU-21253 ofd: commit DIO write after data_version sample

A DIO overwrite that skips the forced commit advances the object
version in a transaction that is not committed and not replayed.
After an OST crash the version is the old one while the data is
new.  A tool that read the data version before the write, like the
HSM copytool, then takes the object for unchanged.

Count the data version reads of an object.  A DIO overwrite keeps
its forced commit while a read is not known to be older than a
committed version change, so the first write after a read gets a
committed, different version.  A forced DIO write covers only the
reads that had finished before it started to change the version;
reads in progress are counted separately for this.  A newly cached
object starts as read.

With `dio_overwrite_nosync` set, a data version read in OST_GETATTR
or OBD_IOC_GET_OBJ_VERSION commits the object first if its version
is not committed; if that commit fails, the read returns the error
and no version.  The OSC marks its data version request with
OBD_MD_FLDATAVERSION, as the MDC does for Data-on-MDT.  From older
clients only a flushing read (OBD_FL_SRVLOCK) is known as one:
their other reads are not committed first, which after an OST crash
can only make the file appear modified, as no later change gets
the same version.  Other getattr requests (lctl getattr, the echo
client) still arm the object but do not commit.  The read counters
are 64-bit, so they cannot wrap around to equal.

`ofd_write_nosync()` checks ofo_dirty_transno again after the version
bump and its full barrier.  An `ofd_object_fallocate()` or another
`ofd_commitrw_write()` that keeps its commit and started after
ofo_attr_inflight was read may have stopped its transaction in
between, as both change the object under `ofd_read_lock()`, and the
write must not skip the commit over that uncommitted change.  A
setattr or punch cannot get in between: it takes `ofd_write_lock()`
and waits for the write.  This narrows a window left by the previous
patches; it uses the barrier added here for data version reads.

Add the reason dv_sampled to `dio_overwrite_sync_reasons`.
Add sanity 398z and replay-ost-single 15.  The crash check of 15 is
retried, then skipped, when a journal commit falls in the crash
window.  398z also checks that a getattr that is not a data version
read does not commit, and fails the commit of a data version read
with the new OBD_FAIL_OST_DV_SYNC_ERR (0x259).
