LU-20689 utils: Support decimal (SI) size units

llapi_parse_size() took a trailing "B" as decoration, so "1GB" meant
2^30 while the kernel's own sysfs parser already reads "GB" as 10^9.
Every 'lfs' size option was thus inconsistent with 'lctl set_param',
and a loose suffix such as "1Gijunk" was silently taken as 1GiB.
Support a trailing "B" as 10^3-based, keep "G" and "GiB" 2^10-based,
and handle the six unit letters in one helper that validates the whole
suffix.  llapi_parse_size() is exported, so this changes what every
caller of it reads, not just 'lfs'.

Scaling a fraction as "frac * size_units / frac_d" overflowed once the
unit was large, so "1.999999999999999999G" came out 1GiB short, and
twenty or more decimal places made frac_d itself wrap.  Note where the
fraction is instead and scale it only after the unit is known, one
digit at a time from the last, so that no intermediate exceeds ten
times the unit however many decimal places were given.  Refuse a size
that overflows once scaled, and one whose integer part saturates
strtoull().

Document the new spelling wherever a size argument is described, in
the manual pages and in the copytool's own usage, and spell as "MiB"
the sizes that prose gave as "MB" while meaning 2^20.
Update replay-single test_203, whose "-E 1MB" component ends are no
longer 64KiB aligned.  Add sanity tests 921a-921d, covering options
that share a parsing site once, and sanity-hsm test_608 for the
copytool.
