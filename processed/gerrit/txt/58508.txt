LU-16049 llite: add sync_on_close option

Add a mount option and tunable llite.*.sync_on_close to give Lustre
clients a more NFS-like experience, with data flush on file close.
Default is disabled, to avoid performance impact under normal usage.

To avoid significant distributed IO performance issues with this
option enabled, ll_fsync() is only called on inodes that were just
created, modified, and/or wrote file data, not on every close.
Explicitly calling fsync() on the file will avoid sync on close.

Reverse semantics for the existing `lli_synced_to_mds` that *always*
requires an MDT sync for every file open to `lli_need_sync_to_mds`
to only force a sync for files that were created or modified.

If an inode was newly created or modified, then there will be both
an data fsync and metadata mdsync, each tracked separately.  If the
MDS fsync has been completed, then later writes only fsync the OSTs.

This is already a useful waypoint, but could potentially be optimized:
- client-side callback when MDT create RPC commits to avoid MDT sync
- client-side callback when OST write RPCs commit to avoid OST sync

This would avoid extra extra sync RPCs on every file close if the
file is held open for some seconds before it is closed, but I'm not
sure if that is very common vs. open-write-close in quick succession.

Add llite.sync_on_close.4 man page.

Add test sanity.sh test_63c to cover various sync_on_close=1 cases.
