LU-21227 lod: fix stripe count overflow in lod_mdt_alloc_specific

lod_prep_md_striped_create() clamps an overstriped request down to
mdt_count * lod_max_stripes_per_mdt in a local stripe_count variable,
and sizes stripes[] and idx_array[] using that clamped value.
lo->ldo_dir_stripe_count is only updated to the final value after
allocation succeeds.

When lo->ldo_dir_stripe_offset is not LMV_OFFSET_DEFAULT, allocation
goes through lod_mdt_alloc_specific(), which read its loop bound from
lo->ldo_dir_stripe_count directly instead of taking it as a parameter,
unlike lod_mdt_alloc_qos() and lod_mdt_alloc_rr(). Whenever clamping
actually shrank the request, lod_mdt_alloc_specific() iterated past
the end of the smaller stripes[]/idx_array[] arrays using the stale,
larger count, overflowing both heap allocations.

Add a stripe_count parameter to lod_mdt_alloc_specific(), matching
lod_mdt_alloc_qos()/lod_mdt_alloc_rr(), and have
lod_prep_md_striped_create() pass its already-clamped local
stripe_count instead. Update the existing lod_mdt_alloc_test KUnit
callers to pass the new parameter.
