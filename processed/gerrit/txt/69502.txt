LU-20650 lfs: find --since, pick before the gather

llapi_scan_fid() gathered every changed object in the filesystem
before find_since_rec_cb() tested the subtree. For "lfs find
/mnt/lustre/small_dir --since 1d" on a busy filesystem that is about
70 KB of buffers, an open and a getattr ioctl for each object that is
then thrown away. llapi_scan_fid() runs lfsp_filter before any of
that, which is the case its documentation names.

So --since now passes find_since_pick() as the filter. The filter
record has the path, the name and the type, which is all the subtree
test, -name and -type read, and the FID and link count that the patch
before this one added. So only a hardlinked file looks up its other
names, as find_since_rec_cb() does. One whose first name the pick
rejects, but another name passes, walks them in both places, which is
rare.

The filter makes the same pick on the same names, so it only rejects
what find_since_rec_cb() would reject, and the answer is the same.
The warnings can differ a little. The fid2path and the statx() still
run before the filter, so an object that has gone, or one under a
directory the caller cannot search, is counted as before. Only a
failure in the gather itself is no longer counted for an object
outside the subtree: an open of a parent the caller cannot read, or
the object changing after the statx(). --changelog is not changed:
-name there tests the name the record carried, not the live one.
