LU-19916 mgs: start MGS follower on MDTs/OSTs

Start MGS followers on all MDTs/OSTs, these MGS followers provide
configuration and imperative recovery services for clients. MDTs/OSTs
connect to MGS0 as before, and connect to MGS followers will be
rejected with -ENODEV.

MGS0 is leader, If combined MGS/MDT0 is deployed, it will stop MGS
follower on the host if another MDT/OST on this host has started MGS
follower already.

MGS follower is a readonly backup of MGS0, and it doesn't handle
ioctls.

Once MGS is stopped, wake up MGC requeue thread to start MGS follower
on another target if possible.

Register MGS follower as observer of MGC, so that it can be notified
when the config is changed.

Add an argument for obd_notify() to pass data.

Add debugfs entry mgs/MGS/state, the content is "leader" for MGS0,
"follower" for MGS follower, and is_mgs() in liblustreapi should
check this because MGS follower is readonly, and doesn't handle ioctl.
