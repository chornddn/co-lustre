LU-11628 lfsck: give OST objects a missing parent FID

Layout LFSCK checks the parent FID (trusted.fid) of each OST object
a layout references, but takes an object that has none as consistent.
Objects that were never written have none, so `lfs fid2path` cannot
map them and a scan of the OST cannot tell which file they belong to.

Repair such an object as an unmatched pair: set its parent FID, with
the stripe index and component, and its owner and project, from the
MDT-object that references it.  The OST sets it only if the object
still has none, so that a write since the check, which also stores
the layout version of an FLR mirror, is not overwritten.  Such
objects are counted in `repaired_unmatched_pair`.  Objects of files
changed since the run started are left, as they may be written now.

Factor lfsck_layout_child_moved() out of the dangling repair, and
call it under the layout lock in the unmatched-pair repair too, so
that a layout swap during the run cannot give an object the wrong
parent.  Also stop the repair from changing the attributes the other
stripes of the file are checked against.

Add sanity-lfsck test 15e.
