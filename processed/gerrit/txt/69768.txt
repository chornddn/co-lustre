LU-11962 flr: fix the handling of foreign mirrors

Several places mishandle a mirror made of a foreign HSM component, as
PCC-RO adds:
- the client copies the EC stripe counts into every layout entry, but
  for a foreign entry they share a union with lsme_foreign_flags, so
  getxattr("lustre.lov") and llapi_layout_get_by_fd() report its HSM
  flags as 0;
- "lfs getstripe" prints all of its lhm_* fields whatever is asked,
  so "lfs getstripe -N" prints them after the mirror count, and it is
  the last initialized component that "-c", "-S" or "-i" show;
- lod_primary_pick() may pick it as the primary mirror for a write
  when the OSTs of the data mirror are unavailable;
- mdd_split_ea(), and data_mirror_remains() and
  last_non_stale_mirror() of lfs, count it as data, so "lfs mirror
  split" can remove the only data mirror, or the only in-sync one;
- a designated read of it, e.g. "lfs mirror read -N", which any user
  with read access can do, hits the LASSERT in
  lov_io_layout_at_mirror(), and "lfs mirror verify" reads from it.

Move the EC stripe counts out of the union, print an HSM component
only for the verbose and layout pattern output and never as the last
initialized one, never pick an HSM mirror in lod_primary_pick(), and
do not count foreign mirrors as data when splitting or verifying.
Refuse designated I/O to a foreign mirror in lov_io_mirror_init().

Add sanity-pcc test_51 to check the HSM flags, "lfs getstripe -N" and
"-c", the split of data mirrors, and the read and verify of a file
attached to PCC-RO.


sanity-pcc test_51 passes.  sanity-flr test_200a failed once with
ENOSPC ("failed writing to 4650240:564704"), because the small OSTs
had filled up during the full run.  It passed twice when rerun on its
own after a reformat, so that's the test environment and not this patch.

The fixes look right to me: lod_primary_pick() skipping HSM mirrors, the
foreign checks in mdd_split_ea() and in lfs split/verify, and -EINVAL in
place of the LASSERT in lov_io_mirror_init().  A couple of points:

1. I agree with the aireview comment on /COMMIT_MSG.  9b625e411a6
   ("LU-20718 ec: ignore stale EC fields from old servers") is in the
   base, and lsm_unpackmd_comp_md_v1() and lov_lsm_pack() already skip
   foreign entries.  So the lov_internal.h move is a cleanup now, not
   the fix for the HSM flags.  Please update the first bullet, and drop
   the Fixes: lines for 472e0f27d411 and 22e9e7e8b264 or say why they
   stay.  If the struct move stays, the lsme_is_foreign() guards around
   the EC fields become redundant, and the "set for all entries" comment
   should change.

2. file_stays_redundant() in lfs.c (around line 3325) uses
   collect_mirror_id() without .cid_data_only, so it still counts a
   foreign mirror as a data copy.  That's the same class of bug this
   patch fixes in data_mirror_remains() and last_non_stale_mirror().
   It's a one-line fix, so I'd rather see it in this patch.

3. _mirror_find_stale() still picks up a stale HSM component, so
   "lfs mirror resync" after "lfs pcc detach" now fails with -EINVAL
   where it used to crash.  That isn't a regression, so a follow-up is
   fine, but please file a ticket for it or mention it in the commit
   message.
