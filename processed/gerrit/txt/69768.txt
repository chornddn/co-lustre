LU-14319 flr: fix the handling of foreign mirrors

Several places mishandle a mirror made of a foreign HSM component, as
PCC-RO adds, which has no data in Lustre:
- "lfs getstripe" prints all of its lhm_* fields whatever is asked,
  so "lfs getstripe -N" prints them after the mirror count, it is the
  last initialized component that "-c", "-S" or "-i" show, and
  lhm_flags repeats its named flags in hex;
- lov_foreign_hsm_to_le() wrote the archive ID and version of the
  buffer to itself, leaving stale values in them on disk;
- lod_primary_pick() may pick it as the primary mirror for a write
  when the OSTs of the data mirror are unavailable;
- mdd_split_ea(), and data_mirror_remains(), last_non_stale_mirror()
  and file_stays_redundant() of lfs, count it as data, so "lfs mirror
  split" can remove the only data mirror, or the only in-sync one;
- a designated read of it, e.g. "lfs mirror read -N", which any user
  with read access can do, hits the LASSERT in
  lov_io_layout_at_mirror(), "lfs mirror verify" reads from it, and
  "lfs mirror resync" tries to copy data into it when it is stale;
- a client setting a layout taken from such a file, e.g. a copytool
  restoring the striping of an archived file, "lfs setstripe --copy"
  or "lfs migrate", gets -EINVAL, as lod_qos_parse_config() parses
  the foreign component as a plain one, and "lfs mirror extend -N"
  uses it as the template of the new mirror and fails the same way;
- the MDT does not see a released file with a foreign mirror as
  released, and returns neither its size nor its block count.

Print the lhm_* fields of an HSM component only for the default, -v
and -L output, not when a single field such as -N or -c is asked for,
and never use it as the last initialized one, never pick an HSM mirror
in lod_primary_pick(), and do not count foreign mirrors as data when
splitting or verifying, or as a redundant copy.  Refuse designated I/O
to a foreign mirror in lov_io_mirror_init().  Fix
lov_foreign_hsm_to_le().  Drop foreign mirrors covering [0, EOF) from
the layout of a new file set by a client, in the lov_foreign_md form
or as the plain component with LOV_PATTERN_FOREIGN that
llapi_layout_to_lum() makes of them.  Skip them in
llapi_layout_get_last_init_comp(), in the stale components that "lfs
mirror resync" copies and reports as resynced, as the source of a
resync in llapi_mirror_find() and lfs_mirror_force_resync(), and in
the mirrors "lfs mirror verify" reports and compares, and do not clear
the stale flag of an HSM or PCC mirror at RESYNC_DONE.  Skip foreign
components in mdt_hsm_is_released(), as mdt_hsm_set_released() does.
Also swab all the components of a layout after a foreign one in
lustre_swab_lov_comp_md_v1().

So "lfs mirror resync" of a file whose only stale mirror is a foreign
one returns without a change, leaving the file WRITE_PENDING until
that mirror is updated, and "lfs migrate" of a file with a foreign
mirror drops the mirror instead of failing.

Add sanity-pcc test_21bb to check the archive ID on disk, mirror
verify, setstripe --copy and mirror extend of a PCC-RO file, and
verify after a write, and test_21bc to check the HSM flags, "lfs
getstripe -N" and "-c", the split of data mirrors, and the read and
verify of a PCC-RO file.


sanity-pcc test_51 passes.  sanity-flr test_200a failed once with
ENOSPC ("failed writing to 4650240:564704"), because the small OSTs
had filled up during the full run.  It passed twice when rerun on its
own after a reformat, so that's the test environment and not this patch.

The fixes look right to me: lod_primary_pick() skipping HSM mirrors, the
foreign checks in mdd_split_ea() and in lfs split/verify, and -EINVAL in
place of the LASSERT in lov_io_mirror_init().  A couple of points:

1. I agree with the aireview comment on /COMMIT_MSG.  9b625e411a6
   ("LU-20718 ec: ignore stale EC fields from old servers") is in the
   base, and lsm_unpackmd_comp_md_v1() and lov_lsm_pack() already skip
   foreign entries.  So the lov_internal.h move is a cleanup now, not
   the fix for the HSM flags.  Please update the first bullet, and drop
   the Fixes: lines for 472e0f27d411 and 22e9e7e8b264 or say why they
   stay.  If the struct move stays, the lsme_is_foreign() guards around
   the EC fields become redundant, and the "set for all entries" comment
   should change.

2. file_stays_redundant() in lfs.c (around line 3325) uses
   collect_mirror_id() without .cid_data_only, so it still counts a
   foreign mirror as a data copy.  That's the same class of bug this
   patch fixes in data_mirror_remains() and last_non_stale_mirror().
   It's a one-line fix, so I'd rather see it in this patch.

3. _mirror_find_stale() still picks up a stale HSM component, so
   "lfs mirror resync" after "lfs pcc detach" now fails with -EINVAL
   where it used to crash.  That isn't a regression, so a follow-up is
   fine, but please file a ticket for it or mention it in the commit
   message.
