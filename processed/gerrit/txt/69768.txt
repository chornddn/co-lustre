LU-11962 flr: fix the handling of foreign mirrors

Several places mishandle a mirror made of a foreign HSM component, as
PCC-RO adds:
- the client copies the EC stripe counts into every layout entry, but
  for a foreign entry they share a union with lsme_foreign_flags, so
  getxattr("lustre.lov") and llapi_layout_get_by_fd() report its HSM
  flags as 0;
- "lfs getstripe" prints all of its lhm_* fields whatever is asked,
  so "lfs getstripe -N" prints them after the mirror count, and it is
  the last initialized component that "-c", "-S" or "-i" show;
- lod_primary_pick() may pick it as the primary mirror for a write
  when the OSTs of the data mirror are unavailable;
- mdd_split_ea(), and data_mirror_remains() and
  last_non_stale_mirror() of lfs, count it as data, so "lfs mirror
  split" can remove the only data mirror, or the only in-sync one;
- a designated read of it, e.g. "lfs mirror read -N", which any user
  with read access can do, hits the LASSERT in
  lov_io_layout_at_mirror(), and "lfs mirror verify" reads from it.

Move the EC stripe counts out of the union, print an HSM component
only for the verbose and layout pattern output and never as the last
initialized one, never pick an HSM mirror in lod_primary_pick(), and
do not count foreign mirrors as data when splitting or verifying.
Refuse designated I/O to a foreign mirror in lov_io_mirror_init().

Add sanity-pcc test_51 to check the HSM flags, "lfs getstripe -N" and
"-c", the split of data mirrors, and the read and verify of a file
attached to PCC-RO.
