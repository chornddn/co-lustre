LU-21178 obdclass: do not retry a full object hash forever

htable_lookup() retries the insertion while rhashtable reports that
the object hash is full (-E2BIG), after asking lu_object_limit() to
trim the cache.  That only reclaims objects idle on the LRU, and in a
client sub-site every stripe object is referenced by its parent LOV
object, so once the site reaches max_elems the inserting thread spins
forever.  max_elems is 2^31 today, so this is latent, but rhashtable
caps it at 2 * max_size as soon as a site sets max_size.

Retry only while a purge frees something, at most
LU_HASH_FULL_RETRIES times, then return -ENOMEM, so that
lu_object_find() reports the failure instead of hanging.  That purge
ignores lu_cache_nr, which lu_site_limit() does not enforce while a
site is under it, and blocks, so that a purge skipped because another
thread holds ls_purge_mutex is not taken for one that had nothing to
free.  Only count LU_SS_CACHE_RACE when a shadow object was found.

Report the failure with LCONSOLE_WARN(), which libcfs rate limits, so
that an admin can tell where an -ENOMEM came from, naming the target
by its OBD name where the site has one.

No site sets max_size yet, so the new error path is not reachable.
