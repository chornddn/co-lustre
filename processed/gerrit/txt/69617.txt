LU-20517 quota: don't grant writes from an outdated usage

sanity-quota test_1k fails on ZFS: the last 1MB write succeeds, but
the test expects EDQUOT. The failing run shows that this write was
within the limit, so test_1_check_write() is fixed first.

test_1_check_write() (shared with test_1a-1j) assumes that the
second write fills the file to the hard limit. It does not: a write
is refused only when it does not fit any more, and the check counts
the pending writes as usage, so the second write can stop well below
the limit (18MB of 20MB in a failing run) and leave real free space.
Keep writing 1MB past the limit until a write is refused, then check
with stat() that the file is not over the limit.

qsd_acquire() decides whether a write fits in the unused part of the
grant from the usage cached on the slave. On ZFS the usage is only
updated at transaction group commit, so that part can look larger
than it is and the write can go over the hard limit. When edquot is
set and the write uses the last part of the grant, sync the backend
and check again. Only the ZFS OSD is affected, and the sync is done
at most once per acquire.
