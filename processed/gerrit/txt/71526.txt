LU-21304 mdt: return encryption context on open by FID

Without the encryption key and with filename encryption enabled, a
long name is presented as a digested no-key name that embeds the FID,
and the client opens it by FID. mdt_open_by_fid_lock() did not pack
the encryption context in the reply, unlike the open by name. The
client then failed to set up the encryption info of the new directory
inode, as the context was not in its xattr cache, so opening such a
directory before any other access to it failed with ENODATA, and a
glob in it returned no entries.

Fix this by calling mdt_pack_encctx_in_reply() in
mdt_open_by_fid_lock(). Add sanity-sec test_109 to execrise this.
