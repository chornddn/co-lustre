LU-20119 selinux: add lustre_helpers SELinux policy module

Helpers launched by the kernel via call_usermodehelper()
(l_getsepol, lctl, l_getidentity, l_getauth) are execed from
kernel_t and, when labeled bin_t, transition into the base
policy's kernel_generic_helper_t domain.  On RHEL/Rocky 9 that
domain is broadly privileged and the helpers work unmodified.
On RHEL/Rocky 10 it is much more restricted -- in particular it
cannot read selinuxfs or the on-disk SELinux policy -- so under
enforcing mode the helpers fail: l_getsepol returns -EACCES
(mount aborts after 30s), lctl cannot apply root_squash, and
l_getidentity/l_getauth are denied.

Introduce a dedicated lustre_helper_t domain with a
lustre_helper_exec_t file type for the Lustre helper binaries.
A type_transition rule moves kernel_t to lustre_helper_t on exec
of those binaries, confining all needed permissions to Lustre
helpers only -- no other call_usermodehelper() callers are
affected, and the shared kernel_generic_helper_t domain is left
untouched.

For that transition to fire the helper binaries must actually
carry the lustre_helper_exec_t label, which requires two things:

  - lustre_helpers.fc lists both /usr/bin and /usr/sbin paths for
    each helper.  The binaries install under /usr/sbin, but on
    RHEL/Rocky 10.2+ SELinux applies a "/usr/sbin = /usr/bin"
    file-context equivalency (file_contexts.subs_dist), so
    restorecon of /usr/sbin/l_getsepol is resolved against
    /usr/bin and only a /usr/bin rule matches; on el8/el9 and
    el10.0/10.1 there is no such equivalency and the /usr/sbin
    rule matches the real path.  Listing both covers every case;
    the unused entry is harmless.

  - The label is applied by restorecon.  semodule -i does not
    relabel already-installed files, and the binaries were
    labeled bin_t at install time (before the module was loaded),
    so lustre.spec.in %post now runs restorecon after semodule -i.
    make install already did this for direct source installs, but
    it is skipped for staged/RPM builds where DESTDIR is set.

Additionally cover lgss_keyring, the GSS/SSK credential helper.
Unlike the helpers above it is not run via call_usermodehelper()
but by the kernel keyring request-key upcall
(/etc/request-key.d/lgssc.conf), so it executes in the base
policy's keyutils_request_t domain rather than lustre_helper_t.
Under enforcing SELinux on el10 that domain lacks access to the
Lustre parameter paths and, critically, to NID->hostname
resolution: lgss_get_service_str() -> ipv4_nid2hostname() ->
getnameinfo() is denied the NSS config reads and the DNS/netlink
sockets it needs, so SSK context negotiation aborts and shared
secret key mounts fail. Grant those permissions on
keyutils_request_t directly, since the request-key upcall does
not use the lustre_helper_exec_t label or transition.

Files added/modified:

  lustre/utils/selinux/lustre_helpers.te  - policy source
  lustre/utils/selinux/lustre_helpers.fc  - file context labels
  lustre/utils/selinux/Makefile.am        - build and install rules
  lustre.spec.in                          - %post restorecon

Build-time detection in config/lustre-core.m4 via the new
LC_CONFIG_SELINUX_POLICY macro auto-enables the module when
PLATFORM_ID is platform:el10 or later; can be overridden with
--with/--without-selinux-policy. Requires checkmodule
(checkpolicy) and semodule_package/semodule (policycoreutils).

For direct source installs (DESTDIR unset), make install runs
semodule -i and restorecon immediately. For RPM installs,
lustre.spec.in runs semodule -i and restorecon in %post and
semodule -r in %preun.

The RPM bcond (lustre_selinux_policy) is enabled by default on
RHEL 10+ (%rhel >= 10) and disabled on all other distros.

RHEL 9.7 (selinux-policy-38.1.65) is unaffected because its
kernel_generic_helper_t domain is broadly privileged. The
call_usermodehelper helpers were tested on Rocky 10.1
(selinux-policy-42.1.7) and RHEL 10.0 with SELinux enforcing. The
lgss_keyring rules were verified on RHEL 10.2 (selinux-policy-
42.1.18) with SELinux enforcing: with them loaded, lgss_keyring
passes all SELinux checks (zero keyutils_request_t denials) and
SSK context negotiation proceeds.
