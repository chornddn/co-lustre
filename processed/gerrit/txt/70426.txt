LU-20730 llapi: run find over a device's LFU chunks

lfs find --device gets its objects from llapi_scan_device(), one
callback per object, so it does not use the LFU Object Stream at all.

Make llapi_find_device() read the target only as a stream, 64 slots
of 64 KiB per read, and judge each object with find_device_cb() as
before. scan_device_lfu_rec() turns a record of a chunk back into the
struct llapi_scan_rec that find_device_cb() takes, through
scan_rec_build(), which is split out of scan_sink_object() so that
both read the EAs the same way.

Everything find needs is in the chunks:
- Each record carries the object's own FID. An OST object's record
  also carries its trusted.fid, the FID of the file on the MDT. On an
  OST, lfs find prints the file's FID for %LF and --print-fid, and the
  object's own for %LO.
- -printf %i prints li_ino, the object's inode number on the target.
- An object without a valid FID, sent with --internal or found
  damaged, is sent with a zero FID and printed by its inode number.
- Pathnames are composed in find from the trusted.link, trusted.lmv
  and encryption context of the directories in the chunks, as before,
  and with --fid2path through a client mount.
- The refusal of -printf %p without --fid2path on a target that has
  no directories checks the kind of target the stream reports.

llapi_find_device() no longer calls the record scan, so fold
scan_device_run_checked() back into llapi_scan_device().

conf-sanity 300a checks that -printf '%LF %i' finds the same objects
as -printf '%LF' and that %i of a directory is the inode number
debugfs reports for it. conf-sanity 300a-300d and 301-306 pass.
