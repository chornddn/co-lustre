LU-12669 ec: create lock placeholder for reconstructed pages

Create client-only ldlm_lock placeholders for sub-locks on
unavailable OSTs (LSS_READ_ERR) during CIT_EC_RD, so reconstructed
pages stay cached and Uptodate across reads instead of being
discarded after each read.  The ldlm_lock is granted locally without
an RPC and attached to the osc_lock via osc_lock_granted.

osc_lock_cancel() only detaches the ldlm_lock (osc_lock_detach)
without cancelling it, so the ldlm_lock survives the EC read loop and
keeps pages cached for concurrent readers.  When the OST recovers,
osc_import_event(IMP_EVENT_ACTIVE) calls
ldlm_cli_cancel_unused(LCF_LOCAL | LCF_EC_PLACEHOLDER) which cancels
placeholder locks with 0 readers/writers, the blocking-AST path
(osc_ldlm_blocking_ast -> __osc_dlm_blocking_ast -> osc_lock_flush),
flushing stale pages.  LRU pressure cancels the same way via
osc_ldlm_weigh_ast.

cl_object_ec_flush() is used to flush stale EC-reconstructed pages
from per-stripe lock enqueue, after a successful normal sub-lock
enqueue on a stripe, it only cancels unused placeholder ldlm locks.

Add ldlm_resource_clear_ec_placeholder_flag() to clear the
has-placeholder flag if the resource holds no granted EC placeholder
locks.

Add ldlm_lock flag LDLM_FL_EC_PLACEHOLDER to indicate a lock is an
EC placeholder lock.  Add ldlm_cancel_flags LCF_EC_PLACEHOLDER to
scope the cancel to placeholder locks only.

Export symbol ldlm_lock_create/ldlm_lock_destroy/ldlm_lock_enqueue/
ldlm_cli_cancel_unused for use in other modules.

Add cl_lock_cancel() before cl_lock_fini() in the lov_lock_sub_init
error path so initialized sub-locks are properly cleaned up.
lov_lock_cancel() also call cl_lock_cancel() with every sublock with
sub_initialized set rather than only sub_is_enqueued, so that
placeholder locks are cancelled and normal locks w/o enqueue are
also cancelled.

Add a test_49a second-read and OST-reactivation check to verify pages
stay cached and are invalidated when the OST comes back.

AI code review results below, please doublecheck

Problematic, see inline comments. The core mechanism does not appear to work as described: on a client namespace ldlm_lock_enqueue() with LDLM_FL_BLOCK_GRANTED puts the lock on lr_waiting rather than granting it, the lock has no l_conn_export and no extent policy, and LDLM has an explicit LASSERTF against locally-created locks in a client namespace (ldlm_cli_enqueue_local()). Since the placeholder never functions, the ClearPageUptodate() removal in vvp_io_ec_rd_end() leaves reconstructed pages Uptodate with nothing able to invalidate them. It would help to build this on ldlm_cli_enqueue_local()'s pattern (policy assignment, addref, ldlm_set_local(), the final ldlm_lock_put()) rather than open-coding it, and to exercise the recovery path with a real OSC import deactivate/reactivate so IMP_EVENT_ACTIVE is actually delivered.
