--- Commit Message ---
LU-21197 llite: pin length-only unaligned DIO pages

Unaligned DIO used one flag for both "needs an internal DIO
buffer" and "sends a partial-page BRW". When only the I/O length
is not page-aligned, user pages already map 1:1 onto file pages,
so copying the whole range is unnecessary.

Add ll_dio_can_pin() and split unaligned (feature/BRW) from
use_dio_buf (internal copy). Pin when the file offset and every
user segment start on a page boundary and only the last segment
ends mid-page. With page-aligned bases and offset 0:

  iovec           before this patch   after
  [4096, 2000]    use_dio_buf         pin (short-tail, no loop)
  [2000, 4096]    use_dio_buf         loop: pin, then use_dio_buf
  [1024]          use_dio_buf         pin (short-tail)

A short non-final segment still makes ll_file_*_iter() loop.  That
segment can pin at a page-aligned file offset; the next segment
uses the buffer because it starts mid file page.  Non user-backed
iterators and encrypted files keep the old rule and pin only fully
aligned I/O.

Partial last pages still require the unaligned_dio OST feature
and the llite.unaligned_dio switch, and unaligned AIO is still
refused.

Also fix designated-mirror short-tail.  ll_file_*_iter() no longer
splits a multi-segment iovec when it can pin, so a combined
[PAGE, short] iter fails ll_iov_iter_starts_on_page() and stays
unaligned.  Against an OST without unaligned DIO that falls back
to page cache and leaves the mirror's pages cached.  Accept the
pinable multi-segment short-tail shape when clearing unaligned
for designated mirrors.

Add OBD_FAIL_OSC_NO_UNALIGNED_DIO so tests can force
ci_allow_unaligned_dio off.  sanity/119ra checks pin vs use_dio_buf;
sanity/119r keeps the copy fail_loc path; sanity-flr/214 covers
designated-mirror multi-segment short-tail.
