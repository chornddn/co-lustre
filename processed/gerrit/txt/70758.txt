--- Commit Message ---
LU-21197 llite: pin length-only unaligned DIO pages

Unaligned DIO used one flag for both "needs an internal DIO
buffer" and "sends a partial-page BRW". When only the I/O length
is not page-aligned, user pages already map 1:1 onto file pages,
so copying the whole range is unnecessary.

Add ll_dio_can_pin() and split unaligned (feature/BRW) from
use_dio_buf (internal copy). Pin when the file offset and every
user segment start on a page boundary and only the last segment
ends mid-page. With page-aligned bases and offset 0:

  iovec           before this patch   after
  [4096, 2000]    use_dio_buf         pin (short-tail)
  [2000, 4096]    use_dio_buf         use_dio_buf
  [1024]          use_dio_buf         pin (short-tail)

A mid-page segment with more I/O after it still uses the buffer.
Non user-backed iterators and encrypted files keep the old rule
and pin only fully aligned I/O.

Partial last pages still require the unaligned_dio OST feature
and the llite.unaligned_dio switch, and unaligned AIO is still
refused.

sanity/119v checks the vfstrace log for pin vs use_dio_buf.
sanity/119r seeks to an unaligned offset so the copy fail_loc
still fires.
