--- Commit Message ---
LU-21197 llite: pin length-only unaligned DIO pages

Unaligned DIO used one flag for both "needs a bounce buffer" and
"sends a partial-page BRW". When only the I/O length is not
page-aligned, user pages already map 1:1 onto file pages, so
copying the whole range is unnecessary.

Add ll_dio_can_pin() and pin user pages when the file offset and
every user segment start on a page boundary and only the last
segment ends mid-page. A segment ending mid-page with more I/O
after it still bounces. Non user-backed iterators and encrypted
files, where a partial page is padded to a whole encryption unit,
keep the old rule and pin only fully aligned I/O.

Partial last pages still require the unaligned_dio OST feature and
the llite.unaligned_dio switch, and unaligned AIO is still refused.

sanity/119v checks the vfstrace log to confirm the pin path is used.
