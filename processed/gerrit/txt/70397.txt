LU-21118 osd-ldiskfs: refuse lookup of names over NAME_MAX

The MDT does not limit the name length before looking it up in
rename and open, so a name longer than 256 bytes from a client
reaches osd_index_ea_lookup(), and osd_olc_save() LBUGs:

  osd_olc_save()) ASSERTION( ln->ln_namelen <= 255 + 1 ) failed
  osd_index_ea_lookup+0x6f8/0x770 [osd_ldiskfs]
  __mdd_lookup.isra.21+0x286/0x370 [mdd]
  mdd_lookup+0x10d/0x150 [mdd]
  mdt_lookup_version_check+0x59/0x2e0 [mdt]
  mdt_reint_rename+0x99b/0x1e30 [mdt]

Clients without LU-18783 on RHEL 10 kernels send such names on
rename. Return ENAMETOOLONG instead, as LU-21031 does for
osd-zfs.

ldiskfs cannot store a name over LDISKFS_NAME_LEN, decoded
encrypted names included, so shrink lce_name[] back to
LDISKFS_NAME_LEN and have osd_olc_save() skip longer names
rather than assert.

Add a rename case with a 257 character target to sanity test_110.
