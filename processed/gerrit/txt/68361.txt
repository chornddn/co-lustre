LU-00000 ec: use RAID10|PARITY (RAID10) so p may exceed k

The k >= p restriction is not a Cauchy/ISA-L limit. It comes from
storing coding stripes as RAID0|PARITY: p objects are concatenated
along the file offset, so nsets * p * stripe_size will not fit in a
finite PFL extent when p > k (for example --ec 2+3 -E 2M).

Write new EC parity as LOV_PATTERN_RAID10|PARITY with RAID10
geometry: outer striping across raidsets (one stripe_size per
raidset in the parity mirror row), and the p coding objects of
a raidset share that same file offset. RAID10 keeps raidset
structure in the file offset (outer RAID0 across raidsets) and
treats the p coding objects of one raidset as a RAID1 mirror
set at that offset. File extent still matches the data component:

  ec_off(row, rs) =
      e_start + row * (nsets * ss) + rs * ss

object_off = row * ss. Within a raidset, resync/verify must pick a
coding stripe via LL_IOC_FLR_SET_STRIPE /
llapi_mirror_{read,write}_stripe(). Punch and truncate still hit
all coding objects.

Example: -E 128M -c 11 -S 1M --ec 4+2

  data/parity extent [0, 128M)
  raidsets [4,2], [4,2], [3,2] (nsets=3)
  parity has 6 OST objects
  one data stripe-set row = 11M
  one parity row = 3M (not 1M flat, not 6M concat)

  row rs   data_pos    RAID10   old RAID0  objs
  --- ---- ----------- -------- ---------- ----
  0   0    [0, 4M)     0        0          0,1
  0   1    [4M, 8M)    1M       2M         2,3
  0   2    [8M, 11M)   2M       4M         4,5
  1   0    [11M, 15M)  3M       6M         0,1
  1   1    [15M, 19M)  4M       8M         2,3
  1   2    [19M, 22M)  5M       10M        4,5

When nsets == 1 (e.g. --ec 2+3), RAID10 degenerates to a single
leg and still fits p > k in a finite PFL extent. With --ec 1+N,
parity offsets align with each data stripe.

Existing RAID0|PARITY files keep the concatenated mapping.
lov_pattern_available() accepts the new combination; old clients
skip the unknown pattern and leave the parity component inert.
Finite-extent stripe-count shrinking is skipped for parity
components. The p <= k checks in lfs and llapi are removed;
k+p <= 256 and p <= 15 remain.

Tests: sanity-ec 4a/10 accept 2+3; test_300 covers PFL -E 2M
--ec 2+3 create/resync/verify; 12c/34c cover holes and multi-leg
offsets (34c asserts leg striping into raidset 1);
llapi_layout_test T47 allows 3+4.
