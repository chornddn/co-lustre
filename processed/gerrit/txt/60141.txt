LU-11520 tests: add run_test_should_fail() wrapper

Add a new run_test_should_fail() test runner that wraps run_test()
which expects the subtest to fail.  This allows splitting a test case
and its fix into two separate patches, where the initial test patch
is expected to fail (which will be considered a "PASS"), and the fix
patch changes run_test_should_fail to run_test to validate the fix.

The run_test_should_fail() code will not handle test failures that
cause the client or server to crash/LASSERT/BUG.  It will only handle
cases where error() is called by the subtest to indicate failure.

Rename $TYPE to $ERROR_TYPE to avoid ambiguity when passing status.

Remove the duplicate TEST_STATUS setting in pass(), since it is set
in run_one_logged() and should not override the set value.

Add test_0f() to exercise the new run_test_should_fail() test runner.

Add cleanup_test_dirs() helper function instead of duplicating
subtest directory cleanup logic in several places.  Move cleanup of
subtest directories with FSTYPE=wbcfs inside run_one_logged() to
avoid masking the return code from run_one_logged().

Minor test script style cleanups in nearby code.
