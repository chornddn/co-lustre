LU-20565 tests: merge similar sanity-ec degraded-read subtests

Many sanity-ec subtests ran the same create, write, resync and
degraded-read sequence and differed only in the file size, stripe
size, read offsets or the write before the resync.  Each repeated
the setup and the fault handling, and most hard-coded a 4+2 layout
with a gate of 6 or 8 OSTs, so they would be skipped on smaller
configurations.

Merge each group into one subtest that loops over the cases, and
keep the number of the subtest that remains:

- 61a: sub-stripe, partial-stripe, partial-row and multi-row file
  sizes with 64K, 256K, 1M and 4M stripes (42b 42c 46a 46b 46c
  61b)
- 58a: every pair of failed data OSTs, for 2+2 and for the default
  layout when it has 2 parity stripes (43b 45b 45d 52a 68b)
- 41a: aligned, unaligned and multi-row reads (41b 41c)
- 70a: overwrite then resync: across a row boundary, unaligned,
  after an extend, a partial row, either PFL component (67c 67d
  70b 70c 70d)
- 62a: staged, unaligned and sub-stripe appends (62b 62d)
- 60a: truncate mid-stripe, to a row boundary, to 0, and before an
  extend (60b 60c 73c)
- 32a: OST stop and start, then write and resync, twice (30c 33a)
- 34a: mirror resync, read and verify keep the size (34b)
- 20: parity component layout and stripe size for 4M, 1M and 64K
  stripes (1j)

Add ec_check_degraded() to read a file with the first, or each, data
OST that holds no parity failed, and optionally two of them.

The merged subtests use EC_ARG, EC_DSTRIPE and EC_CSTRIPE and size
files in rows of EC_DSTRIPE stripes, so they run with 3 OSTs (58a
with 4), and fail two OSTs only when EC_CSTRIPE >= 2.  Every
degraded read now compares the data with the healthy copy and
drops the client locks first: 41c read several ranges after one
drop_caches, 33a only checked that the read succeeded, and the
size of the unaligned appends in 62b was not checked.
