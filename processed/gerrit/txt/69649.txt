LU-20860 doc: add more agent workflow guidance

Add guidance that came up in recent patch work: when to start looking
for existing work, how to split and restack patches, which CI
follow-up an agent may do on its own patches, how to push debugging
patches, how to request extra CI sessions on a build, how to write
kernel compat code, fault injection and cheap, well-sized subtests,
which ZFS version to build against, and to leave master-next changes
alone.

Also address review comments on the first patch: link the ltvm repo
under github.com/lustre, note that auster leaves the filesystem
mounted after a failure, restrict skip_env to required packages, add
build, test and commit-msg traps found by other developers, and ask
for plain English.  Add Marc Vef as a reviewer.
