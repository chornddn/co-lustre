LU-20099 nrs: cache pages that queued reads will read again

When the clients of a job read one file at the same time, such as an
input file, osd-ldiskfs reads each page from storage for every client
once the file is larger than readcache_max_filesize, or the read is
readcache_max_io_mb or larger, because it reads into pages of its own
that it does not cache.

The batches of the TBF and mClock policies queue the reads of an
object in offset order, so the class bucket can tell when another
queued read of the object shares a page with the read it dispatches.
nrs_class_req_pop() then sets nr_read_shared on the request.  It looks
at the queued requests next to the offset of the read, in its round
and in the next round, which are the only rounds queued, so the check
stays cheap.  ofd_preprw_read() passes the new DT_BUFS_TYPE_SHARED to
dt_bufs_get() for such a read, and osd-ldiskfs caches its pages
whatever the size of the read and of the file, unless the read cache
is off.  The queued reads then find the pages in the cache.

Only the reads of one class bucket are compared, so reads of clients
in other classes or CPU partitions, and reads that are not queued
yet, still read the pages again.  DoM reads on an MDT are not changed.

Add sanityn test_77tm, which reads a file larger than
readcache_max_filesize with one O_DIRECT reader and then with eight.
The readers share a group lock, as the client otherwise serializes
O_DIRECT reads of one page.  One reader reads all 1024 pages from
storage.  Eight readers find 7104-7168 of their 8192 pages in the
cache, and none without this patch.
