LU-15873 osd-ldiskfs: support rdonly_dev as a read-only mount

Mounting an ldiskfs target with "-o rdonly_dev" fails with
-EOPNOTSUPP. The option relied on the dev_set_rdonly() kernel
patch, which discarded writes, and that patch is gone. Serving
a snapshot of an ldiskfs target needs rdonly_dev.

Mount the backing ldiskfs read-only and set dd_rdonly. The
existing dd_rdonly checks then skip LFSCK, OI scrub, precreate,
sync and recovery, as on ZFS. Also skip LMA self-repair. A write
that is not skipped fails with -EROFS instead of being dropped.
Do not enable large_dir on a read-only device.

As with any read-only ext4 mount, a journal that needs recovery is
still replayed and orphan inodes are cleaned up. On a read-only
block device, orphan cleanup is skipped and a journal that needs
recovery makes the mount fail. A snapshot taken without freezing
the filesystem needs recovery, so its journal is replayed onto the
snapshot volume.

Run the rdonly_dev part of conf-sanity test_113 on ldiskfs. It
now reads a file back through a read-only client, and checks that
no write was attempted and that the ldiskfs devices are unchanged.
Document rdonly_dev in mount.lustre.8.
