--- Commit Message ---
LU-20637 llapi: find the root of an upgraded filesystem

lfs find --device --paths composes a path by walking the directory map
up to the root, and only LU_ROOT_FID ended that walk. A filesystem
upgraded from before 2.4 keeps an IGIF root, so every object there
had no path.

Take the root from the map instead. ROOT has no linkea, but .lustre
has one, and LFSCK writes it on MDT0 at every mount with the real
root FID as its parent. Without .lustre in the map, as on any other
MDT, the root is LU_ROOT_FID as before. The root is named by the
same test, so --internal prints it as "/". Without --internal an IGIF
root is not printed: it has no linkea, so the scan counts it as
internal.

find_device_cb() and llapi_find_device.3 said .lustre has no linkea
and so no pathname. It has one, and is printed as /.lustre; say so.
The man page also says when an IGIF root is printed.

conf-sanity 305 makes an IGIF root: a metadata copy of MDT0000 by
e2image, then debugfs gives ROOT the IGIF of its inode and rewrites
the linkea of .lustre and the test directory to name it. --paths must
name the same objects as on the copy before the change, and
--internal must name the root. It fails without this change.
