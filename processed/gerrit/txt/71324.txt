LU-21139 ptlrpc: run the ping evictor from a workqueue

The ping evictor thread is started by the first MDT, OST or MGS
device and stopped by the last one.  pet_refcount and pet_state are
not protected, so devices that are set up or cleaned up in parallel
can start several evictor threads, or leave a thread that never
exits.  ping_evictor_stop() does not wait for the thread, so a new
start can also reinitialize pet_waitq while the old thread uses it.

Replace the thread with a work item in each obd_device, queued on
system_long_wq by obd_export_timed_evict().  The work holds a
reference on the obd, so nothing has to be started or stopped.
Remove ping_evictor_start(), ping_evictor_stop(), their callers and
the global list of obds.  The evictor moves to obdclass, next to the
export deadline tree that it walks.  Devices are no longer evicted
one at a time.

The work sets up its own lu_env for each run.  To keep that rare,
ptlrpc_update_export_timer() now queues the work only if an export
has timed out.  It used to wake the evictor on every deadline
update while obd_eviction_timer was zero.
