LU-21139 ptlrpc: run the ping evictor from a workqueue

The ping evictor thread is started by the first MDT, OST or MGS
device and stopped by the last one.  pet_refcount and pet_state are
not protected, so devices that are set up or cleaned up in parallel
can start several evictor threads, or leave a thread that never
exits.  ping_evictor_stop() does not wait for the thread, so a new
start can also reinitialize pet_waitq while the old thread uses it.

Replace the thread with a work item in each obd_device, queued by
obd_export_timed_evict() on a new obd_evict workqueue, which is
WQ_MEM_RECLAIM since eviction frees memory.  The work holds a
reference on the obd, so nothing has to be started or stopped.
class_cleanup() cancels pending work, and the work does nothing once
the obd is stopping.  Like the thread, the work unshares its fs_struct
so osd_create() does not change the umask of init_fs.
Remove ping_evictor_start(), ping_evictor_stop(), their callers and
the global list of obds.  The evictor moves to obdclass, next to the
export deadline tree that it walks.  Devices are no longer evicted
one at a time.

The work sets up its own lu_env for each run.  To keep that rare,
ptlrpc_update_export_timer() now queues the work only if an export
has timed out.  It used to wake the evictor on every deadline
update while obd_eviction_timer was zero.

Since no lu_env is kept between evictions, mdd, osp and mdt are no
longer pinned by an evictor thread that was never stopped, which
made rmmod fail with "Module mdd is in use" in sanity-sec test_31
(LU-21149).

Patch Set 2:

PS2 vs PS1, from a local review:
- Queue the work on a new "obd_evict" workqueue (WQ_MEM_RECLAIM | WQ_UNBOUND) created with zombie_wq at obdclass init, instead of system_long_wq.
- Call unshare_fs_struct() at the start of the work, as the old thread did, so osd_create() saving/zeroing current->fs->umask can't touch the init_fs shared by all kworkers. Unbound kworkers are shared between workqueues, so there is no per-worker init hook; after the first run on a kworker it is just a check.
- class_cleanup() now does cancel_work_sync() after setting OBDF_STOPPING and drops the "evictor" ref if work was pending; the work skips eviction once the obd is stopping.
- Dropped the stale ping_evictor_main entry from crash-find-unique-traces.awk.
- The env-setup CERROR is already rate limited (CERROR is CDEBUG_LIMIT), so that is unchanged.
- Commit message names LU-21149 and has real Test-Parameters in place of "ignore".

Tested locally (rocky9 aarch64, 4 MDT/4 OST): recovery-small 10a 11 18b 24b 58 59 66 108 146 153 161 all pass, and modules unload cleanly with no LBUG. On a 2-node cluster sanity-sec test_31 passes, and mdd/mdt/osp then unload on the server without "Module mdd is in use".
