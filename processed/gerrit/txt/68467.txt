LU-20663 rustreapi: write the stripe pattern through the union

LU-16518 moved lsp_stripe_pattern of struct llapi_stripe_param into
an anonymous union with lsp_hash_type.  bindgen emits that as
__bindgen_anon_1, so rustreapi does not compile against master's
headers: "no field `lsp_stripe_pattern`".

Gating on the Lustre version does not work: lu-version reads the
installed "lfs --version", which need not match the headers bindgen
parses, and 2.17.53 sets LUSTRE_2_18 without having the union.
Probe the generated bindings for lsp_hash_type instead, and set
has_lsp_union.  The setter takes a plain u32, since pre-2.17 headers
declare the field int and have no enum lov_pattern.

Replace the rerun-if-changed on src/bindings.rs, which never existed
and made cargo rerun the build script every time, with bindgen's
CargoCallbacks for the parsed headers.  lu_version::export_features()
declares the lfs binary and PATH, as all callers share that probe.
