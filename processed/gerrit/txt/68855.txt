LU-20107 nrs: lend the idle ceiling share of a global rule

A global rule divides its rate over the CPU partitions of the
service. LNet binds a NID to one partition, so a client with one NID
reaches one partition. That client gets the share of one partition,
and the rule wastes the share of every idle partition. The LU-20107
design has a partition with a backlog borrow the idle quota from its
parent.

Add a shared token pool on the node class of a global rule. Each
partition adds the cost of a dispatched request to a shared counter.
The pool accrues the node rate with the passage of time, and it takes
the counter away. A partition that is over its ceiling asks the pool
to pay for the request. A partition that the pool pays moves
its ceiling deadline back to the current time. The request thus
dispatches at once.

The pool only bridges the interval between two accruals. It therefore
holds at most one bucket depth for each partition. The unit of that
depth is the cost of an RPC with no bulk data. A small request thus
does not discard the saved share. A request that costs more than the
bound can still take the whole pool. An idle rule cannot save more
than that. The measured rate then stays inside the node rate over a
window longer than the depth.

A rate change on a global rule writes the node rate into the node
class. The write holds the pool lock. The pool then reads the new
rate and mode.

The pool lends the ceiling share only. The reserved share of an idle
partition stays with that partition.

Add pool_tokens and pool_draws to the YAML rule dump.

The pool lets the pinned flow of test_77xj reach the node rate. The
test therefore bounds that flow by the node rate.
