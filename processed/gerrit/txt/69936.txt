LU-20791 efalnd: Destroy connections only from the daemon

A connection establishment error destroyed the connection in place, on
the context that hit the error. The connection was already published in
the hash table and visible to concurrent lookups, so another context
could hold a reference and still be using it when it was freed, a
use-after-free. The reference count added to guard this was only honored
by the cleanup daemon, not by these error paths.

Have the error paths deactivate the connection instead of destroying it:
unhash it and mark it for teardown, then leave the actual destroy to the
daemon, which already waits for the reference count to drain and the
transmit queues to empty. The daemon is now the only context that
destroys a published connection.

Deactivation defers the cancellation of the connection's pending
transmits to the daemon, which previously cancelled them all with one
generic status. Record the health status and errno on the connection
when it is marked for teardown so the daemon can apply the specific
reason the tearing-down context knew. The idle scanner stores an
aborted-on-timeout reason and a connection never torn down this way
keeps a benign default.
