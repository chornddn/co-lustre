LU-21241 quota: keep qsd deferred update list sorted

Running four or more lfs setquota commands in parallel can cause quota
limit updates to stall on the slaves.  The QMT global index contains
all the new limits, but only the first few reach the slaves, which
still report themselves as up to date.

qsd_add_deferred() is intended to keep deferred glimpse updates sorted
by version.  After each update is committed, qsd_kickoff_deferred()
processes the next update only if the version at the head of the list
is the expected one.

However, when an incoming update has a higher version than tmp,
qsd_add_deferred() uses list_add_tail() to insert it before tmp.  This
can reverse the order of updates that arrive in ascending version
order, leaving a newer version at the head of the list.  As a result,
qsd_kickoff_deferred() cannot process the next expected version, and
subsequent updates remain stalled until the slave is reintegrated.

Replace list_add_tail() with list_add() to insert the update after tmp
and preserve the correct version order.

Add sanity-quota test_47 to set and delete quota limits for multiple
project IDs in parallel and verify that all updates are applied on the
quota slaves.
