LU-20290 lustre: register servicenode NIDs with LNet visibility

Use the existing --servicenode target configuration to register
servicenode NID membership with LNet.

server_lnet_servicenode_update() publishes one entry per target,
keyed on the target service name (lsi_svname), whose members are
the local NIDs the mkfs failover.node list names. That key choice
is what determines the LNet grouping.

When ptlrpc.target_nid_policy=servicenode, Lustre enables the
corresponding LNet discovery visibility policy so that clients
discover peers partitioned by servicenode.

Without target_nid_policy=servicenode, servicenode information is
registered but does not change legacy discovery behaviour.

Document the option in a new man page, which describes the legacy
and servicenode values, where the groups come from, and what a node
advertises when no group covers a NID.

Add tests for the policy. Verify that:

- legacy discovery behaviour is preserved when the policy is
  disabled;
- the servicenode policy partitions discovery views by
  servicenode;
- the servicenode policy composes correctly with the existing
  self and NUMA discovery grouping policies;
- a local NI that no servicenode group contains stays discoverable;
- the policy is in force before the first target mounts;
- a Push sends a group view and not the merged full view;
- a target formatted with --failnode contributes no group;
- an unknown policy value stops the module load.

The setup helper can now stop after the LNet configuration or after
the first target starts, can make more than two nets, and can give
each target a different set of service-node NIDs. These controls let
a test look at the node before a target mounts, and make more than
one group on one net.

The test environment permits only one LND. The tests thus make
several nets of the same type (${NETTYPE}, ${NETTYPE}1, and so on)
on one interface.
