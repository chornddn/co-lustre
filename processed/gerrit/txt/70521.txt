--- Commit Message ---
LU-17637 tests: use non-zero data in sanity 56xk

sanity test_56xk times 'lfs mirror resync -W 1M' on a 5MB file
and fails with "too fast (0 < 0.95 * 5)" on ZFS. The file is
written from /dev/zero, which ZFS compression stores as holes.
Resync skips holes (SEEK_DATA), so nothing is copied and the
bandwidth limit never applies.

Write the file from /dev/urandom so there is data to copy.
With lz4 compression enabled on the ZFS OSTs, the test failed
"too fast" before this change and passes with it.

Test-Parameters: trivial fstype=zfs testlist=sanity env=ONLY=56xk
