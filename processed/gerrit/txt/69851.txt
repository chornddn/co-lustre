LU-20730 target: limit an object table scan by nodemap

A scan from a client reads the whole object table of each MDT, and
OBD_IDX_READ carries no user credentials.  With nodemaps active the
MDT now decides by the client's nodemap:

- it must be admin and have the byfid_ops role; otherwise -EPERM;
- a tenant, a nodemap with an ID offset, then gets only the records
  whose UID and GID are both in its ranges, as every file it creates
  is, with the IDs mapped back to its own; a dynamic sub-nodemap,
  which shares its parent's ranges, is refused;
- a nodemap without an offset gets everything, so it must also be
  trusted and have no fileset, nor its parent; otherwise -EPERM.

With nodemaps inactive nothing changes.  The ID ranges stand in for
the tenant's fileset: nodemap already puts every file a tenant creates
inside them, and checking a path on the MDT would cost a lookup per
object.  That holds only while no other nodemap creates files with
IDs in the tenant's ranges, which nodemap does not prevent.

The records are filtered in place after dt_index_read(), so the
object walk and the resume hash are unchanged.  What is dropped is
zeroed, since the whole container goes to the client.  A container
can come back with no records; the client already reads on until the
MDT says the table has ended.
