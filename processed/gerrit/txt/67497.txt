LU-6301 llite: clear rq_replay for failed opens in ll_open_cleanup

The first LU-6301 patch added ll_open_cleanup() to send a close RPC
when the client hits an error after the MDT has granted an open,
so the MDT-side open handle is not leaked. That fix only covers
the server side: the original open request is replayable,
so after_reply() left it on the import replay list with rq_replay
set, and because a failed open has no close/commit callback
(mdc_commit_open) nothing ever clears rq_replay.
The request then stays on the committed-replay list until reconnect,
pinning its reply buffer (sized to max_mds_easize, which can be hundreds
of KB with wide/PFL/DoM layouts). Under an open-heavy workload that
takes the open-error cleanup path frequently this accumulates without
bound and can OOM the client.

This becomes easy to hit once ll_splice_alias() uses d_splice_alias()
for directories (which, unlike the old d_add(), can return -ELOOP or
-ESTALE): a racing rename/create workload then drives ll_lookup_it_finish()
into this error path thousands of times per run.

Clear rq_replay in ll_open_cleanup() after the MDT open handle has been
released, so ptlrpc_free_committed() can drop the request once its
transaction commits. The server-side handle is already closed at this
point, so dropping replay for this request is safe.

Make ll_open_cleanup() idempotent and self-guarding while here. It now
takes the lookup_intent: it does nothing unless DISP_OPEN_OPEN is set
(there is no granted open handle to release otherwise, which also stops
it from md_close()ing a bogus handle), and it clears DISP_OPEN_OPEN once
the handle is released. The same intent is shared across ll_prep_inode(),
ll_lookup_it_finish() and ll_atomic_open()'s out_release, so a second
cleanup of the same abandoned open now short-circuits at the guard rather
than double-closing. Only DISP_OPEN_OPEN is cleared; DISP_ENQ_OPEN_REF
must survive so ll_intent_release() still drops the request reference that
mdc_finish_intent_lock() took for the open. The callers reduce to
"DISP_OPEN_OPEN && it_request" and no longer reach into rq_replay /
rq_commit_cb.

Looks good. The rq_replay clear plus the it/DISP_OPEN_OPEN gating and the rq_commit_cb/rc_req guard are consistent: on a replayable MDC import the abandoned-open request stays pinned on the replay list (so rc_req is valid), and rq_early_free_repbuf is only ever set together with rq_commit_cb, so the guard also avoids the freed-reply-buffer LBUG. One trivial style nit inline.
