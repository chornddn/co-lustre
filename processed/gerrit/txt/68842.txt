LU-20340 utils: add recursive option to lfs setstripe

Add a -r/--recursive option to 'lfs setstripe' so a default layout
can be applied to a directory and all of its existing subdirectories
in one command, rather than one directory at a time.

Existing regular files are never touched, since their striping is
fixed at creation. DIRECTORY itself is dereferenced normally if it
is a symlink (matching 'chmod -R'/'chown -R'), but symlinks and
mount points found during the descent are not followed into. An
error applying the layout to one directory does not stop the rest
of the tree, including that directory's own children, from being
visited; the command exits with the first error seen, if any.

The layout is applied through an already-opened, verified fd at
every level, rather than by re-opening a path, so a symlink swapped
in for a target cannot redirect where the layout lands. This needed
a new fd-based counterpart to llapi_file_open_param() for a plain
(non-composite) layout, llapi_stripe_param_apply_by_fd(), plus
llapi_stripe_param_verify_pool() to resolve and verify the pool name
once per run instead of once per directory; llapi_file_open_param()
itself now calls both. Both are declared in lustreapi_internal.h,
alongside other lfs-only helpers, rather than the public lustreapi.h.

-r is rejected up front, before any layout is applied, when combined
with --component-add, --component-del, --component-set, --foreign,
or --mirror-count (mirrors build their layout separately from the
one this option applies recursively), or when the target is not a
directory.
