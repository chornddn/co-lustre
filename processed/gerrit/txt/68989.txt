LU-20645 utils: add --printf and --ls opts to lfs-getstripe

Add --printf and --ls options to lfs-getstripe matching the behavior
of corresponding lfs-find options, for printing specific fields of a
file's layout.

In order to reuse lfs-find code, the following functions have been
exposed in lustre/utils/lustreapi_internal.h: printf_format_string()
and convert_lmd_statx().

Includes documentation and tests for output parity with lfs-find and
symlink behavior during recursive traversal.

Options which select layouts, components, or mirrors (-O, -D,
--mirror-*, and -I/-E/--comp-* with an argument) are rejected with
--printf/--ls, suggesting lfs find instead.

Exporting printf_format_string() lets gcc see a possibly NULL path
in a find error message, so guard it there.

Patch Set 6: Code-Review+1

The code looks good to me, and the earlier review points are all fixed. Two optional points, for whenever the patch is refreshed:

1. There is no test for the new error path. A short check that "lfs getstripe -O <ost> --printf '%p\n' <dir>" and "lfs getstripe --mirror-id=1 --ls <file>" fail would keep it from breaking later.

2. -m and the other display options (-c, -S, -y, -v and so on) are accepted with --printf and have no effect on the output. But without -r they still change how far getstripe goes: "lfs getstripe -m --printf '%p\n' dir" prints only the directory, while "lfs getstripe --printf '%p\n' dir" also prints its entries. It may be worth one sentence in the --printf entry of the man page, as you did for --no-follow.

I agree with the AI review that the --ls format string should be shared with lfs find.
