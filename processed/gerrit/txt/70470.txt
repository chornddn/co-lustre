LU-20908 utils: add llapi_ost_object_migrate()

Emptying an OST with lfs migrate rewrites every file that has an
object there, along with all its other objects, and lfs migrate can
neither take a file by FID nor avoid the side effects of a group lock
on mirrored and PFL files.

Add llapi_lov_object_iterate() to walk the OST objects of a raw
lustre.lov buffer, as fgetxattr() or llapi_scan_device() return it,
and llapi_ost_object_migrate() to move one object to another OST with
the single-object layout swap.  The object is read at its own offsets
through OBJECT I/O scope (LU-20802), so no stripe arithmetic is done
here, and copied into a one-stripe volatile file, skipping holes,
under a read lease that fails the move if another writer opens the
file; the swap checks both data versions.  LLAPI_OBJ_MIGRATE_LOCK_COPY
takes a group lock instead, for files that stay open for writing.

The MDS allocates the new object, as for any new object, unless the
caller names an OST.  The object is never put on an OST the caller
excludes, nor beside another copy of its data: another stripe of a
component that is not overstriped, or a mirror or parity covering the
same extent.  A progress callback lets the caller limit the bandwidth
or stop the copy.
