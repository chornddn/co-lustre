LU-20147 ptlrpc: module-level cache for SELinux policy upcall

Replace the SELinux policy kept in each ptlrpc_sec with one
upcall_cache entry shared by all imports. With a flavor that has a
sec per import (e.g. SSK), l_getsepol now runs at most once every
send_sepol seconds per node, not once per import.

An enforcing mode change is now sent. Before, the kernel dropped a
new policy with an unchanged mtime, so setenforce was not seen.

When a check is due, the kernel runs l_getsepol with the cached
policy mtime and enforcing mode (-t/-m), as before, so it sends a
new policy only if one of them changed. With send_sepol=-1 this
still happens on every call. Between checks, the current policy, or
the cached empty policy or error, is taken without locking.

If SELinux is disabled (-ENODEV), an empty policy is cached and no
policy is sent. A helper error is also cached until the next check,
but a connect runs the helper again, so a mount works as soon as the
helper is fixed. A failed check keeps the cached policy for later
calls, as before.

l_getsepol and the downcall layout are unchanged. It still writes
to the srpc_sepol file of a requesting import, and other callers
wait for that one upcall. All per-OBD srpc_sepol files write to and
show the shared cache.

The upcall_cache wait is now killable for all its users, so a caught
signal does not fail a caller with -EINTR while another process runs
the upcall. The wait does not count in the load average, so a slow
identity or GSS upcall does not raise it on servers.

sanity-selinux: add test_21e, new imports use the cached policy
(fails before this patch with SSK only), and test_21f, an enforcing
mode change is sent after send_sepol seconds.
