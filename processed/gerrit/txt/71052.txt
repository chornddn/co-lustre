LU-19709 osc: reserve grant again on extent restart

A buffered write can hit this LBUG in osc_extent_find():

  ASSERTION( *grants >= chunksize + cli->cl_grant_extent_tax )
  failed: 0/4096/24576.

A page that fits in the extent its writer already holds is
added without reserving grant. If that extent is sent to
writeback before the page joins it, the writer waits for the
write and searches for an extent again. The retry started
below the grant reservation, so it searched with no grant.
When the extent had come from a search instead, the retry
reused a reservation already returned, and the client's
reserved grant went negative.

Retry from the grant reservation, as a first attempt does,
after dropping the page's dirty accounting.

The writer also waited while holding the locks of pages it
had already added to that extent, which the writeback needs:
the write and the writeback waited on each other. Commit those
pages before waiting.

Add OBD_FAIL_OSC_EXTENT_RESTART to force the restart, and
sanity 64l, which hits the assertion without the first fix
and hangs without the second.

This builds on https://review.whamcloud.com/63060 by Qian
Yingjin and Chris Horn, which first moved the retry above the
grant reservation.
