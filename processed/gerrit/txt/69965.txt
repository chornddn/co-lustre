LU-21023 ofd: keep an OST object's parent FID once it is set

ofd_object_ff_update() set the parent FID of an OST object from every
client RPC that carried one. When a file gets a new FID, by migration
or a layout swap, the MDT sets the new parent itself, but a write or
punch that a client built from the old layout could arrive after that
and set the old, destroyed FID back. Layout LFSCK then repaired an
unmatched MDT-OST pair.

Take the parent FID from a client RPC only when the object has none
yet, and keep a component ID set with it too: the MDT rewrites both
when mirror merge or split renumbers components. Once set, the MDT
owns them, so make it rewrite the parent FID wherever objects get a
new parent:

- lod: lod_obj_stripe_replace_parent_fid_cb() also sets it on an
  object not written yet (-ENODATA), which had none to replace.
- mdd: mdd_xattr_split() also rewrites it for the split mirror's
  objects, which move to the new file, unless that is a volatile file
  (lfs mirror split -d), which is destroyed with them right after.
- mdd: mdd_object_pfid_replace() logs a failure, including one to
  create the transaction. It runs after the layout change has
  committed, and layout LFSCK is now what repairs the objects it
  missed.
