LU-20200 utils: report unreachable targets in lfs df -l

"lfs df -l" sends OST_STATFS with no-delay, but since LU-4665 the
-EAGAIN returned for a disconnected OST is treated like an empty OST
index and silently skipped, so the OST is missing from the output
and lfs exits 0.  For MDTs, lmv_iocontrol() ignored the lazy flag
entirely, so "lfs df -l" blocked until a stopped MDT recovered.

Skip -EAGAIN in mntdf() only if no target UUID was returned, which is
the case for an empty index, so unreachable targets are printed with
an error and lfs exits non-zero.  Check the --pool filter before
recording an error, so targets outside the pool do not set the exit
status without being printed.  As for other OST errors, an
unreachable OST excludes MDT space from the summary.  When no path
is given, keep listing the remaining filesystems after one of them
returns an error.

Pass LL_STATFS_NODELAY through lmv_iocontrol() as lov_iocontrol()
already does, and return -EAGAIN instead of the -ENODEV that
mdc_statfs() gets from a stopped MDT, since -ENODEV tells lfs there
are no more targets.

The default "lfs df" behaviour of waiting for recovery is unchanged,
since test-framework relies on it to detect recovery completion.

Add recovery-small test_190 to verify this.
