LU-18456 tcu: delay trash creation ".lustre/.ltrash/MDTXXXX"

The ".lustre/.ltrash/MDTXXXX" directory for each MDT is the storage
for the Trash Can/Undelete feature. The previous patch created it
immediately after the MDT finished stack setup and recovery.

Creating and initializing the Trash Can directory triggers OI scrub
fixing and changes scrub accounting, causing sanity-scrub.sh/test_4b
"prior_updated" checks to fail.

Disable Trash Can initialization by default at server startup. The
startup path can be enabled by a later patch through an MDT mount
option.

Improve the "mdd.*.trash_can_enable" tunable. When Trash Can is
enabled, check whether it is initialized; if not, launch a thread to
create and initialize the Trash Can directory.

The setup thread retries transient failures with capped exponential
backoff and gives up after about 300 seconds. Serialize the startup
and teardown paths with mdt_trash_init_lock, propagate the helper
result through lgt_rc, and do not hold mdt_trash_init_lock while
waiting for the helper so umount cannot be blocked by set_param.

Add mdd_trash.c for per-MDT trash object teardown and its Makefile
entry. Split lu_generic_thread_stop() into lu_generic_thread_wait()
with an abort argument, use complete_all() in
mdt_trash_setup_thread(), and return -EROFS from mdt_trash_setup() on
a read-only device.

Add sanityn test_117a.
