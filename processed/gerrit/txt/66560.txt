LU-20344 lnet: introduce lnet_peer_discovery_mode parameter

The existing lnet_peer_discovery_disabled module parameter is a plain
boolean whose sole role is to toggle peer discovery on or off.
Replace it with lnet_peer_discovery_mode, an enum that will grow to
support NID-filtering modes in a follow-on patch.

Two values are defined for now:
  LNET_DISCOVERY_MODE_DISABLED (0) -- peer discovery off
  LNET_DISCOVERY_MODE_ENABLED  (1) -- merge all NIDs (default)

The deprecated lnet_peer_discovery_disabled parameter is retained as
an override: discovery is off when it is non-zero OR the mode is
DISABLED, resolved by a new lnet_discovery_off() predicate. Existing
sites that set the deprecated parameter keep their behavior regardless
of apply order. Supplying it at module load emits a one-time
deprecation nudge; runtime "lnetctl set discovery" stays quiet.

Introduce lnet_discovery_apply_locked() to centralize the ping-target
feature-bit update. The previous logic in discovery_set() would call
lnet_push_update_to_peers(1) when discovery transitioned from on to
off, but this was dead code as the force argument was ignored with
discovery off, and lnet_peer_needs_push() returns false with
discovery disabled.
Replace every direct lnet_peer_discovery_disabled reference in
api-ni.c, peer.c, and router.c with lnet_discovery_off().

Wire the new parameter through lnetctl (set discovery, global
show, export) and the DLC YAML import path. Update sanity-lnet tests
to load LNet with lnet_peer_discovery_mode=0 instead of the deprecated
parameter. Add new test to exercise the new parameter.

No behavior change.
