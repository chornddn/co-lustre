LU-20862 lmv: treat newline as qos_exclude separator

sanity test_413k and test_413l save the exclude list with
"lctl get_param -n", which prints one pattern per line, and restore
it with "lctl set_param".  The write handler only splits on ':', so
the restore stores both lines, newline included, as one pattern that
matches nothing, as does "echo name > qos_exclude_patterns".  After
413l runs once, the next 413k on that client fails with "_temporary
on MDT1".  It also leaks its prefixes: qos_exclude_prefixes hides
the bogus entry, so 413k saves an empty list, and lctl rejects the
empty value when restoring it.  For example, with the default list:

    client# lctl get_param -n lmv.*.qos_exclude_patterns
    _temporary
    _temporary.*

a restore of that output leaves one entry "_temporary<LF>_temporary.*"
(LF is the newline).  get_param still prints the same two lines, but
qos_exclude_prefixes now prints nothing and "_temporary" is no longer
excluded.  With the fix the restore leaves the two entries as above.

With two mounts on a client, "lmv.*" matches both LMV devices, so a
saved list has every pattern twice, and each restore doubles the
list on both devices.

Treat a newline as a pattern separator like ':'.  Clear the list on a
write with no names and no '+'/'-', as "echo > file" did in effect
before by storing a pattern that matched nothing.  Do not add a
pattern that is already in the list.

Also make sanity 413k and 413l save and restore the full list as a
':'-joined qos_exclude_patterns that is never empty, since prefixes
are stored as two patterns and a prefixes write without '+'/'-'
replaces all patterns.  Check that newline-separated patterns keep
mkdir on the parent MDT.  Add sanityn test_250 to check that adding
patterns twice, or writing back the list of both mounts, does not
duplicate patterns.
