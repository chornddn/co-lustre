LU-14408 osc: skip namespace walk when no lock was taken

osc_object_prune() exists to clear l_ast_data on the DLM locks that
still point at an object when that object is destroyed, and it does so
by looking the object's resource up in the namespace and iterating its
locks. That is only needed if a lock was ever attached to the object:
l_ast_data is set from einfo->ei_cbdata when the lock is created, and
from the object in osc_set_lock_data() when an existing lock is
matched, so both places can record that the object needs pruning.

A client that is evicting a metadata-only population has no locks on
almost all of those objects - the LU-14408 client holds five locks for
16M objects - so the walk is a namespace hash lookup that misses, once
per stripe, for every object that is destroyed. With the 40-stripe
files in that report that is up to 40 misses per inode.

Record on the osc_object whether a lock was attached to it and skip
the walk otherwise. Objects that did take a lock take the existing
path unchanged.
