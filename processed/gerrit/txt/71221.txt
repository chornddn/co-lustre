LU-20904 ofd: no PFID check before a parent FID is stored

With lfsck_verify_pfid enabled, the OST checks the parent FID that
a client sends with a write or punch against the one stored in the
object's filter_fid.  For a mirrored or EC file, the MDT stores the
layout version in the objects' filter_fid before the first write
does, which leaves a filter_fid with no parent FID.  The OST would
take that as a mismatch and ask the MDT to verify the object,
returning -EINPROGRESS to the client meanwhile.  For a mirrored file
the MDT would confirm the object and the OST "repair" it.  For an EC
file the MDT would refuse the parity layout with -EOPNOTSUPP, so the
object was never verified, and the client would resend every I/O to
the file forever.

Treat a filter_fid without a parent FID like a missing one: there
is nothing to check, and the write stores the client's parent FID.

Add sanity-lfsck test_19c to write a mirrored and an EC file with
lfsck_verify_pfid enabled.
