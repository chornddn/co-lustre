LU-20076 tests: stop a target with one remote command

Stopping a target cost three remote commands: a check that
it is mounted, the umount, and the wait for devices in the
ST state, which polls with one more command each time. With
dm-flakey enabled (the default) a fourth checks for module
support on every stop. A ZFS target adds the pool export,
and where the dm-flakey device is removed (a failover pair,
CLEANUP_DM_DEV, or a second file system) the removal adds
more.

Run all of this as one remote script. The wait for the ST
devices runs on the server, with the same intervals and
limit, and wait_exit_ST() also uses that script. Messages
are the same as before, but they are printed when the script
ends rather than as it runs, so the progress of a long wait
shows only at its end. The dm-flakey support check now runs
only where the device is removed.

The return code is that of the remote script. If the remote
command itself fails (the server is unreachable or dies
during the umount), stop() now returns that failure, where
it used to return 0; callers that check it, and stopall, can
fail where they passed before.

Measured on a cluster of one MDS with 4 MDTs, one OSS with 6
OSTs and 2 clients, median of 3 to 6 runs, as is and with
0.25 s added to each remote command (command counts are for
FLAKEY=false; with the default an ldiskfs stop was 4 -> 1):

                cmds       as is           +0.25 s
  stop ost1    3 -> 1   0.29 -> 0.12 s  1.00 -> 0.35 s
  stop mds2    3 -> 1   0.34 -> 0.23 s  1.09 -> 0.47 s
  stopall     34 -> 14  22.5 -> 21.3 s  23.9 -> 23.5 s

stopall's time is mostly an umount wait in the kernel. CI
stops about 8.5 million targets in 30 days; at least two
fewer commands of 0.2 to 0.35 s each, counting a parallel
stop as half, is roughly 430 to 1240 hours of test time, more
on configurations with failover partners.
