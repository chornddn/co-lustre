--- Commit Message ---
LU-20944 lnet: charge routed drops to peer NI health

When lnet_complete_msg_locked() fails to send a message, the error
was returned to lnet_finalize() without running the health check, so
a routed message dropped because the next hop is down left the peer
NI at maximum health and off the recovery queue, black-holing the
peer indefinitely. Record the error in msg_ev.status and run the
health check before retrying the finalize loop.

Also stop lnet_send() from overwriting a health status already set by
lnet_post_send_locked(), and clear the stale status when a message is
queued for resend so the next attempt is classified on its own merit.

Resending a routed message holds a router buffer for the whole retry
sequence, so add the lnet_routed_resend tunable. Set to 0 a failed
routed message is only charged to health and finalized on the spot,
which bounds the buffer usage of a router during a drop storm.

Add sanity-lnet test_229 to verify routed drops decrement peer health
and queue the peer NI for recovery.
