Some concerns, see inline comments. The main one is that the server treats the client's own request as the approved answer whenever the auth helper does not emit the new trailing options field, which inverts the "authorized by external GSSIAM server" model into a client-controlled one.

The new sanity-sec coverage only checks that the option string round-trips through /proc/mounts. Nothing exercises the part that matters: that a client asking for disable_rootsquash is actually squashed when the upcall does not approve it, and not squashed when it does. A test that sets the mock helper to approve/deny and then checks root's effective uid on a created file would cover the feature itself.
