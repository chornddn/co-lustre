LU-19921 sec: add disable_rootsquash mount option

Add -o disable_rootsquash mount option, so each user can
explicitly specify disable_rootsquash options, which will be
sent to the server by GSSIAM init ctx RPC, and authorized by
external GSSIAM server.

To enable this preference to be propagated and dynamic child
nodemaps to raise privileges dynamically, the "gssiam" parent
nodemap's default configuration is updated:
(allow_root: false -> true, deny_unknown: true -> false).
This security-posture change is safe because no client is mapped
directly to the parent nodemap. All clients are mapped to
dynamically created child nodemaps, whose allow_root and
deny_unknown settings are explicitly configured and locked down
per connection inside gssiam_get_nodemap() based on the
authorized options returned by the server upcall.

Additionally, this patch extends the kernel/userspace upcall
contract by appending a fourth ":options" field to the downcall
string format parsed in tgt_gssiam.c. This downcall string format
is now: "mount_option:expire:principal:options". Any third-party
helpers or daemons interacting with this downcall cache interface
must be updated to handle this extended format.

Furthermore, on the client-side, the mount read-only indicator
has been switched from the generic OBD_CONNECT_RDONLY to the
newly defined GSSIAM_OPT_RDONLY flag in the
gssiam_mount_option_flags enum. While both flags share the
numerical value of 0x1, this shifts what the server-side check is
nominally comparing against, cleanly separating the GSSIAM-specific
options space from standard connection flags.

Some concerns, see inline comments. The main one is that the server treats the client's own request as the approved answer whenever the auth helper does not emit the new trailing options field, which inverts the "authorized by external GSSIAM server" model into a client-controlled one.

A test that sets the mock helper to approve/deny and then checks root's effective uid on a created file would cover the feature itself.
