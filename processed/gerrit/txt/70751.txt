LU-20844 tcu: extend fid2path APIs to resolve trash object

Extend fid2path APIs to resolve the original path and the trash path
of an object in Trash Can. The changes include:
- Make the MDT stop the LinkEA walk of mdt_path_current() at
  LU_TRASH_FID and prefix the result with ".ltrash/", so that
  llapi_fid2path/_at() can resolve a deleted object to its trash path.
- Append a new variable length field to struct lustre_unrm_xattr for
  different kinds of extension, but its base header is not changed.
- Add a new flag URM_FL_TS_APPEND and set it when a timestamp is
  appended to the original name on a repeated deletion.
- Add a new unrm xattr extension struct unrm_ts_append with
  uta_orig_namelen, which is the length of the original name. With it
  and URM_FL_TS_APPEND, the original name can be truncated out from
  the renamed one in LinkEA.
- Add llapi_fid2path_special/_at_special() to resolve both paths at
  once. For a common object, the original path is its plain path and
  the trash path is empty. For a trash can object, the original path
  is the path it had before it was deleted, and the trash path is the
  path it currently has in Trash Can.
- Rebuild the original path on the client from the trash path: the
  stub directory named after pFID is resolved by llapi_fid2path_at(),
  and the original name of each deleted object is recovered by
  truncating the name to uta_orig_namelen if URM_FL_TS_APPEND is set.
- The "trusted.unrm" xattr is read through the virtual ".Trash" of
  the parent, so that the caller can have the same access to the
  deleted objects.
- Add "--original|-o" to "lfs fid2path" to print both paths in form
  "$orig_path -> $trash_path". Without it, the live path is printed
  for any FID as before.
- Move the "trusted.unrm" helpers into lustreapi_internal.h so that
  liblustreapi_trash.c and lfs.c can share them.
- Add sanityn.sh test_117ze to verify this patch, which deletes a sub
  directory with a file inside it repeatedly and checks both paths are
  resolved correctly, and test_117zf to verify the same through a
  subdir (FILESET) mount.
- Add man pages llapi_fid2path.3 and llapi_fid2path_special.3, and
  update lfs-fid2path.1 to reflect the new changes.
