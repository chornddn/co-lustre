LU-15834 lod: add a mirror in place for mirror extend

"lfs mirror extend" allocated the new mirror in a separate volatile
file and merged it into the file, so LOD allocated its objects
without seeing the file's other mirrors.  The new mirror could land on
the same OSTs, OSSs and failure domains as an existing mirror, which
defeats the purpose of the mirror.

Add a "lustre.lov.extend" layout operation that adds the components
of one new mirror to the file as a stale mirror without objects, and
llapi_mirror_extend() to send it.  A plain file is converted to a
mirrored file first, and the OST objects of a file without mirrors
get the component ids of mirror 1, as after a merge.  The resync of
the new mirror then instantiates it while all other mirrors are in
view, so the existing OST, OSS and failure domain avoidance applies.
A parity mirror is bound to the data mirror named by its link id, and
the new components are numbered, as a merge does.

"lfs mirror extend" uses it for data and EC parity mirrors when the
MDT has OBD_CONNECT2_FLR_EC, and falls back to the volatile file and
merge otherwise, or when the new mirror names its OSTs, since the OST
list of a component without objects is not stored until the resync,
has an extension component, which only a write instantiates, or a
foreign or released component, is copied with --non-direct, as the
resync uses O_DIRECT, or the file is released by HSM, which the read
of the copy restores, is cached by PCC-RO, as the resync is refused
until that is cleared, or is in SYNC_PENDING, where the resync does
not instantiate the new mirror.  The client refuses an EC mirror when
erasure coding is disabled on it, as for a new file.  A component of
the new mirror without a pool gets the pool of the default layout of
the parent directory or the root, as the copy created there did,
unless it is a DoM component or has a fixed OST index outside that
pool, and the new mirror is checked like the copy was, e.g. for a
pool that does not exist.  llapi_mirror_extend() then takes and
releases a lease, which refreshes the client's layout, as a getxattr
of the layout would return the cached one.

The extend fails before it changes the layout if the file is open
for write elsewhere, as the resync could not start.  An interrupted
extend leaves a stale mirror, like "--no-resync", instead of an orphan
volatile file, but a data mirror that would get EC parity is removed.
With "--no-resync", the new mirror has no objects until "lfs mirror
resync" allocates them.  A resync that lost its lease now fails.

A resync instantiated every stale component within the extent that
the in-sync mirrors had instantiated, which is the whole file once
one mirror covers [0, EOF), so a new PFL mirror of a small file got
objects for all of its components.  Send the file size in rs_size of
MDS_REINT_RESYNC, flagged by MDS_RESYNC_SIZE in rs_bias, and stop the
resync instantiation with the component that holds the file size,
which the truncate at the end of the resync accesses.

lod_verify_layout() verifies the new mirror as a layout of its own,
not as a continuation of the file's layout as for "lustre.lov.add".
A mirror whose DoM size differs from that of the file is refused, as
lod_parse_striping() would refuse the layout.

Add sanity-flr test_8a to check that the new mirror avoids the OSTs of
the existing mirrors, based on the test from Bobi Jam's patch, that
the component at the file size is instantiated, that a busy file, one
with another DoM size or one with only stale mirrors is left
unchanged, that a self-extending mirror is added, that a file in
sync_pending gets a merged mirror, and that a mirror with an HSM
component is refused by "lustre.lov.extend".
Add sanity-flr test_8b to check that the new mirror gets the default
pool of the directory, but not for a DoM component or a fixed OST
index outside the pool, that a pool that does not exist is refused,
and that a relative file name gets the pool of the root default.
sanity-flr test_0f accepts 3/4 of the OSTs for a "-c -1" mirror, as
the in-place mirror avoids the OSTs of the other mirrors like "lfs
mirror create", where the merged copy got all of them.
sanity-flr test_204b expects the component beyond the file size to
stay uninstantiated after the resync, and test_210a and test_210b
inject the bad OST index at a later layout change, as the extend
allocates no objects.
sanity-flr test_61b and test_61d skip their timestamp checks after a
split of an in-place extended file, as the resynced objects keep the
time of the copy until a time-only setattr reaches every mirror
(LU-21006).
