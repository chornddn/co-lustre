LU-17957 mdd: POSIX interface for non-root immutable files

Adds a POSIX-compatible interface for non-root users to set files
as immutable.
The interface allows non-root file owners to make files immutable by:

- Setting the file's access time (atime) to a future time
- Removing all write permissions from the file

The access time must be set at least 60 seconds into the future.
When both conditions are met, the file automatically gets the
`LUSTRE_IMMUTABLE_FL` flag set.

Shared helpers lu_posix_immutable_expired() and
lu_posix_immutable_owner_or_cap()  are used by the
MDD and MDT to agree on what is an expired POSIX immutable file:
a regular file with LUSTRE_IMMUTABLE_FL, no write bits and
atime <= now. A chattr +i file (write bits present) never
auto-expires.

After the retention period expires, the immutable restriction is
lifted for the owner or CAP_LINUX_IMMUTABLE:
- MDD permission, setattr and delete paths allow the operation
  and clear LUSTRE_IMMUTABLE_FL in the same transaction.
- mdd_attr_get() drops an expired LUSTRE_IMMUTABLE_FL on disk,
  and mdt_pack_attr2body() omits it from the getattr reply so
  clients never observe a stale flag.
- ll_refresh_posix_immutable(), called from ll_revalidate_dentry()
  before the VFS IS_IMMUTABLE() check, re-fetches flags from the
  MDS and drops S_IMMUTABLE when LUSTRE_IMMUTABLE_FL is gone.

Because the file remains a‑w, the write still fails with EACCES
until write permission is restored; only the immutable restriction
is lifted.

ll_md_getattr_flags() is factored out of fileattr_get() so the
client revalidation path issues the same MDS getattr used by
lsattr.

test_106d in sanityn.sh covers flag set, retention expiry,
mode-only failure after expiry and root delete after expiry.
