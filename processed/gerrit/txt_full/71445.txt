LU-21328 efalnd: Don't use stale rdma desc for 0 size transfers

Each side of an RDMA transfer registers its buffer and keeps its
address, key and length in the Tx's RDMA descriptor. Txs are reused
from a pool, and the descriptor is only written when a buffer is
registered, so until then it holds the previous transfer's values.

A transfer with no data registers nothing and so uses those old
values. The receiver of a PUT that LNet truncated to zero bytes still
posts a read into the old buffer, and the source of a GET with an
empty reply sends the old descriptor in its ack for the initiator to
read from. The old key usually fails the read, leaving the peer
waiting for a completion that never comes. Once the key is reused,
the read can instead move another transfer's data.

When the receiver of a PUT has no data, complete the PUT right away
instead of reading. When the source of a GET has no data, send an
empty descriptor, and have the initiator complete the GET without
reading, since a read from an empty descriptor fails.

Also reuse the Tx for the PUTR_DONE or NACK sent when mapping the
PUT sink or GET source fails, instead of allocating a second Tx that
may not be available.

An initiator without this patch still reads from an empty
descriptor, but no in-tree LNet user sends a GET that can match an
empty buffer: only the ping buffer allows truncation, and it is never
empty.
