LU-21060 osc: add OSC and MDC job statistics

CSP Managed Lustre users cannot read backend jobstats due to lack of backend server access.  Add per-job
OSC and MDC counters so clients expose resource use without a server
upgrade or wire change.  Keep job-ID selection and cleanup semantics
aligned with server jobstats, with collection disabled by default.

Share the jobstats engine, add a node-wide client record budget and
visible dropped-update counters, and account for successful RPCs and
BRW payload bytes.  Include controls, documentation and focused tests.

This is a WIP review snapshot, not the final landing series.  It
includes the required engine fixes from these existing reviews:

Shaun Tancheff, LU-19555, review 62167 patch set 13:
https://review.whamcloud.com/62167
4b69d9fbacea8074d3e84ac6e881d168122196ef

Oleg Drokin, LU-17000, review 68602 patch set 1:
https://review.whamcloud.com/68602
b95be1553298813870e0b975e5886a46423b5285

Oleg Drokin, LU-20984, review 69763 patch set 1:
https://review.whamcloud.com/69763
53a75006617a030a1e9b255305bf98aaf2ef52fe

The identical ACTIVE_JOBS wakeup appears once.  No unrelated quota
changes are included.  Split and rebase the feature onto the agreed
prerequisites, then repeat validation before marking it ready.

The updated client modules build on Rocky Linux 8.10.  Local Smatch
reproduces all three earlier code warnings and does not report them
after the repair.  Unchanged header diagnostics remain.  The exact
upstream analyzer configuration is unknown.  Twelve controlled
job_lookup cases preserve reference, lock and retry behavior.

Sparse checks all fourteen changed C files.  Its remaining warnings
are outside the feature hunks and retained in the validation record.

Clang rejects -fconserve-stack in the vendor kernel's module probe.
GCC provides the compatible module build.  The kernel's unannotated
rwsem APIs also limit Sparse lock-context checking.

This revision has no fresh mounted-client run.  Earlier focused
tests passed against unmodified 2.15.8 servers.  Shared-engine server
runtime, batch replay and failure paths, allocation failures, and
large-client scaling still need coverage.  Four new man pages also
need release metadata once the introduction version is assigned.
