LU-17238 obd: reserve OBD_CONNECT2_NEG_SYSTEM_XATTR and mbo_xattr_absent

Reserve OBD_CONNECT2_NEG_SYSTEM_XATTR (bit 47) in ocd_connect_flags2
for clients to negotiate negative system xattr caching. When set, the
MDS packs a bitmask in mbo_xattr_absent indicating which system xattrs
were looked up and confirmed absent on the inode.

Repurpose mbo_padding_9 in struct mdt_body as mbo_xattr_absent and
define MBO_XA_* bitmask values for individual xattr names.

This will be used to populate the negative xattr cache feature added in a
following commit. The first implementation will prepack system xattrs during
lookup intent reply, to save on extra RPC round trip for SELinux/ACL, but
mbo_xattr_absent could be used in any metadata RPC to pack on negative xattr
information as needed.

By using a bitmask, the server can communicate negative xattrs with very low
overhead and without committing to adding an xattr list to operations like
lookup. It also has the flexibility to support up to 64 different system xattrs
should future needs arise.
