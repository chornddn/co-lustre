LU-20818 osc: Run writeback and LRU work on submitter's CPT

LU-17180 moved the osc writeback and LRU work from a ptlrpcd
thread of the submitter's CPT to system_wq, which runs it on the
submitter's CPU, competing with the submitter, so single-stream
writes got slower.

Queue the writeback and LRU work on a per-CPT workqueue instead,
so it runs within the submitter's CPT as before, but still outside
ptlrpcd threads. To keep a work item off two CPTs' workqueues at
once, count the requests as ptlrpcd_queue_work() did: only the
first one queues the work, and requests made while it runs make
it run once more. Use WQ_MEM_RECLAIM since the work frees memory.

Single dd (bs=1M, 16GiB, conv=fsync) to a 16-stripe file on 4 OSTs,
client with 4 CPTs of 2 CPUs, MB/s, mean of 5 runs:

                       checksums=0  checksums=1
    master                 627          514
    LU-17180 reverted      919          958
    this patch             968          959
