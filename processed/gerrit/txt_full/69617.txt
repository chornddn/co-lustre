--- Commit Message ---
LU-20517 quota: don't grant writes from an outdated usage

sanity-quota test_1k fails on ZFS: the last 1MB write succeeds, but
the test expects EDQUOT.

The unused grant on the slave is not an overrun by itself: the
master never grants more than the hard limit. But the usage cached
on the slave can be outdated. On ZFS it is updated only at
transaction group commit, so after a write the slave can still think
there is free space and grant the next write from it. When edquot
is set and a write is granted from the unused grant, sync the
backend and check again. Only the ZFS OSD is affected, and the sync
is done at most once per acquire.

The test also assumes that the second write fills the file to the
hard limit. It does not: a write is refused only when it does not
fit any more, and the check counts the pending writes as usage, so
the second write can stop well below the limit (18MB of 20MB in a
failing run) and leave real free space for the next 1MB write.
Keep writing 1MB past the limit until a write is refused.
