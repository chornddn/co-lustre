LU-19848 llite: don't use iov_iter_is_aligned()

Filesystems should probably not use iov_iter_is_aligned().
This function was originally only exported to be used in the
block layer. Once the only user was dropped, it was removed.
No filesystems ever adopted it. When testing on a 6.18
kernel with `gdsio`, this function incorrectly rejected
directIO that was previously accepted in Lustre 2.15. Hence,
remove this check.

We can simplify the function further. The function's first
check requires the total count to be a page multiple:

	if (iov_iter_count(i) & ~PAGE_MASK)
		return true;

so 'count' is always 0 by the time we reach 'if (!count)' and
the function always returns via iov_iter_alignment(). Hence,
everything after 'if (!count)' is dead code, so collapse the
function to the two checks that actually run.

Drop the stale comment about relaxing alignment.
