LU-20099 nrs: add zero reserved and unlimited rates for mClock

Add a zero reserved rate and an unlimited limit rate to the mClock
scheduler. A rule with a reserved rate of 0 reserves nothing. A rule
with a limit rate of "unlimit" or "max" gets no ceiling. A rule that
names no rate takes neither. The default rule still keeps
nrs_class_def_rate in the limit slot, so the traffic that no rule
matches keeps a ceiling.

The head flag helper now masks the rate keys with the configured
dimensions. The auto default rule of a reserve-only policy therefore
takes the reservation slot and enters the reserved tree. The old
code left it in the limit slot, and no tree held it.

The TBF policy needs a ceiling for every rule, so a TBF rule with an
unlimited limit rate returns -EINVAL. So does an mClock rule that
uses no dimension of its policy, because such a rule takes no
service. A rule key that names a dimension the policy does not have
also returns -EINVAL. The log then names the start key that turns
the dimension on.

The deadline minimum of a class bucket returns the current time when
the weight tree holds that bucket. The arrival path then arms the
throttle timer at the right time.

The rule dump prints a rate range. The forms are "R-max", "0-L" and
"rate 0-max", which an administrator reads.

Documentation/man8/lctl-set_param.8 gains a section on the rule keys,
the short forms "R", "L" and "W", and the dimension keys.

Add sanityn/test_77v{k,l,o,p,q,s}, and extend test_77ve.
