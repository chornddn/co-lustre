LU-21023 lod: reload a remote dir's stripes before migrating it

An MDT that migrates a directory whose master is on another MDT
detaches its stripes with the list LOD loaded earlier. If the other
MDT has since changed the stripes, e.g. dropped the source stripe when
it finished an interrupted migration, lod_dir_layout_detach() deletes
the master's entry for a stripe that is gone. The update fails with
-ENOENT on the remote MDT after the deletes before it were applied,
and LFSCK finds the old directory without a name and a stripe whose
linkEA names it.

The migration holds the directory's XATTR lock, which invalidated the
LMV cached by OSP, but lod_invalidate() keeps the stripes. Drop them
in lod_dir_declare_layout_detach() for a remote directory, so they are
loaded again from the current LMV.

Add sanity test_230E: interrupt the migration of a directory, rename
it so that MDT0 loads its stripes, resume the migration, then migrate
the directory again from MDT0.

  env=ONLY=230E,ONLY_REPEAT=20
