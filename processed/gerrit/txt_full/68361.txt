LU-00000 ec: store parity as RAID10|PARITY so p may exceed k

The k >= p restriction is not a Cauchy/ISA-L limit. It comes from
storing coding stripes as RAID0|PARITY: p objects are concatenated
along the file offset, so nsets * p * stripe_size will not fit in a
finite PFL extent when p > k (for example --ec 2+3 -E 2M).

Write EC parity as LOV_PATTERN_RAID10|PARITY. Raidset is an EC
split of the stripe-set; EC chose RAID10 so the p coding objects
of a raidset share one file offset (object_off = stripeset * ss)
instead of concatenating them. File extent still matches the data
component:

  ec_off(stripeset, raidset) =
      e_start + stripeset * (nsets * ss) + raidset * ss

I/O mapping keys off LCME_FL_PARITY, not the RAID10 bit. Within a
raidset, resync/verify must pick a coding stripe via
LL_IOC_FLR_SET_STRIPE / llapi_mirror_{read,write}_stripe():
coding stripes differ, so a RAID10-style fan-out would be wrong.
Punch and truncate still hit all coding objects.

Example: -E 128M -c 11 -S 1M --ec 4+2

  data/parity extent [0, 128M)
  raidsets [4,2], [4,2], [3,2] (nsets=3)
  parity has 6 OST objects
  one data stripe-set = 11M
  one parity stripe-set = 3M (not 1M flat, not 6M concat)

  sset rs  data_pos    EC       old concat objs
  ---- --- ----------- -------- ---------- ----
  0    0   [0, 4M)     0        0          0,1
  0    1   [4M, 8M)    1M       2M         2,3
  0    2   [8M, 11M)   2M       4M         4,5
  1    0   [11M, 15M)  3M       6M         0,1
  1    1   [15M, 19M)  4M       8M         2,3
  1    2   [19M, 22M)  5M       10M        4,5

When nsets == 1 (e.g. --ec 2+3), one raidset still fits p > k in
a finite PFL extent. With --ec 1+N, parity offsets align with
each data stripe.

lov_pattern_available() accepts RAID10|PARITY; old clients skip
the unknown pattern and leave the parity component inert.
Finite-extent stripe-count shrinking is skipped for parity
components. The p <= k checks in lfs and llapi are removed;
k+p <= 256 and p <= 15 remain.

Tests: sanity-ec 4a/10 accept 2+3; test_300 covers PFL -E 2M
--ec 2+3 create/resync/verify; 12c/34c cover holes and
multi-raidset offsets (34c asserts striping into raidset 1);
llapi_layout_test T47 allows 3+4.
