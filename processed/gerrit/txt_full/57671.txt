LU-10499 pcc: add --pin option for 'lfs pcc attach'

Add a --pin|-p option to "lfs pcc attach" and "lfs pcc attach_fid"
to pin each file for the PCC backend before attaching it, so that
users do not need to run "lfs pcc pin" separately.  A file that
cannot be pinned is not attached.  Without --id, the backend is
chosen once, so that the file is pinned for the backend it is
attached to.

Add llapi_pcc_pin_fd(), llapi_pcc_pin_fid(), llapi_pcc_unpin_fd()
and llapi_pcc_unpin_fid() to match the pool pin functions, which
use the same lustre.pin xattr.  attach_fid pins the file with
llapi_pcc_pin_fid(), which also works on subdirectory mounts.  The
pin functions share the pin xattr update and no longer leak the
parsed pin object.

Setting lustre.pin on the MDT took the UPDATE lock as well as the
XATTR lock.  This would cancel a combined UPDATE|LAYOUT lock on the
client and detach a PCC-RO file, so "lfs pcc pin" of an attached
file would detach it.  Do not take the UPDATE lock for the pin,
whether it is set as lustre.pin or as trusted.pin, and do not update
ctime, which clients cache under the UPDATE lock, as for the HSM
state.

Add llapi_pcc_pin_file.3 for the pin functions, and sanity-pcc
test_204d and test_204e.
