LU-21203 osd-zfs: detect pools on non-rotational devices

osd-zfs reports a target as non-rotational only when its
nonrotational parameter is set by hand, while osd-ldiskfs takes the
flag from its block device at mount.  OS_STATFS_NONROT is used to
choose FLR mirrors to read from, so a ZFS OST on SSD or NVMe devices
is treated like one on disks unless the administrator sets it.

ZFS keeps this in vdev_nonrot: a disk vdev takes it from its block
device and a file vdev is always non-rotational.  The value of a
mirror, RAID-Z or dRAID vdev cannot be used: dRAID sets it to true
again when it opens its distributed spares, and older ZFS releases
computed it before the children were open.  At mount, set
od_nonrotational in osd_pool_nonrotational() when every leaf vdev
under the top-level vdevs of the normal class is non-rotational.
Log, special, dedup, hole and removed (indirect) vdevs are skipped,
since bulk file data is not allocated from them, and so are
distributed spares and faulted leaves.  The nonrotational parameter
still overrides the detected value.

Add sanity test_56cb, which sets the rotational flag of the devices
of a ZFS OST to 0 and then 1 and checks the parameter each time the
OST is started again.
