LU-21192 osp: send the parent FID of new OST objects

An OST object learns the FID of its parent MDT-object (trusted.fid)
only from a write, punch, fallocate or setattr from a client.  An
object that is never written, such as one of an empty file or of an
instantiated component past the end of a file, never names its file:
lfs fid2path cannot map it, and a tool that reads an OST to find the
files on it has to walk the namespace for them.

When LOD creates the objects of a layout, pass the parent FID and the
stripe index to OSP in the allocation hint, and OSP keeps it with the
object.  It goes to the OST with the first ownership or layout version
change of the object, at no extra cost.  At the last close of the
file, mdd_close_pfid() sends it to the objects that still lack it,
skipping those that the lazy size shows hold data, which the write
gave their parent FID.  So a file whose data covers all its objects
costs no RPC, and an empty file one per object.  The MDT pays one
local transaction at the last close of each new file.  It is an
OST_SETATTR with OBD_MD_FLFID from the sync llog, in
llog_setattr64_rec_v2, whose padding now holds the parent FID.  It is
best effort: if the MDT restarts while the file is open, objects that
are never written keep no parent FID, as before.  Nor is it sent
when its llog record cannot be declared, as when the sync llog
already holds max_sync_changes records, so it never adds to that
queue past the limit.

The OST stores a parent FID from an MDT setattr only if the object has
none, deciding it again under the object lock, and replies to a
setattr left with nothing to do without a transaction.  A filter_fid
that holds only the layout version of a mirrored or EC file has none.
OSP takes such a reply as committed and cancels the record, as it does
for an object that no longer exists.  A client fallocate now also
stores the layout of an object that has only its parent FID, as a
write or punch does.  An older OST replaces the parent FID instead,
which changes it only if the layout was swapped while the record was
queued.

A layout swap (lfs migrate, lfs mirror extend) skipped objects with no
parent FID, so the volatile file would later be sent as their parent.
It now gives them their new parent, and OSP drops the one it kept. The
swap sets it with out_xattr_set(), which leaves the parent FID that
OFD keeps in memory as it was, so OST fid2path now reads it again.

osp.*.create_pfid (default 1) turns this off.

Add sanity test 27za, with the migrate and mirror extend of empty
files, and the setattr RPCs that written objects and an ownership
change save.  Keep sanity-lfsck 18c creating objects with no parent
FID, and 17 leaving the objects its fault injection orphans without
one, which 18a would otherwise count as orphans to repair.
