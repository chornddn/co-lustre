LU-21192 osp: send the parent FID of new OST objects

An OST object learns the FID of its parent MDT-object (trusted.fid)
only from a write, punch, fallocate or setattr from a client.  An
object that is never written, such as one of an empty file or of an
instantiated component past the end of a file, never names its file:
lfs fid2path cannot map it, and a tool that reads an OST to find the
files on it has to walk the namespace for them.

When LOD creates the objects of a layout, pass the parent FID and the
stripe index to OSP in the allocation hint.  OSP queues a setattr
record for each new object in its sync llog, in the same transaction,
and the sync thread sends it to the OST as an OST_SETATTR with
OBD_MD_FLFID, as it sends ownership changes.  The record is
llog_setattr64_rec_v2, whose padding now holds the parent FID.  It is
optional: if the llog cannot take it, the object gets its parent FID
from its first write, as before.

The OST stores a parent FID from an MDT setattr only if the object
has none, since a record can arrive after a layout swap gave the
object another parent, and replies to a setattr left with nothing to
do without a transaction.  OSP takes such a reply as committed and
cancels the record, as it does for an object that no longer exists.

osp.*.create_pfid (default 1) turns this off.

Add sanity test 27za.  Keep sanity-lfsck 18c creating objects with no
parent FID, and 17 leaving the objects its fault injection orphans
without one, which 18a would otherwise count as orphans to repair.
