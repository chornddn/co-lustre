LU-20365 tests: use sim_du to replace 'du -a' in test_123h

Replace 'du -a' with sim_du to trigger fname pattern statahead.

In Ubuntu 26.04, the gnulib update has changed.
It nolonger sort the outputs following the file traversal
(xtfs_open context) for Lustre. (coreutils (9.7-3ubuntu2) resolute)
This also change the behavior of `du -a`(gnudu).
The command no longer guarantees a sorted directory entry list.

This behavioral change breaks the expected access pattern required by
sanity.sh test_123h. Because it relies on the sorted order to properly
trigger the fname pattern statahead mechanism.
Without the sorted sequence, the statahead engine cannot
detect the fname pattern and the test fails.

To address this compatibility issue, introduce a new simple utility
`sim_du.c` which explicitly simulate the original behavior of `du -a`.
This ensures that the directory entries are presented in
the deterministic order expected by the test, restoring the ability to
trigger fname pattern statahead and allowing test_123h to pass
consistently across different distributions.
