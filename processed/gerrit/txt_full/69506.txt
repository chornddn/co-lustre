LU-20896 llite: transfer ciphertext for O_CIPHERTEXT DIO

A file opened with O_CIPHERTEXT|O_DIRECT reads and writes the data
as stored on the OSTs only when the encryption key is not loaded.
With the key loaded, the same direct IO decrypts on read and
encrypts on write, so "lfs migrate", "lfs mirror extend" and "lfs
mirror resync" decrypt and re-encrypt the data, and EC parity resync
computes the parity from the plaintext and stores it encrypted,
while without the key it is computed from the ciphertext.
Encrypted file backup and restore need the ciphertext whether the
key is loaded or not.

Record O_CIPHERTEXT at open, since the VFS clears O_NOCTTY from
f_flags afterward, and mark the direct IO pages of such a file so
that OSC transfers them as it does without the key.  Let such a read
reach the end of the last encryption unit, as without the key, and
refuse to fall back to buffered IO, which would encrypt or decrypt
the data.  Keep the clear text size of a migrated volatile file and
of a resynced mirror.  Have EC parity resync of an encrypted file
cover its whole last encryption unit.

Do not merge such pages into an RPC with other pages, since OSC
encrypts an RPC or not as a whole.

Also check for all of the O_CIPHERTEXT flags on truncate, rather
than any one of them, which O_NONBLOCK or O_DSYNC alone matched and
skipped re-encrypting the zeroed end of the last page.

Add sanity-sec test_66 to read the ciphertext with the key loaded,
and to migrate and mirror a file with the key loaded.
