LU-20984 lfsck: don't unlock in links_remove() dryrun

A namespace LFSCK dryrun that finds an object with a crashed linkEA
header LBUGs the MDS:

 ASSERTION( dt->dd_owner == env ) failed:
 lfsck_namespace_links_remove+0x566/0x660 [lfsck]
 lfsck_namespace_exec_oit+0x85a/0x9a0 [lfsck]

The LPF_DRYRUN check was moved ahead of lfsck_trans_create() and
dt_write_lock(), but still jumps to "unlock", which unlocks an
object that is not locked and stops a NULL transaction.  Jump to
"log" instead.

Add sanity-lfsck test_2h to run a dryrun over a crashed linkEA header.

Fixes: 441902fa3d44 ("LU-17010 lfsck: don't create trans in dryrun mode")
