LU-20640 pcc: fix deadlock between mmap_lock and active ios

It exists the following deadlock between mmap_lock and active ios:

P1: PCC read
->ll_file_read_iter()
  ->pcc_file_read_iter()
  ->pcc_io_init(): increase pcci_active_ios
   ->xfs_file_buffered_read()
    ->generic_file_buffered_read()
     ->copy_page_to_iter()
      ->page_fault()
       ->do_page_fault()
        -> try to acquire mmap_lock

P2: PCC mmap
->vm_mmap_pgoff(): hole write mmap_lock
 ->ll_file_mmap()
  ->pcc_file_mmap()
   ->pcc_mmap_mapping_set()
    -> wait all active ios finish (pcci_active_ios == 0)

More precisely, P1 waits for P2 to release mmap_lock, and P2 waits
for P1 to complete and so that @pcci_active_ios changes from 1 to
0.

This patch simply fixes the bug by removing the codes to wait
the active IOs to finish in pcc_mmap_mapping_set().
