--- Commit Message ---
LU-21183 mdt: allow fid2path on an MDT mount

Tools on a server node need a client mount to turn a FID into a
pathname, and a client mount on a server causes trouble with HA
failover and module removal.

Let OBD_IOC_FID2PATH work on an MDT's own mount point, with the
same struct getinfo_fid2path as on a client mount.  The target
mount passes it to mdt_iocontrol(), which also takes it from
/dev/obd.  With no client to continue the walk on another MDT, a
remote object is read through OSP, with its cache dropped since no
lock is held, so one MDT mount names any FID in the filesystem.
Encrypted names return -ENODATA, since only a client can encode
them.

"lfs fid2path" accepts an MDT mount point, found by statfs() and
the new LL_SERVER_SUPER_MAGIC, and prints the path from the
filesystem root, as it does when given the fsname.
