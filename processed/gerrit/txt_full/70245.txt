LU-20791 efalnd: Track deactivated connections on a list

A deactivated connection was re-added to the hash table under key 0 so
the connection daemon could find it and clean it on the next daemon
invocation. On connection lookup, we search based on the remote NID
which wasn't changed when the connection was re-inserted to the hash
table in deactivating state. A peer whose key falls in the same bucket
still matched it, so the caller got the dead connection. A send then
left its message pending on it until the daemon cancelled it, without
starting a new connection.

The impact is limited since the daemon removes the connection from the
hash table at its next scan and then cancels its pending messages,
completing them back to LNet with an error instead of leaving them
stuck.

Remove a deactivated connection from the hash table for good and queue
it on a per-NI deactivate list protected by the connection hash lock.
The daemon's scan splices that list onto its cleanup list. The list
reuses the connection's cleanup node, so a connection the scan already
collected as a candidate is moved off the candidate list and reaches
cleanup in the same scan with its own teardown reason. With the key no
longer changing, the connection does not need to store it.
