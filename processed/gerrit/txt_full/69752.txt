LU-20969 pcc: disable PCC-RW by default

PCC-RW is a proof of concept: attaching a file moves the
only copy of its data into the cache of one client, so
losing that client or its cache loses the file. With PCC-RO
generally available in 2.18, PCC-RW must not be used by
accident.

Add client parameters llite.*.enable_pcc_rw and
llite.*.enable_pcc_ro, and MDT parameters
mdt.*.enable_pcc_rw and mdt.*.enable_pcc_ro. PCC-RW is
disabled by default and PCC-RO is enabled. While a mode is
disabled on the client, adding a PCC rule that uses it and
attaching a file in that mode fail with EOPNOTSUPP and a
console message that names the parameter to enable it, and
automatic attach in that mode is skipped. While a mode is
disabled on the MDT, the MDT refuses the attach, and the
creation of a file in a PCC-RW cache, the same way. A file
already attached stays attached until the client drops it
from its cache, and is not attached again.

As LFS_EC_OK does for erasure coding, "lfs pcc attach -w"
and "lctl pcc add" with pccrw=1 refuse to run unless
LFS_PCC_RW_OK is set in the environment.

The server control is an MDT parameter, not a nodemap RBAC
role: roles are enabled by default and a nodemap with all
roles stores none, so a role that is off by default would
change how roles are stored and synced to the targets.

sanity-pcc enables PCC-RW for its tests. Add sanity-pcc
test_1h to check that each control refuses PCC-RW.
