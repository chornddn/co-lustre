LU-18847 mdt: check open parent exists

A volatile open takes no lock on its parent and does no name
lookup there, so it reached the layout version check added
for 2.18 with a parent that no longer exists, such as a cwd
removed by another client or a stale parent FID after a
directory migration. A missing object has no type bits, and
lod_layout_check() asserted it was a regular file, so any
user could crash the MDS by creating a volatile file name
in a directory removed through another mount.

Return -ESTALE from the open when the parent does not exist,
as a non-volatile open-create already gets from the parent
lock, and return -ENOTDIR from the layout check rather than
assert on an object that is neither a directory nor a file.

Add sanityn test_123, with the volatile file on the parent's
MDT and, with DNE, on another MDT, to which the parent is
remote.
