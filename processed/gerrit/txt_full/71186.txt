LU-21253 ofd: keep commit for DIO write changing timestamps

With `obdfilter.*.dio_overwrite_nosync` set, a DIO overwrite that
skips the forced commit can lose its mtime and ctime in an OST
crash.  The OST cannot tell O_DIRECT|O_SYNC from plain O_DIRECT, so
such a write got fdatasync semantics.

OST timestamps are whole seconds taken from the client, so only the
first write to an object in a second advances them.  Skip the commit
only if the write advances no stored timestamp, and then do not set
the timestamps at all, so an older mtime or ctime from a client
whose clock lags is not stored either.  A write that advances mtime
or ctime, or sets atime, keeps the forced commit.  O_SYNC writes are
then fully synchronous for all clients without a protocol change.
Only the object version advanced by `tgt_obj_version_bump()` can
still be lost.

A write may read new timestamps from memory while the request that
set them has not committed.  Count requests that are changing the
object in ofo_attr_inflight, from before `dt_attr_set()` or
`dt_write_commit()` until ofo_dirty_transno is set after the
transaction stop, in write (every write that is not a nosync
candidate, and a candidate that sets timestamps), setattr, punch and
fallocate, and keep the commit while the count is not zero.  Mark
the object dirty for every setattr, not only for truncate.

Add `obdfilter.*.dio_overwrite_sync_reasons` with the number of
forced commits per reason, and the number of failed writes as
"error"; a failed write is in neither count.  With the tunable at 0
only the in-memory bookkeeping is added.

Add sanity 398y, adjust 398w and 398x for the commit per second and
check the reason of each forced commit, and check the on-disk
timestamps after the crash in replay-ost-single 14.  The crash check
is retried, then skipped, when a journal commit falls in the crash
window.

Add OBD_FAIL_OST_DIO_NOSYNC_ERR (0x258) to fail a write after a
nosync decision; 398y checks that such a write is counted only as
"error" and that the next overwrite of the object keeps the commit.
