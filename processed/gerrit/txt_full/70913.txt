LU-21229 ptlrpc: start threads when threads_min is raised

Writing SERVICE.threads_min to a running service only changed the
lower limit for threads_max and started no threads, since a running
service adds threads only when one of its threads wakes up and finds
the others busy.  On a server that had just started with few threads
in a partition, raising threads_min had no effect, and requests that
take long to handle could queue behind each other.

Start the missing threads in each CPU partition at once, up to
threads_max (ptlrpc_start_threads_min()), with the loop that starts
a service's threads when it is set up (ptlrpc_svcpt_start_threads()).
ptlrpc_start_thread() checks srv_is_stopping again under scp_lock, so
a thread started from outside the service does not join a partition
whose threads were already stopped, and a partition whose threads
were not started yet is left to ptlrpc_start_threads().
ptlrpc_unregister_service() removes the service's sysfs files before
it stops the threads, so that it waits for a threads_min write that
is still starting a thread, which would otherwise wake up on a
thread that was freed.

Add man pages for threads_min, threads_max and threads_started,
hosted under the ldlm_cbd service, which also runs on clients, with
links for every other service, and check in conf-sanity test_53a and
test_53b that a raised threads_min starts its threads.
