LU-21202 lod: don't reclaim update catalogs still in use

When MDT recovery is aborted, lod_sub_recreate_llog() marks the
owner's update catalog on each target with LLOG_F_MAX_AGE and
LLOG_F_RM_ON_ERR before it creates the replacement and writes it
to the target's catlist.  If the create or the catlist write
fails, the catlist still names the marked catalog.  The owner
reopens it at its next start, and lod_update_log_dir_gc() on the
target deletes it at the first mount 30 days after the mark,
without checking the catlist.  The owner's next catalog write then
crashes the target in out_tx_write_exec():

  dt_record_write()) ASSERTION( dt->do_body_ops->dbo_write ) failed

and the resent update crashes it again after every recovery, until
the owner restarts.

Retain the old catalog in lod_sub_recreate_llog() only after the
catlist names the new one.  If the replacement fails, keep using
the old catalog, and retain the unused new one so that the cleanup
reclaims it.  Make lod_sub_prep_llog() replace a catalog that is
already marked, which older versions can leave behind.  Make
lod_update_log_dir_gc() keep a retained catalog that the catlist
still names, and reclaim nothing if it can't read the catlist.
Make out_tx_write_exec() fail a write to a non-existent object
with -ENOENT instead of asserting.

Add OBD_FAIL_UPDATE_LOG_RECREATE to fail the catlist update.

Add replay-single test_100f, test_100g and test_100h: a cancelled
catalog that is still in use is replaced when its owner starts,
kept by the cleanup, and left unmarked when its replacement fails,
while the unused replacement is marked.
