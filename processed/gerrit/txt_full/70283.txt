--- Commit Message ---
LU-20984 lnet: check Netlink attributes fit in the message

The LNet Netlink handlers walk the nested attributes of a request
using the length stored in its first attribute header, which was
never compared with the length of the message received.  They also
step to a value attribute with nla_next() and read it without
checking that it is still within the enclosing attribute, and
read integer values without checking that the attribute is long
enough to hold one.  A malformed request could therefore make the
parser read past the end of the message.

Check the first attribute with nla_ok() against the message length
before walking it, and check every attribute reached by nla_next()
before using it.  Add lnet_nla_is_int() to check both the type and
the length of an integer value attribute, and use it everywhere such
a value is read, including the LND tunables handlers.  Also check
that each CPT given for a NI is in range and that the list fits in
the configuration it is stored in.
