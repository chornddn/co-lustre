LU-21253 ofd: skip forced commit for DIO overwrite

`ofd_commitrw_write()` forces a journal commit for every write whose
pages lack OBD_BRW_ASYNC, so each O_DIRECT write waits for a jbd2
commit even when it only overwrites blocks that are already
allocated, written and committed.

Add `obdfilter.*.dio_overwrite_nosync` (default 0).  When set, such
a write skips the commit if osd-ldiskfs reports th_overwrite, the
object has no uncommitted replayable change (ofo_dirty_transno, set
after write, punch, fallocate and truncate), no attribute had to be
set for the write, and the request is neither retried nor replayed
and the target is not in recovery.  The write is made a local
transaction, so the client keeps no request to replay from pages it
has returned to the application, and the object version is advanced
with the new `tgt_obj_version_bump()` so data_version still changes.
If the OST crashes before the next commit, the timestamps of such a
write and its object version can fall back to older values although
the data is new, so the tunable must not be enabled on a file system
that uses HSM.  With this patch alone the timestamps can roll back
after an OST crash when the tunable is enabled; the following patch
keeps the commit for a write that changes a timestamp.
The client sends no OST_SYNC after an O_DIRECT write, also with
O_SYNC (`ll_direct_IO()` returns -EIOCBQUEUED, so
`vvp_io_write_start()` skips `generic_write_sync()`), so
O_DIRECT|O_SYNC writes get fdatasync semantics in this mode;
fsync() still commits.  With the tunable at 0 (the default) the
write path is unchanged apart from the in-memory ofo_dirty_transno
bookkeeping.

`tgt_obj_version_bump()` takes the version from lut_last_transno, so
no later transno can reuse it: after every restart
`tgt_boot_epoch_update()` moves lut_last_transno past the epoch of
every transno restored from disk, which includes the boot epoch
start and the last committed transno, before any new transno is
assigned.  A version above both the boot epoch and the epoch of the
last committed transno keeps its commit; the first such forced write
commits a transno in the new epoch and re-enables the skip.  A
refused bump consumes no transno.

The dirty mark of a write or fallocate is set at the end of the
request, also when a restarted pass failed or the write failed after
a nosync decision.  A request without transno marks the object dirty
until a later transno commits, as its handle may commit after the
last assigned transno.  A newly cached object starts the same way.

Add `dio_overwrite_nosync_count` and `dio_overwrite_sync_count`, and
the obdfilter.dio_overwrite_nosync(4) man page.
Add sanity 398w, 398x and replay-ost-single 14.
