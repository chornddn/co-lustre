--- Commit Message ---
LU-20455 tests: run subtests from separate .ltsh files

Test scripts like sanity.sh (38000 lines) and conf-sanity.sh (13000
lines) are hard to read and navigate, and patches conflict often
because every new subtest is added to the same few files.

Allow subtests to be kept in lustre/tests/$TESTSUITE.d/*.ltsh files,
each holding one or more test_NNN() functions and the helpers they
share.  build_test_filter() finds the files and reads the YAML header
in the leading comment block of each one, run_test() first runs the
file subtests that sort before the subtest it is called for, and runs
the rest after the last subtest in $TESTSUITE.sh, before the suite's
own cleanup.  The suite scripts need no changes, and the subtests run
in numeric order interleaved with the subtests still in
$TESTSUITE.sh.  ONLY, EXCEPT, always_except(), EXCEPT_SLOW,
START_AT and STOP_AT apply to them as usual.  Each file is sourced
only when the first of its subtests runs.  The code is in the new
ltsh.sh, sourced by test-framework.sh, with the header parser in
ltsh.awk.

The header gives the summary passed to run_test(), with the Jira
ticket added to the banner, and a description and list of subsystems
that are not printed but help to find and understand the subtest.  It
replaces the usual skip checks at the start of a subtest: MDT, OST and
client counts, server and client versions, OSD type, separate MGS,
required tools, free space and inodes of the filesystem or of the
least free MDT or OST, PARALLEL and SLOW, with a "reason:" added to
the skip message.  "start:" and "end:" declare the filesystem state
(mounted, unmounted with servers up, stopped, or freshly formatted)
that the subtest needs and leaves, by default mounted.  The framework
changes the state only as needed and trusts "end:" rather than
checking it, so that later the subtests can be reordered to avoid
needless remounts.  "formatted" has the framework reformat before or
after the subtest, skipping the reformat at the start if the previous
subtest reformatted at its end.  This setup runs in the subtest's
subshell, so a failure fails only that subtest.  "expect: must_fail"
or "should_fail" runs the subtest with run_test_must_fail() or
run_test_should_fail() (LU-11520), and skips it until those exist.
"modifies:" lists the global state a subtest changes, such as
fail_loc, mounts or config, for running subtests in parallel later.  A
file with one subtest can leave out "subtests:".  Errors in a
subtest's header keys fail that subtest, YAML errors fail all subtests
of that file, and a test_NNN() missing from the header fails as a
subtest of its own, rather than any of them stopping the whole suite.

conf-sanity-framework.sh uses its own reformat_and_config(), setup()
and start_servers() for this, and keeps the client unmounted between
subtests.

Move some subtests to exercise each part of this, with a description
of each from its original commit and ticket.  Their version checks now
use the "git describe" form of the commit that added each feature,
since the history of those lines is lost by the move:
- sanity 27I: single subtest without "subtests:", OST count,
  parallel: false
- sanity 33h, 33hh: shared helper, MDT count for both subtests with
  a different version check for each
- sanity 51b, 51c: free inodes on every MDT, shared helper
- conf-sanity 151a, 151b: OSD type, start stopped, end formatted
- conf-sanity 153a, 153c: start formatted, run before and after
  153b in conf-sanity.sh, shared helper.  Also mount $FSNAME there
  instead of a hard-coded "lustre".

Describe the file format and header fields in
lustre/tests/README-ltsh.md.  Install the files with the test scripts,
and have prepare-commit-msg run shellcheck on them as it does for *.sh
files, with --shell=bash since they have no #! line.
