LU-21211 ldlm: optimize client lock enqueue handling

The server LDLM enqueue path does not need to process locks that
are a different type from the namespace, running useless lock-type
processing for a request that did not fit that namespace.

 - ldlm_handle_enqueue() fetched a reply field from a request that
   packed no reply message
 - A request named a lock type the namespace did not serve (an MDT
   serves IBITS, FLOCK and quota PLAIN locks; an OST serves EXTENT;
   the MGS serves PLAIN).  Record the namespace type at creation
   and skip a mismatched or unsupported type, so per-type processing
   never runs on a lock its resource does not need to process.
 - ldlm_inodebits_add_lock() and ldlm_inodebits_unlink_lock() walked
   the inodebits queues through a server lock that has no inodebits
   node; skip it in both (only the add_lock granted branch did so
   before).
 - ldlm_flock_blocking_ast() assumed a cancellation and unlinked the
   lock from the deadlock list; return early for any other flag.
