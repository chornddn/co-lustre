LU-20643 utils: do not reuse an lmd buffer across objects

get_lmd_info_fd() reuses one struct lov_user_mds_data for every object
and convert_lmd_statx() writes only the fields lstat(2) supplies, so
stx_attributes, stx_attributes_mask, stx_btime and the mask bits above
STATX_BASIC_STATS keep whatever was there before.

Two ways that is not this object's data.  On the V1 ioctl path lmd_st
covers lmd_stx, so stx_attributes_mask ends up holding st_atim.tv_sec
-- never 0 in practice -- and stx_mask picks up bits from st_nlink,
which reads as STATX_BTIME on a directory whose link count has 0x800
set.  On the lstat fallback the buffer still holds the file name that
was written into it for the ioctl: those bytes sit in lmd_fid, where
fid_is_sane() accepts a short name as an IGIF, and in the statx fields
convert_lmd_statx() does not write.

So a walk that crosses onto a non-Lustre subtree can answer -btime and
the attribute predicates from a file name, and report a FID made of
one.

Clear what is about to be reused on both paths.  The glimpse path is
left alone: there the MDT's answer is still wanted.
