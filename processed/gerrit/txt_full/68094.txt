LU-20603 llapi: namespace scanner API

Add llapi_scan_namespace(), which walks a namespace and delivers one
record per object to a consumer callback.

The traversal is not new: llapi_find_with_cb() already walks with a
thread pool and fetches attributes through LL_IOC_MDC_GETINFO_V2. What
is missing is a contract a consumer can hold on to instead of reaching
into struct find_param, which is internal to lfs find and changes with
it. This is the client-side Input Scanner of the Lustre Find Utility
(LU-20462).

struct llapi_scan_rec is versioned by sr_size and carries a validity
mask, so a field the scanner could not answer for is distinguishable
from one that is genuinely zero; fields are only ever appended. The
layout is handed over raw as sr_lmm for llapi_layout_get_by_xattr() to
decode. sr_projid, LLAPI_SCAN_MDT_INDEX and the HSM state each cost
an open and an ioctl per object here, so sp_want gathers them only
when it names them; a scanner reading a target's inode table answers
them for free, which is the point of a demand mask. An object the
caller cannot open leaves the bit clear rather than dropping out of
the scan.

A caller whose struct llapi_scan_param is shorter than this library's
is accepted, the fields it did not know about reading as zero; a
longer one is refused, because a field the library does not know
cannot be honoured.  An sp_flags bit it does not define is refused for
the same reason: setting a flag leaves sp_size unchanged, so nothing
else would keep a newer caller's flag from being ignored in silence.

The callback writes the directory descriptor back to the traversal
after gathering, because cb_get_dirstripe() may have closed it and
reopened it O_NOFOLLOW; LU-20624 fixes the two callers that predate
this one.  It matters more here than there: that retry fires for every
directory that is not on Lustre, and this scanner asks for a directory
stripe on all of them by default rather than only under the few
predicates that need one.

Two changes in liblustreapi_pfind.c come with this rather than after
it.  convert_lmdbuf_v1v2() now zeroes lmd_fid: the V1 ioctl put
lmd_st's bytes where V2 keeps the FID, and reading them as one gave
every object from an old client module a FID that was never a FID.
And get_projid() loses its static, because the gather path here is the
second caller of it.

The record is in memory and deliberately not a serialization: it
holds pointers and open descriptors, so the Object Stream that
crosses a network or the kernel boundary is a separate flat encoding.
sp_filter is a callback because an in-process consumer needs one; a
filter that crosses those boundaries is data rather than a function.
An object that is a mirror of another is not distinguishable yet, LMR
being LU-16742 and LU-17820.

sanity test_157c runs llapi_scan_test over that contract.
