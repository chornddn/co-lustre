LU-15834 lod: add a mirror in place for mirror extend

"lfs mirror extend" allocated the new mirror in a separate volatile
file and merged it into the file, so LOD allocated its objects
without seeing the file's other mirrors.  The new mirror could land on
the same OSTs, OSSs and failure domains as an existing mirror, which
defeats the purpose of the mirror.

Add a "lustre.lov.extend" layout operation that adds the components
of one new mirror to the file as a stale mirror without objects, and
llapi_mirror_extend() to send it.  A plain file is converted to a
mirrored file first.  The resync of the new mirror then instantiates
it while all other mirrors are in view, so the existing OST, OSS and
failure domain avoidance applies.  A parity mirror is bound to the
data mirror named by its link id, as a merge does.

"lfs mirror extend" uses it for data and EC parity mirrors when the
MDT has OBD_CONNECT2_FLR_EC, and falls back to the volatile file and
merge otherwise, or when the new mirror names its OSTs, since the OST
list of a component without objects is not stored until the resync,
has an extension component, which only a write instantiates, or is
copied with --non-direct, as the resync uses O_DIRECT.  A component
of the new mirror without a pool gets the pool of the default layout
of the parent directory or the root, as the copy created there did.
The client refreshes the layout after the extend, as a getxattr of
the layout returns the cached one.

The extend fails before it changes the layout if the file is open
for write elsewhere, as the resync could not start.  An interrupted
extend leaves a stale mirror, like "--no-sync", instead of an orphan
volatile file.

A resync instantiated every stale component within the extent that
the in-sync mirrors had instantiated, which is the whole file once
one mirror covers [0, EOF), so a new PFL mirror of a small file got
objects for all of its components.  Send the file size in rs_size of
MDS_REINT_RESYNC, flagged by MDS_RESYNC_SIZE in rs_bias, and stop the
resync instantiation there, keeping at least the first component as
a create does.

lod_verify_layout() verifies the new mirror as a layout of its own,
not as a continuation of the file's layout as for "lustre.lov.add".
A mirror whose DoM size differs from that of the file is refused, as
lod_parse_striping() would refuse the layout.

Add sanity-flr test_8a to check that the new mirror avoids the OSTs of
the existing mirrors, based on the test from Bobi Jam's patch, that a
busy file or one with another DoM size is left unchanged, and that a
self-extending mirror is added.
Add sanity-flr test_8b to check that the new mirror gets the default
pool of the directory.
sanity-flr test_0f accepts 3/4 of the OSTs for a "-c -1" mirror, as
the in-place mirror avoids the OSTs of the other mirrors like "lfs
mirror create", where the merged copy got all of them.
sanity-flr test_61b and test_61d skip their timestamp checks after a
split of an in-place extended file, as the resynced objects keep the
time of the copy until a time-only setattr reaches every mirror
(LU-21006).
