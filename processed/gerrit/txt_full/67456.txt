--- Commit Message ---
LU-20497 efalnd: Add protection against stale Rx completions

On Rx completion, we immediately fetch the Rx using the pointer stored
in the WR ID. If the Rx is stale due to NI destroy and creation, we
defer an Rx not relevant for the completion resulting in failures in
unpack flow or even crashes if the Rx is currently not posted so its
rx_nob is -1. To handle this situation, instead of storing the Rx
address in the WR ID, store its index in the first 4 bytes and part of
the NI epoch in the upper 4 bytes. This way we can validate the Rx
completion is for the current NI and if not drop it.
