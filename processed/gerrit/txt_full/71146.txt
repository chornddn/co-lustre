LU-21246 quota: report usage when ID is enforced by default

The QMT enforces limits against the space granted to slaves, not
against usage. When an ID gets an explicit limit, each slave reports
its usage above the grant in qsd_adjust(). When an ID becomes
enforced through the default quota, slaves don't report it. Usage
written while the ID was not enforced stays unknown to the QMT on
every target the ID doesn't write to again, and the ID can exceed its
limit by that amount.

This happens in two ways:
- the default limit is set while the ID uses the default quota:
  qsd_entry_def_iter_cb() only sets lqe_enforced.
- the ID is switched to the default quota with "lfs setquota -D":
  qsd_update_lqe() returns early for a DEFAULT record, so
  qsd_process_upd() calls qsd_adjust() while the ID is still not
  enforced, and enforcement is set only afterwards.

Set the default quota state and enforcement in qsd_update_lqe(), so
that the following qsd_adjust() reports the usage, and remove the late
update from qsd_process_upd(). In qsd_entry_def_iter_cb(), schedule
an adjust when the enforcement of an ID changes, as for an explicit
limit. Unlike an explicit limit, this only reaches IDs cached on the
slave. An ID with usage but without a global record is not cached
after a restart and reports its usage on its next write there.

Also take the lqe lock in qsd_update_lqe() when it sets
lqe_is_default and lqe_enforced. They share a bitfield word with
flags that other threads change under the lock, such as
qsd_entry_def_iter_cb() from a glimpse, which now also checks
lqe_is_default under the lock.

Reintegration also calls qsd_update_lqe(), so it now updates the
default quota state of a cached ID as well.

Also apply the default limit in qmt_dqacq0() to an ID on the
default quota that is not enforced yet. qmt_set_with_lqe() notifies
the slaves of a new default limit before it applies the limit to the
IDs, so the usage reported in between was rejected with -ESRCH and
retried only after QSD_WB_INTERVAL.

Add sanity-quota test_102a and test_102b for both cases. Add a "time"
field to get_quota_on_qsd() and an option to wait_quota_synced() to
wait without force_reint, which reports the usage and hides the bug.
