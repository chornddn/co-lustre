DRAFT LU-21180 lod: add kunit coverage for lod_declare_layout_set/del

Add KUnit coverage for lod_declare_layout_set() and
lod_declare_layout_del(), the "lfs setstripe --component-flags" and
"--component-del" entry points. Both only walk/mutate an object's
existing ldo_comp_entries[] array and declare the resulting LOVEA on
dt_object_child(dt), so a bare struct lod_object with a hand-built
static component array and the shared mock_ost_obj "next" object is
enough; no real OST/OSP is needed.

lod_declare_layout_set()/_del() leave info->lti_buf.lb_buf unset when
declaring the new LOVEA xattr (only lb_len is set), since real
->do_declare_xattr_set() OSD implementations only consult the length
to reserve transaction credits. Exercising that call convention
against mock_ost_obj_declare_xattr_set() crashed with a NULL pointer
dereference, because the mock unconditionally memcpy()'d from
buf->lb_buf to record it for the test to inspect. Fix the mock to
treat a NULL buf->lb_buf as valid, matching real declare-only
backends, recording a NULL/len pair instead of crashing. Also add the
mock's missing do_declare_xattr_del() op, needed by the "del" with no
remaining components test case.

Export lod_declare_layout_set()/lod_declare_layout_del() and declare
them in lod_internal.h so the test module can call them directly.
