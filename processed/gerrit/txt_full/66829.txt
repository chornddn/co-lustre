LU-20132 lnet: statically initialize acceptor wait queue

The LNet acceptor installs lnet_acceptor_ready() as the data_ready
callback on each listening socket from lnet_acceptor_add_socket(),
which runs on the LND startup path before the acceptor thread is
started. lnet_acceptor_ready() wakes the acceptor wait queue, but
that wait queue was only initialized inside the acceptor thread via
init_waitqueue_head(), which runs later.

If an inbound connection completes its TCP handshake in this window,
the listening socket's data_ready callback fires and wakes a wait
queue whose list head is still NULL, crashing in __wake_up_common().

  BUG: unable to handle kernel NULL pointer dereference
  RIP: __wake_up_common+0x4c/0x190
   __wake_up_common_lock
   tcp_child_process
   tcp_v4_rcv

Move the wait queue to a file-scope variable statically initialized
at module load with DECLARE_WAIT_QUEUE_HEAD(), so it is always valid
before any listening socket is hooked. Drop the now redundant
init_waitqueue_head() in the acceptor thread.
