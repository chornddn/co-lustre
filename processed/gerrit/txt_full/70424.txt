LU-20730 llapi: read a device scan as LFU chunks

llapi_scan_device() calls back once per object. A program that wants
the objects in bulk, to save them or to pass them to another process
or node, has to copy each one into a buffer of its own.

Add llapi_scan_open(), llapi_scan_read(), llapi_scan_info() and
llapi_scan_close(). They are the LfuOpen, LfuRead and LfuClose calls
of lfu.capnp: each read fills the caller's buffer with whole LfuChunk
slots and returns a cursor to continue from. The first source is a
target's device, LFU_SOURCE_DEVICE.

struct llapi_scan_open_param says which attributes and EAs the
records carry, by LFU_ATTR_BIT() and LFU_EA_BIT(), and has its own
flags, thread count, fsname check and filter, which sees each object
as a struct llapi_scan_inode. The structures the library fills
(llapi_scan_info, llapi_scan_reply and llapi_scan_summary) start with
their size, so that each can grow; the library accepts any size from
the first release's on.

A device stream reads in the caller's thread. To read in parallel,
open several shards: shard i of n is the i-th n-th of the target. A
cursor names a position on the target and the first object there not
yet sent, so a read stops when the buffer is full and the next read,
or a new stream after a restart, starts at that object. A cursor from
another target or shard is refused with -ESTALE. A read that fails
before it places any record returns the error and keeps its cursor;
one that fails later returns the records it has, and the next read
returns the error.

A record carries the inode's attributes, with the nanoseconds of its
times, its inode number on the target and the EAs asked for, as they
are stored, the encryption context included. An OST object's file is
in its trusted.fid. An object without a FID is sent with a zero FID
and is named by its inode number. An object too large for a slot gets
a jumbo chunk if the reader accepts those, and is otherwise counted as
an error and listed in the chunk's skipped list. A target of another
filesystem than lsop_fsname is refused with -EXDEV. The ldiskfs
backend now reports the nanoseconds of the times and the target's
UUID, and sb_scan_chunk() takes the first object id still wanted, so
that a resumed read starts at the block group holding it. The backend
plugin gets an ABI version, which the library checks before it uses
one.

llapi_scan_device_test test8, run by conf-sanity 300a and 300b, reads
an MDT and an OST in reads of three 4 KiB slots and checks that the
stream sends the same objects as llapi_scan_device(), also when it is
resumed on a new stream and when it is read as three shards. It also
checks the filter, the EAs sent, a failed read, and that foreign
cursors, another fsname and bad parameters are refused.
