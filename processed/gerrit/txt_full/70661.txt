LU-21159 llite: fall back to buffered IO on hybrid DIO ENOMEM

An unaligned buffered read() or write() that hybrid IO switches to
DIO takes all bounce pages of a sub_dio from the OBD page pool at
once.  The pool returns -EINVAL for more than it can hold and -ENOMEM
without waiting when other IO holds its pages, and the LU-19536 retry
only helps when earlier sub_dios of the call are in flight.  On a 4 GB
client one 300 MiB write at offset 1, or four concurrent 100 MiB
unaligned writes, failed.

Redo a hybrid-switched IO that fails with -ENOMEM as buffered IO from
ll_file_io_generic(), with the iterator and ki_pos restored, since a
failed DIO reports no bytes for chunks already done.  Leave out
O_APPEND, which would append those chunks twice, so an unaligned
O_APPEND write can still fail with -ENOMEM.  Clear IOCB_DIRECT
afterwards so the next iovec of do_loop_readv_writev() is not taken
for O_DIRECT, and set via_hybrid_switched on every read.

Cap an unaligned sub_dio at a quarter of the pool, which also fixes
the -EINVAL.

Add sanity test_119x using OBD_FAIL_LLITE_DIO_BUFFER_ALLOC.

Fixes: 985f49cf2e63 ("LU-17422 clio: use page pools for UDIO/hybrid")
