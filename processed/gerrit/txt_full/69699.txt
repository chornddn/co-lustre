LU-20963 osp: treat disconnected OST as ENOTCONN in osp_statfs

OST umount (OSS failover) only raises IMP_EVENT_DISCON: opd_imp_active
stays set, so osp_statfs() kept returning cached statfs and LOD left
the target ACTIVE. Also return -ENOTCONN while an import that was
connected is disconnected (opd_imp_connected), so that
lod_statfs_and_check() can clear ltd_active and set ltd_discon. Do not
use opd_pre_status for this: it stays -ENODEV after reconnect until
orphan cleanup is done, and a create would fail instead of waiting for
that in osp_precreate_reserve().
Refresh ltd_discon from every statfs result while the target is
already inactive (e.g. ENOSPC then DISCONNECT), not only on the
active-to-inactive transition.

sanity test_27F may now create its layout with one stripe if the
resent create arrives before both OSTs reconnect, so only check that
the layout has one or two stripes on distinct OSTs.

Add sanity.sh test_27ya to verify LOD marks the OST INACTIVE after
umount and setstripe avoids the disconnected OST.
