LU-20963 osp: treat disconnected OST as ENOTCONN in osp_statfs

OST umount (OSS failover) only raises IMP_EVENT_DISCON: opd_imp_active
stays set, so osp_statfs() kept returning cached statfs and LOD left
the target ACTIVE.  Also return -ENOTCONN while the import is
disconnected (opd_imp_connected), so that lod_statfs_and_check() can
clear ltd_active and set ltd_discon.  Do not use opd_pre_status for
this: it stays -ENODEV after reconnect until orphan cleanup is done,
and a create would fail instead of waiting for that in
osp_precreate_reserve().

osp_statfs() still fills in the cached data for a disconnected OST,
and lod_statfs() counts it, so that client df does not lose the space
of an OST during failover.  An inactive (deactivated) OST is still
left out, since it returns no data.  lod_trans_space_check() skips
the space check for a disconnected target, as it does in recovery,
so that a distributed transaction (e.g. migrate) does not return
-ENOTCONN to the client, which would reconnect and resend.

Since a disconnected OST is now inactive in LOD, an FLR write picks
a primary mirror without it and marks its mirror stale, and a SEL
component is not extended onto it, the same as for a deactivated OST.

Move opd_imp_connected out of the osp_device bitfield, since LOD
allocation now depends on it, and osp_import_event() writes it without
a lock while the precreate thread updates other bits in the same word.

Refresh ltd_discon from every statfs result while the target is
already inactive (e.g. ENOSPC then DISCONNECT), not only on the
active-to-inactive transition.

sanity test_27F may now create its layout with one stripe if the
resent create arrives before both OSTs reconnect, so only check that
the layout has one or two stripes on distinct OSTs.

Add sanity.sh test_27ya to verify LOD marks the OST INACTIVE after
umount and setstripe avoids the disconnected OST.  Create its
directory on MDT0000, whose OSP import the test checks.
