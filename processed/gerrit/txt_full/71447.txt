LU-20791 efalnd: Refresh peer NI data from a connection probe

When a peer restarts, its connection manager QP changes. The cached
peer NI data holding the peer's address and manager QP lives as long
as any connection uses it, and a probe that created a new responder
connection reused it without updating it. Our reply went to the old
QP, so the peer could not connect until all old connections were
gone. A probe from a restarted peer that found a connection still
being set up was answered with the peer's old epoch, which the peer
drops, and through the old address.

Update the peer NI data from the probe when creating a responder
connection, and replace a connection still being set up whose peer
restarted, as is already done for an active one.
