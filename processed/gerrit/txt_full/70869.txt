LU-21216 ldiskfs: do not normalize with empty prealloc_table

ext4_mb_normalize_request() of ext4-prealloc.patch takes the goal
window from s_mb_prealloc_table.  When the table is empty
("echo 0 > /proc/fs/ldiskfs/<dev>/prealloc_table"), neither window
branch runs: start stays 0 and size stays the file size in blocks.
For a write far beyond the allocated blocks of a file, the goal then
starts right after them and is trimmed to a group, so it need not
contain the request.  ext4_mb_use_inode_pa() computes a negative
length for it, and the OST aborts its journal:

  LDISKFS-fs error (device dm-1): ldiskfs_mb_mark_diskspace_used:
  3476: comm ll_ost_io00_005: Allocating blocks 1297408-1048576
  which overlap fs metadata
  Aborting journal on device dm-1-8.
  LDISKFS-fs (dm-1): Remounting filesystem read-only

Kernels that align the goal to the group of the request (Linux 5.19
and later, RHEL 8.8+ and 9.1+) instead preallocate up to a whole
group for the write.

Keep the original request when the table is empty, as for requests
that are not normalized.  Add sanity test_445.
