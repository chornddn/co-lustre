--- Commit Message ---
LU-19455 llite: switch statahead from readdir to name order

When the first stat() in an opened directory is for its first
entry in readdir order, statahead picks the directory listing
pattern and prefetches in hash order. A scan that stats the names
in numeric order then misses almost every lookup. sanity test_123h
hits this whenever its lowest numbered name happens to hash first,
about one run in 2000.

Check the next two stat() calls as well. If they continue the
numbering of the first name and the readdir order missed any of
them, stop the readdir walk, drop what it fetched, and continue
with file name order statahead from where the scan has got to.
Lookups that miss while the walk switches over are not counted
against its hit ratio, or it would stop at once.

A switch counts in both list_total and fname_total in the
statahead_stats file, so their sum can exceed the total.

Parse the file name number as decimal: a zero padded name such as
f000010 was read as octal.

Add sanity test_123o, which makes the lowest numbered name the
first readdir entry.
