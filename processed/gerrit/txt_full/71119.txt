LU-20730 llapi: scan past an unreadable inode table block

A target scan of ldiskfs stops with -EIO at the first block of the
inode table that cannot be read, so every object after that block is
lost too, although the rest of the table reads fine.

Give each worker's libext2fs handle a read error handler, as e2fsck
does: a failed read of several blocks is read again one block at a
time, and an inode table block that still fails comes back as zeroes
and is remembered. The scan counts the objects in that block as
skipped (LLAPI_SCAN_SKIP_IO) and goes on with the next one. A failed
read of any other block keeps its error.

conf-sanity 306 puts a dm "error" target over one inode table block
of a stopped MDT. lfs find --device fails without this patch and with
it finds every other file and warns about the skipped objects.
