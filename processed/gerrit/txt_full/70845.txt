--- Commit Message ---
DRAFT LU-21180 lod: add kunit test for defined striping

lod_use_defined_striping() builds the in-core layout (and the
per-stripe dt_object array) from an already fully-defined on-disk LOV
EA, as happens on replay of a layout-extend intent. It was untested.

Add lod_defined_striping_test.c, covering a plain LOV_MAGIC_V1 EA
(every stripe instantiated in order), a LOV_MAGIC_V3 EA with a pool
name (pool copied onto the component), and an EA with an unrecognized
magic (rejected with -EINVAL, no striping left behind). As in
lod_init_obj_test, stripe instantiation is redirected to a canned
mock_ost_obj per OST via a KUnit static stub on
lod_lookup_stripe_object(), so no real OSD/OSP is needed.

Export lod_use_defined_striping() and lod_striping_free(), needed by
the new test module, and register it in lustre/kunit/Makefile,
KUNIT.modules_list and lod/KUNIT.list.
