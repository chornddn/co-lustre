--- Commit Message ---
LU-21089 utils: warn about thin pool geometry on md arrays

The first write to a thin pool block after a snapshot copies the
whole block. On a parity md array the copy avoids parity reads only
when the block is a whole number of rows and kcopyd copies it in one
piece, and on raidkm only with rk_row_write set.

lctl snapshot create now checks this for LVM targets and warns when
the pool block is not a multiple of the array's optimal_io_size, when
dm_mod kcopyd_subjob_size_kb is less than a row of up to 1 MiB, or
when rk_row_write is 0. It only warns, since none of these affects
the snapshot's data.
