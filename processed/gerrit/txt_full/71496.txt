LU-20377 mgs: fix llog_catlist paging leak and duplicates

When the ioctl buffer for "lctl --device MGS llog_catlist" filled
up, mgs_list_logs() jumped to "out" with the rest of log_list still
linked, so those mgs_direntry entries were never freed.  An MGS with
many config logs would leak memory on every llog_catlist call.  The
returned ioc_count also pointed at the last listed log rather than
the next one, so that log was listed again at the start of the next
page, and del_ost would process it twice.

Free the remaining entries at "out", and return the index of the
first log not yet listed.

Also free dentry_list in mgs_clear_configs() if allocating namedash
fails.

Add conf-sanity test_123al to list enough logs for several pages.
