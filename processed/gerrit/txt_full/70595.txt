LU-19823 lod: lower EC parity and fill parity to fit OSTs

A layout whose raid sets get smaller to fit the OSTs or failure
domains may need more parity stripes than it has data stripes, e.g.
"-c 4 --ec 4+4" on 7 OSTs as 3+4.  Dropping up to 1/4 of the data
stripes does not help there, so the create would fail with ENOSPC
although the same file without EC is created.  Instead, when fitting
to the OSTs or failure domains, lower M by one at a time and fit K
again each time, since a smaller M can allow larger raid sets again,
so M is only as much smaller as needed and the example is 4+3.  When
shrinking at allocation K is fixed, so M becomes the most parity
stripes those raid sets can have.  The QoS single raid set shrink also
keeps at least as many data stripes as parity, by lowering M to half
of the usable OSTs.  M is not lowered for a component whose extent
holds too few stripes for its parity, e.g. "-E 1M" with 1MiB stripes.
Say in lfs-setstripe.1 that a lowered M protects against fewer OST
failures.

The allocators try each OST for the parity of one raid set only, the
one being placed when they get to it, and with -c never an OST with
data.  lod_ec_add_parities() then only tried the data OSTs of the
other raid sets.  An OST in a domain of an earlier raid set was not
tried for a later one, and the parity OSTs of other raid sets were not
tried at all, so a create could fail with ENOSPC for some RR start
positions or QoS choices although the domains fit every raid set, e.g.
"-c 5 --ec 2+2" on 8 OSTs in 5 domains as 1,2,3,4,5,1,2,3 with data on
OST5,6,7,0,1: raid set 0 takes OST3 and OST4 for its parity, and raid
set 1 needs two of domains 3, 4 and 5, but only OST2 is left.  Have
lod_ec_add_parities() try every OST of the pool for each raid set,
first those no component of the file uses and mirror avoidance
allows, then those used by other components or mirrors, such as the
data of other raid sets, then those with the parity of other raid
sets, each only if it has precreated objects and is not degraded.
Last, only from RR, which does not hold the QoS lock, also try OSTs
that are reconnecting, degraded or short of precreated objects,
waiting for objects to be precreated; QoS falls back to RR if the
parity is still short.  Keep bitmaps of the OSTs with data and parity,
so a wide layout needs no scan of its stripes for each OST.
An OST whose object can not be declared is tried at most once more,
on that last pass.  If the parity component is complete and reuses an
OST, mark it overstriped.  A raid set still never uses an OST or a
domain of its own stripes, nor a domain of an overlapping component
of another mirror, so as long as the OSTs or domains that other
mirrors leave free fit the largest raid set the parity fits.  Say in
failure-domain.txt and ec.txt that parity may share an OST or domain
with the parity of another raid set.

Add sanity-ec test_31i for "-c 5 --ec 2+2" with 4 and 5 failure
domains, with both allocators, created on MDT0000 since the MDTs
refresh the OST failure domains independently, and have test_27i
check that "-c 4 --ec 4+4" on 7 OSTs is created as 4+3 and resyncs.
