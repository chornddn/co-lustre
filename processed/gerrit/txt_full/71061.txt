LU-21239 ldlm: mix all name words in the resource hash

ldlm_res_hop_hash() sums the resource name words, so for a FID
resource the hash is effectively seq + oid.  FID sequences are
consecutive and each restarts at a small oid, so resources from
different sequences collide, and only a small part of the 2^21
MDT hash chains is used.  LU-8130 moved the MDT and MDC namespaces
from a hash that mixed seq and oid to this plain sum.

On a busy MDS with 1.4M to 3.2M resources, ldlm_resource_get()
walked 16 to 100 entries per lookup under the bucket lock, and
ldlm_res_hop_keycmp() took about 10% of CPU per service thread.

Mix every name word with hash_64() and pick the chain with
hash_32().  Only placement in the table changes.

rsync test with 4096 workers on seven clients against a two-MDT
filesystem, patch on the MDS only (seconds, before -> after):

                          MDT1 subdir       MDT0 root
warmup (all workers)       818.6 -> 729.2     778.4 -> 744.2
ext4 -> Lustre update      366.7 -> 293.4     325.1 -> 296.3
Lustre -> ext4 scan         10.30 -> 3.98       7.71 -> 5.28

ldlm_res_hop_keycmp() falls from 7.19% to 0.22% of perf samples.
