LU-20718 llapi: ignore stale lcme_time_and_id from old servers

Servers without EC support only write lcme_timestamp for NOSYNC
components and leave the field alone otherwise, so on every other
component it holds whatever the packing buffer contained before.
EC redefined the field as lcme_time_and_id, a 48-bit timestamp and
a 16-bit mirror link id, and the client reads both unconditionally.
A layout from such a server therefore carries random link ids and
timestamps:

- "lfs setstripe --component-add" merges the new component into
  the layout read from the file, the stale link id becomes
  LCME_FL_IS_LINK_ID on an on-disk component, and the layout
  sanity check rejects it with "Wrong flags" (sanity-pfl test_18).
- "lfs getstripe --comp-flags" appends the stale timestamp to the
  flags as a date in the year 56546 (sanity-pfl test_19e).

Only read the field where it is defined: the link id when the
layout has a parity component, the timestamp when the component is
NOSYNC or the layout has a parity component, and print them under
the same conditions.  The EC stripe counts that follow the field
are left unset by the same servers, so read them only for a layout
with a parity component as well.
