LU-20690 ec: no raid set with a single data stripe

ec_split_stripes() split an odd number of data stripes with k=2
into raid sets of 2 and one set with a single data stripe, e.g.
{2, 2, 1} for 5 stripes.  The parity of that set is only a copy
of its one data stripe, but it needs as many parity stripes as
a full raid set, and the extra set made layouts such as
"-c 5 --ec 2+2" fail the check that the parity stripes fit in
the data stripe count.

Use one raid set fewer in this case, so the residual stripe goes
into the first raid set, {3, 2} for 5 stripes and {3, 2, 2} for 7.
k=2 with an odd total of 5 or more stripes is the only case that
made a single-stripe raid set, other splits are unchanged.  All
users of the split size their buffers from esc_k0 rather than k,
as a 3-stripe file with k=2 already gives one raid set of 3.

The split is computed from the layout rather than stored in it,
so it has to change before EC layouts are in use.

lod_ec_shrink_data_geometry() reduced the split one data stripe at
a time when fewer OSTs were available, which could still leave a
single-stripe raid set, e.g. {2, 2, 1} for 5 of 6 stripes, unlike
the {3, 2} that clients compute from the layout.  Use
ec_split_stripes() for the reduced stripe count instead.

Add sanity-ec test_31h to check the new raid sets with --ec-map
and that "-c 5 --ec 2+2" works, and test_65e for recovery of a
3-stripe raid set.
