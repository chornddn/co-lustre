LU-21035 lnet: don't hold traffic on discovery push

When the local NI configuration changes, or the first discovery
of a Multi-Rail peer reaches the Push stage, the peer is not up
to date until the Push is acknowledged, so
lnet_initiate_peer_discovery() queues all messages to the peer on
lp_dc_pendq. If the Push goes over an interface that is not usable
yet, e.g. a newly added NI, messages are held for up to the
transaction timeout and then finalized with an error, and the next
message triggers another Push and is held again. The peer's NIDs
are already known at this stage; the Push only tells the peer
about the local NIDs.

Add lnet_peer_is_sendable_locked() and use it as the traffic gate
in lnet_initiate_peer_discovery(). It also allows traffic when the
peer's NIDs are merged and only a Push is outstanding: in flight,
failed or still needed. Gateways keep the original behavior. Once
the Push is sent, release the messages on lp_dc_pendq, and if
discovery fails only because of the Push, send them instead of
finalizing them. Retry a needed Push from the traffic path at most
once per lnet_transaction_timeout, based on lp_last_queued, which
is now set from the monotonic clock.

lnetctl discover, LNetAddPeer() and LNetPeerDiscovered() still
wait for the Push ACK and report Push failures.
