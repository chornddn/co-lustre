LU-20974 gss: drop unused multi-round context negotiation

Lustre clients always initiate GSS context negotiation with
PTLRPC_GSS_PROC_INIT and an empty handle, and complete it in a
single round. PTLRPC_GSS_PROC_CONTINUE_INIT is never sent, so the
server-side support for multi-round negotiation is dead code.

Remove it:
- in gss_svc_accept(), stop routing PTLRPC_GSS_PROC_CONTINUE_INIT
  to gss_svc_handle_init(), so it is dropped as an unknown proc;
- in gss_svc_handle_init(), refuse any init request carrying a
  non-empty handle;
- in lsvcgssd, refuse requests with a non-empty input handle, and
  treat GSS_S_CONTINUE_NEEDED from gss_accept_sec_context() as a
  negotiation failure, releasing the context.
