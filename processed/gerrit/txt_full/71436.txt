LU-20993 mdt: don't re-create unlinked file on open replay

A client can keep an open request on its replay list after the
file was unlinked and its MDT object destroyed, e.g. when the open
had no md_open_data so the close could not clear rq_replay. At the
next MDT restart the open is replayed, mdt_open_by_fid() returns
-ENOENT and mdt_reint_open() re-creates the destroyed FID with
no_create set: the file comes back with the client's saved layout
and no OST objects, so stat returns ENOENT while lfs fid2path and
lfs getstripe succeed.

A re-create is only valid if the original create never committed.
If the replayed request transno is at or below last_committed, the
create committed and the object was destroyed afterwards, so refuse
the replay with -ENOENT instead of re-creating the object.

Add OBD_FAIL_MDS_REPLAY_OPEN_SKIP to skip open replays, so orphan
cleanup destroys an unlinked file that a client still holds open,
and replay-single test_204 that uses it and then replays the open
again, checking the FID is not re-created.

Test-Parameters: testlist=replay-single env=ONLY=204,ONLY_REPEAT=10
Test-Parameters: mdscount=2 mdtcount=4 testlist=replay-single
