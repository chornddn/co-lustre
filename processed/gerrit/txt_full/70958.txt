LU-21069 osp: keep cache of new object with queued writes

osp_create_interpreter() drops the attribute cache of a remote object
once its create is confirmed, without marking it stale. For a new
remote update llog the first appends are already queued behind the
create and accounted for in the cached size only. A later append then
fetches the remote size, which does not include them yet, and writes
its record at the same offset: the llog header claims a record that
is overwritten on disk, and recovery fails with
'missed desired record? 2 > 1' / 'get update log failed: rc = -2'.

Keep the cache while the object has writes in flight, and update the
cached size and the pending-write list under opo_lock so the check is
atomic.

Add OBD_FAIL_OSP_LLOG_CREATE_RACE, which delays the create reply of
a new remote object and then the next queued update, and
replay-single test_136, which uses it to reproduce the race on a new
remote update llog and checks that recovery replays both hard links.
