LU-20869 tests: run sanity-quota test_91 on the live fs

test_91 reformatted and restarted the whole filesystem before and
after its check, so two formatall and a setupall dominated its run
time (385 s mean in CI, 94 s on a single node 1 MDT 2 OST VM).

Run it on the mounted filesystem instead: enable user quota on the
OSTs, create the pool, stop the MDS, delete the two OSTs' slave
index files and restart it, so the LU-17770 path with pool OSTs
lacking an index file at QMT start is still exercised. The pool,
quota limit and quota_slave.enabled are restored on exit, and mds1
is restarted if a failure left it stopped.

The group and project slave indexes that earlier subtests leave
are deleted too: they would put the OSTs into the global pool's
slave array at QMT start without counting them as user slaves,
and the MDS can then hit the qmt_seed_glbe_all() LBUG.

sanity-quota test_91, ldiskfs, 1 MDT 2 OST VM, 3 runs each:
  before: 92, 99, 91 s
  after:  61, 44, 45 s (44 s once warm)

Depends on the ldiskfs-only skip in change 69759.
