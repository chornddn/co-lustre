LU-20954 build: auto-detect o2ib on kernels without IB

Configuring against a kernel without InfiniBand, such as many
aarch64 VM kernels, fails unless --with-o2ib=no is given:

  configure: error: cannot compile with OpenIB gen2 headers

The --with-o2ib default is "yes", so it cannot be told apart from
an explicit --with-o2ib=yes.  The in-kernel o2ib check only looks
for the rdma headers, which are in every kernel tree, and the gen2
compile test then fails as a hard error.

Make the default --with-o2ib=auto.  Only build the in-kernel
o2iblnd if the kernel has CONFIG_INFINIBAND_ADDR_TRANS (which
depends on CONFIG_INFINIBAND).  In auto mode, build without
o2iblnd, with a warning, if neither the in-kernel nor an external
o2iblnd is usable.  A gen2 compile failure for an o2iblnd that was
found is still an error.  An explicit --with-o2ib=yes now fails if
no o2iblnd can be built, instead of only warning.

Pass ENABLEO2IB back to configure for deb builds, so auto mode
stays auto, and skip in-kernel ko2iblnd in the DKMS configs when
the kernel lacks CONFIG_INFINIBAND_ADDR_TRANS.
