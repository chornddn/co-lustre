LU-20726 tests: restore at_max after sanity test_401dc

sanity test_401dc raises at_max by 10 with "set_param -P", and its
cleanup set at_max back with "set_param -P" without waiting for the
clients to apply it.  The change reaches the client only after its
config lock is revoked and the params llog is reprocessed, so the
next tests could start with the raised at_max.  test_401gb would
then save the raised value, remount the client, which applied the
restored at_max from the params llog, and fail with:

    at_max not 610, got 600

The cleanup also left an at_max record in the params llog, so every
later remount in the session applied it.

Delete the at_max records from the params llog first, so no node
applies them on a later llog reprocess, then set the original
at_max directly on all nodes before the test returns, since
deleting the records does not change the value on the nodes.

Drop the default EXIT argument from the test's stack_trap calls.
