LU-21204 lod: do not let another component's OSTs cost stripes

A plain component whose stripe count is larger than the number of OSTs
is clamped to the OST count and flagged LOD_USES_DEFAULT_STRIPE, so
only 3/4 of the count has to be found before allocation succeeds.
lod_ost_alloc_rr() keeps its first pass off the OSTs used by another
component of the file and retried only while short of that minimum, so
a trailing PFL component could stop one OST short: -c 40 on an 8-OST
file system, with one OST taken by an earlier component, allocated 7
stripes instead of 8 and capped the file at 112 TB, while -c 8 reused
the OST and got all 8.

An OST used by another component is only a preference, so it must not
cost stripes: count the OSTs skipped for that reason and, while the
component is short of the requested count, repeat the first pass with
the preference relaxed.  Only that preference is relaxed, so slow,
degraded and reconnecting OSTs are still avoided, and an allocation
that is short of healthy OSTs behaves as before.

Record the two decisions in lod_rr_retry_comp() and
lod_rr_retry_slow() so they can be tested, with KUnit cases for them
and for the minimum stripe count of a default-striped component, and
add sanity-pfl test 30, which creates a PFL file whose last component
asks for more stripes than there are OSTs and checks that it gets one
object per OST.
