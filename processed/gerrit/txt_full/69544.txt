LU-20909 sec: decrypt units after a hole in a large page

The read paths of encrypted files stop decrypting a page at its
first all-zero 4KiB encryption unit, treating it as the start of a
hole that runs to the end of the page.  With PAGE_SIZE > 4KiB a hole
may be followed by data in the same page, e.g. after punching the
first 4KiB of a page, so the rest of that page is returned to the
application still encrypted.  osc_brw_fini_request() also marks
such a page empty for ll_io_zero_page(), which then skips zeroing
the truncated unit.

Skip empty units and keep decrypting the rest of the page in osc,
DoM read-on-open and PCC-RO, and only mark the page empty when no
unit holds data.

Also fix ll_io_zero_page() truncating the file offset of the page
to 32 bits, so a truncate past 4GiB set up the IO and lock at the
wrong offset.

Add a hole-before-data check to sanity-sec test_38.
