LU-21272 o2iblnd: map bulk DMA in IOVA-cacheable chunks

Behind a translating IOMMU, every dma_map_sg() allocates one IOVA
range for the whole scatterlist. The IOMMU layer only caches ranges
up to dma_opt_mapping_size() (128 KiB on current kernels) per CPU.
o2iblnd maps a whole LNet bulk (up to 1 MiB, 256 pages) in one call,
so every bulk map and unmap goes to the rbtree allocator under the
IOMMU domain's iova_rbtree_lock, first trying the 32-bit window. On
RoCE clients with the IOMMU in translated mode, Lustre bulk throughput
drops to 1/2 or 1/3 of line rate on about a third of boots. With
iommu=pt, 0 of 21 boots degraded, versus 8 of 21 without it.

Map tx_frags with one dma_map_sg() per chunk of at most
dma_opt_mapping_size(), so each IOVA comes from the per-CPU cache.
The DMA segments of all chunks are packed into a new tx_dma_frags
array, which feeds rd_frags and ib_map_mr_sg(). FastReg still
registers the whole bulk as one MR, so the wire protocol and the
number of RDMAs are unchanged. Unmap splits the list the same way,
using only the page offsets and lengths that dma_map_sg() leaves
intact.

By default, chunk only when the IOMMU translates the device's DMA
addresses in lazy mode, the x86 default, and then follow
dma_opt_mapping_size(). Without a translating IOMMU there is no IOVA
to allocate, and in strict mode each chunk unmap also flushes the
IOTLB. Kernels without dma_opt_mapping_size() do not chunk by default.
Chunking is off when the IOMMU granule is smaller than PAGE_SIZE. The
chunk IOVAs then do not meet at page boundaries, and FastReg cannot
register them as one MR. Bulks that already fit in one chunk, and P2P
buffers, are still mapped in a single call. The chunk size is a
property of the HCA and is read at map time. The tx_dma_frags array
(IBLND_MAX_RDMA_FRAGS entries per tx) is only allocated for pools
that chunk.

At device setup, print the chunk size when bulk DMA is chunked. Warn
when the IOMMU translates the HCA's DMA addresses but bulks are still
mapped in one call.

Add compat helpers for dma_get_merge_boundary(),
iommu_is_dma_domain() and dma_opt_mapping_size().

Add a ko2iblnd module parameter:
  dma_map_chunk_kb=-1  use dma_opt_mapping_size() behind a lazy
                       IOMMU (default)
  dma_map_chunk_kb=0   map each bulk in one call (old behaviour)
  dma_map_chunk_kb=N   chunks of N KiB on any device, e.g. on kernels
                       without dma_opt_mapping_size()

Add sanity-lnet test_316, which runs LST with data checks over 16 KiB
chunks, and test_317, which fails a chunk mapping with the new
CFS_FAIL_O2IBLND_DMA_CHUNK_MAP and checks the unwind. Both skip when
the HCA cannot chunk, e.g. on software RDMA devices. Move the o2ib
node pair setup of the bounce tests into setup_o2ib_pair().
