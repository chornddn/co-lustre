LU-20739 build: check vfs_mkdir() and can_mmap_file() alone

RHEL 10.3 (kernel 6.12.0-264) backports half of two upstream changes,
and the client modules fail to build on it:

- can_mmap_file() without vfs_mmap_prepare(), so the can_mmap_file()
  that lustre_compat defines without HAVE_VFS_MMAP_PREPARE is a
  redefinition.
- inode_operations.mkdir returning a dentry without vfs_mkdir()
  returning one, so ll_vfs_mkdir(), keyed on
  HAVE_IOPS_MKDIR_RETURNS_DENTRY, assigns an int to a dentry in
  pcc_mkdir().

Add HAVE_CAN_MMAP_FILE and HAVE_VFS_MKDIR_RETURNS_DENTRY and key the
two compat helpers on them.  vfs_mkdir() with a delegate argument
returns a dentry as well but fails the new test, so the delegate test
defines HAVE_VFS_MKDIR_RETURNS_DENTRY too.

Also make the vfs_mmap() fallback use call_mmap().  On RHEL 10.3,
ext4 sets only .mmap_prepare, which the kernel's can_mmap_file()
accepts, so pcc_file_mmap() on an ext4 PCC backend would call a NULL
.mmap.  RHEL 10.3's call_mmap() handles .mmap_prepare, and on older
kernels it calls .mmap as before.
