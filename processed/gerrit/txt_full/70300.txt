LU-21089 utils: add LVM thin backend to lctl snapshot

lctl snapshot_* works only for ZFS targets. An ldiskfs target on
an LVM thin LV can be snapshotted the same way: dm suspend freezes
the filesystem, so a thin snapshot taken under the write barrier
is a clean image. dm-thin copies a block once per snapshot
generation, so the cost does not grow with the snapshot count, as
it does with classic LVM snapshots.

Accept "lvm:/dev/<vg>/<lv>" devices in ldev.conf. The snapshot
piece is the read-only thin LV <lv>_ss_<ssname>, and the lustre:*
ZFS properties become lustre_* LV tags, with the comment
hex-encoded. Nothing is written into a piece: it is mounted with
rdonly_dev (LU-15873) and fsname=<snapshot fsname>.

Unlike ZFS, an LVM piece is made on the node where the origin LV
is active, with no retry on the failover node, and a target with
an external journal is refused. Pieces keep the LVM activation
skip flag, so they are active only while mounted.

Let sanity-lsnapshot run on ldiskfs when every target is an LVM
thin LV, with FLAKEY=false. CI has no such targets, so CI only
checks that the ZFS path is unchanged.
