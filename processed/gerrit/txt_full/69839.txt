--- Commit Message ---
LU-20999 utils: remove lctl add_conn and del_conn commands

lctl add_conn and del_conn injected LCFG_ADD_CONN and LCFG_DEL_CONN
records into a device by hand. Nothing in the test suite, lustre-iokit
or the man pages uses them, and del_conn was actually sending
LCFG_DEL_MOUNTOPT, so it never worked as documented.

The kernel handling of LCFG_ADD_CONN stays, since the MGS config logs
still emit it for failover nodes and tgt_mount.c synthesizes it for
LWP devices. LCFG_DEL_CONN, however, has never been written by the
MGS or any other in-tree producer, so the kernel path behind it is
dead: drop the class_process_config() case, class_del_conn(),
obd_del_conn(), the o_del_conn method and client_import_del_conn().
The LCFG_DEL_CONN value itself is kept in the UAPI header since it is
part of the config record format checked by wirecheck.
