--- Commit Message ---
LU-20211 osc: discard a truncate size range from cache

To replace the objects of an unavailable OST past a truncate size,
the client discards its dirty pages from the page after the size
before the layout change, since the replaced objects hold no data
before the size.  That discard is page aligned, but
osc_cache_writeback_range() drops whole extents and asserts that the
chunk-aligned range contains each extent, which is only true for a
lock cancel.  An extent that starts before the range would hit the
assertion, or with 1MiB ZFS chunks lose the dirty pages below the
size.  Write such an extent back instead: only a kept object maps
data below the size, and the truncate punch removes the rest.

An active extent of an mmap write racing the discard asserted too.
Leave it to the truncate instead.  mdc_io_fsync_start() discarded
the whole DoM object for any range: discard only the requested range.
