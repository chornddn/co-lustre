LU-16475 mgc: answer whether a removed OST is set up

Before the MGS lets a new OST take the index of an OST removed by
"lctl del_ost", it needs to know that no mounted client or MDT still
has the old OST set up, since a new OSC or OSP with the same name
cannot be added there while the old one exists.

Add a glimpse of the config lock, with a new ldlm_gl_config_desc that
names an OST index and a new config_lvb for the reply.  The MGC
answers it by looking for an OSC or OSP of that OST on the node, for
the locks of both the config and the sptlrpc logs, which share one
lock resource.  Nodes without this reply -ENOSYS, as for any lock
without a glimpse callback.  The desc op names the target type, so
that removing an MDT can add its own op later.
