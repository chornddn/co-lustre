LU-17238 llite: negative xattr cache

Implement a negative xattr cache using ERR_PTR(-ENODATA) as a
sentinel value in ll_xattr_entry to indicate a confirmed-absent
xattr. This avoids repeated RPCs for xattr names known to be absent.

This target begins by targeting SELinux and POSIX ACL xattrs, but the cache
can work for any xattr.

When an inode has no POSIX ACL, every inode_permission() call during
path walks triggers a getxattr RPC for system.posix_acl_access that
returns -ENODATA. On busy clusters this produces hundreds of
thousands of RPCs per second.

Similarly, when a SELinux-enabled client accesses files created by a
client without SELinux, the kernel security hooks call getxattr for
security.selinux while holding the LOOKUP lock, which can cause the
deadlock described in LU-9193.

Negative entries are skipped in listxattr output.

Since both ACL and SELinux xattrs can be granted under locks that are
not MDS_INODELOCK_XATTR, targeted cache invalidation is used to remove
the entries as the corresponding locks are revoked. Because they reuse
the xattr cache infrastructure, they will also be invalidated if an
MDS_INODELOCK_XATTR lock is revoked, but they are typically only read on
open/lookup and very rarely modified, so this is deemed acceptable.

ACL negative caching:
- ll_update_inode(): when OBD_MD_FLACL is set with NULL ACL,
  inserts a negative entry for system.posix_acl_access
- ll_get_acl_common(): checks negative cache before RPC
- ll_set_acl(): removes negative entry when ACL is set
- ll_lock_cancel_bits(): clears negative ACL and seclabel
  entries on LOOKUP | PERM lock cancel

Seclabel negative caching (requires subsequent server patch to trigger):
- ll_xattr_list(): checks negative cache for seclabels before
  falling through to the RPC path
