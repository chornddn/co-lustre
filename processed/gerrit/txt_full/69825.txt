LU-12668 utils: resync EC parity with mirror resync API

'lfs mirror resync' would resync stale data components with
llapi_mirror_resync_many_params() and then stale parity components
with a separate llapi_ec_resync_many_params().  Other callers of the
generic resync functions would never resync parity, and parity
components passed to llapi_mirror_resync_many_params() would have
file data copied into them.  Running `lfs mirror resync --only' on
a data mirror would also leave the stale parity protecting it, as
only the parity mirror's own id selected parity components.

Instead, resync parity components in llapi_mirror_resync_many_params()
from the data components they protect, after the data components have
been copied, and skip a parity component whose data component failed
in the same call.  Count --stats and bandwidth progress once over
both, with the EC struct llapi_resync_progress.  Replace
llapi_ec_resync_many_params() and llapi_ec_find_stale(), which are not
yet included in a release, with llapi_mirror_find_stale_flags(), which
collects the stale data components and, with LCME_FL_PARITY, then the
stale parity components, also those protecting a mirror given in
@mirror_ids, and resync both kinds of component in one call from
lfs.  With LCME_FL_NOSYNC it also collects the components of NOSYNC
mirrors without listing them in @mirror_ids.
llapi_mirror_find_stale() still returns only data components, for
callers that copy data themselves.

An error in one component no longer undoes the others: lrc_synced
stays set for each component that was synced, and lfs still clears
LCME_FL_STALE from those before returning the error.
'lfs mirror resync --force-resync' now marks components to be synced
as llapi_mirror_find_stale() does, not after.

Add man pages for llapi_mirror_find_stale(3), covering the new
llapi_mirror_find_stale_flags(), and llapi_mirror_resync_many(3).

Add sanity-ec test_12i.
