LU-12668 utils: resync EC parity with mirror resync API

`lfs mirror resync` would resync stale data components with
llapi_mirror_resync_many_params() and then stale parity components
with a separate llapi_ec_resync_many_params().  Other callers of the
generic resync functions would never resync parity, and parity
components passed to llapi_mirror_resync_many_params() would have
file data copied into them.  Running `lfs mirror resync --only` on
a data mirror would also leave the stale parity protecting it, as
only the parity mirror's own id selected parity components.  Parity
would also be recomputed from a stale data mirror and marked in sync,
with `--only` on the parity mirror, or when the data mirror was
NOSYNC and so not resynced.

Instead, resync parity components in llapi_mirror_resync_many_params()
from the data components they protect, after the data components have
been copied, and skip a parity component whose data component failed
in the same call.  Return an error for a parity component whose data
component is stale and not resynced in the call, and do not collect
the parity of a stale NOSYNC mirror unless the mirror is collected
too.  Copy data only over the extents of the data components.  Count
`--stats` and bandwidth progress once over both, with the EC struct
llapi_resync_progress.  Replace llapi_ec_resync_many_params() and
llapi_ec_find_stale(), which are not yet included in a release, with
llapi_mirror_find_stale_flags(), which collects the stale data
components and, with LCME_FL_PARITY, then the stale parity components,
also those protecting a mirror given in @mirror_ids, and resync both
kinds of component in one call from lfs.  With LCME_FL_NOSYNC and no
@mirror_ids it also collects the components of NOSYNC mirrors.
llapi_mirror_find_stale() still returns only data components, for
callers that copy data themselves.

An error in one component no longer undoes the others: lrc_synced
stays set for each component that was synced, and lfs still clears
LCME_FL_STALE from those before returning the error.  An error before
anything is copied clears lrc_synced of every component, and an
error in one parity component no longer leaves the later ones stale.
A failed punch or truncate of a stale component is now returned,
where it was ignored before, so `lfs mirror resync` fails with it.
A stale component that is not instantiated is no longer punched or
truncated if the in-sync mirrors have no instantiated component at the
end of the copy either, as it has nothing to remove and I/O to a
designated mirror cannot instantiate it, so it is synced instead of
left stale.
llapi_mirror_find_stale() now accepts exactly @comp_size stale
components instead of returning -EINVAL, and returns -errno instead
of -1 if reading the layout fails.  `lfs mirror resync` and
`lfs mirror verify` treat the stale parity of a stale NOSYNC mirror
as NOSYNC, as resync does not recompute it.
`lfs mirror resync --force-resync` now marks components to be synced
as llapi_mirror_find_stale() does, not after, and still rewrites the
listed data mirrors when only the parity protecting them is stale,
then recomputes that parity.  It no longer picks a parity mirror as
the source of the forced resync, which would have left the data
mirrors stale with nothing to resync them from.

Add man pages for llapi_mirror_find_stale(3), covering the new
llapi_mirror_find_stale_flags(), and llapi_mirror_resync_many(3), and
describe how lfs-mirror-resync(1) handles EC parity mirrors.

Add sanity-ec test_12i, test_12j, test_12k and test_12l.
