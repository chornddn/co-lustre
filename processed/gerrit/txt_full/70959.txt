--- Commit Message ---
LU-19536 obdclass: keep a failed unaligned DIO read error

When the read of an unaligned DIO sub DIO failed, its end
still copied the bounce pages out to the user buffer, and the
result of that copy replaced the read error. That result is
the only way the error reaches the parent DIO, so with
parallel DIO the read returned success with the contents of
bounce pages the read never filled.

Copy out only when the read succeeded, and keep the read error
otherwise.

Add sanity test_119x, which fails the read on the OST and
checks that the reader gets the error.

Fixes: 7194eb6431d2 ("LU-13805 clio: bounce buffer for unaligned DIO")

Tested PS8 on a RHEL 9.6 client (5.14.0-570.37.1), master 54dc726b562 with 70957 PS8 under it:
- with only the test of this patch and without the cl_io.c change, 119x fails: "failed read succeeded, 24576 bytes of C". The read returned success, and the whole buffer held the other file's data from the page pool.
- with the whole patch, 119v, 119w and 119x pass, 3 runs each.

The fix looks right to me: ret in cl_sub_dio_end() is the sub DIO's I/O result (anchor->csi_sync_rc), so a failed read no longer copies the bounce pages out, and the count of a successful copy no longer replaces the error; a failed copy still reports its own error. OBD_FAIL_OST_BRW_READ_BULK returns err_serious(-EIO), so the client does not resend and the test cannot hang.

[nit] The CLIENT_VERSION check in 119x is not needed: the fix is client-only and the test runs on the local client, so an older client has no such test and the check can never skip it (lustre-test-scripts, "Version checks for interop"). The same applies to 119v and 119w in 70957.
