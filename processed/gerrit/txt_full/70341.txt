--- Commit Message ---
LU-21099 build: pass WQ_PERCPU to per-CPU workqueues

Linux 7.2 warns, with a stack trace, when alloc_workqueue() is given
neither WQ_PERCPU nor WQ_UNBOUND, then sets WQ_PERCPU itself:

  workqueue: cfs_rh is using neither WQ_PERCPU or WQ_UNBOUND.
  Setting WQ_PERCPU.
  WARNING: kernel/workqueue.c:5851 at __alloc_workqueue+0x468/0x4d0

This fires on every obdclass load, and panics hosts running with
panic_on_warn.

Pass WQ_PERCPU explicitly to the cfs_rh, kfilnd_wq, gss_cleanup_wq
and osd-ldiskfs integrityd workqueues, which were already per-CPU by
default, so behaviour is unchanged. Add a configure check for
WQ_PERCPU and define it as 0 on older kernels.
