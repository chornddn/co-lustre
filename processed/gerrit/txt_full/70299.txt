--- Commit Message ---
LU-21089 utils: mount a read-only target under another fsname

An ldiskfs snapshot has to start under its own fsname. Today that
needs tunefs.lustre --rename, which writes into the snapshot. ZFS
snapshots avoid it: the new name is a dataset property.

Add the mount.lustre option fsname=<name>, allowed only with
rdonly_dev. It replaces the fsname in the on-disk mount data and in
the service name before the kernel mount. The kernel already
accepts the renamed target under rdonly_dev (tgt_server_data_init()
ignores the old last_rcvd UUID). With rdonly_dev, mount.lustre also
no longer clears the LDD_F_UPDATE flag on the device, so it writes
nothing. The "update" mount option is still passed to the kernel.

conf-sanity: add test_176, start an OST under a forked fsname with
rdonly_dev, then under its own name again, and check that fsname=
is refused without rdonly_dev and on a client.
