DRAFT LU-21180 lod: dedup ku dependency reloads, scope KUNIT.list

ku reloads any dependency .ko living in the same directory as a
changed file before every selected module, to guard against a stale
instance predating a rebuild. When several modules in one run share
a dependency, such as lod_comp_test, lod_merge_test, lod_mdt_alloc_test
and lod_mirror_test all depending on lod.ko, this reloaded lod.ko once
per module instead of once per run, adding ~0.3s per extra module, and
tore each dependency down and rebuilt it between modules even when
nothing about it had changed.

Compute the union of every selected module's dependencies up front
(GLOBAL_DEPS, in first-seen order - KUNIT.modules_list already lists
each module's own deps in load order, so concatenating them produces
a valid combined order), force-reload only the ones that are both
stale - living in the same directory as a changed file - and already
loaded, then insmod whatever is not yet loaded, all once before any
module's tests run. Record exactly what this invocation inserted in
LOADED_BY_US, and unload it again in reverse order once every
selected module has run, leaving the system as it was found instead
of leaving dependencies loaded for a later ku invocation to reuse.

Also narrow the lod_comp_test, lod_merge_test and lod_mirror_test
entries in lustre/lod/KUNIT.list from bare "*.[ch]" patterns, which
fire on any change anywhere in lustre/lod/, to the functions they
actually exercise (lod_comp_prep_create, lod_declare_layout_merge,
lod_last_non_stale_mirror), matching the file:function convention
the other entries already use.

Together these cut a realistic multi-function ku run (3 modules
correctly selected instead of 4+ from the stale globs) from 1.6s to
1.17s, a single-function change to ~0.5s, and a full 29-module LOD
suite run to ~4.2s with dependencies loaded and unloaded exactly once.
