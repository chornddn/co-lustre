LU-19548 lfs: mirror extend support for EC

Add three EC modes to 'lfs mirror extend':

--mirror-id N --ec D+P   attach a parity mirror to existing data
                         mirror N (N >= 1; id 0 is reserved for
                         non-FLR layouts and is rejected)

-N [K] --ec D+P          add K new data+parity mirror pairs
                         (K defaults to 1)

--ec D+P                 attach a parity mirror to the file's lone
                         data mirror; a file with 2+ mirrors errors
                         out asking for --mirror-id or -N

As a regular extend never leaves a new mirror stale, the new mirrors
are in sync when the command returns: data mirrors are populated by a
copy before the layout merge, parity mirrors are computed in place
with the machinery 'lfs mirror resync' uses.

A parity mirror is attached by merging a layout of parity components
only, leaving the data mirror they protect in place. The new
llapi_layout_comp_add_parity_only() builds that layout, and
client-side layout sanity no longer requires a data component for
every parity component.

Two lod changes support that split pair. lod_qos_prep_create() takes
the parity stripe count from the client, as the data component it
would size from is not in the volatile file being created.
lod_declare_layout_merge() stamps the data component with the parity
mirror id, without which 'lfs mirror split' cannot see the pair, and
refuses a dangling or already-used link.

A stale data mirror is refused, as parity computed from superseded
data is never re-staled by a later resync. A 'nosync' data mirror is
refused for now, as is a second parity mirror of a different geometry
on one data mirror; neither refusal is asserted by a test.

A rider in lod_qos_prep_create() rejects an EC data stripe count of
zero: lod_verify_striping() bounds only k + m, so a k == 0 layout
reaches ec_split_stripes() and divides by zero in the kernel.

An older MDS refuses a parity-only create buffer, so the new sanity-ec
subtests are gated on the server version and skip on an interop run.
