LU-21325 osd-zfs: keep the xattr dnode in osd_add_projid()

osd_add_projid() gives an object made before the pool had
project_quota a slot for the project ID. It rebuilds the SA with
sa_replace_all_by_template(), which drops every attribute that is
not in the template, and the template lacks SA_ZPL_XATTR. The first
time such an object gets a project ID, with "lfs project -p" or by
a rename into a project directory, the pointer to its xattr dnode
is dropped.

The xattr dnode holds the xattrs, and a layout, that do not fit in
the SA. The MDT keeps using its cached copy of the object, so
nothing shows until it loads the object from disk again, at a
restart or when the cache is trimmed. After that those xattrs are
gone, and a file whose layout spilled reads as empty.

List SA_ZPL_XATTR in the template when the object has an xattr
dnode. It goes after RDEV, so UID, GID and PROJID keep the offsets
that zfs_space_delta_cb() reads. __osd_sa_attr_init() builds its
template the same way and gets the same entry. The assertion on the
template size moves after the last attribute is added. Objects that
already lost the pointer are not repaired.

The test for this also found that osd_add_projid() sleeps, and
osd_attr_set() calls it with oo_attr_lock held for write.
sa_lookup() and sa_replace_all_by_template() take SA mutexes, and
zio_buf_alloc() and nvlist_pack() allocate with KM_SLEEP. On a kernel
that counts preemption, such as RHEL 9, an allocation that has to
grow its slab cache schedules inside the lock:

  BUG: scheduling while atomic: mdt00_000/1212285/0x00000002
   schedule_timeout+0x87/0x160
   spl_cache_grow+0x1bb/0x2b0 [spl]
   spl_kmem_cache_alloc+0x148/0x160 [spl]
   osd_add_projid+0x616/0x8b0 [osd_zfs]
   osd_attr_set+0xce4/0x1070 [osd_zfs]

The same thread then fails an assertion in lnet_ni_send() and the
MDS panics.

The rest of osd_attr_set() only updates the cached attributes under
the lock and calls osd_object_sa_bulk_update() after it. Do the same
for the project ID: call osd_add_projid() before taking the lock,
still under oo_guard, and read the cached attributes in it under a
read lock. The project ID is then set with the other attributes
under the lock, which stores the value osd_add_projid() wrote a
second time.

conf-sanity 141 makes the MDT pool without project_quota, makes
files whose xattrs and layout spill out of the SA, enables the
feature, gives the files a project ID, restarts the servers and
compares data, layout, xattrs and project ID. On RHEL 9 the MDS
panics without the lock change, and the files lose xattrs and
layouts without the template change.
