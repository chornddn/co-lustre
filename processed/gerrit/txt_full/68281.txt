--- Commit Message ---
LU-17000 lfsck: do not fail a scan for a vanished directory

GOTO() does not assign its second argument, so the ternary in
lfsck_namespace_assistant_handler_p1() was discarded and the target
label still saw the -ENOENT that lfsck_assistant_object_load() returns
when the object is already dead. A directory unlinked while the
namespace LFSCK was running was therefore logged and counted as an
LFSCK failure, and with LPF_FAILOUT it aborted the scan.

One of the four sites jumps to stop:, which falls through to out:.
The reload there is guarded by dir == NULL, so the failed load left an
ERR_PTR in dir that could reach lfsck_namespace_repair_bad_name_hash()
and be dereferenced. Clear dir on that path as well.

Assign the result, spelled as the three working instances of the same
idiom already in this file.
