LU-20235 utils: replace llapi_mirror_copy_many() code

The llapi_mirror_copy_many() function was implemented during early
FLR development and has remained largely unused/unchanged since
then. It appears only to be used by the (unused?) "lfs mirror copy"
command and a few test cases. It is lacking "proper" sparse file
support, in that it is truncating the whole target mirror(s) and
then copying the data over, which has some risk of data loss if
the copy process is interrupted and the primary mirror is lost.

While this function cannot immediately be removed due to API
compatibility requirements, it would be better to use the copy engine
in llapi_mirror_resync_many() function that is used by "lfs mirror
resync", that has seen a number of improvements (better sparse file
handling, progress statistics) and will continue to be improved in
the future.

- The pragmas are narrowly scoped to only the specific function call

### Error 2: Unrecognized compiler flag
```
cc1: error: unrecognized command line option '-Wno-gnu' [-Werror]
```

**Fix:** Removed `-Wno-gnu` from compilation flags in:
- `autoMakefile` (EXTRA_CFLAGS and EXTRA_KCFLAGS)
- `config/Makefile` (CFLAGS, EXTRA_CFLAGS, and EXTRA_KCFLAGS)

**Rationale:** The `-Wno-gnu` flag is Clang-specific and not recognized by GCC. The configure script incorrectly detected support for this flag because GCC silently ignores unrecognized `-Wno-xxx` flags UNLESS there are other warnings/errors present. When the deprecated function warning triggered, GCC then complained about the unrecognized flag as well.

Additionally, I updated `config/lustre-toolchain.m4` to add an `AM_CONDITIONAL` for the NO_GNU flag (similar to NO_STRINGOP_OVERFLOW pattern), which will help prevent this issue in future builds when the configure script is regenerated.
