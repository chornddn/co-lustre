LU-6689 nodemap: add layout_ops rbac role

Add a new 'layout_ops' nodemap rbac role, so that clients can be
prevented from changing the layout of files and directories. When
the role is removed from a nodemap, files created by clients of
that nodemap can only inherit the layout from the default layout
of their parent directory.

The role is enforced on the MDT for every client-driven layout
modification:
- specifying a layout when opening/creating a file, as done by
  'lfs setstripe' on a file, and by the volatile file creation
  behind 'lfs migrate' and 'lfs mirror extend';
- setting the default layout of a directory, as done by
  'lfs setstripe' on a directory;
- modifying layout components via the lustre.lov.{add,del,set}
  xattrs, as done by 'lfs setstripe --component-add/--component-del';
- swapping layouts, as done by 'lfs swap_layouts';
- swapping, merging or splitting layouts on close, as done by
  'lfs migrate' and 'lfs mirror extend/split'.

Open replays are let through, because the layout they carry was
already accepted when the request was first processed.

PCC read-write attach on create is covered as well, because it asks
the MDT for a released layout when the file is created.

Reading layouts is not affected, and neither is the instantiation
of layout components triggered by regular IO, nor PCC read-only
attach, which both go through a layout intent. The directory layout
in the DNE sense is still governed by the 'dne_ops' role.

Like all other roles, 'layout_ops' is part of the default 'all'
value, so the behavior is unchanged unless it is explicitly
removed from a nodemap.

Add sanity-sec test_64m, and make test_64i request the new role
where it calls 'lfs setstripe'.
