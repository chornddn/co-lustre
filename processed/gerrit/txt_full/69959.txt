--- Commit Message ---
LU-21023 mdt: revoke the layout lock of a migrated file

A migrated file gets a new FID on the target MDT but keeps its OST
objects. A client that still had the layout of the old FID cached
found the stripes already owned when it opened the new FID, and the
I/O failed with -EIO.

- mdt: in mdt_reint_migrate(), add MDS_INODELOCK_LAYOUT to the source
  lock of a regular file, so clients drop the layout cached under the
  old FID. Skip it for a released file, which has no OST objects and
  whose layout lock an HSM restore holds until it ends.
- llite: in cl_file_inode_init(), mark a layout that no layout lock
  covers invalid after applying it, so the inode of the new FID can
  take its stripes over (lov_init_sub() returns -EAGAIN for them).
- llite: refresh the layout in ll_lov_setstripe_ea_info(), so one
  set through the lustre.lov xattr or LL_IOC_LOV_SETEA is installed
  under the lock, not only one set through LL_IOC_LOV_SETSTRIPE.
