--- Commit Message ---
LU-21023 lov: keep an unlocked layout invalid until locked

A migrated file gets a new FID on the target MDT but keeps its OST
objects. Migration now revokes the layout lock of the source, but a
client can still get the old FID's layout from an MDT reply, which no
layout lock covers. lov_conf_set() marked it valid, so the old object
kept owning the stripes, and opening the new FID failed with -EIO.

In lov_conf_set(), keep a layout set without a layout lock invalid,
so the object of the new FID can take its stripes over (lov_init_sub()
returns -EAGAIN for them) until a layout lock covers it.

Fixes: 1d6b96a1cf04 ("LU-15529 mdt: optimize dir migration locking")
