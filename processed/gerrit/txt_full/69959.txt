--- Commit Message ---
LU-21023 mdt: revoke the layout lock of a migrated file

A migrated file gets a new FID on the target MDT but keeps its OST
objects. A client that still had the layout of the old FID cached
found the stripes already owned when it opened the new FID, and the
I/O failed with -EIO.

- mdt: take MDS_INODELOCK_LAYOUT with the source lock when the inode
  of a regular file is migrated, so clients drop the layout cached
  under the old FID.
- llite: a layout that comes without its layout lock, on a new inode
  or after the lock was lost, stays invalid until I/O refreshes it
  under the lock, so its stripes can be taken over.
