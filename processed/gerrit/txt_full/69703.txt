LU-20690 ec: verify parity against data, allow p > k

With the RAID10-like parity layout the p parities of a raidset share
one offset, so the parity of a component fits in its extent whatever
p is. Remove the p <= k checks in lfs and llapi; k+p <= 256 and
p <= 15 remain. Also drop the mirror-extend stripe_count < p guard
in ec_check_data_comp() so --ec 2+3 works on a two-stripe target.

An instantiated parity is checked against its data component in
lod_verify_ec_parity_comps(), using lod_comp_find_linked() for the
same pairing rule as the allocator. A parity with linked data needs a
bidirectional link, matching k/p and stripe size, and parity stripe
count ec_raidset_count() * p. A parity whose data mirror was split
off or deleted has no linked data and is skipped. A mismatch fails a
layout from the user or replay in lod_use_defined_striping(), but is
only logged for a layout loaded from disk by lod_parse_striping(), so
an existing file with a bad parity can still be opened and removed.
lod_verify_striping() checks k/p and rejects an instantiated parity
with stripe_count == 0 before DEFINED object init.

Also skip instantiating a parity in
lod_declare_instantiate_components() when its linked data is still
uninit and not in the same instantiate list. A mirror-targeted
RESYNC lease walks every component of the named mirror, and would
otherwise leave INIT parity over uninit PFL data that
lod_verify_ec_parity_comps() then rejects.

Tests: sanity-ec 4a and 10 accept p > k, and 4b rejects k == 0 and
k > 255. 8d no longer expects narrow components or -c 5 --ec 4+3 to
be refused. 8m covers mirror extend --ec 2+3 on a two-stripe target.
8n covers a mirror-targeted RESYNC lease that must not INIT parity
over uninit PFL data. 8o covers PFL -E 2M --ec 2+3
create/resync/verify, and 8p covers p > k multi-raidset
create/resync/verify. llapi_layout_test test47 allows 3+4.
