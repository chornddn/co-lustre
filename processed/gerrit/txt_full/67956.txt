LU-20522 obdclass: keep llog record swabs inside the record

lustre_swab_llog_rec() locates a variable-length record's
tail from its own lrh_len before llog_verify_record()
checks it, so a corrupt length swabs past the buffer, up to
eight bytes for most types and, for UPDATE_REC, as far as
its untrusted op counts walk. A foreign-endian peer reaches
this over the network through llog_client_next_block().

Pass the swabber the number of bytes actually readable
at the record and bound every case, and the tail it
locates, inside them. UPDATE_REC's ops are walked against
the record's own end instead of trusting the counts,
and its tail now comes from lrh_len like every other
variable-length record, so the separate op walk once
used to find it is gone.

llog_reverse_process() and llog_osd_next_block() could
already hand the swabber a record outside the buffer,
from an lrh_len or tail length neither had checked; both
now bound it first.  The same checks close a hang in
llog_reverse_process(): a corrupt on-disk index, or the
zero-filled hole a failed changelog write can leave, could
send the reverse walk back over the same chunk forever.
recovery-small test_163 now remounts the MDT to exercise
this path; OSP's setattr record read gets the matching v2
length check. The UPDATE_REC path itself has no new test,
since recovery-small's update catalog is still empty when
it runs.
