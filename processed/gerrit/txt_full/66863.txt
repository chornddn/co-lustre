LU-20426 lnet: add per-operation latency stats

LNet exposed no per-operation latency, only send, receive and drop
counts and credit levels in "lnetctl peer show -v". When a cluster
performance problem was suspected to be in the network there was no
per-peer or per-NI latency to confirm or refute it, and rebuilding it
from +net debug timestamps is impractical under concurrent load.

One completion timestamp does not answer the question on its own. The
LNET_EVENT_SEND of an originated message marks local send completion,
so for a PUT it measures egress, but the matching GET reply or PUT ACK
is a separate event. Some LNDs make it worse: o2iblnd holds the GET
transmit open until the reply lands, so a GET sampled at SEND means
egress on socklnd and a round trip on o2iblnd. Folding those into one
figure leaves the minimum meaningless.

Track three latencies separately, per peer NI and per local NI:

  1. PUT egress, from commit to send completion at LNET_EVENT_SEND.
  2. GET round trip, from request to REPLY.
  3. acked PUT round trip, from request to ACK.

The egress sample reuses the commit and finalize timestamps already on
the message. For the round trips, lnet_attach_rsp_tracker() arms a
response tracker on the originating MD for GET and acked PUT and
stamps a deadline from ktime_get(); record that same read as the
start, and take the delta when the response detaches the tracker in
lnet_finalize(). Round trip tracking therefore follows
lnet_response_tracking (default full); with it disabled only egress is
recorded.

The counters live in self-initializing lnet_latency_stats (sample
count, sum, min and max nanoseconds) embedded per operation in
lnet_peer_ni and lnet_ni, so allocation and reset need no special
handling and the data path takes no new lock. A module parameter
lnet_latency_stats (default 1) gates the work; when disabled the path
is unchanged but for one predicted branch.

The values appear as put_egress, get_rtt and put_ack sample, min, max
and average nanoseconds: in the per peer NI block of "lnetctl peer
show -v" and the local NI block of "lnetctl net show -v", alongside
the existing counts. Nanoseconds avoid truncating a sub-microsecond
egress to zero. The LNet netlink interface sends its key schema to
userspace, so the new keys are rendered by name and existing lnetctl
binaries are unaffected.
