LU-20963 lod: clear ltd_discon when an MDT is reactivated

Since lod_statfs_and_check() also sets ltd_discon for a target that
is already inactive, an MDT deactivated with "mdc.active=0" got
ltd_discon set by the next statfs update.  Reactivating it with
"mdc.active=1" only set ltd_active again in lod_process_config(), and
statfs left ltd_discon set for an active target, so
lod_mdt_alloc_rr(), lod_mdt_alloc_qos(), lod_sync() and
lod_obd_set_info_async() would skip the MDT indefinitely.

Clear ltd_discon when lod_process_config() makes the MDT active.
Change ltd_active there under lod_lock, as lod_statfs_and_check()
does, and also mark the MDT inactive before closing its update llog,
so that new distributed transactions don't use it in between.

lod_process_config() also did not update ld_active_tgt_count when it
changed ltd_active, so the count of active MDTs could be wrong after
an MDT was deactivated or reactivated by config.  Update it and set
LQ_DIRTY there, as lod_statfs_and_check() does.

Add sanity test_27yc to check that a striped directory uses an MDT
again after it is reactivated by conf_param.
