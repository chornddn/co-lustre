LU-20963 lod: clear ltd_discon when an MDT is reactivated

An MDT deactivated with "mdc.active=0" got ltd_discon set by the
next statfs update, as lod_statfs_and_check() now sets it also for a
target that is already inactive.
Reactivating it with "mdc.active=1" only set ltd_active again in
lod_process_config(), and statfs left ltd_discon set for an active
target, so lod_mdt_alloc_rr(), lod_mdt_alloc_qos(), lod_sync() and
lod_obd_set_info_async() would skip the MDT indefinitely.

Clear ltd_discon when lod_process_config() makes the MDT active.
Change ltd_active there under lod_lock, as lod_statfs_and_check()
does, and also mark the MDT inactive and disconnected before closing
its update llog, so that new striped directories are not allocated on
it in between.

When the MDT was reactivated, the OSP could be evicted by the MDT as
it reconnected, so setting up the update log failed with -ESHUTDOWN,
and the MDT stayed inactive in that LOD until it was restarted.  Retry
the setup from a delayed work item until the OSP has reconnected,
doubling the wait from 1s up to 32s, and cancel it when the MDT is
deactivated again, removed or unmounted.  Statfs does not make an MDT
deactivated by config active again before its update log is set up, as
distributed updates to it would not be logged.
A reactivation replayed from the config log at mount only marks the
MDT active, as lod_prepare() then sets up its update log.

lod_process_config() also did not update ld_active_tgt_count when it
changed ltd_active, so the count of active MDTs could be wrong after
an MDT was deactivated or reactivated by config.  Update it and set
LQ_DIRTY there, as lod_statfs_and_check() does.  Do the same when the
delayed work makes the MDT active, and rebuild the RR arrays where
ltd_active changes rather than once after the config record is
processed, so that an MDT activated by the delayed work is not left
out of them.

Add sanity test_27yc to check that a striped directory uses an MDT
again after it is reactivated by conf_param, also when chosen by
index, with the first update log setup failing as for an evicted OSP
(OBD_FAIL_MDS_LOD_ACTIVATE_LLOG).
