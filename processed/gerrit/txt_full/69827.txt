LU-20995 compat: make kallsyms lookups safe with x86 kernel IBT

On x86 kernels with CONFIG_X86_KERNEL_IBT, loading libcfs can BUG
with "Missing ENDBR" when Lustre calls kernel functions through
pointers obtained from kallsyms.

find_kallsyms_lookup_name() takes kallsyms_lookup_name() from a
kprobe, but kp.addr is the probe address, which with IBT is placed
after the ENDBR64 (kallsyms_lookup_name+0x4). Calling that address
indirectly raises #CP. In addition, the kernel seals the ENDBR of
functions whose address is never taken, so other symbols resolved
via kallsyms may not be callable through a pointer at all.

Rewind the kprobe address to the start of the symbol using
sprint_symbol(), and verify that the function starts with ENDBR64
when IBT is enabled before using it. Add and export
cfs_kallsyms_lookup_func() to do the same check for the other
functions looked up in lustre_symbols_init(), so a sealed function
makes module init fail cleanly instead of crashing the kernel.

In osd-wbcfs, also use cfs_kallsyms_lookup_func() for
flush_delayed_fput(), and fail osd_init() before
class_register_type() if the lookup returns NULL. Previously a
failed lookup left cfs_flush_delayed_fput NULL while the module
still loaded, so osd_umount()/osd_flush_fput() would later call
a NULL pointer.
