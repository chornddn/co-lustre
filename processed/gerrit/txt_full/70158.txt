LU-21066 ldiskfs: avoid FORTIFY warning in ext4_set_dirdata()

ext4_set_dirdata() writes the LUFID record (and the CFHASH record)
after the filename through de->name[], which is declared as
char name[EXT4_NAME_LEN].  For names of 238 bytes or longer the
17-byte LUFID record runs past the end of that array.  The bytes are
still inside the directory record, but on kernels built with
CONFIG_FORTIFY_SOURCE (all EL10 kernels) the memcpy() triggers:

  memcpy: detected field-spanning write (size 17) of single field
    "&de->name[de->name_len + 1]" at ldiskfs/namei.c:1720 (size 16)
  WARNING: ... at ldiskfs/namei.c:1720 ldiskfs_set_dirdata+0xc2/0xe0

on the MDS, from mdt_create() -> ... -> add_dirent_to_buf(), for any
client create with such a name.  With panic_on_warn this panics the
MDS.

Address the dirdata area from the start of the name instead of through
de->name[], so the write is no longer bounded by the declared array
size.  The on-disk format and the bytes written are unchanged.

Fixed in all ext4-dirdata-core.patch copies: rhel10.0, rhel10.1,
linux-6.12, linux-6.18 (also used by the rhel10.2 series) and
linux-7.0 (also used by ubuntu26).
