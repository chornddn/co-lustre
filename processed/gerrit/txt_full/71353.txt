LU-20514 llite: find NFS name of a directory from its linkEA

ll_get_name() is called by exportfs to reconnect a disconnected NFS
file handle of a directory to its parent.  It read the whole parent
directory to find the entry with the child FID, holding the parent
i_rwsem exclusively.  For a directory with millions of entries, each
call read hundreds of MiB of directory pages and blocked all creates
and lookups in that directory on the client, while the other nfsd
threads queued up behind it and the NFS server stalled.

Take the name of a directory from its linkEA instead, which needs
one getxattr RPC, or none if the xattr is cached.  Files still read
the parent, since a cached linkEA of a file with hard links may still
have a name unlinked by another client.  A name in a striped
directory is linked to the stripe holding it, so also match the
stripe FIDs of the parent.  Decode a name in an encrypted parent as
readdir does, to the plaintext name with the key, or to the no-key
name without it.  Read the directory only if the linkEA has no name
in the parent, and take i_rwsem shared for this, as readdir does, so
lookups in the directory can proceed.

Also get the encryption context of an inode found by its FID in
search_inode_for_lustre(), as a lookup does.  Without it, a directory
in an encrypted parent reached only by its file handle could not be
reconnected, and failed with -ESTALE.

Split ll_linkea_read() out of ll_getparent() for this, and check that
each linkEA entry fits in the xattr returned by the MDT before use.

Add sanityn test_102c to check that a directory opened by handle is
reconnected without reading its parent, unless it has no linkEA.
Check the same in test_102b for an encrypted parent, with and without
the key, and drop its directory listing that loaded the key.

Reconnecting a directory of a 100k-entry parent from a second client
mount, in a single-node VM, needed 1-8 READPAGE RPCs (1-8 MiB of
directory pages) without the patch, and none with it.
