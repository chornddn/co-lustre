LU-20490 osp: fix TOCTOU race in lu_object_attr

The lu_object_attr() function asserts LOHA_EXISTS via LASSERT(),
triggering an LBUG kernel panic when object does not exist. When an
OSP proxy object receives a remote -ENOENT, it asynchronously clears
LOHA_EXISTS. If an MDT thread checks mdt_object_exists() (reads
LOHA_EXISTS=1) before OSP clears it, but calls lu_object_attr()
afterwards (LOHA_EXISTS=0), the LASSERT fires and panics the node.

This is a TOCTOU race because LOHA_EXISTS is a shared memory field
with no synchronization between OSP writer and MDT reader. The
window spans ~70 lines of mdt_getattr_name_lock().

Fix by introducing seqcount_t to protect LOHA_EXISTS transitions:
- Add loh_attr_seq to struct lu_object_header
- OSP clearing points: atomically clear LOHA_EXISTS and set
  LU_OBJECT_HEARD_BANSHEE under write_seqcount_begin/end
- lu_object_attr(): return 0 instead of LASSERT for nonexistent
  objects, so S_IS*() macros naturally return false
- mdt_getattr_name_lock(): wrap all 4 lu_object_attr call sites
  with read_seqcount_begin/read_seqcount_retry loops

The seqlock reader side uses pure memory reads (no atomics, no bus
locking), so there is zero overhead on the hot getattr path. The
writer side is triggered only on remote object deletion.

This prevents the crash observed during racer test_1:
  LustreError: (lu_object.h:873:lu_object_attr())
    LASSERT(LOHA_EXISTS) failed -> LBUG
