LU-21332 lnet: rewind the ping dump when an entry does not fit

"lnetctl ping" with a few hundred targets oopsed the node with a NULL
write in lnet_ping_show_dump(), called from netlink_dump().

When the skb filled, nla_nest_start() returned NULL and nla_nest_end()
wrote through it.  Failure of genlmsg_put() also left lgpl_index stale
and leaked the peer's list.  If the dump resumed from the old index,
it would ping targets again.  At index 0 it resent the key table and
re-initialised lgpl_failed under a stale lgpl_failed_count.  The
failed-ping section restarted from entry 0 as well.
lnet_genl_parse_list() also ignored failed puts, so a key table added
to a partly filled skb could go out incomplete.

Check all attribute insertions and nest allocations.  On a full skb,
drop the partial entry, free the peer list and rewind one entry, then
return msg->len, or -EMSGSIZE when the entry does not fit by itself.
Send the key tables and headers only once, initialise lgpl_failed in
lnet_ping_show_start() and give the failed list its own index.
Make lnet_genl_parse_list() return -EMSGSIZE for a full skb so that
the failed-ping key table can be retried in the next dump round.

Also return -ENOMEM, not the ping error, when a failed-ping entry
cannot be allocated, free the peer list on that path and increment
lgpl_failed_count only after successful allocation.

Add sanity-lnet test_247, which pings enough targets in one command
to exercise dump continuation and verifies the total reply count.
