LU-21081 quota: don't let a deferred adjust delay a release

When a DQACQ fails with a recoverable error such as -EINPROGRESS,
the quota slave queues its next adjust for QSD_WB_INTERVAL later.
An immediate adjust request for the same lqe was then ignored
because the lqe was already queued. On ZFS the slave adjusts quota
only from the writeback thread after each commit, so the space freed
by a delete was not released to the master for up to 60 seconds.
sanity-quota test_63 waits 10 seconds for that release and failed
with "granted N > N after cleanup".

Requeue a deferred lqe when an immediate adjust is asked for, as is
already done for one queued for a per-ID lock cancel.

Add sanity-quota test_100, which makes one DQACQ fail with
-EINPROGRESS and checks that the grant is released after the file
is deleted.
