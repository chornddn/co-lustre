LU-17158 nrs: per-rule statistics for the class scheduler

The rule dump shows the configured rate only. An operator cannot see
what a rule achieves, and a test must measure the rate on the client.

Add six counters to each rule: enqueue, dispatch, exhausted, one
dispatch count for each mClock tree, and the reset time. The enqueue
path and the dequeue path update the counters under scp_req_lock.

Add a proc entry nrs_<policy>_rule_yaml that prints the rule list with
the counters in YAML. The old entry does not change. lctl get_param
--yaml reads the new entry when the entry exists.

Add a reset_stat command on the rule entry. The command takes an
optional rule name.
