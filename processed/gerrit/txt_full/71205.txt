LU-21254 lod: give up update replay before the llog cancel

lod_llog_cancel() replaces the update llog on each MDT in sequence.
An MDT that is not connected keeps its update records.  If the MDT
that aborts its recovery then stops, its next recovery replays such a
record.  It executes committed local updates again.  The inode then
has nlink 0 and no destroy.  The MDT frees it at object release, and
the name entry stays.

Add distribute_txn_abort_replay() and call it before the cancel.  It
writes a new batchid as the committed batchid and waits for the
commit.  It takes the batchid under the batchid write mutex, so each
later commit thread write is above it.  At mount,
distribute_txn_init() starts tdtd_batchid above the committed batchid
on disk, so a new transaction gets a higher batchid.  Add test_122b.

Fixes: b054fcd7852f ("LU-16159 lod: cancel update llogs upon recovery abort")
