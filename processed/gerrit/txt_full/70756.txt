LU-8933 lod: don't start two RR layouts on the same OST

Shifting the round-robin start by one target every N/gcd(stride, N)
layouts, where N is the OST count, moves the start of the next layout
by stride + 1.  When the stride is N - 1, e.g. 1 stripe on 2 OSTs,
that is a whole lap of the array, so two layouts in a row start on
the same OST.  With 2 OSTs a migrated PFL file then often gets the
same OSTs as before, and sanity test_56xe fails.

The stride alone already starts layouts on every OST in that case,
so skip the shift.  This changes no object or first stripe balance
in lod_rr_test.  Make lod_rr_test check that consecutive layouts
start on different OSTs, which fails 119 of the 2097 combinations
in sanity test_51g without this change.
