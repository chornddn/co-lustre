LU-20966 tests: make sanity 17h inject a live create failure

sanity test_17h is meant to check that the MDS does not LBUG while
freeing the layout after a failed striped create. It armed
OBD_FAIL_MDS_LOV_PREP_CREATE (0x141), but that value is only a #define
in lustre/include/obd_support.h and no CFS_FAIL_CHECK site uses it.
The test also discarded touch's exit status with "|| true". As a
result it only did an ordinary create, never ran any stripe-
preparation error unwind, and could not fail.

The test now arms OBD_FAIL_MDS_ALLOC_OBDO (0x128) on the MDS that
serves the directory. That fail point is still checked at the top of
lod_declare_striped_create() in lustre/lod/lod_object.c, where it
returns -ENOMEM and frees the layout already initialised from the
directory default through lod_striping_free(). The test now requires
the create to fail. It then clears fail_loc and requires a second
fully striped create to succeed, which shows the MDS survived the
unwind. The directory is created with "-c 1" so that "lfs getdirstripe
-i" names the MDT that actually handles the create, and the setup
commands now check their return codes.

With the patch applied, the fail point fired once on the serving MDS.
The -ENOMEM from lod_declare_striped_create() reached the client
through mdd_create() and mdt_reint_open(), and the following 8-stripe
create succeeded. Note that this fail point fires before any stripe
object is reserved, so the cleanup it exercises is shallow.
