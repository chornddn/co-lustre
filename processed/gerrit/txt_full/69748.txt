--- Commit Message ---
LU-11484 ofd: don't walk extents on count-only FIEMAP

The OSS can crash in ofd_get_info_hdl() reading past the reply
buffer when a FIEMAP probe with fm_extent_count == 0 arrives with
OBD_FL_SRVLOCK, e.g. from multiop in sanity/44f on a PFL file.

A count-only FIEMAP returns the number of extents in
fm_mapped_extents without filling fm_extents[], but
lock_zero_regions() and dom_has_zero_regions() walk that many.

Bound both loops by fm_extent_count, so a count-only request
locks the whole requested range before the extents are counted.
Drop the DoM PR lock mdt_fiemap_get() takes: it was never released,
so it could not be cancelled and blocked conflicting locks and umount.
