--- Commit Message ---
LU-18502 ptlrpc: print enable_cap_mask as a YAML flow mapping

When the cap type is not "off", nodemap.*.enable_cap_mask prints
"type: ..." and "caps: ..." on two lines. "lctl get_param --yaml"
puts the first line on the line of the key. A YAML parser rejects
this output.

Print the type and the caps as one YAML flow mapping on one line.
The other nodemap parameters also use the flow style. Quote the
caps, because a comma ends a plain value in a flow mapping.

cfs_mask2str() no longer adds a newline. Its callers add the newline,
so the output of the other callers does not change.

In sanity-sec test_25c, set a cap mask on the nodemap and check the
exact value.

Looks good. The new output parses as YAML for every multi-line nodemap value (idmap, ranges, offset, fileset, exports, enable_cap_mask). There are optional notes inline that can wait until the patch is next refreshed.

One gap in coverage: sanity-sec test_25c never makes a block-mapping value, so it passes with or without this fix. Only nodemap.*.enable_cap_mask prints a block mapping ("type: ...\ncaps: ..."), and only when the cap type is not "off". test_25c leaves it at the default "off", which prints one line. If test_25c ran something like `$LCTL nodemap_set_cap --name $nm --type mask --caps cap_chown` before the get_param, it would catch this bug, and it would also make the Test-Parameters run worth something.
