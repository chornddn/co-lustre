LU-20290 lnet: add NUMA-node discovery-view group source

Add a numa group source alongside the per-ni source. It buckets a
node's participating NIs by NUMA node -- ni->ni_dev_cpt, the same
locality the send-path affinity steering keys on -- so the NUMA-local
NICs of one target form one group and a client coalesces them into
one multi-rail peer. Grouping is a local rule, not an enumerated NID
list, so the same configuration applies to every server regardless of
its NIDs.

The source is selected by a new lnet_group_numa_nets module param,
mutually exclusive with lnet_self_nets (both feed the same
participating-net list and differ only in the source). It is correct
iff a node's targets map one-to-one to NUMA nodes and the CPT table is
NUMA-aligned -- the same assumption the affinity path already makes; a
custom partition table that collapses NUMA nodes over-merges groups,
an accepted deployment precondition.

The collect mirrors the per-ni discipline of no allocation under the
net lock: walk the NIs once into an off-lock (nid, cpt) scratch, drop
the lock, then build the variable-size groups. The same global
lnet_interfaces_max cap bounds total members; every numa view is a
subset of the full view, so its pi_nnis cannot exceed the limit the
full view already satisfies.

A locally-initiated Push has no ingress NI to key on. per-ni keeps the
plain net test, but a numa net can carry members of more than one
group, so the numa case matches only when the destination's net
singles out one group and otherwise declines, aborting the Push rather
than advertising an arbitrary group.

To exercise distinct groups on a single-NUMA host -- where every NI
reads the same ni_dev_cpt and real distinct cpts are unreachable -- a
test-only fault injection overrides the bucket key with a synthetic
per-NI value. It is inert unless armed and never writes ni_dev_cpt.
