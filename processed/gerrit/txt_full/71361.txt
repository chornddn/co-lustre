LU-20090 nrs: add a two-stage class lookup for TBF

A TBF class bucket caches its rule. After a rule add, the bucket
matches again and takes the new rule. Its queued requests and its
heap slot carry over. A bucket thus has no fixed rule, and a rule
cannot set the key of its buckets.

Split the lookup in two stages. A rule cache entry holds the request
key and points at the class bucket of the matched rule. The key of
the bucket adds the rule ID, so the bucket keeps its rule for life.
A hit costs one lookup and no walk of the rule list. The rule dump
adds the rule ID, and the CPT line adds the lookup counters:

    CPT 0: key=nid, miss 2, walk 2, checked 4, lru_free 0, rerate 0,
      rcache 2, class 2
    default * 10000, id 1, ref 0

The counter lru_free counts the rule cache entries that the LRU shrink
frees. A miss count that grows with lru_free shows a cache thrash. A
miss count that grows alone shows new keys or rule changes. A rule
start moves the head sequence, and a rule stop ends the entries of its
rule. The next request of each key then counts as a miss. Each miss
runs one walk here. A later patch can refuse a walk, so the two
counts can then differ.

A rule add no longer moves a bucket to a new rule. The queued requests
of the old bucket drain at the rate of its rule. The next request of
the key goes to a bucket of the new rule.

A rate command now reaches every bucket of its rule at once. Each rule
keeps a list of its buckets. A rate change sets the new rate on each
bucket of the rule under scp_req_lock and tr_rule_lock. A rule stop
gives the buckets of the rule the rate of the default rule. A stop
thus clears a queue that a low rate caused, with no new request. A
new bucket copies the rate of its rule under tr_rule_lock, so a
command cannot miss it. A bucket with a new rate can send its first
queued request at once. The throttle timer moves to that time.
The counter rerate counts the buckets with queued requests that a
rate command reached. The rule generation is gone, so the request
path takes no scp_req_lock to classify a request.

A rule stop also copies the realtime flag of the default rule. After
a rule stop, a later change of the default rule does not reach the
buckets of the stopped rule.

Since 3408489c96ba, the key holds the UID, the GID and the project ID.
When ptlrpc_body lacks an ID that the policy type needs, the fallback
in nrs_tbf_id_cli_set() fills all three IDs. Also, ptlrpc_body gives
the UID and the GID together. A uid policy thus put one UID in a
bucket for each GID. The fallback also split it by project ID. Each
bucket had the full rate. The key now clears each ID field that the
policy type does not use.

A request with no export, such as a first connect, gets the nodemap
ID LUSTRE_NODEMAP_MAX_ID. Before, nodemap_get_from_exp() read a NULL
export. With GFP_ATOMIC, a lookup that meets a freeing object now
returns -EBUSY, and does not call schedule(). The high priority move
classifies a request under exp_rpc_lock. The request then uses the
fallback policy.
The command structures lose the TBF prefix for a second policy.

The rule stop path removed a rule from the list under nrs_lock only.
A walk of the list holds th_rule_lock, so it could reach the removed
rule. The stop path now holds th_rule_lock over the removal.

A rule start takes the type of the head that runs it. Before, a rule
start failed with -EINVAL when the two heads had different types.
The policy start parses its argument with the command parser, so a
later patch can add start keys. A bad key value now returns the
error of its parse, not -EINVAL. An empty policy start argument now
starts the generic type, as no argument does. Before, it failed with
-EINVAL. A trailing space in the argument is now valid.

Fix three test defects. The 77k cleanup left TBF rules for the next
test, so 77k now registers it with stack_trap. 77kb restored the
jobid_var from the wrong variable. 77kj did not wait for the servers
to get the nodemap. Also, tbf_verify() no longer sets an EXIT trap,
which dropped the stack_trap handlers of the 77k tests.
