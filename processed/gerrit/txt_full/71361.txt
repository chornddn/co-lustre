LU-20090 nrs: add a two-stage class lookup for TBF

A TBF class bucket caches its rule. After a rule add, the bucket
matches again and takes the new rule. Its queued requests and its
heap slot carry over. A bucket thus has no fixed rule, and a rule
cannot set the key of its buckets.

Split the lookup in two stages. A rule cache entry holds the request
key and points at the class bucket of the matched rule. The key of
the bucket adds the rule ID, so the bucket keeps its rule for life.
A hit costs one lookup and no walk of the rule list. The rule dump
adds the rule ID, and the CPT line adds the lookup counters:

    CPT 0: key=nid, miss 2, walk 2, checked 4, lru_free 0, rcache 2,
      class 2
    default * 10000, id 1, ref 0

The counter lru_free counts the rule cache entries that the LRU shrink
frees. A miss count that grows with lru_free shows a cache thrash. A
miss count that grows alone shows new keys.

A rule stop or a rule add no longer moves a bucket to a new rule.
The queued requests of the old bucket drain at the rate of its rule.
The next request of the key goes to a bucket of the new rule.

The key now clears each ID field that the policy type does not use.
The command structures lose the TBF prefix for a second policy.

The rule stop path removed a rule from the list under nrs_lock only.
A walk of the list holds th_rule_lock, so it could reach the removed
rule. The stop path now holds th_rule_lock over the removal.

A rule start takes the type of the head that runs it. Before, a rule
start failed with -EINVAL when the two heads had different types.
The policy start parses its argument with the command parser, so a
later patch can add start keys. A bad key value now returns the
error of its parse, not -EINVAL. An empty policy start argument now
starts the generic type, as no argument does. Before, it failed with
-EINVAL.

Fix three test defects. The 77k cleanup left TBF rules for the next
test, so 77k now registers it with stack_trap. 77kb restored the
jobid_var from the wrong variable. 77kj did not wait for the servers
to get the nodemap.
