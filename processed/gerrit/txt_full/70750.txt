LU-21194 tests: use PAGE_SIZE in sanity 150f, 151 and 156

sanity 151 and 156 (via roc_hit_init) write the file with bs=4k and
expect the OSS cache_access/cache_hit counters to rise by one per 4k
page.  With 64KiB pages, 4k writes fill a single page, so a 16KiB read
raises the counter by 1 instead of 4 and the tests fail with "roc_hit
is not safe to use".  Write whole PAGE_SIZE blocks so that the number
of pages written, and so the expected counter change, is the same for
any page size.

sanity 150f expects a 20KiB file to use 40 sectors and 24 after
punching 8KiB.  The OSD maps and writes whole pages, so with 64KiB
pages the last page is fully allocated: the file uses 128 sectors, 112
after the punch, and the test fails with "punch failed: blocks 112 !=
24".  Add the unused part of the last page to the expected counts.
Also keep the second sub-case (a 3000 byte punch, which frees no whole
block) at the full allocation.
