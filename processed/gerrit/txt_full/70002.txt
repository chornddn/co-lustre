LU-20995 compat: call kallsyms functions via static_call

On x86 kernels with CONFIG_X86_KERNEL_IBT running on an IBT-enabled
CPU, libcfs refuses to load with -EOPNOTSUPP: kallsyms_lookup_name(),
alloc/free/apply_workqueue_attrs() and security_file_alloc/free()
have their ENDBR sealed because the kernel never takes their address,
so calling them through a pointer would raise #CP.  Lustre can only
be used with ibt=off.

A direct call or jmp does not need an ENDBR.  With IBT, define a
static_call() in libcfs for each function that lustre_symbols_init()
looks up, and for kallsyms_lookup_name() itself, and point it at the
kallsyms address with static_call_update().  The call sites are then
patched into direct calls to the kernel function, so the ENDBR check
is no longer needed for them.  Other kernels keep calling through a
function pointer, behind the same CFS_DEFINE_SYMBOL(),
cfs_symbol_call() and cfs_symbol_set() helpers.

cfs_kallsyms_lookup_func() keeps its ENDBR check for callers outside
libcfs that call the result through a pointer.
