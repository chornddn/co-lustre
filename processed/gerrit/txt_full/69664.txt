LU-20950 lnet: reject fault commands before LNet is up

Before "lnetctl lnet configure", any "lnetctl fault" add, del or show
command oopses in lnet_drop_rule_add(), lnet_delay_rule_del() or
lnet_drop_rule_collect(). After an oops in an add or del command,
the thread holds LNET_LOCK_EX. "lnetctl lnet unconfigure" then stays
in D state.

Only LNetNIInit() initializes the rule list heads. The ioctl path
calls it first, but lnet_fault_cmd() and lnet_fault_show_start()
call the rule functions directly.

Take an LNetNIInit(LNET_PID_ANY) reference in both handlers. It fails
with -ENETDOWN or -ESHUTDOWN when LNet is not up. Do not hold
ln_api_mutex, because lnet_delay_rule_del() can send queued messages,
and a send can need ln_api_mutex. Add sanity-lnet test 637.
