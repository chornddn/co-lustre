LU-20713 mdt: fix missing close when migrate fails

mdd_migrate_close() is only called from mdt_reint_migrate_internal()
on the success path (after the source open_sem has been taken).  If
the migration fails earlier or later - e.g. the directory is already
being migrated and the source lookup returns -EALREADY, migrate is
disabled, or mdo_migrate() errors out - the server-side close of the
file that carries the lease is skipped.

The client has already canceled its lease lock when it packs the
close intent, so the server-side lease lock is never revoked and
leaks until the export is evicted.  If the client then retries on
-EAGAIN (e.g. from mdt_migrate_links_lock()) it overwrites its open
handle, and the open file (mfd) leaks on the MDT too, keeping the
file busy (e.g. for HSM release or future migration).

Move the handler into mdt_reint_migrate_internal() and have
mdt_reint_migrate() call mdd_migrate_close() after it returns if
sp_migrate_close is still set, so every return path of the handler
closes the file.  sp_migrate_close is cleared once the in-path close
has been attempted.  mdd_migrate_close() may now be called with a
NULL obj, so only log the "lease broken" message when obj is non-NULL.
Failures before the handler runs (mdt_reint_internal()) are not
covered.  Also fix the mot_open_sem comment in mdd_migrate_close().
