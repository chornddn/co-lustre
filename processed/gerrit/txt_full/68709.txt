LU-20713 mdt: cancel the lease when migrate fails

lfs migrate of a regular file takes a lease and sends the migrate
with MDS_CLOSE_MIGRATE; mdc_close_intent_pack() cancels the client
copy of the lease lock locally.  On the MDT the lease is revoked when
mdt_reint_migrate() locks the source with the OPEN bit, and cancelled
in mdd_migrate_close() at the latest.  A request that fails before
the source is locked, e.g. with -EPERM when migration is disabled,
with -EALREADY from the lookup when an interrupted directory
migration is repeated, or in mdt_reint_internal() before the handler
is called, leaves the lease lock granted on the MDT.  The client
closes the file with a plain close, which does not cancel the lock,
so it stays until a conflicting lock request revokes it with a
blocking AST that the client answers with -EINVAL.  Repeating the
migration of a large directory thus leaves a lease lock for each
file migrated before, and an MDS thread was seen spinning in
ldlm_reclaim_ns().

Split the lease cancel out of mdd_migrate_close() into
mdt_migrate_lease_end() and call it from mdt_reint() through
mdt_reint_migrate_cleanup() when mdt_reint_migrate() did not get to
mdd_migrate_close(), so that every failed migrate ends its lease.
Leave the file open then: the reply carries no
OBD_MD_CLOSE_INTENT_EXECED and the client closes it as before, a
close that would fail with -ESTALE ("mdc close failed: rc = -116")
had the MDT closed the file.  As the lease may now be ended for a
refused request, cancel only a lock of the requesting export.  Also
fix the mot_open_sem comment, which did not hold when
down_write_trylock() fails.

Add sanity test_211: a migrate refused with -EPERM must not leave a
lease lock on the MDT.
