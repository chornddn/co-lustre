LU-20107 nrs: add node tier hierarchical scheduling

Implement a per-server node parent class bucket for hierarchical
scheduling.
Each flow classification for a service (ptlrpc_service) on an
individual server node has a parent class bucket.
The leaf class buckets are the same as before, and a CPT tier TBF
scheduler or mClock scheduler manages them.
The node tier class buckets coordinate the bandwidth allocation
between the CPT tier schedulers.

Each ptlrpc service also gets a "nrs_hsch" debugfs entry. A write to
that entry configures the node tier global rules and class buckets.
For example:
	lctl set_param ost.OSS.ost_io.nrs_hsch=
	"<mclock|tbf> [reg|hp] start rulename projid={100} rate=100 \
	 root=0 node=0"
	lctl set_param ost.OSS.ost_io.nrs_hsch=
	"<mclock|tbf> [reg|hp] stop rulename"

A write of a NULL argument or of an empty argument returns -EINVAL.

The node tier first divides the global rate equally between the CPT
tier rules. A command with no queue token builds a rule for the
regular head. It builds a second rule for the high priority head.
The divisor is then the CPT count of the service multiplied by 2.
The two heads therefore share one node ceiling. A global rate below
the divisor returns -EINVAL. The service also logs one error line.
Without that test an IOPS rule divides by zero.

Each CPT tier rule owns a shared class bucket. The class bucket LRU
mechanism does not manage that bucket. The node tier needs no rule
key of its own for the share. The rule flag records the share, and
the rule dump reports a share field.

The rule allocation calls a policy callback for the shared class
bucket. The mClock callback clears the 3 red-black nodes. The TBF
callback writes the token fields. Without the callback the first
request of a global rule meets an assertion under mClock. The same
request stalls under TBF.

The rule stop removes the shared class bucket from the scheduler
before the rule frees it. The bucket holds a reference of its own
for its life cycle. The free path also asserts that the bucket holds
no request and no heap entry.

The teardown of a class head destroys the hash table of the leaf
class buckets first. It then destroys the hash table of the shared
class buckets, and then the rules. The rule owns the shared class
bucket, so the walk of a live rule cannot reach a freed bucket. A
class head also holds a ready flag. A teardown after a failed setup
therefore does not touch an uninitialised hash table.

Add a test case sanityn/test_77wa to verify the debugfs interface
works as expected. The test finds the share field, the global
field and the class ID field by name. The dimensions of the
policy decide how many rate fields come first.

Add sanityn/test_77wb. The test asserts that a malformed node tier
command returns an error. It also asserts that a global rate below
the CPT count returns -EINVAL.

Add sanityn/test_77wc. The test stops the policy while a global node
tier rule is in place. It then asserts that the input and output
path still works.

Add sanityn/test_77wd. The test starts a global rule under mClock
and under TBF. It then reads and writes a matched project directory
through each rule. The share class bucket of the rule therefore
schedules a request for the first time. The test asserts that the
OSS log holds no warning, no oops and no LBUG.
