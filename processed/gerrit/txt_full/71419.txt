LU-21323 ofd: do not reset OST object owner on fallocate

ofd_object_fallocate() calls ofd_attr_handle_id() with is_setattr=1,
so the uid/gid/projid sent by the client are applied to the OST object
without any check. These ids come from the client's cached inode and
may be stale: if the file is chowned from another mount while a client
still has an fd opened before the chown, fallocate resets the OST
object to the old owner. The MDT keeps the new owner, so the space is
charged to the old owner's quota and nothing to the new owner.

Use is_setattr=0, the same as write and punch. The client ids are
then only accepted to initialize a precreated object that still has
the SUID/SGID/VTX bits set, which is what LU-19018 needs; an object
that already has an owner keeps it.

Add sanity-quota test_1m: hold an fd on one mount, chown the file from
a second mount, then check that fallocate charges the new owner.
