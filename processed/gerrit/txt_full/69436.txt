LU-20879 ptlrpc: send batched RPCs to the MDS request portal

The client has sent MDS_BATCH to OUT_PORTAL since batching was added,
so batched statahead is served by mdt_out, and also by ost_out on a
node that runs an OST, since the two share the portal. Yet a batched
getattr is ordinary client work: for a child on another MDT it sets
up the remote object, which fetches the attributes from that MDT, and
then locks the child there.

Those threads are also what MDT-to-MDT traffic depends on, which is
how recovery can hang. A restarting MDT reads the update logs that
its peers keep for it, through OUT on each peer, and cannot finish
its recovery without them. Meanwhile, on a peer, a batched getattr
for a child on the restarting MDT waits in an OUT thread for that
MDT, as OSP holds requests to an MDT until it has recovered. Once
such getattrs hold all the OUT threads of the peer - ost_out has
few - the update log read of the restarting MDT is queued behind
them and never served: it waits for the getattrs, and they wait for
its recovery.

Send MDS_BATCH to MDS_REQUEST_PORTAL, with replies on
MDC_REPLY_PORTAL, as for an unbatched getattr. The server needs no
change: the mdt service dispatches MDS_BATCH by opcode like any other
request, and its request and reply limits are larger than mdt_out's.
A client without this change can set statahead_batch_max to 0.

That puts batches in the threads that handle every other client
request, and exposes an old bug there. mdt_intent_policy() decides
whether it is handling a batch sub-request from
mdt_thread_info::mti_batch_env, which mdt_batch() sets and nothing
clears: it is only reset by mdt_thread_info_init(), which has not run
yet at that point. A thread that handled a batch request earlier
therefore still looks like it is in one, and the next intent it
handles trips:

  LustreError: (mdt_handler.c:5509:mdt_intent_policy())
  ASSERTION( pill == &info->mti_sub_pill ) failed
  Comm: mdt00_001

Read the flag from tgt_session_info::tsi_batch_env instead. It lives
in the request's own session, which is set up afresh for every request
and cleared again by tgt_ses_key_exit(), so it describes the request
in hand. Also clear mti_batch_env when mdt_batch() is done.

Add sanity test 123ae, which checks that the mdt service serves
batched statahead RPCs.
