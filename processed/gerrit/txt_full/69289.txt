LU-20840 mdt: cap dir auto-split to the MDT count LOD has

mdt_auto_split() caps the target stripe count with the number of MDTs
connected to this one (mdt_mds_mds_conns + 1).  LOD allocates the new
stripes and rejects a split with -E2BIG when the target exceeds the
MDT count it knows about (lod_remote_mdt_count + 1), which can be
smaller for a while when an MDT is added: the new MDT's OSP connects
before LOD processes the config record that adds it.
mdt_getattr_internal() re-queues the directory for auto-split on every
getattr once its dirent count exceeds the split threshold, so such a
split repeatedly takes the parent PW lock and the stripe EX locks,
blocking clients.

Ask LOD for the MDT count it has when a split fails with -E2BIG, and
cap the target with that answer until it expires a second later: the
directory is split as far as LOD can, right away when it can still
grow, instead of failing again and again until LOD catches up.  LOD
answers the existing KEY_TGT_COUNT key with the number of MDTs, as LMV
does on a client, and MDD forwards that query to LOD, so the MDT asks
with the obd_get_info() call it already uses for KEY_OSP_CONNECTED,
and the count is only asked for after a split has failed.

Also drop the unused mot_auto_split_disabled flag, which the earlier
negative-cache approach used.
