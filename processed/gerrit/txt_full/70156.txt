LU-20690 ec: place EC parity of an unaligned e_start

RAID0 places data rows from file offset 0, but EC counts rows and
raidsets from e_start. When e_start is not a multiple of the data
stripe width, the k stripes EC groups as one raidset are not the
objects lod paired with that raidset's parity OSTs, and a degraded
read rebuilds a lost stripe from the wrong parity. For example
-E 4M -c 1 -E eof -S 1M -c 8 --ec 4+1 puts offset 4M on object 4
(raidset 1), which EC encodes into the parity of raidset 0.

Count rows and raidsets from file offset 0, as RAID0 maps the data
objects:

  row = off / (stripe_count * stripe_size)
  ec_off = O
      + (row - row of e_start) * raidset_count * stripe_size
      + raidset * stripe_size + off % stripe_size

Data before e_start is taken as zero, and so is its parity, which is
not stored: the origin O moves back from e_start over the raidsets of
the first row that end before e_start, and over the part of the
raidset of e_start below e_start % stripe_size when e_start is in its
last data stripe. slot % raidset_count stays the raidset, so the
parity OSTs lod pairs are unchanged, and every stored parity byte has
data in the component, so the parity of common PFL layouts with an
unaligned e_start (-E 1M -c 1 -S 1M -E 64M -c 1 -S 4M -E eof -c 4
-S 4M --ec 4+2) ends by e_end. With --ec 1+N, ec_off is the data
offset. O depends only on e_start, the data stripe count, k and the
stripe size, not on e_end. When e_start is a multiple of the stripe
width, O is e_start and the placement is unchanged.

Add struct ec_parity_geom with ec_parity_geom_init(), and
ec_raidset_start(), ec_data_to_parity() and its inverse
ec_parity_to_data() in lustre_user.h, and use them in lov and llapi.
lov caches O in lsme_parity_origin when the layout is unpacked and
returns it from lsme_stripe_origin(), and lov_parity_geom() fails a
degraded read whose pair does not match in stripe size, raidsets or
origin; the parity mirror EOF of such a pair is also bounded by one
parity row per stripe set from e_start. Raidset objects before e_start
read as zero in degraded reads and resync.

A component that ends within the stripe of an unaligned e_start that
is not the last of its raidset still has no room for the parity of
that stripe (--ec 2+2 -c 2 -S 4M over [1M, 4M)). ec_parity_fits()
detects it: llapi_layout_sanity() refuses such a layout with
LSE_EC_PARITY_FIT, which lfs setstripe now reports,
llapi_ec_check_comp_match() refuses to resync or verify it, and
lod_comp_prep_create() checks it again with the final data stripe
count, also for a parity created by lfs mirror extend --ec. Resync
and verify leave the part of the first parity slot below e_start
alone, which is in the extent of the previous component, and lfs
mirror read dumps the first slot from e_start.

Tests: sanity-ec 301 covers an e_start that stripe_size does not
divide and checks that a component whose parity would pass e_end is
refused for that reason, 302 resyncs, verifies and reads degraded
common PFL layouts with an unaligned e_start, 303 recovers reads when
e_start is not a multiple of the stripe width, with equal and unequal
raidsets, and 312 also truncates before an unaligned component start.
llapi_layout_test 68 checks the parity placement over a range of
geometries and extents.
