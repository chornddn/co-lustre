LU-21253 osd-ldiskfs: flag overwrite of committed blocks

OFD forces a journal commit for every write that does not come from
the client cache, but it cannot tell an in-place overwrite of
committed blocks from a write that changes the block mapping or the
object size and really needs its transaction to be committed.

Add thandle::th_overwrite and set it in osd_write_commit() when every
page of the request was written in this pass (no skipped, DONE or
unmapped page), ldiskfs_map_blocks() did not allocate or convert any
block (LDISKFS_MAP_NEW), the write ends inside i_size sampled before
mapping, the inode is extent mapped, its i_datasync_tid is committed
and the block device has no volatile write cache (or the journal is
mounted without barriers).  The tid is read after the mapping, so an
allocation by a concurrent writer is seen as uncommitted.  A write
that extends the size raises i_datasync_tid before the new size
becomes visible.  Setattr (also used for truncate), punch and
fallocate raise it only when ldiskfs marks the inode dirty, after the
new size is visible; only the trunc lock (punch, fallocate) and the
OFD object lock (setattr) order them against the write, so the user
of th_overwrite must not rely on those locks and must also check the
object for other uncommitted changes.

Use bdev_write_cache() where the kernel has it (new configure check
HAVE_BDEV_WRITE_CACHE), otherwise QUEUE_FLAG_WC.

osd-zfs never sets the flag.  Nothing reads it yet, so there is no
functional change.
