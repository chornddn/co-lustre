LU-20856 osc: send at most one reclaim sync per target

Writeback started by memory reclaim forces a commit for each file
it visits. One reclaim in a memory-limited cgroup starts such a
pass over the dirty files of every cgroup on the client, and each
file sent its own OST_SYNC for each of its stripes whenever the
target had any uncommitted pages at all. A client writing from
several small cgroups sent hundreds of OST_SYNC a second, each a
forced journal commit on the target.

Syncing an object commits every write the target did up to that
object's last one, so one sync covers the other files' earlier
writes as well. Track the transno of the latest bulk write reply
per object, and per target the write covered by the reclaim sync
last sent. Send a reclaim sync only for an object with an
uncommitted write, and only when no earlier reclaim sync to that
target is still waiting for its commit. If the reply shows the
target did not commit that far, release the claim so that a later
pass can send another. Short I/O writes pin no pages and are not
tracked. Data-on-MDT objects get the same gate.

An object refused while a sync is in flight, whose write that sync
does not cover, is not revisited until it writes again: its pages
wait for the target's own commit or a later reclaim sync to that
target.

With llite.*.unstable_stats off, the old test never saw uncommitted
pages, so reclaim now also syncs objects it used to skip.

With 4 cgroups of 4 writers on one OST and memory.max 256M, this
cuts OST_SYNC from about 700 to about 100 per 12 GB written, with
no change in throughput and no OOM.
