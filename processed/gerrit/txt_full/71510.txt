LU-16475 mgs: reuse the index of an OST removed by del_ost

"lctl del_ost" cancelled the records that add an OST to the client
and MDT config logs, but the MGS kept the OST index in use and kept
the OST config log, so a newly formatted OST with the same index
would fail to register with "The config log for ... already exists",
and mounted clients and MDTs kept the old OST until remounted.

After cancelling the records, "lctl del_ost" now calls the new
OBD_IOC_DEL_TARGET ioctl on the MGS.  The MGS appends LCFG_DEL_TGT
records to the client log and to each MDT log, so mounted nodes stop
using the OST and free it once unused, frees the OST index, erases the
OST config log, and revokes the config lock.  It accepts only the
exact name of an OST that is configured, and lctl only that name.

Before the MGS lets a new OST take an index freed by del_ost, it
glimpses all holders of the filesystem's config lock, which answer
whether they still have that OST set up.  If one does, or cannot
answer, the registration fails with -EBUSY and the MGS names that
node.  While the config lock is being revoked, for some time after
that while nodes take it again, and soon after the MGS started, not
every node holds it, so the registration fails with -EAGAIN to be
tried again.  A registration refused this way writes nothing, so it
does not revoke the config lock.  The MGS rebuilds the freed indices
from the config logs at restart, and does not hand them out to a new
OST that asks for any index.

Add conf-sanity test_123al to remove an OST while a file on it is in
use and add a new OST with the same index once it is freed, without
remounting, and test_123am to add it after a restart.  Update
test_123ah for the new records.
