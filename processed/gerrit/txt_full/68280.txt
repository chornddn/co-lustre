--- Commit Message ---
LU-6142 checkpatch: warn on GOTO() with a bare constant

GOTO() only logs its second argument, it never assigns it, so
GOTO(label, -ENOMEM) reads like it sets the return value while
actually discarding it and letting the target label return whatever
was there before. This turned out to be the common cause of several
real bugs, so warn about it at review time instead of finding the
next one the hard way. Existing occurrences are addressed separately.

GOTO(label, rc), GOTO(label, rc = -ENOMEM) and GOTO(label, 0) stay
silent, and RETURN(), which does return its argument, is not matched.
The advice is worded conditionally because some matching sites are in
functions with no rc to assign to. Only a plain constant is matched;
the same trap spelled as an expression is left for a follow-on, since
covering it multiplies the number of sites to triage.
