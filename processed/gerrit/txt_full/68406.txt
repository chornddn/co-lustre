LU-10026 llite: skip layout changes if update is held

skip minor layout changes (like incompressability) when the client
helds UPDATE lock as MDT grabs UPDATE lock for this kind of changes.

llite: do not update layout from fsync

fsync can be called from within write. in this case there would be one
active IO (from LOV's point of view). if we update the layout at this
point, then fsync would need to refresh the layout to proceed, but
given there is an active IO, LOV would block layout refresh waiting
for all IOs to finish - a dealock.

DDN-bug-id: EX-10979
Was-Change-Id: I6d1cd7787f4c0d9f75f01030ed1235279bb6d301

llite: do not update layout at umount

umount can race with ptlrpcd finishing IOs and locks.
at the same time, umount resets sb->s_root to NULL which
is needed to form new RPCs, so it's safer to skip minor
layout update.
