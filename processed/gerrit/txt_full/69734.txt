DRAFT  LU-xxxxx lod: add standalone kunit test for RR/QoS stripe allocators

Add lustre/kunit/lod_alloc_test.c, a standalone kunit module that
exercises lod_ost_alloc_rr() and lod_ost_alloc_qos() directly against
a loaded lod.ko, without mounting a Lustre filesystem or going through
lod_comp_prep_create()/lod_prepare_create(). It builds a minimal
lod_device and a set of fake OSTs (fake dt_device + obd_export +
lu_tgt_desc) by hand, and verifies that each allocator, when every OST
is healthy and overstriping is not requested, allocates exactly the
requested number of stripes using distinct, valid OST indices -- up to
and including using every OST in the pool.

This deliberately only tests the allocators in isolation: EC
data/parity pairing and FLR mirror allocation live one layer up in
lod_comp_prep_create() and will need a separate kunit module driving
that entry point.

To make this possible:
- De-staticize and export lod_ost_alloc_rr() and lod_ost_alloc_qos(),
  and export lod_lu_ops and lod_thread_key, so the test module can
  call into the allocators and build a usable lod_device/lu_env.
- Add a KUNIT_STATIC_STUB_REDIRECT() to lod_qos_declare_object_on(),
  so a kunit test can replace it with a fake dt_object, since the real
  path requires a live OSD/OSP under each OST.
- Add a timer_container_of() compat fallback in
  lustre_compat/linux/timer.h for older kernels that don't provide it.

The test module is a real kunit_test_suite(), reporting results via
native KTAP output, and is wired into lustre/kunit/Makefile under
CONFIG_LUSTRE_FS_SERVER alongside the other kunit test modules.
