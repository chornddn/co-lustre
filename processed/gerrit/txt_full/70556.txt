LU-20958 llite: do not shrink i_size before fallocate

vvp_io_setattr_start() merges the stripe attributes into the inode
before a fallocate, and extends the file from the merged size.  The
fallocate only locks the stripes of its own extent, and a stripe this
client never held a lock on only has the size last cached for it, 0
if never seen, so the merge could replace a valid i_size, e.g. a
strict SOM size from the MDS, with a smaller one.  A fallocate with
FALLOC_FL_KEEP_SIZE in the first stripe of a 3MiB file with three
1MiB stripes would leave i_size at 1MiB.

A fallocate never makes a file shorter, so merge the attributes there
with ll_merge_attr_write(), which only grows i_size while the size of
some stripe is unknown, as after a write.

Add sanity-flr test_44k, which checks with stat --cached=always that
a fallocate does not shrink the strict SOM size of a mirrored file.
The fallocate stales the other mirror, so a plain stat would glimpse
the size again and hide the smaller i_size.
