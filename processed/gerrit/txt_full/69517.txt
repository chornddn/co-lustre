LU-20690 llite: implement STRIPE I/O scope

In the RAID10-like EC parity layout the p parity objects of a
raidset share one file offset but hold different data, so parity
read and write must name one of them. Implement
LL_IO_SCOPE_STRIPE for that.

ll_io_scope_validate() accepts STRIPE with ios_mirror_id in
[1, MIRROR_ID_MAX] and ios_stripe_idx below
LOV_EC_MAX_CODING_STRIPES. ios_stripe_idx must be 0 for FILE and
MIRROR. It is not checked against p here: the scope outlives the
layout and the I/O type is not known yet. ll_io_scope_init()
handles STRIPE like MIRROR and copies ios_stripe_idx into the new
cl_io::ci_designated_stripe. OBJECT stays reserved.

ci_designated_stripe is -1 when unset, since 0 is a valid parity
index. cl_io_reset() sets that and is used by vvp_env_new_io() and
osc_env_new_io() instead of a bare memset(). A cl_io that is zeroed
some other way still reads as unset, because lov only honours the
index when ci_designated_mirror is set.

lov visits only the stripes an I/O touches through
lov_foreach_io_stripe(), and maps an offset to a stripe through
lov_io_stripe_number(). On a parity component, read and write use
only the designated parity of each raidset and fail with -EINVAL
if it is unset or not less than p. Punch, truncate, fallocate and
lseek reach every parity and ignore the index, value and range
alike, so a leftover STRIPE scope does not fail them. Page fault is
rejected on parity.

These helpers apply only to the bare LOV_PATTERN_PARITY encoding.
Current RAID0|PARITY parity components are unaffected, so
existing layouts see no functional change.

llapi_io_scope_set(3) and the uapi comment document STRIPE.
sanity-flr test_213a now expects EINVAL for STRIPE without a
mirror id or with an index out of range, and checks that STRIPE
with a mirror id can be set. sanity-ec test_311 checks that lseek,
truncate and fallocate do not depend on the index. io_scope gains
-x, -r, -t, -f and -l for that.
