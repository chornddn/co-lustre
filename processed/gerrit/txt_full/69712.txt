LU-20965 llite: change layout before zeroing truncated page

When truncating an encrypted file to a size that is not a multiple
of PAGE_SIZE, ll_io_zero_page() initializes a write IO on the page
at the new EOF. If the layout must change before writing to that
page, cl_io_rw_init() returns 1. This happens when the page is in a
PFL component not instantiated yet, or when the file is mirrored and
in sync. ll_io_zero_page() returns this 1 as is, so ll_setattr_raw()
does not truncate OST objects, and ftruncate() returns 1 with the
file size unchanged. It also skips cl_io_fini().

Call cl_io_fini() in that case, so that the layout intent is sent,
and restart the IO if needed, as cl_setattr_ost() does.

ll_io_zero_page() also ignored the designated mirror of the file.
'lfs mirror write' truncates the file with a designated mirror while
it holds a lease, and its truncate was silently skipped because of
the above. With the layout intent now sent, it fails with -ESTALE.
So pass the file to ll_io_zero_page() and set the designated mirror
on the IO, as cl_setattr_ost() does.

Finally, ll_io_zero_page() computed the offset of the page to zero
in an unsigned int, which wraps for a page at or beyond 4 GiB. So
compute the offset as a loff_t.

Add sanity-sec test_48e to truncate encrypted files to a size that
is not page aligned:
- extending into an uninstantiated PFL component;
- beyond 4 GiB, while a second mount holds a lockahead lock
- for a mirrored file in sync.
