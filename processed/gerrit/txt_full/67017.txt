LU-20403 ptlrpc: refresh import conn on primary migration

ptlrpc_connection_get() resolves the peer primary once and freezes it
in the cached connection; reconnect reuses the connection and never
re-resolves. ptl_send_rpc() keys the reply ME on that frozen NID. When
LNet's primary for the peer later migrates, which can happen for any
unlocked peer, the reply ME no longer matches the source NID LNet
stamps on the reply. Each reply then either takes the costly
lnet_try_match_md() same-peer fallback, or it can be dropped, which
leaves the import stuck in CONNECTING.

Add LNetPeerPrimaryNID(), a non-blocking primary lookup that neither
discovers nor allocates, and call it from ptl_send_rpc() before the
reply ME is posted. On a change, swap in a connection keyed on the
current primary. This covers client RPCs and server reverse-channel
ASTs alike, since both reach ptl_send_rpc() through their import.

The lookup takes a per-CPT lnet_net_lock and does one peer-table
lookup. This is the same work lnet_select_pathway() already performs
for the send that immediately follows, so it is resolved on every
send. ptlrpc_connection_put() does not free a connection at
runtime (connections are cached in the hash until module unload), so
the connection swap is safe.
