LU-20290 lnet: add servicenode discovery visibility policy

Add a discovery visibility policy that groups local server NIDs by
servicenode.

Servicenode membership is explicitly provided through a new internal
LNet API rather than inferred from interface topology. The policy
contributes visibility groups through the generic discovery visibility
framework and participates in normal visibility composition.

LNetDiscServiceNodePolicySet() alone puts the policy in force. A count
of the registered servicenodes must not control it. Discovery operates
as soon as LNet starts, but a servicenode registers only when a target
mounts. If the count controlled the policy, the node would send all of
its NIDs between these two times, and a peer would merge them into one
multi-rail peer. No later group corrects this.

The policy set can now change while LNet runs, so the enable and
disable helpers are replaced by a scratch set that is filled in and
then published in one step. Publication stores the slots before it
grows the count, and the two full-view voters read the slots with
READ_ONCE() and skip an empty one. Those voters run under the net
lock, not under ln_api_mutex, and thus can read the set as it
changes. A change of servicenode membership leaves the set alone and
only rebuilds the views.

The new group algebra needs groups of a size that is known only at
run time, so a lnet_group_alloc() and lnet_group_free() pair replaces
the open-coded allocation. The existing collect and release paths are
converted to it. This is a mechanical change with no effect on
behavior.

A servicenode group contains only the NIDs of a target that is
already mounted, and the policy refuses the full view on all nets but
lo0. A NID that no group contains would thus match no view and would
also get no full view. The node would drop all discovery GETs to that
NID, and no peer could find it. A target that registers on that NID
could not mount. The enumerate pass therefore makes a group of one
NID for each live NI that no other group contains. Each NI stays
discoverable, and the node keeps the groups separate. lo0 keeps the
full view instead of a group of its own, because the peer on the far
side of it is this node.

Groups that share a NID are folded into one. Two such groups cannot
be kept apart: a peer that reaches this node on the shared NID gets
one group's NIDs, a peer that reaches it on a NID private to the
other group gets that group's NIDs, and the shared NID makes the peer
merge the two sets. The usual case is exact duplication, because all
of the targets of a server register the same NID list, and each group
costs a view with a ping buffer and an MD.

The Push path keys on the destination when the peer never reached
this node on a local NI. A destination behind a router is on a net
that no group holds a NID on, so no view claims the Push and the
group is chosen on the route to the destination. The policy keeps the
full view for the destination that no group can route to at all,
because the alternative is to abort the Push and end discovery for
that peer.

A base source composes with the servicenode groups through an
intersection, which keeps the ingress semantics of the base group.
The Push path keys a group on the destination net only for the
per-ni kind. Only per-ni makes all of the groups on a net equal, one
NI each, and lets the first match stand for all of them.

This patch introduces only the LNet policy implementation and its
internal interfaces. Subsequent patches will populate servicenode
membership from Lustre.
