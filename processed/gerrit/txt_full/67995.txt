LU-20590 ldlm: pin a lock out of the client LRU

An in-flight IO can depend on a client lock without a mode reference
on it. The LRU age reaper, the cache policy and the pool shrinker can
then drop that lock.

Add ldlm_lock_pin_lru() and ldlm_lock_unpin_lru(). A caller can now
exclude a granted client lock from voluntary reclaim. Pins nest
through the new l_lru_pins count, and the exemption ends on the last
unpin. The kernel-doc holds the contract. It names the three failures
which a caller can see: -ESTALE, -EALREADY and -EOVERFLOW.

The pin sets LDLM_FL_NO_LRU and removes the lock from the LRU in one
critical section. The refusal of the parent patch then keeps the lock
off the list. That refusal covers the convert path as well.

The pin adds no mode reference. A blocking callback, an eviction and a
namespace cleanup all still cancel the lock at once. No remote peer
ever waits on a pin. A caller can therefore hold a pin for the length
of a syscall.

The pin does hold an l_refc reference. The exemption cannot outlive
the lock, and a caller can carry the pin alone. The mode reference
count of the same file takes its reference in the same way.

-EALREADY separates the two kinds of owner of the flag. An enqueue
which passes LDLM_FL_NO_LRU owns the flag for the life of the lock.
This interface must not clear such an exemption. It therefore takes no
pin. The caller gets -EALREADY, which reports that the lock is already
out of the LRU.

l_lru_pins takes the spare u16 beside the other LRU policy fields, so
struct ldlm_lock does not grow. The pin fails at U16_MAX, so the count
never wraps.

An unpin which files the lock again also runs the pool recalculation.
The unpin can therefore sleep, and it can cancel unrelated locks of
the namespace. A final decref does the same from the same position in
ldlm_lock_decref_internal().
