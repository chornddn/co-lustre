LU-20076 tests: start a target with one remote command

Starting a target cost 12 to 14 remote commands for the one
mount it does: the dm-flakey check and device setup, the
block device test, three label reads, the mount, the OST
sequence width, the health check, the debug masks, the FLR
EC flag, the label wait and the commit sync. Each is an ssh
round trip, 0.2 to 0.4 s in CI, so a target start spent far
longer in round trips than in the mount itself.

Build those steps into one script and run it with a single
remote command. The script reports what mount_facet() needs
back (the device, the health, the label) on its own output
lines, and mount_facet() makes the same checks and prints
the same messages as before, printed when the script ends.
The steps run in the same order and use only commands an
older server already has. With
VERBOSE, the log and the debug log mark show "mount_facet
<facet> <options>" rather than the whole script.

dm_create_dev() and import_zpool() also take one remote
command each now, and start() no longer makes the mount
point separately.

Measured on a cluster of one MDS with 4 MDTs, one OSS with 6
OSTs and 2 clients, median of 3 to 6 runs, as is (about
0.05 s a remote command there) and with 0.25 s added to each
remote command, near CI's cost:

                cmds      as is           +0.25 s
  start ost1  13 -> 1  1.03 -> 0.27 s  4.45 -> 0.86 s
  start mds2  12 -> 1  1.61 -> 0.76 s  4.63 -> 1.20 s

CI starts about 8.5 million targets in 30 days. At 11 fewer
commands of 0.2 to 0.35 s each, counting a parallel start as
half, that is roughly 2300 to 6800 hours of test time.
