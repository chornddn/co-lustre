LU-20433 utils: fix 'lfs find ! -m <idx>' negation

LU-16622 unified the handling of the lfs-find -m/-i/-O options into a
single case, but in doing so it dropped the
'param.fp_exclude_mdt = !!neg_opt;' assignment that used to live
inside the 'if (c == "m")' block.  Only 'param.fp_exclude_obd' is now
set, so fp_exclude_mdt is never assigned anywhere in lfs.c.

The MDT matcher in check_mdt_match() (liblustreapi_pfind.c) still
reads fp_exclude_mdt, so with it always 0 a negated MDT-index query
loses its negation: 'lfs find ! -m <idx>' returns the files ON <idx>
instead of those NOT on it (exactly what 'lfs find -m <idx>' returns).
The -i and -O paths use fp_exclude_obd and are unaffected.

Restore the fp_exclude_mdt assignment for c == 'm'.  Add sanity test
56vb to exercise the negation on a DNE filesystem.  Rename the
existing test 56v to 56va, since basetest() leaves '56v' a prefix of
'56vb' and a bare '56v' cannot be selected on its own via ONLY=.
