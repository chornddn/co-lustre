LU-7880 target: return target load in statfs

Clients and applications have no cheap way to see how busy each
OST or MDT is, so they cannot steer IO or file creation away
from busy targets, or delay a checkpoint while the filesystem
is loaded.

Return a coarse view of the target load in statfs replies when
the client asks for it with OBD_STATFS_PERFSTATS.  The request
flag is sent in mbo_flags of MDS_STATFS_NEW, or in o_flags of
the ost_body of OST_STATFS_NEW, only to servers that support
OBD_CONNECT2_PERFSTATS.  Other requests still get the original
144-byte reply.

tgt_perfstats_fill() samples the existing per-target stats at
most every 5s from the statfs handler, so the IO path has no new
cost.  It returns the read and write bandwidth in KiB/s and the
read and write RPCs/s, as a decaying average and a slowly
decaying peak, and sets OS_STATFS_PERFSTATS in os_state.  The
first sample is the average since the target was set up.  On OSTs
reads are BRW reads and getattr, and writes are BRW writes and
other modifying RPCs.  On MDTs, reads are open, close, getattr,
getxattr, readpage and DoM reads, and writes are the namespace
and attribute changes and DoM writes.

Use enum obd_statfs_req_flags for the flags of the statfs
methods.  The lmv and lov IOC_OBD_STATFS handlers now pass
OBD_STATFS_PERFSTATS from userspace down to mdc and osc, and clear
OS_STATFS_PERFSTATS in cached data when it was not asked for.
obd_statfs() refreshes cached data that lacks the requested stats.
