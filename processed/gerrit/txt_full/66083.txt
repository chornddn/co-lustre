--- Commit Message ---
LU-20221 lnet: fix panic in lnet_net_show_dump with >128 NIDs

Dumping more than ~128 NIDs at high verbosity exhausts the hardcoded
64 KiB Netlink buffer. When the buffer is full, nla_nest_start()
returns NULL. The code previously failed to check this return value,
resulting in a NULL pointer dereference and an immediate kernel panic.

This patch fixes the crash by adding proper NULL checks. If the buffer
is full, we now call nla_nest_cancel() and return -EMSGSIZE, allowing
the Netlink dump state machine to gracefully paginate the remaining
data to userspace.

To prevent excessive pagination overhead, cb->min_dump_alloc is now
dynamically sized based on lnet_count_nis(). While strace profiling
shows a typical NI payload takes ~480-520 bytes, NET_MSG_PER_NI_SIZE
is set to 1056 bytes (LNET_NIDSTR_SIZE + IFNAMSIZ + 216 bytes static
attributes + 760 bytes dynamic padding). This provides a safe >2x
margin for complex UDSP rulesets and massive IPv6 NIDs.

test_630 is added to sanity-lnet.sh to exercise high-stress
Netlink dumps using 140 dummy NIDs and 50 UDSP policies.
