LU-21074 mdt: revoke cached open handles on exec conflict

With the exec open flag sent to the MDS again, a write open of a
running program fails with -ETXTBSY as intended.  An exec of a file
whose write handle a client only keeps cached under a CW OPEN lock,
after the file was closed, fails the same way until the lock is
cancelled by LRU aging.  Likewise, an exec open handle that a 2.16.51
or older client keeps cached under a PR OPEN lock after the program
has exited denies write opens from any client, as a plain open takes
no OPEN lock that would revoke it.

When a write open finds the file open for exec, or an exec open finds
it open for write, enqueue a local OPEN lock in the conflicting mode
first, as is done to revoke a lease.  Clients then close the handles
they only keep cached, and mdt_write_get() or mdt_write_deny() return
-ETXTBSY only for handles that are really in use.

The sanityn test_14e that checks this is added together with LU-10948
"mdt: grant write open locks without LOOKUP", which makes the cached
write handle survive the lookup of the file by another client.
