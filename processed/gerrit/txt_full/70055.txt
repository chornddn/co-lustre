LU-21046 utils: lhsmtool_posix daemon exits once registered

"lhsmtool_posix --daemon" forked with daemon() before registering as
a copytool, so the command returned while the copytool was not yet
able to receive requests.  sanity-hsm tests start the copytool and
then stop it with SIGSTOP to keep requests in STARTED state.  If the
signal arrived before llapi_hsm_copytool_register(), the copytool was
never registered, the request stayed WAITING, and e.g. test_251
failed with "request ... is not STARTED on mds1".

Make the parent wait until the child has registered, and exit with
an error if the child exits before that.  "--daemon" now waits for
the MDTs to answer the registration, and reports a startup failure,
e.g. a pid file held by another copytool, with a non-zero exit.

Remove the second copytool started by sanity-hsm test_31a, test_260b
and test_260c while the first one was still running.  It always
failed to lock the pid file and exited, which is now an error.
