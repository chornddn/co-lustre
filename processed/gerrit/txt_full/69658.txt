LU-17916 osc: encrypt by copy with in-kernel fscrypt

With in-kernel fscrypt, osc_encrypt_pagecache_blocks() is mapped to
fscrypt_encrypt_pagecache_blocks(). That function cannot encrypt a
direct IO page: it takes the inode and file index from a locked page
cache folio, whereas a direct IO folio is part of the user buffer,
and it is not locked for encryption.

In-kernel fscrypt does not export a function to encrypt out of
place at a given inode and file index. So copy the clear text into a
bounce folio from the OSC pool, and encrypt it in place there with
fscrypt_encrypt_block_inplace(), for all pages. This costs a copy
of each page, which embedded llcrypt avoids by encrypting into the
bounce folio directly. Get bounce folios from the pool with
in-kernel fscrypt too, and save the source folio in the private
data of the bounce folio, to get it back in
osc_finalize_bounce_page().
Lustre no longer uses fscrypt bounce pages, so it opts out of the
fscrypt mempool.

Calling fscrypt_encrypt_pagecache_blocks() for page cache folios
would save the copy, but would cost more than it saves:
- it allocates its own bounce page from the fscrypt mempool, page
  by page. The mempool reserves 32 pages by default, shared by all
  filesystems, whereas an RPC is typically 1024 pages, and up to
  16384. Under memory pressure, each allocation goes to direct
  reclaim, from the thread that prepares an RPC to write dirty pages
  back, or waits for a page to return to the mempool. But bounce pages
  only return when RPCs complete, and an RPC being prepared keeps the
  ones it already got, so RPCs prepared concurrently can exhaust the
  reserve and end up waiting for each other. Moreover, an RPC cannot
  be sent before all its pages are encrypted.
- it needs the folio to be locked while it runs, so
  osc_brw_prep_request() would have to call folio_trylock(), and
  still copy when another thread holds the lock.
On the other hand, the copy is small compared to the encryption.
On a simple test system, copying 4KiB takes 30 to 80ns, and encrypting
300 to 500ns.

The wrappers of fscrypt_encrypt_pagecache_blocks() and
fscrypt_finalize_bounce_page() are no longer used, so remove them
along with LC_FSCRYPT_ENCRYPT_PAGECACHE_BLOCKS_FOLIO.

Without client encryption support, osc_encrypt_pagecache_blocks()
used to map to the stub of llcrypt_encrypt_pagecache_blocks(), so make
it a stub that returns -EOPNOTSUPP.

Add LC_FSCRYPT_ENCRYPT_BLOCK_INPLACE_NO_GFP, as kernel 6.17 removed
the gfp_t argument of fscrypt_encrypt_block_inplace().
