LU-20594 tests: fix sanity/33h MDT mismatch counter

sanity test_33h (and 33hh) failed with "MDT index mismatch 10/250
times" (e.g. https://testing.whamcloud.com/test_sets/40896730-b84b-
471e-8147-e9db30c6d6bc, and https://testing.whamcloud.com/test_sets/
1342ffd3-f234-46f4-a329-1df9aef2f7df for 33hh).

This is a test-accounting defect, not a hash bug.  The mismatch loop
runs 250 times for each of the two mktemp patterns, so 500 files are
created, but $failed accumulates across both patterns while the error
message and gate use $count = 250 as the denominator.  The reported
"10/250" is really 10/500.

All ten mismatched names in both failures have all-uppercase or
all-lowercase suffixes (e.g. .kqmkkk, .YWBSMW, .NZCJOHXI), which
lu_name_is_temp_file() intentionally treats as non-temporary names
that hash on the full name and may be created on a different MDT:

  upper == suffixlen || lower == suffixlen  ->  return false

mktemp() generates the suffix from 62 alphanumeric characters, so
2 * (26 / 62)^6 = 1.09% of 6-char suffixes (~2.7 of 250) and
2 * (26 / 62)^8 = 0.19% of 8-char suffixes (~0.5 of 250) are
expected to mismatch, i.e. ~3.2 of 500 in total.  The combined
count is binomial with sd ~1.5, so the old gate "failed < 10"
rejects a tail 4.6 sigma out, but that tail is sampled frequently
across all CI runs; the combined count also hides the per-pattern
mismatch rates, which differ by an order of magnitude between the
6-char and 8-char patterns.

Count and gate each pattern separately (reset $failed per pattern),
which keeps the 10-per-250 threshold from the test comment and
reduces the simulated false-failure rate ~6x, while printing a
denominator that matches the gate.

Test-Parameters: trivial testlist=sanity mdscount=2 env=ONLY=33h,ONLY_REPEAT=200
