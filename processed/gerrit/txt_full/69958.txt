--- Commit Message ---
LU-21023 obdclass: stop llog_osd_next_block() at a short read

The cached size of a remote llog can be past its real end. A read
there comes back short, its last record has an index below the one
wanted, and llog_skip_over() returns to the same block, so
llog_osd_next_block() reads it again forever. The update log recovery
thread looped like that while holding the llog read lock, and the
directory migrations that needed the write lock hung.

When the last record of a short read is still before the wanted
index, the read hit the end of the llog: return -EBADR.
