LU-21148 socklnd: Validate HELLO NID against TCP addresses

SockLND identifies remote peers using the NID advertised in the
HELLO message without verifying that it matches the underlying
TCP connection. In addition, outgoing connections may select a
source IP address different from the configured NI address.

Introduce an optional strict_mode module parameter with three
settings:

- off: preserve existing connection behavior (default).
- warn: log and count address mismatches without rejecting
  connections or changing source address selection.
- enforce: bind outgoing connections to the NI address and
  reject connections whose HELLO NID or local TCP address is
  inconsistent with the connection's addresses.

Validate the advertised NID's network and address before peer
lookup or modification, preventing inconsistent HELLO messages
from affecting established peer connections.

Handle explicit source-address binding failures without
unnecessary reserved-port retries, and improve IPv6 address
handling.

Add sanity-lnet tests 630-635 covering policy configuration,
source address selection, HELLO validation, peer incarnation
handling, and local NI address consistency.
