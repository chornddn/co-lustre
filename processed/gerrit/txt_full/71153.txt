LU-21252 quota: drop deleted IDs from global index on reint

When a quota slave misses a deletion glimpse, for example while
the target is down, the deleted ID remains in its copy of the
global index. Reintegration only updates entries returned by the
master, so neither force_reint nor a remount removes the stale
limit.

The slave may continue enforcing the limit and request quota
space for the deleted ID. The master rejects the request with
-ESRCH, and the client may fall back to synchronous, ungranted
writes. This can degrade I/O or result in ENOSPC.

Record the IDs returned during global index reintegration in
qsd_reint_index(). qsd_reint_stale() finds the local entries that
were not returned and have a limit or use the default quota, and
qsd_reint_prune() removes them; other entries enforce nothing and
are kept. Mark the lqe of each removed ID deleted, as on the
master: not enforced, edquot cleared, and not following the
default quota. Set these flags directly instead of calling
lqe_set_deleted(): on a slave lqe, its writes to the master limits
overwrite lqe_qtune, lqe_lockh and lqe_pending_write, which share
the same union.

The default quota update in qsd_entry_def_iter_cb() can run
concurrently with the pruning, so check lqe_is_default under the
lqe lock there. In qsd_update_lqe(), switch an lqe to the default
quota when its record uses it, instead of leaving the lqe
unchanged. Otherwise a removed ID restored to the default quota
stays unenforced when the slave gets the record from a
reintegration. Set the lqe flags there under the lqe lock as well,
and read the default limits inside it. Clear lqe_is_deleted there
too, as qmt_set() does on the master when a deleted ID gets a limit
again.

Since LU-15283, qsd_updating delays the start of a reintegration
while the writeback thread applies the updates it has dequeued, but
only on ldiskfs. On ZFS, an update dequeued before a reintegration
starts can complete after the index transfer. It then marks the
global index up to date and kicks off the deferred updates that
follow it. So an ID set on the master after the transfer can be
written to the global index copy before the pruning, which then
removes it as stale and stops enforcing its limit. Set qsd_updating
on ZFS too: a reintegration now waits for the dequeued updates to
be applied, as on ldiskfs. A reintegration delayed this way is
started again by the writeback thread, which can take up to
QSD_WB_INTERVAL (60 seconds) when it has nothing else to do. The
writeback thread on ZFS still doesn't wait for a running
reintegration.

If the index version changes during the transfer, look for stale
entries with qsd_reint_stale(), and transfer the index once more
only if it finds some or fails, which repeats the whole transfer.
Without stale entries there is nothing to prune, so a change of
the index alone does not cost a second transfer. Skip pruning if
the version changes again, if the transfer is incomplete, or if
collecting the IDs failed; in the last case, don't transfer again.
Preserve ID 0. Entries left by a skipped or failed pruning stay
until the next index transfer.

As after a deletion glimpse, the master and the slave can still
disagree on the default quota of a deleted ID when only one of
them restarts. A restarted master applies the default quota to it
while the slave keeps it unenforced. A restarted slave enforces
the default quota while the master still rejects the ID with
-ESRCH. They agree again once the other side restarts too.

Add sanity-quota test_7g: quota entries deleted while an OST is
down are removed after reintegration, and the limits of other IDs
are kept. Add test_7h and test_7i, run with a default quota set: a
running OST misses the deletion of an ID with a limit (7h) or of
an ID using the default quota (7i). After force_reint, the OST
drops the cached ID and stops enforcing it. When the ID is then
restored to the default quota and the OST misses that update too,
the next force_reint makes the OST enforce the default quota.
