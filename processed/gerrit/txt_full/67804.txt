LU-20560 contrib: make checkpatch man4 nag satisfiable

The LUSTRE_{RO,RW,WO}_ATTR spelling.txt entries nag every new sysfs
parameter to add a Documentation/man4/ page, but fire on the macro
token unconditionally: with CI gating on warnings, a patch adding a
parameter fails whether or not the page exists. Suppress the warning
when a matching Documentation/man4/<name>.4 page is present, so the
check enforces what it claims to enforce.

A page added by the same patch that adds the LUSTRE_*_ATTR() using
it isn't on disk yet when checkpatch reads a bare patch, which is
how contrib/scripts/gerrit_checkpatch.py invokes it in CI (patch
piped on stdin, no working tree checked out) -- the main case this
change is meant to unblock. Pre-scan the patch for any
Documentation/man4/*.4 hunks it adds and accept those too. Also
anchor the on-disk lookup to checkpatch.pl's own directory instead
of the current working directory, since the lookup was silently
inert whenever checkpatch ran from anywhere but the tree root.

MODULE_PARM_DESC and LDEBUGFS_SEQ_FOPS_* carry the same unsatisfiable
"create Documentation/man4/ page" text and take the parameter name
the same way, so extend the same tree/patch lookup to them instead
of leaving them nagging unconditionally.

Also exempt the spelling dictionaries from their own typo scan --
any addition to spelling-userspace.txt used to trip its own entry,
so the dictionary could never be extended through a warnings-gated
CI. Anchor the exemption to contrib/scripts/spelling*.txt instead of
any path containing "scripts/spelling", which exempted more than
intended.
