LU-20199 osd: Introduce osd-*.*.dio_alloc{,_stats} parameters

This change aims to parametrize in a common way the approach to
osd_thread_info.oti_dio_pages entries allocation. The core aim
is for larger(2..64 MiB) RPC requests to more coherently translate
into equally large bio requests when RPC/request pages consist of
osd_thread_info.oti_dio_pages entries.

Pros:
- Reduces luck-based element in whether or not biovec entries are
  physically continious
- Allows to tailor the allocation expectations
- Slightly alleviates memory fragmentation issue from
  the allocator side
- Graceful fall-back to lower-order allocations

Cons:
- Possibly longer allocation time on the cold path
  (first time OSD thread receives an RPC that large)
- The effect varies depending on the filesystem parameters
- Does not affect server-side page-cache-backed RPC requests
- Admin-set server-side maximum RPC size is unknown at osd level,
  reducing possibilities for automatic adjustments
- Minimum effect for osd-zfs and none for osd-wbcfs
- The maximum continious allocation is capped at MAX_PAGE_ORDER
  value, and CMA API that could allow to allocate whole oti_dio_pages
  continiously is gatekeeped.

The parametrization represented by new procfs parameter
osd-{ldiskfs,zfs}.*.dio_alloc, that takes value in bytes in order
to detach it from PAGE_SIZE and other nuances of kernel memory
allocation.

Statistics for this allocation path and allocations failures are
accounted for at osd-{ldiskfs,zfs}.*.dio_alloc_stats attribute.
