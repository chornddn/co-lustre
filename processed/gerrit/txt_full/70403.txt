LU-20076 tests: make conf-sanity 35a reach MDT0000

test_35a stops and restarts MDT0000 with a df running, then
looks in the client debug log for the server the client
tried first when it reconnected. With several MDTs, df's
statfs can be answered by any one of them, so nothing makes
the client notice that MDT0000 went away. When the restart
is quick the client has not reconnected by the time the log
is read, no connection line is found, and the test fails
with "Tried to connect to  not last active server". This
happens every time on a VM cluster with 4 MDTs, where
MDT0000 restarts in under a second.

Use "lfs df", which sends a statfs to every MDT and waits
for each to answer, so the client reconnects to MDT0000
before the test reads the log.

Test-Parameters: trivial testlist=conf-sanity env=ONLY=35a,ONLY_REPEAT=5
Test-Parameters: mdtcount=4 testlist=conf-sanity env=ONLY=35a,ONLY_REPEAT=5
