--- Commit Message ---
LU-19809 utils: do not reopen a migrated regular file

"lfs migrate -m" on a regular file exits with ENOTDIR even when the
migration succeeds: after the migrate ioctl the path is reopened with
O_DIRECTORY to refresh the directory handle, and for a file that
open fails and replaces the result. Reopen the path only when it was
opened as a directory.

With the reopen skipped the traversal also runs the shrink step for
the file. Skip it when there is no directory handle, since the shrink
is only meaningful for directories and a non-root user would get
EPERM from the trusted xattr.

Add sanity test_230F to migrate a file whose inode is on another MDT
than its parent directory and check the exit status.

Patch Set 2:

Thanks for picking this up. The fix is right: the O_DIRECTORY reopen in cb_migrate_mdt_init() is only meant to refresh the handle of a directory that was closed before the migrate ioctl, and with reopen set only in that case a regular file keeps the result of its migration. Setting *dp to -1 after close() also keeps the caller from seeing a closed descriptor.

The ENOTDIR became visible with edf4ac967e (LU-19809 utils: fix lfs migrate to return correct exit code, https://review.whamcloud.com/63511): before it, the depth marker ret = 1 overwrote the failed reopen at the maximum depth; since then the real error is kept and the traversal reports it. [minor] Please add Fixes: edf4ac967e ("LU-19809 utils: fix lfs migrate to return correct exit code"), so that this goes along with any backport of that change.

test_230F covers the case: a file whose inode is on MDT0000 and whose only name is in a directory on MDT0001, migrated to MDT0001. Without the fix lfs migrate returns the ENOTDIR of the reopen; with it the exit status is 0 and the inode is on MDT0001.
