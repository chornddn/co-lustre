LU-19921 ptlrpc: fix SEC_CTX_INIT timeout on undiscovered peer

When mounting an IAM-enabled Lustre filesystem (gssiam) where MDT/OST
servers reside on separate VMs from the MGS and peer discovery is
disabled (discovery=0), LNetPeerDiscovered(&peer_nid, false) in
import_select_connection() returns -EAGAIN (-11) and queues background
peer discovery, leaving the client import's initial connection with
oic_uptodate == -11.

With krb5 and sk, sptlrpc_req_get_ctx() returns a newly allocated
context with PTLRPC_CTX_NEW_BIT set, allowing
ptlrpc_request_bufs_pack() to complete and
ptlrpc_connect_import_locked() to queue the CONNECT RPC to ptlrpcd and
register the import with the pinger. When the initial context refresh
or CONNECT times out over the non-uptodate peer,
ptlrpc_connect_interpret() schedules a reconnect attempt, which calls
import_select_connection() again and refreshes oic_uptodate to 1 once
background LNet peer discovery completes.

By contrast, gssiam performs synchronous context initialization inside
gssiam_lookup_ctx() -> gssiam_send_init_rpc(). Because SEC_CTX_INIT
(o801) blocks ptlrpc_connect_import_locked() inside
ptlrpc_request_bufs_pack() before the CONNECT RPC is queued,
import_select_connection() is not called again to refresh
oic_uptodate, and ptl_send_rpc() silently drops both attempts of
SEC_CTX_INIT while oic_uptodate == -11. Consequently,
gssiam_lookup_ctx() returns -ETIMEDOUT directly to
ptlrpc_request_bufs_pack(), causing ptlrpc_connect_import_locked() to
abort before the CONNECT RPC is queued or ptlrpc_connect_interpret()
can drive a reconnect retry.

Fix this in two ways:
1. Fast path in ptl_send_rpc() (lustre/ptlrpc/niobuf.c): when
   oic_uptodate <= 0 during LUSTRE_IMP_CONNECTING and
   request->rq_ctx_init is set, re-query LNetPeerDiscovered() to
   refresh oic_uptodate (matching import_select_connection()) before
   dropping the RPC. When background peer discovery completes within
   the first SEC_CTX_INIT attempt's 1s timeout, the retry inside
   gssiam_send_init_rpc() refreshes oic_uptodate to 1 and succeeds
   immediately on the first connect pass without logging an error.
2. Fallback path in lustre/ptlrpc/gss/sec_gssiam.c (if background peer
   discovery takes longer than gssiam_send_init_rpc()):
   - In gssiam_lookup_ctx(), when gssiam_send_init_rpc() returns
     -ETIMEDOUT while imp->imp_state == LUSTRE_IMP_CONNECTING, return
     the uncached, non-uptodate context (without
     PTLRPC_CTX_UPTODATE_BIT set and without caching it in
     gssiam->gis_ctx) after incrementing sec->ps_nctx. This allows
     ptlrpc_connect_import_locked() to queue the CONNECT RPC and enter
     the normal ptlrpc_connect_interpret() / pinger reconnect state
     machine, which refreshes oic_uptodate via
     import_select_connection() on subsequent connect passes.
   - In gssiam_ctx_sign(), reject GSS-framed non-SEC_CTX_INIT requests
     (such as CONNECT) with -ETIMEDOUT if PTLRPC_CTX_UPTODATE_BIT is
     not set on the context.
