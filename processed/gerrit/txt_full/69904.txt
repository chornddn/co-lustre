LU-19921 ptlrpc: fix SEC_CTX_INIT timeout on undiscovered peer

When mounting an IAM-enabled Lustre filesystem (gssiam) where MDT/OST
servers reside on separate VMs from the MGS, the client import's
initial connection (oic_uptodate) starts at -EAGAIN (-11) because
LNetPeerDiscovered(&peer_nid, false) has not yet discovered the peer's
NIDs and instead queued background peer discovery.

Next, preparing the client's CONNECT RPC triggers synchronous GSSIAM
context initialization via sptlrpc_req_get_ctx() -> get_my_ctx() ->
gssiam_lookup_ctx() [via sec->ps_policy->sp_cops->lookup_ctx =
gssiam_sec_cops.lookup_ctx] -> gssiam_send_init_rpc(), which sends a
synchronous SEC_CTX_INIT (o801) RPC on the same import while
imp->imp_state is still LUSTRE_IMP_CONNECTING and oic_uptodate == -11.
Because SEC_CTX_INIT blocks ptlrpc_connect_import_locked() inside
ptlrpc_request_bufs_pack() before the CONNECT RPC is even queued,
import_select_connection() is not called again to refresh
oic_uptodate, and ptl_send_rpc() silently drops both the initial
SEC_CTX_INIT RPC and its single retry (with rq_timeout = 1s and
rq_real_sent = 0), causing the cold mount to fail with -ETIMEDOUT
(-110).

Fix this in ptl_send_rpc() (lustre/ptlrpc/niobuf.c): when
oic_uptodate <= 0 during LUSTRE_IMP_CONNECTING and
request->rq_ctx_init is set, re-query LNetPeerDiscovered() to refresh
oic_uptodate (matching import_select_connection()) before dropping
the RPC.
