LU-20808 ptlrpc: add the MDT-to-MDT read intent wire format

A cross-MDT create, rename or unlink reads the remote parent's state
with synchronous OUT_UPDATE RPCs after it has taken the parent lock,
one getter at a time. The MDT that grants that lock already has the
state in hand, so it could read it back while it grants the lock and
send it in the enqueue reply.

Define the wire format for that:

  - IT_MDT_TO_MDT_READ, the intent opcode, never sent by a client;
  - struct mdt_read_req/rep. The request names the locked object and,
    as a bitmask, what to bring back: the resolution of a name in it,
    its attributes, and xattrs. The same bits in the reply say which
    of them came back;
  - RQF_LDLM_INTENT_MDT_READ, which carries the request, the name and
    the names of the xattrs to read, and returns the reply with the
    attributes, a struct mdt_read_xattr for each xattr name, and the
    values, as stored, in a single buffer.

Xattrs are asked for by name, so that reading another one changes
nothing in the format, and its buffers stay the same whatever is
read. struct mdt_read_xattr says what came of each: read, absent, too
large for the room the requester gave all the values together - with
the length it needs - or not read, and why.

The MDT granting the lock checks nothing on the requester's behalf:
no credentials travel with the intent, and the requester makes every
permission and inheritance decision itself, from what comes back.

Add wirecheck and wiretest entries for IT_MDT_TO_MDT_READ, struct
mdt_read_req/rep/xattr, the bits that select what the intent reads,
and the most xattr names a request can carry.

An MDT only sends the intent to a peer that has agreed on
OBD_CONNECT2_DNE_INTENT, which the MDT advertises once it can handle
the intent.
