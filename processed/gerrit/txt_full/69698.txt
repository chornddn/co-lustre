LU-19066 target: add failure domains for MDT devices

A per-OST failure_domain was added so the MDS can keep mirror and EC
parity stripes in different hardware fault domains from the data
stripes.  MDTs have no equivalent, so fault domains cannot be taken
into account when placing remote directories or DNE layouts across
MDTs.

Add the same failure_domain to MDT devices.  Move the local-file
read/write code out of the OFD into generic tgt_failure_domain_read()
and tgt_failure_domain_write() helpers in the target layer shared by
OST and MDT, and rename OFD_FAILURE_DOMAIN_OID to FAILURE_DOMAIN_OID.
The MDT loads its failure_domain at setup, exposes it through the
mdt.*.failure_domain parameter, and reports it in obd_statfs so that
"lfs df --mdt=N --output=domain" and the LOD object allocator can use
it, as for OSTs.

Also make the shared helper safe on a read-only device: read without
creating the file and write returns -EROFS, so an rdonly_dev or
snapshot mount of a target formatted before the file existed still
works.

The failure_domain is a lone __u32 with no invariant tying it to any
neighbouring field, so access it with READ_ONCE()/WRITE_ONCE() rather
than taking ofd_flags_lock, keeping a lock out of the OST_STATFS reply
path, as suggested in review of the LU-17000 data-race fix.
