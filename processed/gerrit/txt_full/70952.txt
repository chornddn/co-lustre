LU-21232 osp: fix OSP adopting seq 0 from a zero last oid

The opd_last_used_fid is loaded from the internal files lov_objid
and lov_objseq when the OSP starts. If lov_objid is zero, this fid
is still accepted, and osp_precreate_cleanup_orphans() sends it to
the OST in a KEY_LAST_FID request to fetch the last id of this
sequence. ostid_seq() reads {seq, 0} as sequence 0, so the OST
returns the last id of sequence 0 instead, and the OSP switches to
sequence 0. The objects it creates afterwards get IDIFs and collide
with the objects of MDT0000.

Use oid 1 for such a fid in osp_last_used_init(), so the OST is
asked about the right sequence, and refuse the reply in
osp_get_lastfid_from_ost() if it is for a different sequence

Fixes: 6c4c51e3079e ("LU-1445 osp: Use FID to track precreate cache.")
