LU-20923 mdt: validate metadata request fields before use

Several MDT request-handling paths assumed the request format and the
operation encoded in the request agreed, and read format-specific
fields or mapped values without first checking that assumption.  Make
each path validate its inputs:

 - mdt_getxattr_pack_reply() serves both the intent getxattr format
   (no RMF_NAME, sized into RMF_EAVALS) and the plain MDS_GETXATTR
   format (RMF_NAME, sized into RMF_EADATA), selecting the operation
   from mbo_valid.  Require that the requested operation matches the
   fields the format provides - a name is fetched only when RMF_NAME
   is present, and OBD_MD_FLXATTRALL is requested exactly when the
   reply format carries RMF_EAVALS - and return -EPROTO otherwise.

 - mdt_reint_open() serves only the open intent.  Confirm the request
   uses RQF_LDLM_INTENT_OPEN, returning -EPROTO before fetching
   RMF_DLM_REP, rather than relying on the format.

 - mdt_create_unpack() and mdt_open_unpack() take the create mode from
   the request, and object creation maps its file type with
   dt_mode_to_dft().  Force S_IFREG for an O_CREAT open (which only
   ever creates a regular file, keeping the permission bits), and
   reject a REINT_CREATE whose mode does not name a supported file
   type with -EINVAL.

 - mdt_intent_getattr() and mdt_intent_lock_replace() hold a
   remote-object lock in mlh_rreg_lh.  Release that lock on the
   no-positive-disposition and no-local-lock exits, where it was
   previously left held, so it is dropped on those paths too.
