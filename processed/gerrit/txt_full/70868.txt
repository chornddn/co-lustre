LU-21215 llite: reclaim dentries/inodes in smaller amounts

Before Linux 6.7, shrink_slab() and shrink_slab_memcg() hold
shrinker_rwsem for read across each do_shrink_slab() call and check
only between shrinkers whether a writer waits.  The superblock
shrinker reports all unused dentries and inodes of the mount from
super_cache_count(), and do_shrink_slab() scans up to twice that
number in one call under heavy memory pressure or for drop_caches.
Evicting a Lustre inode can be slow, as ll_delete_inode() may close
an open handle on the MDS, so on a client with millions of cached
inodes one call holds shrinker_rwsem for minutes.  Every down_write()
of it waits meanwhile, e.g. shrinker registration on any mount and
memory cgroup creation: systemd cannot start services or sessions,
logins hang, and nodes with hung_task_panic set panic.

Add the llite.*.max_shrink tunable, the number of objects one call
of the superblock shrinker scans at most.  ll_fill_super() wraps the
shrinker methods.  ll_sb_count_objects() keeps the count, so the
kernel computes the same reclaim target, and refills a scan budget
of max_shrink objects.  ll_sb_scan_objects() takes nr_to_scan from
the budget and returns SHRINK_STOP once it is used: do_shrink_slab()
then carries the rest of its target over to its next calls in
nr_deferred, and shrink_slab() can release shrinker_rwsem in between.
Capping the count instead would cut the reclaim target, e.g. to none
at DEF_PRIORITY for max_shrink below 4096.  The default 0 sets no
limit.

As drop_slab() stops once a pass frees fewer than 2^pass objects
(Linux 5.15, RHEL 8.10 and 9), one write to drop_caches frees only
about max_shrink * log2(max_shrink) objects of a mount with a limit.

Check whether super_block.s_shrink is a pointer: RHEL 9.6 has
shrinker_alloc() but keeps it embedded.  The wrappers are installed
only while s_shrink is embedded: with the lockless shrinkers of Linux
6.7 they would bring no benefit, so max_shrink has no effect there.

Add sanity test_444 with OBD_FAIL_LLITE_SLOW_EVICT to slow down
ll_delete_inode().
