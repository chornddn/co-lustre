LU-20238 ec: tighten GFNI configure probe, doc fixes

The configure GFNI probe used a static function that -O2 drops
before target codegen, so it passed even without GFNI support in
the target attribute. Make the probe functions non-static, and add
an AVX-512 probe that uses the {1to8} inline asm the AVX-512
kernels need, so the assembler is checked too.

Also fix comments from the review of "LU-20238 ec: GFNI-accelerated
EC primitives": the base tables are nibble-product tables, not
log/exp; tables from ec_init_tables() and ec_init_tables_base()/
gf_vect_mul_init() must not be mixed on a GFNI host; the
gfni_ec_test checklist now matches what it checks; and
gf_vect_dot_prod()/gf_vect_mad() need kernel_fpu_begin() before
GFNI dispatch is enabled in the kernel.

gfni_ec_test now fills its test data with a local xorshift32
instead of rand(), which Coverity flags (CID 293327), and takes
-s/--seed so a failing run can be repeated.

sanity-ec test_0 now forces m=5 and len=4065, so the 5-vect AVX-512
kernels and the AVX2 32B block run on every host with GFNI.  It
also passes a seed to each run and prints it with the result.
