DRAFT LU-21180 lod: add kunit test for lod_initialize_objects

Add lod_init_obj_test, covering lod_initialize_objects(): turning the
on-disk lov_ost_data_v1[] slots of an already-fully-defined striping
into the in-core stripe dt_object array.

The real function instantiates each stripe via lu_object_find_at() on
the target's OSD/OSP, which needs a live device underneath. Break that
single call out into a new lod_lookup_stripe_object() in lod_lov.c,
with a KUNIT_STATIC_STUB_REDIRECT() like lod_qos_declare_object_on()
already has, so a kunit test can redirect it to a canned mock_ost_obj
per OST (via the existing mock_tgt/mock_ost infrastructure) instead of
needing lu_site/device object-cache allocation.

Covers: every slot naming a valid OST, a dummy (all-zero) slot being
skipped per lovea_slot_is_dummy(), and a slot naming an OST index
outside the target table failing the whole call.

EXPORT_SYMBOL() lod_initialize_objects() and the new
lod_lookup_stripe_object() so the loadable test module can call/stub
them.

Test-Parameters: trivial
