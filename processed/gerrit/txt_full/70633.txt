--- Commit Message ---
LU-18133 tests: check setstripe in sanity 398m

sanity 398m ignores the result of "lfs setstripe -o 0,1,0,1".
When it fails (ENOSPC is seen in CI, as the MDS can still see an OST
as full after a preceding test), the file gets default striping, the
injected bulk write failure never hits the first stripe and the test
reports that the dio write succeeded.

Fix the cleanup traps in 398l (and add them to 398k) so deletes
complete before the MDS/OST sync wait, leaving later tests a correct
view of OST space. In 398m, wait for deletes and MDS/OST sync, retry
setstripe for up to 30 seconds, and fail with a clear error if it
never works.
