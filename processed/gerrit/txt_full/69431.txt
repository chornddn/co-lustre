--- Commit Message ---
LU-20635 lnet: adopt an existing unlocked peer

With lock_prim_nid=0, a client mount can fail with -EIO. This
failure occurs when the server advertises a primary NID that is not
the mount NID.

LNetAddPeer() adds the NIDs that Lustre knows for a node. When an
unlocked peer holds one of these NIDs as a non-primary NID,
lnet_peer_add() deletes that peer. It then makes the NID the primary
NID of a new peer. Discovery can move the primary NID back, so the
primary NID of the node changes on each add. PtlRPC posts reply
buffers for the cached primary NID, so replies stop matching them.

When the caller does not configure or lock the peer, adopt an
existing peer that is not CONFIGURED or LOCK_PRIMARY. Return -EEXIST.
At lock_prim_nid=1, LNetAddPeer() then merges that peer into the
primary peer, as LU-20439 requires.

Add sanity-lnet test_43 for the lock_prim_nid=0 case.
