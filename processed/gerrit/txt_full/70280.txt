LU-20869 tests: parallelize sanity-sec 31 tunefs

test_31 and cleanup_31 run about 40 serial tunefs calls per pass,
three or more per target, each with its own ssh and a stop and
writeconf round trip.

Do two tunefs per target, one to erase the old mgsnode and one to
set the new one with writeconf, with the mds1 service node options
in the same calls, on all targets in parallel. The two must stay
separate: on ZFS a key erased and set in one call is stored with a
leading ':'. The parallel calls use parallel_start() with a new
TUNEFS operation, so PARALLEL_OPS=0 or PARALLEL_TUNEFS=0 serializes
them. MMP is left enabled by the servicenode tunefs, as before.

cleanup_31 restored an existing mds1 failover node with
--servicenode, though the framework formats with --failnode, so
mds1 was left with only its partner as a service node and could
not mount. Restore it with the option it was set with.

On a rocky9 ldiskfs cluster (1 MDS with 4 MDTs, 1 OSS with 4 OSTs,
1 client), test 31 took 422s before and 400s after. At about 20s
saved per run and 6972 CI runs per 30 days, an estimate of roughly
40 hours.
