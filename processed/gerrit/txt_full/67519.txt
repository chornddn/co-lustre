--- Commit Message ---
LU-18687 build: make lustre_compat headers transparent

Put include/lustre_compat ahead of the kernel headers from the
top-level Kbuild, which in-kernel builds do not use, and filter it
out again for ldiskfs, which is kernel code. Have each compat header
named after a kernel header pull in the real one using include_next,
so including the native header also brings in the compat additions.
Kernel headers now reach these wrappers too, so they must not drag
in heavy headers or need types that are not yet complete, and
lustre_compat must define COMPAT_BUILD before its first include.

Existing <lustre_compat/...> includes keep working; the following
patches move users over a directory at a time.
